ドメイン移管ができない原因とロックの解除

Web制作ドメイン移管ができない原因とロックの解除NORTIQ LABS · COLUMN

ドメインの移管が進まない原因はどこにある？

多いのは、指定事業者変更ロックが設定されている場合と、認証コードを受け取れていない場合です。どちらも現在の管理指定事業者を経由して進めます。

管理指定事業者とは、JPドメイン名の登録や変更の手続をJPRSに対して行う事業者です。制作会社やサーバ会社がこの役割を担っている場合があります。

止まっている箇所の切り分け

JPRSの規則では、手続の段階が条文で分かれています。どの段階で止まっているかを先に特定します。

止まっている箇所 根拠となる条項 次にすること
変更の手続そのものが進まない 第5条第4項 (管理指定事業者の変更) 現在の管理指定事業者に申込の状況を確認します
ロックがかかっている 第5条第4項の2 (指定事業者変更ロックの設定) 第5条第4項の3にもとづき解除を依頼します
認証コードが手元に無い 第5条第4項の4 (最新の認証コードの取得) 管理指定事業者を経由して取得します
登録者を変える手続と混同している 第25条第2項の2 (ドメイン名移転ロック) どちらの手続が必要かを確認します

出典: 株式会社日本レジストリサービス『汎用JPドメイン名登録等に関する規則』。

変更先の事業者に制限がある点にも注意します。同規則第5条第4項では、取次規則第15条の2で業務委託の一時停止を受けている事業者を、変更先として指定することはできないとされています。

  1. 新しい制作会社に、どの段階まで進んでいるかを確認します。所要時間の目安は即日です。
  2. 現在の管理指定事業者に、ロックの状態と認証コードの発行を確認します。つまずきやすい点は、窓口が制作会社経由になっていて、問い合わせの往復で数日かかることです。
  3. 登録者の情報が自社になっているかを確認します。詳しくは後述します。

JPRSに直接申し出る手続ではない理由

同規則では、ロックの設定も解除も、登録者が管理指定事業者を経由して行う形で定められています。登録者がJPRSに直接申し出る形ではありません。

このため、現在の事業者への依頼が実質的な第一歩になります。移管先の新しい制作会社に頼んでも、ロックは解除できません。

なお、認証コードを用いない方法は経過措置で終わっています。同規則の附則18では、2022年11月13日から2023年11月11日までの間、管理指定事業者の変更手続と移転登録申請について認証コードを用いない方法によることができるとされていました。現在は認証コードを前提に段取りします。

指定事業者変更ロックはどう解除する？

登録者が管理指定事業者を経由して、いつでも解除できると規則に定められています。依頼の相手は現在の管理指定事業者です。

指定事業者変更ロックとは、汎用JPドメイン名を指定事業者変更禁止状態にする設定です。第三者による勝手な移管を防ぐための仕組みです。

規則上の位置づけ

JPRSの規則では、設定と解除がそれぞれ別の項に定められています。

  • 第5条第4項の2では、登録者は管理指定事業者を経由して、汎用JPドメイン名を指定事業者変更禁止状態 (指定事業者変更ロック) に設定することができるとされています。この状態では管理指定事業者を変更できません。
  • 第5条第4項の3では、登録者は管理指定事業者を経由して、いつでもこのロックの設定を解除することができるとされています。

出典: 株式会社日本レジストリサービス『汎用JPドメイン名登録等に関する規則』。

規則で「いつでも解除することができる」と定められている点が要点です。待機期間の定めがあるわけではありません。実際にかかる時間は、事業者側の受付と作業の体制によります。

解除を依頼するときに伝えること

依頼の連絡に含める内容は次のとおりです。

  1. 対象のドメイン名を正確に書きます。所要時間の目安は即日です。つまずきやすい点は、サブドメインを含めて書いてしまい、対象が曖昧になることです。
  2. 指定事業者変更ロックの解除を依頼する旨を明記します。ドメイン名移転ロックとは別の設定なので、名称をそのまま使います。
  3. 併せて最新の認証コードの発行を依頼します。解除と発行を1回の連絡でまとめると、往復が減ります。
  4. 登録者としての本人確認に必要な書類を確認します。つまずきやすい点は、管理画面の権限が制作会社にしか無く、登録者本人からの依頼と認められるまでに時間がかかることです。

解除の窓口が変わる場合

同規則では、第5条第5項に定める対象のドメイン名にロックがかかっている場合は、JPRSが指定する事業者に解除を求める形になるとされています。

通常の汎用JPドメイン名であれば、依頼の相手は現在の管理指定事業者です。自社のドメイン名がこの対象に当たるかどうか分からない場合は、現在の事業者に確認します。

なお、ロックの具体的な解除の操作手順は管理指定事業者ごとに異なります。規則から分かるのは、解除を現在の管理指定事業者を経由して行うという筋道までです。

認証コードは誰から受け取る？

管理指定事業者を経由して、JPRSが発行する最新の認証コードを取得します。ロックが設定されている場合は、先に解除します。

認証コードとは、申請者が登録者本人、または登録者から申請権限を委任された人であることを確認するための文字列です。JPRSが生成するもので、利用者が文字列を指定することはできません。出典: JPRS『ドメイン名の管理指定事業者の変更』。

取得の順番

JPRSの公式ページでは、指定事業者変更の手続きが10段階として示されています。変更元である現在の事業者が関与する段階が含まれます。

  1. JPRS WHOISでロックの状態を確認します。所要時間の目安は数分です。指定事業者変更ロックが設定されていれば、ロック状態の欄に「AgentChangeLocked」と表示されます。
  2. ロックがあれば、現在の管理指定事業者に解除を依頼します。
  3. 現在の事業者に認証コードを確認します。事業者がJPRSに発行を依頼する流れです。
  4. 新しい事業者に指定事業者変更を申し込みます。
  5. JPRSが変更元に意思確認を依頼し、登録者が変更元に承認または不承認を回答します。つまずきやすい点は、この回答が止まると手続が進まないことです。
  6. 承認されるとJPRSが管理指定事業者を更新します。

手続き全体には数日程度かかる場合があるとされています。前の制作会社が変更元として関与する段階があるため、日程には余裕が必要です。

認証コードの扱いの注意

規則では、認証コードの管理についても定めが置かれています。

  • 第5条第4項の5では、受領した認証コードを厳重に管理し漏洩してはならないこと、変更手続以外の目的で第三者に開示してはならないことが定められています。
  • 第5条第4項の6では、JPRS所定の方法により認証コードが正当であることをJPRSが確認した場合、その変更手続は登録者の意思に基づいて真正に行われたものとして取り扱うとされています。

出典: 株式会社日本レジストリサービス『汎用JPドメイン名登録等に関する規則』。新しい制作会社に渡す場合も、変更手続のためという目的の範囲で扱います。

有効期限があることを前提に段取りする

認証コードの有効期限は、JPRSが認証コードを生成した日の翌日を1日目とした35日後の23時59分59秒です。出典: JPRS『ドメイン名の管理指定事業者の変更』。

  • 期限が切れた場合は申請が受け付けられず、変更元への認証コードの確認からやり直しになります。
  • 変更が承認されると、申請に使った認証コードは利用できなくなります。再度変更する場合も確認からやり直します。

つまずきやすい点は、先に認証コードだけ取って、制作会社の選定や契約に時間をかけてしまうことです。35日の期限内に申請まで終える段取りにします。

指定事業者変更とドメイン名移転はどちらが必要？

管理する事業者を変えるだけなら指定事業者変更、登録者そのものを変えるならドメイン名移転です。規則の上でも別の手続です。

登録者とは、そのドメイン名の権利を持つ主体です。御社の名義になっていれば、制作会社を変えるだけなら指定事業者変更で足ります。

2つの手続の違い

JPRSの規則では、条文が分かれています。

手続 変わるもの ロックの条項 認証コードの条項
指定事業者変更 管理する事業者 第5条第4項の2 (指定事業者変更ロック) 第5条第4項の4
ドメイン名移転 登録者 第25条第2項の2 (ドメイン名移転ロック) 第25条第2項の4

出典: 株式会社日本レジストリサービス『汎用JPドメイン名登録等に関する規則』。

第25条第2項の3では、登録者は管理指定事業者を経由して、いつでもドメイン名移転ロックを解除することができるとされています。解除の筋道は指定事業者変更ロックと同じです。

ロックの効き方には違いがあります。JPRSの公式ページによると、指定事業者変更ロックは、汎用JPドメイン名と都道府県型JPドメイン名ではドメイン名移転申請と指定事業者変更申請の両方を受け付けない設定で、属性型と地域型では指定事業者変更申請のみが制限されます。出典: JPRS『ドメイン名の管理指定事業者の変更』。

登録者が制作会社になっている場合

自社ではなく制作会社が登録者になっている場合は、指定事業者変更だけでは解決しません。

  1. JPRS WHOISで登録者の表示を確認します。所要時間の目安は数分です。
  2. 自社名義になっていなければ、ドメイン名移転の手続が必要になります。つまずきやすい点は、指定事業者変更の申込を進めてから名義の問題に気づき、手続をやり直すことです。
  3. 移転と指定事業者変更の両方が必要な場合の扱いを、事業者に確認します。JPRSの公式ページでは、指定事業者変更を伴うドメイン名移転の手続きも、指定事業者変更の手続きに含まれるとされています。

名義が自社かどうかは、移管の作業に入る前に確かめておく項目です。契約名義の決め方そのものは、当社の別の記事で扱っています。

なお、都道府県型JPドメイン名には別の規則があり、属性型 (co.jpなど) も登録の条件が異なります。gTLD (.comなど) はICANNの移管ポリシーが適用される別の制度です。本記事で引用した条文は汎用JPドメイン名の規則です。

移管の期間はリニューアルの日程にどう影響する？

認証コードの有効期限とDNSの反映の時間があるため、公開日の直前に移管を入れると間に合わない場合があります。移管は公開日より前に終わらせる工程として置きます。

移管の手続は、自社だけで完結しません。前の事業者の承認と、JPRSの更新を待つ段階が挟まります。

逆算で押さえる期限

日程に効く公式の期限は次のとおりです。

項目 期間 出典
認証コードの有効期限 発行日の翌日を1日目とした35日後の23時59分59秒まで JPRS ドメイン名の管理指定事業者の変更
DNSのTTLで示されるキャッシュ可能時間の例 3600秒 (1時間) JPRS用語辞典 TTL
TTLが取りうる値の上限 2147483647秒 JPRS用語辞典 TTL

URLが変わるリニューアルを行う場合は、さらに次の期間が関わります。

  • Search Consoleのアドレス変更ツールで、Googleが旧サイトのシグナルを新サイトへ優先的に移す動作が続く期間は180日です。リダイレクトを維持すべき最低期間も180日です。出典: Google Search Console ヘルプ アドレス変更ツール。
  • 旧ドメインの料金は、悪用を防ぐため1年以上払い続けることが推奨されています。出典: 同ヘルプ。
  • リダイレクトは1年以上保持する案内があり、Googlebotがたどれるリダイレクトの上限は10ホップ、推奨されるチェーンの長さは5未満 (理想は3以下) です。出典: Google 検索セントラル URLの変更を伴うサイト移転。

公開日から逆算する手順そのものは、当社の別の記事で扱っています。

移管と公開を同じ日にしない

工程を重ねると、問題が起きたときに原因の切り分けができなくなります。

  1. 移管を先に終わらせます。所要時間の目安は、手続き全体で数日程度かかる場合があるとされています。
  2. 移管が完了したことをWHOISで確認します。つまずきやすい点は、申込の完了と移管の完了を取り違えることです。
  3. その後にDNSの切り替えと公開を行います。TTLは切り替えの前に短くしておきます。

実装の観点では、DNSの反映を待つ間に古いサーバと新しいサーバの両方が応答する状態になります。移管と公開を同日にすると、この状態と移管の遅れが重なり、どちらが原因か分からなくなります。

移管を止めないために発注前にできることは？

契約名義と管理画面の権限、ロックの状態を発注前に確認しておくと、移管の段階で止まりません。いずれも新しい制作会社を決める前に自社で確かめられます。

移管が止まる原因の多くは、権限と名義が自社の手元に無いことです。確認は数十分で済みます。

発注前に確認する3点

確認する項目 確認する場所 自社になっていない場合
登録者の名義 JPRS WHOIS ドメイン名移転の手続が必要になります
指定事業者変更ロックの状態 JPRS WHOISのロック状態の欄 現在の管理指定事業者に解除を依頼します
Search Consoleの権限 Search Consoleのユーザと権限 自社の担当者を所有者にします

Search Consoleの権限は4種類に分かれています。所有者はプロパティを完全に管理でき、ユーザの追加と削除、設定変更、全データの表示ができます。プロパティには確認済み所有者が1人以上必要とされています。出典: Google Search Console ヘルプ『ユーザと権限の管理』。

確認済み所有者は管理画面の操作だけでは外せません。同ヘルプでは、確認済み所有者はHTMLファイルやHTMLタグなどの確認トークンで所有権を証明した人であり、削除するにはサイトからそのトークンを取り除く必要があるとされています。トークンが残っていると、削除された所有者が再確認によってアクセスを回復できるとされています。

つまずきやすい点は、確認トークンが他のサービス (Merchant CenterやGoogle Workspaceなど) でも使われている場合に、削除がそれらに影響することです。前の制作会社の所有権を外すときは、何のためのトークンかを確認してから消します。

新しい制作会社に伝える情報

移管をスムーズに進めるため、次を先に共有します。

  1. 現在の管理指定事業者の名前を伝えます。所要時間の目安は即日です。
  2. ロックの状態と、解除を依頼済みかどうかを伝えます。
  3. 認証コードを取得済みの場合は、発行日を伝えます。有効期限から逆算した日程が組めます。
  4. 登録者の名義が自社かどうかを伝えます。つまずきやすい点は、名義の確認を飛ばして日程を組み、移転の手続が後から追加されることです。

御社で移管の段取りまで含めて任せたい場合、当社ではリニューアルの工程に移管の確認を先に置く形で進めています。現在のドメインの状態が分からない段階でも整理できます。お問い合わせ (/contact) から、ドメイン名と現在の制作会社との契約の状況をお知らせください。

よくあるご質問

ドメインの移管で止まったときに多い質問をまとめます。個別の手続は、現在の管理指定事業者への確認が前提です。

ロックがかかっているかどうかは、自社で確認できますか

確認できます。ロックの状態はJPRS WHOISの「ロック状態」の欄に表示され、指定事業者変更ロックが設定されていれば「AgentChangeLocked」と表示されます。出典: JPRS『JPRS WHOIS検索結果の表示例』。

手続きを始める前にこの欄を見ておくと、申請が受け付けられない状態かどうかが先に分かります。

制作会社が解除に応じてくれない場合、JPRSに直接依頼できますか

汎用JPドメイン名の規則では、ロックの解除は登録者が管理指定事業者を経由して行う形で定められています。登録者がJPRSに直接申し出る手続ではありません。出典: 株式会社日本レジストリサービス『汎用JPドメイン名登録等に関する規則』第5条第4項の3。

JPRSの公式ページでは、解除の方法は管理指定事業者によって異なり、指定事業者によっては本機能の取り扱いを行っていない場合があるとされています。まずは現在の事業者に、登録者からの依頼として解除を求める形になります。

認証コードを教えてもらえない場合はどうすればよいですか

認証コードはJPRSが生成し、現在の事業者がJPRSに発行を依頼する流れです。利用者が文字列を指定することはできません。出典: JPRS『ドメイン名の管理指定事業者の変更』。

登録者本人からの依頼であることを示す形で、改めて発行を依頼することになります。管理画面の権限が制作会社にしか無い場合は、本人確認の書類をそろえる時間を見込んでおきます。

属性型 (co.jpなど) や.comでも同じ手続ですか

同じではありません。本記事で引用した条文は汎用JPドメイン名の規則です。都道府県型JPドメイン名には別の規則があり、属性型と地域型も登録の条件が異なります。

ロックの効き方にも違いがあります。JPRSの公式ページによると、指定事業者変更ロックは汎用と都道府県型ではドメイン名移転申請と指定事業者変更申請の両方を受け付けない設定で、属性型と地域型では指定事業者変更申請のみが制限されます。gTLD (.comなど) はICANNの移管ポリシーが適用される別の制度です。

移管の手続中にサイトやメールは止まりますか

指定事業者変更は管理する事業者が変わる手続で、DNSの設定の切り替えとは別です。移管だけでサイトやメールの配信先が変わるわけではありません。

止まるかどうかは、サーバの移転を同時に行うかで変わります。サーバを移す場合は、メールの扱いを含めた手順を別に組む必要があります。サーバ移転でメールを止めない手順は、当社の別の記事で扱っています。
