ホームページ改ざんの復旧期間と費用の目安

Web制作ホームページ改ざんの復旧期間と費用の目安NORTIQ LABS · COLUMN

ホームページが改ざんされたら、何から始めますか？

最初に行うのは公開の停止と証跡の保全で、サイトを元に戻す作業はその後です。先に上書きで直すと、原因の特定ができなくなります。

原因がわからないまま元に戻すと、同じ入口から再び改ざんされます。急いで直したい気持ちは当然ですが、順番を守るほうが結果的に早く終わります。

発生直後の5手順

  1. サイトの公開を止める (所要時間の目安: 10分から30分)。サーバのメンテナンス表示に切り替えます。つまずきやすい点は、止める権限を制作会社しか持っていない場合で、連絡がつくまで何もできません。
  2. 証跡を保全する (目安: 30分から2時間)。改ざんされたファイルとアクセスログを、上書きせずに別の場所へ複製します。この時点で消してしまうと、後の調査ができません。
  3. 制作会社とサーバ会社へ連絡する (目安: 当日中)。両方へ同時に連絡してください。サーバ側のログは保存期間が限られており、時間が経つと取得できません。
  4. 影響範囲を確認する (目安: 半日から数日)。問い合わせフォームの送信先、会員情報、決済の有無を確認します。個人情報が関係する場合は報告の義務が生じる可能性があります。
  5. 復旧の方針を決める (目安: 半日)。バックアップから戻すのか、該当ページを削除するのか、作り直すのかを決めます。

やってはいけない対処

次の3つは、被害を長引かせる原因になります。

やってはいけない対処 何が起きるか
改ざんされたファイルをその場で修正する 証跡が消え、どこから侵入されたかを特定できなくなります
ログを消す、サーバを初期化する 原因の特定に必要な記録が失われ、再発防止策を決められません
復旧だけ済ませて公開を再開する 同じ脆弱性が残ったままなので、数日で再び改ざんされます

実装の側からもう1つ注意点を挙げます。改ざんはトップページだけに起きるとは限りません。検索エンジン向けにだけ別の内容を返す形で仕込まれる場合があり、画面を見て確認しても気づけません。確認はファイルの差分とログで行ってください。

復旧にかかる期間と費用は次の見出しで扱います。

ホームページ改ざんの復旧にはどのくらいの期間がかかりますか？

原因が特定できていてバックアップがある場合は数日、原因の特定からやり直す場合や記録が残っていない場合は1か月以上かかる例もあります。期間を決めるのは被害の派手さではなく、記録と復元手段が残っているかどうかです。

期間を分ける3つの条件

条件 揃っている場合 欠けている場合
アクセスログが残っている 侵入経路の特定が数日で済みます 経路を推定で絞るしかなく、調査が長引きます
改ざん前のバックアップがある 復元して差分を当て直せます 作り直しに近い作業量になります
止める権限と連絡先が社内にある 発覚から数時間で公開を止められます 連絡がつくまで被害が広がり続けます

実装の側から見ると、最も時間を奪うのは1つ目です。侵入経路がわからないまま復旧すると、公開を再開したあとに再発し、調査を最初からやり直すことになります。

公的資料から読める期間の幅

ホームページの改ざんに限った復旧期間の公的な集計はありません。近いものとして、ランサムウェア被害の集計から期間の幅が読み取れます。

警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」(令和7年3月13日) によると、被害に遭った企業・団体等へのアンケートで、調査と復旧に1か月以上を要した組織の割合は令和5年の44%から令和6年は49%に増加しました。この1か月以上の集計には、回答時点で復旧中だった組織も含まれます。

備えの有無で差が出る点も同じ資料に示されています。調査・復旧に1,000万円以上かつ1か月以上を要した組織のうち、サイバー攻撃を想定状況に含むBCPを策定済みだった組織は11.8%にとどまる一方、1週間未満で復旧した組織では23.1%が同種のBCPを策定していました。

出典: 警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」(令和7年3月13日)

いずれもランサムウェア被害の数値であり、改ざんだけを対象にした集計ではありません。ただし復旧が長引く原因は共通しています。あらかじめ手順を決めていた組織のほうが短く収まる、という傾向は改ざんでも同じです。費用への影響は次の見出しで扱います。

改ざんの復旧費用はいくらかかりますか？

費用は調査、復旧作業、再発防止の3つに分かれ、このうち調査の費用が期間に比例して伸びます。復旧作業そのものは、バックアップがあれば金額の読める作業です。

ホームページの改ざんに限った費用の公的な集計はありません。費用の規模の目安としては、前の見出しと同じランサムウェア被害の集計が参考になります。

費用が発生する3区分

区分 含まれる作業 金額の決まり方
調査 ログの解析、侵入経路の特定、影響範囲の確認 調査にあたる人の工数。期間が伸びるほど増えます
復旧作業 バックアップからの復元、差分の適用、動作確認 作業量でほぼ確定します
再発防止 脆弱性の修正、認証の強化、構成の見直し 直す範囲で変わります。ここを省くと再発します

見落としやすいのは、この3区分の外にある費用です。問い合わせへの対応、取引先への説明、個人情報が関係する場合の報告の手続きは、社内の人の時間として発生します。

期間が長いほど費用が上がる理由

費用が期間に連動するのは、調査が人の時間で積み上がるからです。警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」(令和7年3月13日) では、調査・復旧に1,000万円以上の費用を要した組織の割合が令和5年の37%から令和6年は50%に増加したと示されています。同じ資料では、1億円以上の費用を要した組織の割合は、復旧に要した期間が長い方が高いという傾向も示されています。

出典: 警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」(令和7年3月13日)

これもランサムウェア被害の数値で、ホームページの改ざんだけを対象にした集計ではありません。ただし費用の構造は同じです。期間を短くできれば調査の工数が減り、総額も下がります。

費用を抑える手段は被害後ではなく事前にあります。具体的には次の3つです。

  1. アクセスログの保存期間を延ばす (調査の対象が残り、経路の特定が早く終わります)
  2. バックアップを別の場所に世代で持つ (復元できれば復旧作業が確定した金額になります)
  3. 誰がどこへ連絡するかを一枚の紙にしておく (発覚から公開停止までの時間が短くなります)

この3つはいずれも、平常時の保守の範囲で用意できるものです。保守契約との関係は次の見出しで扱います。

復旧の費用は保守契約に含まれますか？

多くの保守契約では、改ざん後の調査と復旧は月額に含まれず別請求になります。含まれるのは一次対応とバックアップからの復元までという契約が一般的です。

御社の契約がどちらかは、契約書の文言を見れば判断できます。確認する箇所は「保守の範囲」と「免責」の2つです。

含まれる作業と含まれない作業

作業 月額に含まれることが多い 別請求になることが多い
発覚後の一次対応 (公開停止、状況の確認) 含まれる
バックアップからの復元 含まれる (世代と保管条件の範囲内)
ログの解析と侵入経路の特定 別請求
影響範囲の調査と報告書の作成 別請求
脆弱性の修正と構成の見直し 別請求
第三者の専門業者による調査 別請求 (実費)

境目は「元に戻す作業か、原因を調べて直す作業か」です。戻すだけなら月額の範囲、調べて直すなら別請求と覚えてください。

契約書で確認する文言

契約書と保守の仕様書で、次の5点を確認してください。

  1. 保守の範囲に「障害対応」とだけ書かれていないか。改ざんのような第三者の行為による事象が障害に含まれるかは、この一語では判断できません。
  2. バックアップの世代と保管場所が書かれているか。何世代をどこに置くかが書かれていなければ、復元できる保証はありません。
  3. 復旧作業の費用の扱いが書かれているか。月額の範囲か、別請求か、上限があるかを明示します。
  4. 免責の条項に何が挙げられているか。第三者の不正アクセスを免責としている契約では、復旧の義務自体が制作会社側にありません。
  5. 一次対応までの時間と対応する時間帯が書かれているか。発覚が金曜の夜で、対応が平日の日中のみであれば、公開停止は週明けになります。

実装の側から1点補足します。改ざんの復旧は、技術的には「どの時点の状態に戻すか」を決める作業です。バックアップが1世代しかない場合、そのバックアップ自体が改ざん後に取得されたものである可能性があります。世代で持つ意味はここにあります。

責任の帰属そのものの判断は、公開後の脆弱性と保守の責任範囲を扱った記事で詳しく解説しています。本記事では費用の負担がどちら側になるかの線として押さえてください。

改ざんはなぜ起きますか？復旧後に何を直しますか

入口になるのは公開後に公表された脆弱性の放置と、管理画面の認証の弱さです。復旧後に同じ構成へ戻すと再発します。

改ざんは狙い撃ちではなく、自動化された探索によって起きることが多いです。小規模なサイトだから対象外になる、という前提は成り立ちません。

公開後も脆弱性が見つかり続ける前提

改ざんの件数は四半期ごとに大きく動きます。JPCERT/CCの四半期レポート (2025年4月1日から6月30日) では、Webサイト改ざんに分類されたインシデントが231件で、前四半期の95件から143%増加したと報告されています。

改ざんされたサイトの使われ方も同じ資料から読み取れます。2026年4月1日から6月30日の四半期レポートでは、インシデント報告のうち89.3%がフィッシングサイトに分類されています。

出典: JPCERT/CC「四半期レポート」(2025年4月1日から6月30日、2026年4月1日から6月30日)

入口となる脆弱性も、公開後に見つかり続けます。IPA「ソフトウェア等の脆弱性関連情報に関する届出状況 2026年第2四半期」では、ウェブサイトに関する脆弱性の届出が同四半期に65件、届出受付開始からの累計で13,599件に達しています。

出典: IPA「ソフトウェア等の脆弱性関連情報に関する届出状況 2026年第2四半期」

つまり、公開した時点で安全だった構成が、半年後も安全である保証はありません。更新を止めた期間の長さが、そのまま入口の数になります。

復旧とあわせて直す項目

復旧のタイミングは、構成を直す機会でもあります。元に戻すだけで終わらせず、次の5点を同時に行ってください。

  1. CMS本体とプラグイン、サーバのソフトウェアを最新に上げる (目安: 半日。つまずきやすい点は、長く放置した環境では一度に上げられず、段階的に上げる必要があることです)
  2. 管理画面のパスワードを全件変更し、多要素認証を有効にする (目安: 1時間)
  3. 使っていないプラグイン、テーマ、古い管理アカウントを削除する (目安: 1時間。残っているだけで入口になります)
  4. ファイルの書き込み権限を見直す (目安: 1時間。つまずきやすい点は、権限を絞ると管理画面からの更新ができなくなる場合があることです)
  5. アクセスログの保存期間とバックアップの世代を見直す (目安: 半日)

実装の側から1点だけ強調します。2の多要素認証は、費用がほぼかからないうえに効果が最も大きい項目です。復旧のついでに必ず入れてください。

保守契約で決め直す項目は次の見出しで扱います。

保守契約でいま決め直す項目は何ですか？

決め直すのはバックアップの世代と保管場所、復旧の目標時間、調査費用の扱い、連絡の経路の4点です。被害が起きる前にこの4点を書面にしておくと、復旧の期間と費用がどちらも下がります。

被害は規模に関係なく起きます。警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」では、令和6年中に報告されたランサムウェア被害222件のうち、中小企業が140件、大企業が61件を占めています。件数では中小企業が全体の約63%です。

出典: 警察庁「令和6年におけるサイバー空間をめぐる脅威の情勢等について」第3項 ランサムウェアの情勢

バックアップの世代と保管場所

決めるのは3点です。何世代を残すか、どこに置くか、復元の試行を誰がいつ行うかです。

項目 決めておく内容
世代 日次で何世代、週次で何世代を残すか
保管場所 本番と同じサーバ以外に1か所を置くか
復元の試行 年に何回、誰が実際に戻してみるか

本番と同じサーバだけにバックアップを置く構成は避けてください。侵入された範囲にバックアップが含まれると、戻す先がなくなります。

復旧の目標時間の決め方

目標時間は、サイトが止まることで何が止まるかから決めます。

  1. 会社案内が主たる役割のサイト: 公開停止のまま数日かかっても業務は止まりません。一次対応は平日の日中で足ります。
  2. 問い合わせや採用の応募が入るサイト: 止まる時間がそのまま機会損失になります。代替の連絡先を載せたお知らせページへ即時に切り替えられる手当が要ります。
  3. 予約や受注が入るサイト: 復旧の目標時間を時間単位で決め、休日と夜間の一次対応を契約に含めます。

多くの中小企業のコーポレートサイトは1か2です。3の水準を契約すると月額は上がるため、自社がどれに当たるかを先に決めてください。

費用の上限と事前合意

調査と復旧が別請求になる前提で、次の2点を事前に合意しておきます。

  1. 調査に入る前に見積もりを出す取り決め (金額がわからないまま作業が進むことを防ぎます)
  2. 自社で判断できる上限額と、それを超える場合の決裁の経路

実務では、被害の当日に決裁者へ連絡がつかないことが起きます。上限額と代理の決裁者を先に決めておくと、復旧の着手が1日早まります。

連絡の経路も同じです。制作会社、サーバ会社、社内の決裁者の連絡先を一枚にまとめ、年に1回更新してください。

改ざんに備える年次の点検手順

年に1回、復元の試行と連絡先の確認を行えば、実際に起きたときの復旧期間を短くできます。点検は半日で終わる作業です。

点検の目的は、書面どおりに動くかを確かめることです。契約書にバックアップと書かれていても、実際に戻せるかは試すまでわかりません。

年次で行う4つの点検

  1. バックアップからの復元を試す (目安: 2時間から半日)。検証用の環境に戻し、表示とフォームの送信まで確認します。つまずきやすい点は、データベースだけ戻してファイルを戻し忘れる構成で、画面は出ても機能が動きません。
  2. 連絡先の一覧を更新する (目安: 30分)。制作会社、サーバ会社、社内の決裁者と代理の決裁者を確認します。担当者の異動で連絡がつかなくなっているのが最も多い不具合です。
  3. 管理アカウントの棚卸しを行う (目安: 1時間)。退職者と委託終了した業者のアカウントを削除し、残すアカウントの多要素認証を確認します。
  4. 更新の滞留を確認する (目安: 1時間)。CMS本体とプラグイン、サーバのソフトウェアに未適用の更新がどれだけ溜まっているかを一覧にします。

この4つのうち、年1回では足りないのは4です。更新の確認は月次で行うのが前提で、年次の点検は溜まっていないかの確認にあたります。

実装の側から1点補足します。1の復元の試行は、本番環境で行ってはいけません。検証用の環境を用意するか、制作会社に作業として依頼してください。本番で試すと、戻した時点より後の更新が消えます。

当社に相談する場合の進め方

改ざんの相談で多いのは、保守契約の内容を把握していないまま被害に遭った状態です。原因は契約時に復旧の条件を詰めていないことで、被害の前に書面を見直せば避けられます。

当社では、現在の保守契約と構成を確認したうえで、バックアップの世代と保管場所、復旧の目標時間、調査費用の扱い、連絡の経路の4点を文書にしてお渡ししています。他社で制作したサイトの保守の引き継ぎもお受けしています。

いまの契約で改ざんに対応できるかを確認したい場合は、無料診断で契約書と構成をもとに不足している項目をご提示します。すでに改ざんが起きている場合は、公開の停止と証跡の保全を先に行い、そのうえでご連絡ください。

よくあるご質問

この記事に関して多い質問と回答をまとめます。回答はいずれも2026年10月時点の情報です。

ホームページが改ざんされたか、どうやって気づけますか？

多くは外部からの指摘で気づきます。検索結果に身に覚えのない文言が出る、ブラウザが警告を表示する、サーバ会社から連絡が来るという順です。自社で早く気づくには、ファイルの変更の検知とアクセスログの定期確認を保守の範囲に入れておく必要があります。検索エンジンにだけ別の内容を返す形の改ざんは、画面を見るだけでは気づけません。

改ざんされたページを消すだけで対処は終わりますか？

終わりません。入口になった脆弱性や認証の弱さが残っていれば、同じ経路から再び改ざんされます。ページの削除は被害の拡大を止める手段であって、原因の除去ではありません。公開を再開する前に、更新と認証の見直しを済ませてください。

復旧の費用は保守の月額に含まれますか？

多くの契約では、一次対応とバックアップからの復元までが月額の範囲で、ログの解析や影響範囲の調査、脆弱性の修正は別請求です。境目は「元に戻す作業か、原因を調べて直す作業か」です。契約書の保守の範囲と免責の条項を確認してください。

バックアップがあれば必ず元に戻せますか？

戻せない場合があります。1つは、バックアップが改ざん後に取得されたもので、改ざんの内容ごと保存されている場合です。もう1つは、バックアップが本番と同じサーバにしかなく、侵入された範囲に含まれていた場合です。世代で残し、別の場所に1か所置く構成にしてください。

改ざんされたことを公表する必要はありますか？

事案によります。個人情報の漏えいのおそれがある場合は、個人情報保護法にもとづく報告と本人への通知が必要になる可能性があります。会員情報や問い合わせフォームの送信内容が関係するかを先に確認し、判断は弁護士など専門家に相談してください。公表の有無とは別に、取引先への説明は早いほうが影響を小さく抑えられます。
