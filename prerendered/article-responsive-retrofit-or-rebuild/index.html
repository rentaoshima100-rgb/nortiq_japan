ホームページのスマホ対応｜後付けと作り直しの判断

Web制作ホームページのスマホ対応NORTIQ LABS · COLUMN

スマホ対応は後付けで直せますか？

現在の構成がレスポンシブかどうかで分かれます。別URLや動的配信で作られている場合は、構成の変更を伴うため後付けでは収まりません。

Googleがモバイル対応の構成として挙げているのは3構成です。出典: Google検索セントラル「モバイルサイトとモバイルファーストインデックスに関するおすすめの方法」。どれで作られているかが、作業量を決めます。

つまり、見積もりの前に調べるのは見た目ではありません。配信の仕組みです。各構成の違いは後述します。

あなたのホームページは、いま何点ですか？

URLを入れるだけで、SEO・セキュリティ設定・表示速度・AI対応をその場で採点します。登録は不要、無料です。

ホームページを無料診断する →

最初に確認する3つのこと

次の3点を調べます。所要時間の目安は、サイトの規模が数十ページなら半日程度です。

  1. スマホとパソコンでURLが同じかどうか つまずきやすい点: スマホで見たときにアドレスがsp付きのURLに変わる場合、別URLの構成です。
  2. ブラウザの幅を狭めたときにレイアウトが変わるかどうか つまずきやすい点: 横スクロールが出るだけの場合は、レスポンシブの指定が入っていません。
  3. モバイル側のCore Web Vitalsのどの指標が外れているか つまずきやすい点: パソコン側の数値で判断しないでください。モバイルとデスクトップは分けて集計されます。

3番目の計測結果が、後付けで足りるかの判断材料になります。計測の方法と見方は後述します。

後付けで済む場合と済まない場合

同じ「スマホで見づらい」でも、原因によって作業の重さが変わります。

現在の状態 対応の見込み
レスポンシブだがレイアウトが崩れている 後付けの調整で収まることが多いです
レスポンシブの指定が入っていない テンプレートの改修になります
別URLまたは動的配信で運用している 構成の移行を伴い、作り直しに近い作業です
CMSが古く、テンプレートを直せない 土台の入れ替えを含む判断になります

実装の側から言うと、2行目と3行目の差は見た目では分かりません。HTMLの配信の仕組みを見ないと区別できないため、自己判断で見積もりを依頼すると前提が食い違います。

まずは構成を確定させてください。その後に、どの指標が外れているかを測ります。

スマホ対応の構成は何種類ありますか？

Googleが挙げる構成は3種類です。同じURLで同じHTMLを配信するレスポンシブデザイン、同じURLで端末ごとに異なるHTMLを配信する動的配信、別URLで配信する方式です。

出典: Google検索セントラル「モバイルサイトとモバイルファーストインデックスに関するおすすめの方法」。このうちどれで作られているかが、後付けで済むかどうかを決めます。

3つのうち、現在の新規制作で選ばれるのはほぼレスポンシブです。別URLと動的配信は、過去に作られたサイトで残っている構成です。

3つの構成の違い

同ガイドの定義を整理すると次のようになります。

構成 URL 配信するHTML
レスポンシブデザイン 端末によらず同じ 同じHTMLを配信し、表示だけ画面サイズに応じて変える
動的配信 端末によらず同じ user-agent判定で端末ごとに異なるHTMLを配信する
別URL 端末ごとに別 端末ごとに異なるHTMLを別々のURLで配信する

同ガイドは、レスポンシブデザインでは本文とメタデータがモバイルとデスクトップで同じになるとしています。別URLと動的配信は、2つの内容を維持する必要があります。

Googleが推奨している構成

同ガイドはレスポンシブウェブデザインを推奨しています。理由として、実装と保守が最も容易なデザインパターンであることを挙げています。

あわせて同ガイドは、ガイドの内容が動的配信と別URLの構成に適用されるものだとしています。つまり、注意事項が必要なのはこの2つの構成です。

既に別URLで運用している場合、レスポンシブへ移行すれば以後の保守は軽くなります。ただし移行そのものはURLの統合を伴う作業です。費用の比較は、移行の作業と以後の保守の両方で見てください。

自社サイトがどれかを調べる方法

調べる順序は次のとおりです。所要時間の目安は15分程度です。

  1. パソコンでトップページを開き、URLを記録します。
  2. スマートフォンで同じページを開き、URLを比べます。 違っていれば別URLの構成です。spやmで始まるサブドメイン、または末尾にsp付きのパスが典型です。
  3. URLが同じ場合、パソコンのブラウザの幅を狭めます。 レイアウトが段組みから1列に変われば、レスポンシブの指定が入っています。
  4. 幅を狭めても変化せず横スクロールが出る場合、レスポンシブの指定がありません。
  5. URLが同じでスマホだけ別のレイアウトが出る場合、動的配信の可能性があります。

5番目は3と4では判別できません。実装の側では、同じURLをパソコンのブラウザからスマートフォンの表示に切り替えて確認します。HTMLの中身自体が入れ替わる場合、動的配信です。判別が付かない場合は、制作会社に配信方式を確認してください。

スマホ対応を急ぐ必要はありますか？

端末別の利用状況から見ると、スマホで読めない状態は多数の訪問者に影響します。総務省の調査では、個人のインターネット利用でスマートフォンがパソコンを上回っています。

総務省「令和6年通信利用動向調査」（調査時点は令和6年8月末）によると、端末別のインターネット利用では、スマートフォンがパソコンを27.6ポイント上回っています。

保有の状況も同じ方向です。数字を整理すると次のようになります。

端末別の利用状況

項目 割合
世帯のスマートフォン保有割合 90.5%
個人のスマートフォン保有割合 80.5%
個人の携帯電話（スマートフォンを除く）の保有割合 16.8%
端末別インターネット利用でスマートフォンがパソコンを上回る差 27.6ポイント

出典: 総務省「令和6年通信利用動向調査」（調査時点 令和6年8月末）。同調査は、個人のスマートフォン保有割合は増加傾向にあり8割を超えた一方、携帯電話（スマートフォンを除く）の保有割合は減少傾向にあるとしています。

同調査の報告書によると、年齢階層別ではスマートフォンは20歳から59歳の各年齢階層で9割、60歳から69歳の年齢階層で約8割が使用しています。想定読者が高齢層であっても、スマホで見られない前提は取りにくい状況です。

ただし、この数字は「全業種で急ぐべき」という話ではありません。自社サイトの訪問者のうちスマホがどれだけかは、アクセス解析で確認できます。全体の傾向と自社の実績は分けて見てください。

検索の評価に使われるのはどちら

検索側の評価に使われるのはモバイル版のコンテンツです。Googleの公式ブログは、ランキングの評価、構造化データの把握、スニペット表示にモバイル版を主に使う方針を示しています。

あわせて同ブログは、単一のインデックスは維持されるためモバイルファーストインデックスは別個のインデックスではないとしています。レスポンシブデザインや動的配信を使うサイトは、一般的にこの方式の対象になるとされています。

注意したいのは、ここから「スマホ対応していないと順位が下がる」とまでは読めないことです。公式に確認できるのは、評価に使われるのがモバイル版であるという方針までです。

実装の側で実際に問題になるのは順位より先に表示です。別URLの構成でスマホ側のページだけ内容が薄い場合、評価の対象になるのはその薄い側です。構成を確認する価値はここにもあります。

後付けで足りるかを測る基準は？

モバイル側のCore Web Vitalsのどの指標が外れているかで判断します。表示の崩れだけなら後付けで動き、読み込みの設計に原因がある場合は土台の見直しになります。

web.dev「Web Vitals」によると、評価はページ読み込みの75パーセンタイルで測定します。モバイルとデスクトップは分けて集計されます。

3つの指標すべてが75パーセンタイルで推奨値を満たしていれば合格とみなされます。まずどれが外れているかを特定します。

3つの指標と良好のしきい値

指標 良好のしきい値 何を測るか
LCP（Largest Contentful Paint） 2.5秒以内 主要な内容が表示されるまでの時間
INP（Interaction to Next Paint） 200ミリ秒以下 操作に対する反応の速さ
CLS（Cumulative Layout Shift） 0.1以下 表示中にレイアウトがずれる量

出典: web.dev「Web Vitals」。しきい値は、モバイル側の数値で判定してください。

指標ごとの原因と対処の重さ

外れている指標によって、作業の重さが変わります。

  1. CLSだけが外れている場合 画像や広告枠のサイズ指定が抜けているケースが多く、後付けの調整で収まることが多いです。 つまずきやすい点: 原因が特定の1ページだけという場合もあり、全体改修の前に該当ページを絞ります。
  2. LCPが外れている場合 画像の大きさや読み込みの順序に原因があります。テンプレートの改修が必要になることがあります。 つまずきやすい点: 画像を圧縮しても改善しない場合、読み込みの設計そのものが原因です。
  3. INPが外れている場合 スクリプトの実行に原因があります。使っているプラグインやタグの見直しを含みます。 つまずきやすい点: 計測ツールやチャットの埋め込みが原因という例があり、制作側だけでは解決しません。
  4. 3つすべてが大きく外れている場合 土台の作りが古いことが多く、作り直しの検討に入ります。

実装の側で経験的に言えるのは、1と4の区別が費用を大きく分けることです。CLSだけの不具合なら数ページの調整で済みますが、3指標とも外れている場合は、テンプレートを入れ替えないと数値が動きません。計測せずに見積もりを取ると、この差が反映されません。

「3秒で離脱」という数字の扱い

「3秒で53%が離脱する」という数字を根拠に提案されることがあります。この数字には出どころがあり、現行でGoogleが示す表示速度のしきい値とは別のものです。

判断に使うなら、Core Web Vitalsのしきい値を基準にしてください。数字の出どころと検証の方法は、表示速度の根拠を扱った別の記事で詳しく触れています。

作り直しが必要になるのはどんな場合？

別URLや動的配信からの移行、画像と読み込みの設計に原因がある場合、CMSが古く編集画面から直せない場合です。いずれもテンプレートや土台に手が入ります。

Google検索セントラルのガイドは、注意事項の対象が動的配信と別URLの構成であるとしています。レスポンシブへ移す場合は、この2構成に固有の作業が発生します。

順に見ていきます。

構成の移行を伴う場合

別URLから移行する場合、スマホ用のURLを統合する作業が加わります。やることは次のとおりです。

  1. スマホ用URLからパソコン用URLへの転送を設定します。 つまずきやすい点: ページ単位で対応付けないと、転送先がトップページに集まります。
  2. 2系統で分かれていた本文とメタデータを1つに統合します。 つまずきやすい点: スマホ側だけにある情報が落ちる例があり、公開前に差分を洗い出します。
  3. 統合後の表示を、主要なページで確認します。

動的配信から移行する場合も、2系統のHTMLを1つに統合する作業が中心になります。見た目は変わらなくても、裏側は作り直しに近い工数です。

テンプレートの作りが原因の場合

LCPが外れていて、画像の圧縮では改善しない場合があります。この場合は読み込みの順序や画像の指定方法がテンプレート側にあり、該当箇所の作り直しになります。

原因の所在 作業の範囲
特定ページの画像や広告枠 そのページの調整で収まります
共通テンプレートの画像指定や読み込み順 テンプレートの改修になります
CMSのテーマが古く、編集画面から直せない テーマの入れ替えを含みます
3指標とも大きく外れている 土台からの作り直しを検討します

CMSが古い場合は、スマホ対応だけを切り離して直すのが難しくなります。この場合、リニューアルとして一体で見積もるほうが結果的に安く収まることがあります。

判断の分岐表

ここまでをまとめます。

構成 外れている指標 判断
レスポンシブ CLSのみ 後付けの調整
レスポンシブ LCPまたはINP テンプレートの改修
レスポンシブ 3指標とも 作り直しの検討
動的配信または別URL 問わず 構成の移行を伴う作り直し
CMSが古く編集不可 問わず 土台の入れ替えを含む判断

実装の側から1点だけ補足します。4行目の構成の移行は、転送の設計を誤ると公開後に検索からの流入が落ちます。URLが変わる移行は、スマホ対応とは別の論点を含みます。移行の工程と転送の設計は、見積もりの段階で分けて示してもらってください。

確認から見積もりまでの手順は？

現在の構成の判定、モバイル側の指標の計測、外れている指標の原因の切り分けの3段で進めます。計測結果を添えて見積もりを依頼します。

この順で進めると、制作会社との前提がそろいます。計測結果がない状態で依頼すると、提案の範囲が会社ごとにばらつき、相見積もりの比較ができません。

必要な作業は社内で完結します。外部に依頼する前の段階です。

手順と所要時間の目安

  1. 現在の構成を判定します。所要時間の目安は15分程度です。 パソコンとスマートフォンでURLを比べ、幅を狭めたときの変化を見ます。 つまずきやすい点: 判別が付かない場合は動的配信の可能性があり、制作会社に配信方式を確認します。
  2. モバイル側のCore Web Vitalsを計測します。所要時間の目安は1時間程度です。 主要なページを5ページから10ページ選び、モバイルの数値を記録します。 つまずきやすい点: デスクトップの数値で記録しないでください。判定はモバイルとデスクトップで分けて集計されます。
  3. 外れている指標の原因を切り分けます。所要時間の目安は半日程度です。 LCP、INP、CLSのどれが外れているか、全ページか特定ページかを整理します。 つまずきやすい点: 計測は75パーセンタイルで評価されるため、1回の測定値だけで判断しません。
  4. 結果を1枚にまとめ、見積もりを依頼します。所要時間の目安は1時間程度です。

計測の数値はSearch Consoleでも確認できます。期間の区切りや集計の条件があるため、記録するときは測定した期間を併記してください。

制作会社に渡す資料

渡すのは次の4点です。これがあると、提案の範囲が絞られます。

渡す資料 内容
構成の判定結果 レスポンシブ、動的配信、別URLのいずれか
計測結果の一覧 ページごとのLCP、INP、CLSの数値と測定期間
外れている指標の整理 全ページか特定ページか、どの指標か
対応の希望範囲 全ページか主要ページのみか

実装の側から言うと、2行目の測定期間を書き添えるかどうかで話が変わります。期間を書かないと、改善の前後比較ができません。公開後に効果を確認するときの基準にもなるため、依頼の前に必ず記録してください。

4行目の希望範囲は、決めずに依頼しても構いません。ただし決めずに出すと、全ページ前提の金額が返ってきます。予算に上限がある場合は、主要ページのみの案も併記してもらってください。

見積もりで確認する項目は？

対応する構成、対象ページの範囲、しきい値を満たす指標の保証範囲、公開後の計測方法の4点を明記してもらいます。この4点が曖昧だと、完了の判断ができません。

特に3番目が抜けやすい箇所です。「スマホ対応一式」という項目だけでは、どこまで直れば完了かが決まりません。

見積書を受け取ったら、この4点が書かれているかを確認してください。

発注書に入れる4項目

確認項目 書いてもらう内容
対応する構成 レスポンシブに統一するのか、現在の構成のまま調整するのか
対象ページの範囲 全ページか、主要ページのみか。ページ数を明記
指標の保証範囲 どの指標をどの水準まで改善するか。保証しない指標も明記
公開後の計測方法 誰がいつ測り、どの数値で完了を判断するか

3番目については、全指標の達成を約束できないケースがあります。INPは埋め込んだ外部のタグに左右されるため、制作側だけでは制御しきれません。保証しない指標があること自体は問題ではなく、どれを保証しないかが書かれていることが重要です。

4番目は、完了の判断を後から揉めないために入れます。計測の時期と担当を決めておきます。

後から追加費用になりやすい箇所

次の項目は、見積もりに含まれていないことが多いです。発注前に確認してください。

  1. スマホ用URLからの転送設定 つまずきやすい点: 別URLからの移行で、ページ単位の対応付けが別見積もりになる例があります。
  2. 画像の差し替えと書き出し つまずきやすい点: 既存画像が大きすぎる場合、素材の作り直しが発生します。
  3. 問い合わせフォームのスマホ表示の調整 つまずきやすい点: フォームが外部サービスの場合、制作会社の対応範囲から外れることがあります。
  4. 公開後の計測と報告 つまずきやすい点: 計測は含まれても、報告書の作成が別扱いという場合があります。

実装の側から言うと、1番目を軽く見ないでください。転送の対応付けはページ数ぶんの作業になり、数百ページあるサイトでは工数がまとまった量になります。概算でも構わないので、見積もりの段階で行数を出してもらうと後の増額を避けられます。

スマホ対応は、やり方によって数十万円から数百万円まで幅が出ます。当社ではWeb制作を300,000円からお受けしており、構成の判定と計測から入って、後付けで足りるかどうかを先に切り分けています。現在のサイトで判断が付かない場合は、無料診断でご相談ください。

スマホ対応とレスポンシブに関するよくある質問

判断の前に確認されることの多い5点をまとめます。

自社サイトがレスポンシブかどうかはどう調べますか？

パソコンとスマートフォンでURLを比べ、次にブラウザの幅を狭めます。URLが違えば別URLの構成です。URLが同じで、幅を狭めるとレイアウトが1列に変われば、レスポンシブの指定が入っています。

幅を狭めても変化せず横スクロールが出る場合は、指定がありません。スマホだけ別のレイアウトが出る場合は動的配信の可能性があり、配信方式を制作会社に確認してください。

スマホ対応していないと検索順位は下がりますか？

公式の記述から「下がる」とまでは読み取れません。確認できるのは、評価に使われるのがモバイル版のコンテンツであるという方針までです。

Googleの公式ブログは、ランキングの評価、構造化データの把握、スニペット表示にモバイル版を主に使うとしています。別URLの構成でスマホ側の内容が薄い場合、評価の対象になるのはその薄い側です。

後付けの対応と作り直しで、工程はどれくらい違いますか？

レスポンシブでCLSだけが外れている場合は、該当ページの調整で収まることが多いです。一方、別URLや動的配信からの移行は、2系統のHTMLとメタデータの統合、ページ単位の転送設定を伴います。

見た目の変化が小さくても、裏側の作業量は大きく変わります。工程の差は、構成と外れている指標の組み合わせで決まります。

Core Web Vitalsのどの指標が外れていると作り直しになりますか？

3つすべてが大きく外れている場合です。土台の作りが原因であることが多く、テンプレートを入れ替えないと数値が動きません。

LCPのみの場合は、画像や読み込みの設計に原因があり、テンプレートの改修で収まることがあります。CLSのみであれば、画像や広告枠のサイズ指定の追加で改善する例が多いです。しきい値はLCPが2.5秒以内、INPが200ミリ秒以下、CLSが0.1以下です。出典: web.dev「Web Vitals」。

表示速度は3秒以内に収める必要がありますか？

判断の基準に使うのはCore Web Vitalsのしきい値です。LCPであれば2.5秒以内が良好とされ、評価はページ読み込みの75パーセンタイルで測定されます。

「3秒で53%が離脱する」という数字が提案の根拠に使われることがありますが、これは現行でGoogleが示すしきい値とは別のものです。数字の出どころの検証は、表示速度の根拠を扱った別の記事で触れています。
