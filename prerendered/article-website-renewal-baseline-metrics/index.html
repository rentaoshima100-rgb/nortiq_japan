ホームページリニューアル前に記録する指標と保持期間

Web制作ホームページリニューアル前に記録する指標と保持期間NORTIQ LABS · COLUMN

リニューアル前に何を記録すればよい？

検索の実績、アクセスの実績、表示速度、そしてページの一覧の4つを記録します。着手の前に取っておかないと、後から同じ数値を再現できません。

リニューアルの成否は、公開前と公開後を同じ物差しで比べて初めて判断できます。比べる相手がなければ、順位が下がったのか、もともと低かったのかも分かりません。

記録する4種類の数値

記録するのは次の4つです。どれも無料のツールで取得できます。

記録するもの 取得元 残す形式
検索の実績（表示回数、クリック数、掲載順位） Google Search Console CSV
アクセスの実績（セッション、ページ別の閲覧数、流入元） Googleアナリティクス4 CSV
表示速度（Core Web Vitalsの3指標） Google Search Consoleのレポート、PageSpeed Insights CSVまたは数値の書き出し
ページの一覧（URL、タイトル、公開日） サイトマップ、CMSの管理画面 CSV

4つ目のページの一覧は見落とされがちですが、URLが変わるリニューアルでは最も重要です。旧URLの一覧が無いと、リダイレクトの設定漏れを後から検証できません。

記録の作業手順

作業は次の順に進めます。着手の決定から1週間以内に終えてください。

  1. 対象の期間を決めます。直近12か月と、前年の同じ期間の2本を基本にします。所要時間の目安は30分です。つまずきやすい点は、ツールによって取得できる期間の上限が違うことです。
  2. Search Consoleから、ページ別とクエリ別のデータをCSVで書き出します。つまずきやすい点は、画面上の表示が1,000行までに制限される場合があることです。
  3. Googleアナリティクス4から、ページ別の閲覧数と流入元をCSVで書き出します。
  4. Core Web Vitalsの3指標を記録します。所要時間の目安は30分です。
  5. ページの一覧を書き出します。つまずきやすい点は、サイトマップに載っていないページの存在です。CMSの管理画面と突き合わせてください。

実装者としての注意点を1つ挙げます。書き出したCSVは、必ずファイル名に取得日を入れて保存してください。日付が分からない書き出しは、後から比較の基準として使えません。

「2026-09-22_search-console-pages.csv」のように、日付を先頭に置く名前が扱いやすくなります。

なお、なぜ着手前でなければならないのか、その期限の根拠は次で説明します。

なぜ着手前に記録が必要なのですか？

計測ツールのデータには保持期間があり、期限を過ぎた分は遡れなくなるためです。Google Search Consoleは最長16か月、Googleアナリティクス4は既定で2か月です。

つまり、記録は「やっておくと便利な作業」ではありません。期限を過ぎると、いくら費用をかけても取り戻せない情報です。

データ保持期間の上限

主な計測ツールの保持期間は次のとおりです。

ツール 保持期間 備考
Google Search Console（検索パフォーマンス） 最長16か月 画面上の操作にもAPIにも適用されます
Googleアナリティクス4（無料版） 既定2か月、上限14か月 設定で変更できます
Googleアナリティクス360 最長50か月 有償版の場合です

Search Consoleで遡れる期間は最長16か月です。比較したい期間がこの範囲から外れると、後から当時の表示回数やクリック数を確認する手立てがありません。

Googleアナリティクス4は、公式ヘルプによるとイベントデータの保持期間を2か月または14か月から選択する形になっています。既定の設定のままでは、2か月より前のデータが残りません。

出典: Google Search Console ヘルプ「検索パフォーマンス レポート（検索結果）」、Google アナリティクス ヘルプ「データ保持期間」

前年同期と比べたい場合、Search Consoleの16か月という上限は余裕があるように見えます。ところが、リニューアルの検討から公開まで半年かかると、公開の1年後に比べる時点では、着手前の1年分がすでに範囲の外に出ていることがあります。

設定を確認する手順

まず、いまの設定を確認してください。作業は10分ほどで終わります。

  1. Googleアナリティクス4の管理画面を開き、データ設定からデータ保持の項目を確認します。つまずきやすい点は、この設定の変更に管理者の権限が必要なことです。
  2. 2か月になっている場合は、14か月に変更します。つまずきやすい点は、変更しても過去に遡って復元はされないことです。変更後に蓄積される分から適用されます。
  3. Search Consoleで、遡れる最も古い日付を確認します。ここが記録できる範囲の限界になります。

実装者としての注意点です。保持期間を14か月にしても、14か月を超えた比較はできません。年に1回、決まった月にCSVを書き出して保管する運用にしておくと、この上限に縛られなくなります。

リニューアルの予定が無い時期でも、この書き出しは続けてください。次にサイトを触るときの基準値になります。

表示速度については、Googleが公式に基準を示しています。その見方は後述します。

検索とアクセスの実績は何を残しますか？

ページ単位とクエリ単位の表示回数、クリック数、平均掲載順位を、期間を揃えて書き出します。期間が揃っていない数値は、公開後の比較に使えません。

どちらも、集計し直せるCSVの形で残してください。画面の写真は、後から期間を変えて見直すことができません。

Search Consoleから出すもの

Google Search Consoleの検索パフォーマンスレポートで確認できるのは、クリック数、表示回数、CTR、平均掲載順位の4つの指標です。CTRはクリック数を表示回数で割った値、平均掲載順位は検索結果における掲載順位の平均です。

出典: Google Search Console ヘルプ「検索パフォーマンス レポート」

書き出すのは次の2種類です。

種類 何が分かるか 使いどころ
ページ別 どのページが表示されクリックされているか URLが変わるページの前後比較
クエリ別 どの検索語で表示されているか リニューアル後に失った検索語の特定

特にクエリ別は、公開後に順位が落ちた原因を絞り込む唯一の手がかりになります。ページ別だけでは、どの検索語を失ったのかが分かりません。

Googleアナリティクスから出すもの

Googleアナリティクス4からは、次を書き出します。

  1. ページ別のセッション数と閲覧数を、期間を指定して書き出します。所要時間の目安は20分です。
  2. 流入元の内訳（検索、直接、参照、SNS）を書き出します。つまずきやすい点は、参照元の分類の定義がツールごとに違うことです。同じツールで前後を比べてください。
  3. 問い合わせや資料請求のページへの到達数を書き出します。つまずきやすい点は、計測の設定自体が入っていない場合があることです。

実装者としての注意点です。リニューアルでは計測タグの入れ替えが発生します。旧サイトの最終日と新サイトの初日の間で、タグの設定が変わっていないかを必ず確認してください。設定が変われば、数値の増減はサイトの良し悪しではなく計測の違いになります。

比較のための期間の決め方

期間は、次の2本を基本にします。

  • 直近12か月: 季節の変動を含んだ全体像
  • 前年の同じ期間: 同じ季節どうしの比較

リニューアルの公開月をまたぐ比較は避けてください。移行の前後は順位が一時的に動くため、公開の翌月からを比較の対象にするほうが実態に近くなります。

表示速度についても同じ考え方で記録します。その基準は次で説明します。

表示速度はどの基準で記録しますか？

Core Web Vitalsの3指標を、公式のしきい値と同じ見方で記録します。平均値ではなく75パーセンタイルで残してください。

見方を揃えないと、公開後に「速くなった」と言えるかどうかの判断ができません。基準はGoogleが公式に示しています。

3指標の合格基準

良好と判定される基準は次のとおりです。

指標 内容 良好の基準
LCP（Largest Contentful Paint） 最も大きな要素が表示されるまでの時間 2.5秒以内
INP（Interaction to Next Paint） 操作してから画面が反応するまでの時間 200ミリ秒以下
CLS（Cumulative Layout Shift） 表示中にレイアウトがずれる量 0.1以下

判定は、実際の利用者のデータの75パーセンタイルで行われます。平均値ではありません。利用者の4分の3が良好の基準を満たして初めて、そのページは良好と判定されます。

出典: Google「Web Vitals」および「How the Core Web Vitals metrics thresholds were defined」（web.dev）

記録するときも、この75パーセンタイルの値をそのまま残してください。平均値で残すと、公開後の数値と比べられなくなります。

記録の粒度と対象ページ

全ページを記録する必要はありません。次の手順で対象を絞ります。

  1. Search Consoleの検索パフォーマンスから、表示回数の多い順に上位20ページを選びます。所要時間の目安は20分です。
  2. そこに、問い合わせページと料金ページを加えます。つまずきやすい点は、表示回数が少なくても事業上は重要なページがあることです。
  3. 選んだページごとに、3指標の75パーセンタイル値を記録します。つまずきやすい点は、データが不足しているページでは実利用者の値が表示されないことです。その場合は、測定ツールの試験値を、試験値と明記したうえで残してください。
  4. パソコンと携帯端末で値が違うため、両方を分けて記録します。

実装者としての注意点です。リニューアルでは画像の扱いとフォントの読み込み方が変わるため、LCPとCLSは大きく動きます。着手前の値を残していないと、変わった原因が新しい設計なのか個別の実装なのかを切り分けられません。

なお、社内でリニューアルの必要性を説明する場面では、公的統計も根拠になります。総務省「令和6年 通信利用動向調査報告書（企業編）」によると、日本企業全体のホームページ開設率は9割前後で推移し、大企業ではほぼ100%に達する一方、従業者数が少ない企業ほど開設率が低い傾向が続いています。

出典: 総務省「令和6年 通信利用動向調査報告書（企業編）」

開設していることが当たり前になった以上、差が付くのは内容の鮮度と機能です。現状の数値を記録することは、その差を自社で把握する最初の作業にあたります。

記録した数値は発注時にどう使いますか？

現状の数値をRFPと見積もりの前提として共有し、公開後に比べる指標としてあらかじめ合意します。数値を渡さずに発注すると、提案は一般論になります。

制作会社にとっても、現状が分からないまま提案するのは難しい作業です。数値があれば、どのページを優先するかの根拠が提案に入ります。

RFPに載せる現状値

提案依頼の資料には、次の4つを載せてください。

載せる項目 具体的な内容
検索の実績 表示回数の多い上位20ページと、上位のクエリ一覧
アクセスの実績 ページ別のセッション数と、流入元の内訳
表示速度 主要ページのCore Web Vitalsの3指標（端末別）
ページの一覧 現在のURLとタイトル、最終更新日

詳細な数値を外部に出すことに抵抗がある場合は、上位ページの順位と表示回数だけでも構いません。ゼロよりは、提案の精度が上がります。

なお、ページの棚卸しで残すか削除するかを判断する基準は、この記録とは別の作業です。判断の観点は別の記事で扱っています。

制作会社と合意する測り方

発注の前に、次の3点を書面で合意してください。

  1. 比較に使う指標を決めます。所要時間の目安は打ち合わせ1回です。つまずきやすい点は、指標を増やしすぎることです。3つから5つに絞ってください。
  2. 比較する時期を決めます。公開の翌月からの3か月と、その前年の同じ期間、といった形です。つまずきやすい点は、公開直後の変動期を比較に含めてしまうことです。
  3. 誰が測るかを決めます。自社で測るのか、制作会社の報告を受けるのかで、必要な権限の付与が変わります。

実装者としての注意点です。計測の権限を制作会社のアカウントにだけ付けると、契約が終わった後に自社でデータを取り出せなくなります。Search Consoleとアナリティクスの所有権は、必ず自社のアカウントに置いてください。

制作会社にはユーザとして権限を追加する形にします。これは契約の終了時だけでなく、担当者が変わったときにも効いてきます。

現状の記録と、比較の約束。この2つが揃っていれば、公開後に成果を巡って話がこじれることはほとんどありません。数値の取得や整理の進め方に迷う場合は、無料診断でご相談ください。

記録を残すときの保存方法は？

画面の写しではなく、CSVなどの表形式で残します。後から集計し直せる形でなければ、比較に使えません。

報告書に貼った画像は、見返す分には十分でも、期間を変えて集計し直すことができません。元のデータを残すことが前提です。

保存する形式と置き場所

保存の方針は次のとおりです。

項目 方針
形式 CSVを原本とする。表計算ファイルは加工用の写しとして扱う
命名 先頭に取得日を置く（例: 2026-09-22_gsc-queries.csv）
置き場所 担当者個人の端末ではなく、会社が管理する共有の場所
権限 担当者が退職や異動をしても、後任が開ける状態にする
期間 少なくとも、次のリニューアルまで保管する

置き場所の条件は、担当者が変わっても残ることです。個人の端末や個人アカウントのクラウドに置いた記録は、担当が変わった時点で失われます。

実装者としての注意点です。CSVは文字コードの扱いで開けなくなることがあります。日本語を含むファイルは、開いた直後に文字化けしていないかを1度確認してから保管してください。

化けたまま保管すると、数年後に開いたときに復元の手間がかかります。確認は1分で済みます。

更新の頻度と担当者

1回記録して終わりにせず、次の頻度で続けてください。

  1. リニューアルの着手前に1回。これが基準値になります。所要時間の目安は半日です。
  2. 公開の直前に1回。移行の直前の状態を残します。つまずきやすい点は、公開作業に追われて飛ばしてしまうことです。作業予定表に項目として入れてください。
  3. 公開後は毎月1回。3か月は必ず続けます。
  4. その後は年に1回。保持期間の上限に縛られないための保管です。

担当者は1人に決め、代理を1人置いてください。担当が決まっていない記録は、必ず途切れます。

記録は地味な作業ですが、リニューアルの成果を語れるかどうかを分けます。半日の作業を惜しんだために、数百万円の投資の効果を説明できなくなる例は珍しくありません。

当社では、リニューアルの前の現状の記録から、公開後の比較までを一貫して支援しています。社内に担当者がいない場合でも進められますので、お問い合わせからご相談ください。

よくあるご質問

この記事に関して多い質問と回答をまとめます。

リニューアルの何か月前から記録を始めればよいですか？

着手を決めた時点で、すぐに1回目の記録を取ってください。何か月前という目安よりも、設計や制作が始まる前であることが重要です。制作が始まると、計測の設定やページの構成が少しずつ変わり始め、記録した数値の意味が揺らぎます。

Googleアナリティクスの保持期間の設定は変更しても大丈夫ですか？

2か月から14か月への変更は、今後蓄積されるデータの保持期間が延びるだけで、既存のレポートが壊れることはありません。ただし、変更しても過去に遡って復元はされません。すでに2か月を超えた分は戻らないため、変更と同時にCSVの書き出しも行ってください。

すでにリニューアルに着手してしまった場合、どうすればよいですか？

いま取れる範囲で記録してください。Search Consoleは最長16か月まで遡れるため、公開前であれば多くの場合は間に合います。公開後であっても、旧URLごとのデータが残っている間に書き出せば、比較の材料になります。優先するのは、表示回数の多い上位ページとクエリの一覧です。

記録は制作会社に任せてもよいですか？

書き出しの作業を依頼することは問題ありません。ただし、Search Consoleとアナリティクスの所有権は自社のアカウントに置いてください。所有権が制作会社側にあると、契約の終了後に自社でデータを取り出せなくなります。受け取ったCSVも、自社が管理する場所に保管してください。

比較する期間は、前年同期と直前のどちらがよいですか？

両方を記録し、状況に応じて使い分けてください。季節の変動がある事業では前年同期が実態に近くなります。一方で、事業の内容が1年で大きく変わった場合は、直前の期間のほうが参考になります。どちらを主に使うかは、発注の前に制作会社と合意しておくと、公開後の評価で食い違いません。

なお、リニューアルの進め方を社内で検討する段階の方には、DXの進め方をまとめた資料をご用意しています。DXガイドブックをご覧ください。
