# 生成AIに顧客情報を入力してよいか｜社内ルールの決め方

## 社内ルールは何から決めればよいですか？

最初に決めるのは、入力してよい情報の線引きです。その判断の根拠になるのは、個人情報保護委員会が2023年6月2日 (令和5年6月2日) に公表した「生成AIサービスの利用に関する注意喚起等について」に挙げられた2点です。

ルール作りは、ツールの選定から入ると行き詰まります。公的な基準が先に求めているのは、自社が持つ情報の側の線引きです。

### 公的な判断基準は2点に絞られます

同注意喚起は、個人情報取扱事業者における注意点として次の2点を挙げています。

1. 個人情報を含むプロンプトを入力する場合には、特定された当該個人情報の利用目的を達成するために必要な範囲内であることを十分に確認すること
2. あらかじめ本人の同意を得ることなく個人データを含むプロンプトを入力し、その個人データが応答結果の出力以外の目的で取り扱われる場合、個人情報保護法の規定に違反することとなる可能性があること

出典: 個人情報保護委員会「生成AIサービスの利用に関する注意喚起等について」(令和5年6月2日公表)

2点目について、委員会はさらに、サービスを提供する事業者が当該個人データを機械学習に利用しないこと等を十分に確認するよう求めています。つまり社内ルールは、入力する社員の心得だけでは足りません。使うツールごとに確認する工程が必要になります。

なお、社内ルールのひな型そのものを国が示した公的資料は確認できていません。入力の可否を判断する公的な基準は、この2点にあたります。

### 決める順番は線引き、ツールの確認、記録、事故時の手順

御社でこれから着手する場合は、次の順番で決めると後戻りが起きにくくなります。

1. **入力してよい情報の線引きを決める** (目安1週間から2週間)。つまずきやすい点は、顧客名や住所といった情報の種類だけで決めようとすることです。基準は利用目的の側にあります
2. **使うツールの学習利用の有無を確認する** (目安数日)。つまずきやすい点は、同じサービスでも無料版と法人向けプランで扱いが異なる場合があることです
3. **確認した内容を記録に残す** (目安半日)。つまずきやすい点は、最初に作った記録がその後更新されず、実態と合わなくなることです
4. **入力してしまったときの手順を決める** (目安数日)。つまずきやすい点は、社内の連絡経路を決めていないために、後述する報告の期限に間に合わなくなることです

各手順の中身は、この後のセクションで順に取り上げます。

実装する側から1点補足します。自社でAPIを使ってツールを組んでいる場合、画面から使うときと API 経由のときで、入力データの扱いが別に定められていることがあります。管理画面の設定だけを見て判断すると、実態とずれたルールになります。社内で開発したツールがある御社では、経路ごとに確認してください。

## 顧客情報を入力してよいかは何を基準に判断しますか？

情報の種類で一律に線を引くのではなく、その情報をもともと何のために取得したかという利用目的に照らして判断します。顧客名だから禁止、社内資料だから自由という切り分けでは、公的な基準に合いません。

### 利用目的の達成に必要な範囲内かを確認する

個人情報保護委員会の注意喚起は、個人情報を含むプロンプトを入力する場合には、特定された当該個人情報の利用目的を達成するために必要な範囲内であることを十分に確認することを求めています。

ここでいう利用目的とは、その個人情報を取得したときに本人へ示した使いみちです。たとえば問い合わせ対応のために取得した連絡先なら、問い合わせ対応の範囲を超える使い方はできません。

そのため、同じ顧客名でも判断が分かれます。問い合わせへの返信文を整えるために顧客名を入れるのは、取得時の目的の範囲内に収まる余地があります。一方、同じ顧客名を営業先リストの分析のために入れると、目的の外に出る可能性があります。

出典: 個人情報保護委員会「生成AIサービスの利用に関する注意喚起等について」(令和5年6月2日公表)

### 本人の同意を得ていない個人データを入力する場合の制約

同注意喚起の2点目は、あらかじめ本人の同意を得ることなく個人データを含むプロンプトを入力し、その個人データが応答結果の出力以外の目的で取り扱われる場合、個人情報保護法の規定に違反することとなる可能性があるとしています。

この一文は、判断の条件が2つあることを示しています。本人の同意があるかどうかと、入力したデータが応答の出力以外に使われるかどうかです。

同意を取っていない場合、御社が確認できるのは後者だけです。だからこそ委員会は、サービスを提供する事業者が当該個人データを機械学習に利用しないこと等を十分に確認するよう求めています。この確認の進め方は次のセクションで扱います。

### 判断に迷う具体例の整理

線引きを文章だけで示すと、現場で解釈が割れます。次のように、情報と用途の組み合わせで表に落とすと運用しやすくなります。

| 入力しようとする内容 | 判断の軸 |
| --- | --- |
| 顧客の氏名や連絡先 | 取得時の利用目的の範囲内か。範囲外なら入力しない |
| 取引先との契約書の条文 | 相手方との守秘義務の範囲に収まるか |
| 社員の人事評価の記述 | 評価のために取得した情報を、評価以外の用途に回していないか |
| 顧客名を伏せた問い合わせ文 | 他の記述から個人が特定されないか |
| 公開済みの自社サイトの文章 | 個人情報を含まなければ、この基準の対象外 |

最後の行は実務上の抜け道になります。個人が特定できない形に直してから入力すれば、そもそも個人情報の入力にあたりません。顧客名を社名の一般名詞に置き換える、日付をぼかすといった加工を先に挟む運用は、判断の手間を減らす現実的な方法です。

ただし、伏せたつもりで特定できてしまう例には注意が必要です。取引の規模と地域と業種を並べると、該当する会社が1社に絞れることがあります。

## 使うツール側は何を確認すればよいですか？

入力したデータが応答結果の出力以外の目的、とくに機械学習に利用されないことを、ツールごとに確認します。サービス名で一括りにせず、御社が実際に使っているプランと経路ごとに確認する必要があります。

### 学習に利用しないことの確認が要件になる理由

この確認は、御社の社内都合ではなく公的な基準に書かれた要件です。個人情報保護委員会の注意喚起は、本人の同意なく個人データを含むプロンプトを入力する場合について、サービスを提供する事業者が当該個人データを機械学習に利用しないこと等を十分に確認することを求めています。

出典: 個人情報保護委員会「生成AIサービスの利用に関する注意喚起等について」(令和5年6月2日公表)

言い換えると、学習に使われない状態を確認できていないツールには、同意を得ていない個人データを入れられません。確認できないツールは、個人情報を含まない用途に限って使う、という整理になります。

### 設定で切るのか契約で担保されているのかを分けて見る

確認の結果は、同じ「学習に使われない」でも強さが違います。次の3つを分けて把握してください。

| 担保の形 | 性質 | 運用上の注意 |
| --- | --- | --- |
| 既定でオフ (法人向けプランなど) | 契約や仕様の側で担保される | プランを変更したときに前提が変わる |
| 設定でオフにできる | 担保は設定の維持に依存する | 誰かが戻すと担保が消える。設定画面の権限を絞る |
| 既定でオンのまま使える | 担保がない | 個人情報を含む入力には使えない |

設定でオフにしている場合は、その設定を変更できる人を限る必要があります。アカウント管理者が複数いる御社では、設定の変更権限を1人か2人に絞っておくと、意図せず戻る事故を防げます。

実務でハマりやすいのは、経路の違いです。同じサービスでも、ブラウザの画面から使う場合とAPI経由で自社ツールに組み込む場合で、入力データの扱いが別に定められていることがあります。無料版と法人向けプランの差も同様です。自社開発のツールがある場合は、画面の設定ではなくAPIの利用規約の側を確認してください。

### 確認した内容の記録の残し方

確認は一度で終わりません。ツールの仕様は更新されるため、いつ何を見て確認したのかを残しておく必要があります。記録に入れる項目は次の4つで足ります。

1. ツール名とプラン名、利用経路 (画面またはAPI)
2. 学習に利用しないことの担保の形 (上の表のどれか)
3. 根拠にした規約やページの名称と、確認した日付
4. 個人情報を含む入力を許可するかどうかの結論

この記録は、社内ルールの付表として持つのが実用的です。ツールを追加するときは、この4項目を埋めてから使い始める、という順番にしておくと抜けが出ません。

## 社内ルールには具体的に何を書けばよいですか？

入力してよい情報の区分、承認が必要な場面、使ってよいツール、確認の記録、違反と事故が起きたときの手順の5項目を書きます。この5つが揃っていれば、分量は数ページで足ります。

前述のとおり、社内ルールのひな型そのものを国が示した公的資料は確認できていません。項目立ては各社で決める必要があります。

### 情報の区分表を先に作る

本文を書き始める前に、情報を3つの区分に割り振ります。区分が決まっていない状態で文章を書くと、読んだ社員が自分で判断することになり、ルールの意味がなくなります。

| 区分 | 扱い | 例 |
| --- | --- | --- |
| 入力禁止 | 例外なく入れない | 要配慮個人情報、未公表の取引条件 |
| 承認が必要 | 定めた人の承認を得てから入れる | 顧客の氏名や連絡先を含む文面 |
| 入力可 | 申請なしで入れてよい | 公開済みの自社資料、個人が特定されない文章 |

区分の境目は、前のセクションで整理した利用目的の考え方で引きます。判断に迷った場合は承認が必要な側に置く、という原則も1行で書き添えてください。

### 承認が必要になる場面の決め方

承認の仕組みは、厳しくするほど守られなくなります。承認者を1人に限ると不在時に業務が止まり、社員は承認を飛ばして使い始めます。実務で回っているのは次の形です。

1. 承認が必要な場面を区分表の1行に限定する (目安半日)。つまずきやすい点は、場面を増やしすぎて申請が日常業務になることです
2. 承認者を2人以上決める (目安半日)。つまずきやすい点は、代理の承認者を決めていないことです
3. 承認の記録をチャットの履歴など既存の手段で残す (目安半日)。つまずきやすい点は、専用の申請フォームを作り、運用が重くなって使われなくなることです

### AIに業務システムを操作させる場合に加える権限の制限

生成AIに文章を入力するだけでなく、AIが自社のシステムを操作する構成に進む場合は、ルールに権限の項目が加わります。

総務省と経済産業省が公表した「AI事業者ガイドラインの令和7年度更新内容」(令和8年3月12日) では、AIエージェントを「特定の目標を達成するために、環境を感知し自律的に行動するAIシステム」と定義しています。同資料の更新内容では、留意すべき事項として「人間の判断を介在させる仕組みの構築や最小権限設定、ハードウェア残存データへの配慮等」が追加されたと記載されています。

同資料は、外部システムとの連携について「適切な連携ツール・システムの制限が重要である旨を追記」とし、あわせて「意図しないデータの漏洩リスクの被害を抑えるため、データ最小化が重要である旨を追記」としています。権限を絞ること、つなぐ相手を絞ること、渡すデータを絞ることが、それぞれ別の論点として挙げられています。

リスクの側も具体的です。同資料は「AIエージェントが外部システムと自律的に連携する際、アクセス可能なデータベースを含む内部データが不正に外部へ送信されるリスク」を追記しています。読み取り権限を与えた範囲が、そのまま外部に出る可能性のある範囲になるという見方です。御社でエージェントを使う場合は、与える権限の一覧をルールの付表に書き出してください。

## 入力してしまったときはどうなりますか？

報告対象となる4類型に当たるかを確認し、当たる場合は速報を発覚日から3日から5日以内、確報を30日以内に個人情報保護委員会へ報告します。入力したすべての事例が報告対象になるわけではありません。

まず押さえておきたいのは、入力してしまった時点では事実関係が分からないことです。どのツールに、どの情報を、何件入れたのかを確定させる作業が、期限の中に含まれます。

### 報告対象となる4つの類型

個人情報保護委員会は、報告対象となる事態として次の4類型を挙げています。

1. 要配慮個人情報が含まれる個人データの漏えい等
2. 不正に利用されると財産的被害が生じるおそれがある個人データの漏えい等
3. 不正の目的で行われたおそれがある行為による個人データの漏えい等
4. 本人の数が1,000人を超える個人データの漏えい等

出典: 個人情報保護委員会 漏えい等の対応とお役立ち資料

1番から3番は件数にかかわらず対象です。1,000人超という件数の条件は4番だけにかかります。社員が1件の顧客情報を入力した事例でも、それが要配慮個人情報であれば1番に当たります。

この構造があるため、御社のルールでは要配慮個人情報を入力禁止の区分に置く意味が大きくなります。前述の区分表で禁止側に置いておけば、1件の操作で報告義務が生じる場面を減らせます。

### 速報と確報の期限と、不正の目的が疑われる場合の違い

期限は2段階です。

| 報告 | 期限 | 内容 |
| --- | --- | --- |
| 速報 | 発覚後速やかに (発覚日から3日から5日以内) | その時点で把握している範囲 |
| 確報 | 発覚日から30日以内 | 原因や再発防止を含めた報告 |
| 確報 (不正の目的で行われたおそれがある場合) | 発覚日から60日以内 | 同上 |

出典: 個人情報保護委員会 漏えい等の対応とお役立ち資料

速報の期限が数日しかない点が実務上の要です。原因が分からなくても、分かっている範囲で出す必要があります。調査が終わるまで待つという判断をすると、速報の期限を越えます。

### 社内の連絡経路を先に決めておく

期限に間に合わない原因は、調査の難しさよりも社内の連絡の遅れです。社員が入力に気づいてから責任者へ届くまでに数日かかると、速報の期限が残りません。ルールに次の3点を書いてください。

1. 気づいた社員が最初に連絡する相手と手段 (目安半日で決まります)。つまずきやすい点は、連絡先を部署名で書き、誰に言えばよいのか分からなくなることです
2. 連絡を受けた担当者が確認する項目 (ツール名、入力した情報、件数、日時)。つまずきやすい点は、入力した本人が履歴を消してしまい件数が確定できなくなることです
3. 報告するかどうかを判断する人の名前。つまずきやすい点は、判断者が不在のときの代理を決めていないことです

2番について1つ補足します。社員に「消さずに残す」と伝えておくことが実務では効きます。あわてて会話履歴を削除すると、4類型のどれに当たるかを判断する材料が消え、安全側に倒して報告するしかなくなります。

## 他社はどこまでルールを決めていますか？

業務で生成AIを利用している企業は多数を占める一方、組織的な取組がないと回答した企業が約3割あり、その割合は中小企業で特に高い傾向が示されています。使うことは先に進み、決めることが後に残っている状況です。

### 利用の広がりとルールの整備には差があります

総務省「令和8年版情報通信白書」によると、自社の何らかの業務で生成AIを利用している旨を回答した割合は、日本において86.4%でした。同白書は、これが2024年度企業向け調査に比べて大幅に上昇したと記載しています。

一方、同白書で生成AI活用による業務変革等に関して組織的に取り組んでいる割合は65.6%です。「組織的な取組はない」と回答した割合は27.0%と約3割に上り、米国・ドイツ・中国に比べて顕著に高い結果と記載されています。さらに同白書は、企業規模別に見た場合、この回答割合は中小企業で特に高くなっている傾向が見られたとしています。

出典: 総務省「令和8年版情報通信白書」(生成AIの業務利用状況、組織的な取組状況)

この2つの数字の差が、本記事の前提にあたります。使っている社員がいるのにルールがない状態は、珍しい事故ではなく、相当数の企業で起きている普通の状態です。

### 活用方針の策定状況は企業規模で開きがあります

方針の側でも規模による差が出ています。同白書では、生成AIの活用方針について「積極的に活用する方針である」および「活用する領域を限定して利用する方針である」と回答した割合の合計が、日本全体で68.9%でした。前年度の2024年度企業向け調査では49.7%です。

| 区分 | 活用方針を定めている割合の合計 |
| --- | --- |
| 日本全体 | 68.9% |
| 大企業 | 74.0% |
| 中小企業 | 58.1% |
| 日本全体 (2024年度企業向け調査) | 49.7% |

出典: 総務省「令和8年版情報通信白書」(生成AIの活用方針等)

大企業と中小企業の差は約16ポイントです。ただし中小企業の58.1%という水準は、前年度の日本全体の49.7%を上回っています。方針を決める動き自体は中小企業にも広がっており、着手が特別に早いわけでも遅いわけでもない時期だと読めます。

なお、この調査の数字をそのまま社内の説明に使う場合は、調査の設計を確認してから引いてください。企業のAI導入率は調査によって幅が出ます。この点は別の記事で扱います。

## ルールを作ったあとは何を続ければよいですか？

ツールの仕様変更と新しいツールの追加に合わせて、確認した記録と区分表を更新し続ける運用が必要です。ルールは作った時点ではなく、更新が止まった時点で実態と合わなくなります。

### ツールの仕様変更に追随する

生成AIのサービスは、プランの構成や設定項目が入れ替わります。学習に利用しないという担保が、ある日から別の設定項目に移っていることもあります。

更新の頻度は、四半期に1回を目安にしてください。確認するのは、前のセクションで作った付表の4項目のうち3番目です。根拠にした規約やページを開き直し、記載が変わっていないかだけを見ます。全項目を見直す必要はありません。

実務でよくある落ち方は、担当者が異動したあと誰も付表を開かなくなることです。四半期の確認を、既存の定例の議題に1行足しておくと残ります。新しい会議体を作ると、その会議が先に消えます。

### 新しいツールを使い始めるときの手順を1本にする

ルールが形だけになる最大の原因は、社員が新しいツールを勝手に使い始めることです。禁止しても止まりません。申請の手順を軽くするほうが現実的です。

1. 使いたいツール名とプラン、使いたい用途を1行で出す (目安5分)。つまずきやすい点は、申請書の様式を作ってしまい提出されなくなることです
2. 付表の4項目を担当者が埋める (目安半日から数日)。つまずきやすい点は、無料版で試し始めてから法人向けプランに移るときに、担保の形が変わったことを見落とすことです
3. 区分表のどの区分で使えるかを決めて社員に返す (目安半日)。つまずきやすい点は、結論だけ伝えて区分を伝えないため、社員が顧客情報も入れてよいと解釈することです

この3ステップが2週間かかる運用なら、社員は待ちません。数日で回る形にしてください。

### ルールづくりが止まってしまう場合は

ここまでの手順は、やることが決まれば難しくありません。それでも止まる理由は、判断の根拠を確かめる作業と、ツールの仕様を経路ごとに読み解く作業が、通常業務の片手間では終わらないことにあります。とくにAPIを使って自社の仕組みに組み込んでいる場合は、画面の設定だけを見ても結論が出ません。

当社はWeb制作とあわせて、AIチャットボットの構築やAI活用の伴走支援を手がけています。実際に実装する側として、どの経路でどのデータが外に出るのかを前提から確認します。社内ルールの項目立てと、ツールごとの確認の進め方を一緒に整理したい場合は、[無料診断](/diagnostic)からご相談ください。現在の使い方を伺ったうえで、先に決めるべき項目をお伝えします。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 生成AIに顧客の氏名や連絡先を入力することは、個人情報保護法に違反しますか？

入力そのものが直ちに違反になるわけではありません。個人情報保護委員会の注意喚起は、個人情報を含むプロンプトを入力する場合には、特定された当該個人情報の利用目的を達成するために必要な範囲内であることを十分に確認することを求めています。判断の軸は情報の種類ではなく利用目的です。

あわせて、本人の同意を得ずに個人データを入力し、それが応答結果の出力以外の目的で取り扱われる場合は、同法の規定に違反することとなる可能性があるとされています。この2点の両方を満たしているかで判断します。

### 有料版や法人向けプランを使っていれば、顧客情報を入力してよいのですか？

プランの種類だけでは決まりません。確認が必要なのは、入力したデータが機械学習に利用されないかどうかです。法人向けプランで既定でオフになっている場合は担保が強い形になりますが、プラン名ではなく規約や仕様の記載で確認してください。

また、同じサービスでも画面から使う場合とAPI経由で使う場合で扱いが別に定められていることがあります。御社が自社のツールに組み込んでいる場合は、経路ごとに確認が必要です。

### 入力を禁止するルールにすれば、確認の記録は残さなくてよいのですか？

全面禁止を選ぶ場合でも、使ってよいツールと用途の記録は必要です。禁止だけを伝えたルールは守られにくく、社員が個人のアカウントで使い始める形に移りやすいためです。

実務上は、個人情報を含まない用途に限って認め、その範囲を記録しておくほうが運用が安定します。何も認めない場合は、どの業務で何を使っているかを把握する手段が社内に残りません。

### 社員が個人のアカウントで業務に生成AIを使っている場合、会社の責任はどうなりますか？

個別の事案の法的な評価は弁護士の判断になりますが、実務の備えとしては、会社として把握できていない利用がある状態を解消することが先になります。把握できていなければ、どの情報がどのツールに入ったのかを確認できず、事故が起きたときに報告の判断ができません。

本記事の手順でいえば、申請の手順を軽くして、認めたツールを明示することが対応になります。

### 顧客情報を入力してしまった場合、必ず個人情報保護委員会へ報告しなければならないのですか？

すべての事例が報告対象になるわけではありません。報告対象は、要配慮個人情報が含まれる漏えい等、不正に利用されると財産的被害が生じるおそれがあるもの、不正の目的で行われたおそれがある行為によるもの、本人の数が1,000人を超えるものの4類型です。

このうち前の3つは件数にかかわらず対象で、1,000人超という条件は4番目にのみかかります。対象に当たる場合は、速報を発覚日から3日から5日以内、確報を30日以内 (不正の目的で行われたおそれがある場合は60日以内) に報告します。

出典: 個人情報保護委員会 漏えい等の対応とお役立ち資料
