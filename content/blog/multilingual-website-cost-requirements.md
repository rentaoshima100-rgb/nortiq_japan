# ホームページの多言語対応、費用の内訳と要件

## 多言語対応の費用は、何にいくらかかりますか？

費用は翻訳の費用と実装の費用に分かれます。見積書でこの2つが分かれていない場合、後から追加費用が発生しやすくなります。

多言語対応は、既存のサイト制作に上乗せされる要件です。まず土台となる制作費用を押さえてから、上乗せ分を見てください。

### 費用の内訳を4つに分けて見ます

見積書は次の4つに分解して読みます。

| 区分 | 多言語対応で発生するもの |
| --- | --- |
| 初期費用 | 言語切替の実装、言語ごとのページの作成、URLの設計 |
| 月額 | 翻訳した内容の更新、言語ごとのページの保守 |
| オプション | 翻訳そのものの費用、ネイティブによる校正、言語の追加 |
| 従量課金 | 自動翻訳ツールの利用料（文字数や閲覧数に応じて課金されるもの） |

このうち見落とされやすいのは月額と従量課金です。初期費用だけを比べて発注すると、公開後の負担が想定を超えます。

土台となる制作費用の相場は、次のとおりです。複数の制作会社が公開する相場データによると、小規模なコーポレートサイト（5ページから10ページ程度）を中小規模の制作会社へ依頼した場合、30万円からが目安とされています。出典: Web幹事「ホームページ作成費用・制作費用の料金相場をプロが解説！相場早見表付き【2026年最新版】」。

月額の管理と保守の費用は、小規模サイトで月額5,000円からが相場の下限とされています。出典: あきばれホームページ「ホームページ維持費の相場は月いくら？ランニングコストの内訳を全公開」。

多言語対応を加えた場合の金額は、案件の規模と要件により大きく変動します。言語数とページ数、翻訳の方式で幅が出るためです。具体的な変動要因は後述します。

### 基準日と前提

本記事の内容は2026年9月時点のものです。相場の数値は上記の出典によります。

前提として、次の2点を確認してください。

1. 既存サイトがあるのか、新規に作るのか。既存サイトへの後付けは、URL設計の見直しが必要になる場合があります
2. 対象の言語が英語1つか、複数か。複数の場合は言語の追加ごとに費用が積み上がります

なお、補助金による負担の軽減を検討する場合は、制度の内容が年度ごとに変わります。対象や要件は[補助金のご案内](/subsidy)をご確認ください。

翻訳と実装の切り分けは、次で整理します。

## 翻訳と実装、どちらが制作費に含まれますか？

実装は制作費に含まれますが、翻訳は別費用として扱われることが一般的です。見積書のどこに書かれているかを必ず確認してください。

ここが曖昧なまま発注すると、原稿が用意されないまま納期が来ます。制作は止まり、公開が遅れます。

### 制作会社が担う範囲と担わない範囲

一般的な切り分けは次のとおりです。ただし会社によって違います。契約前に必ず確認してください。

| 作業 | 一般的な扱い |
| --- | --- |
| 言語切替のボタンや仕組みの実装 | 制作費に含まれます |
| 言語ごとのページの枠組みの作成 | 制作費に含まれます |
| URLの設計と検索エンジン向けの設定 | 制作費に含まれます |
| 日本語から他言語への翻訳 | 別費用、または発注者側の用意 |
| 翻訳内容の正しさの確認 | 発注者側の責任になることが多い |
| 画像内の文字の差し替え | 見落とされやすい追加作業 |

4行目からが問題になります。制作会社は翻訳の専門家ではありません。翻訳を依頼できる場合も、外部の翻訳会社への取り次ぎという形が多くなります。

### 原稿の用意は誰の仕事になるか

原則として、原稿の用意は発注者側の仕事です。日本語のサイト制作でも同じですが、多言語ではここが重くなります。

理由は3つあります。

1. 翻訳する前に、日本語の原稿を確定させる必要がある
2. 専門用語や社名、サービス名の訳し方を決める必要がある
3. 訳された文章が自社の意図と合っているかを、発注者側でしか判断できない

2つ目は見落とされやすい作業です。自社のサービス名を英語でどう表記するかを決めていないと、ページごとに違う表記になります。

実装する側から見ると、この用語の一覧があるかどうかで作業の見通しが大きく変わります。発注前に、社名、サービス名、部署名、よく使う専門用語の対訳表を作っておいてください。

画像内の文字も忘れないでください。バナーや図の中に日本語が入っている場合、画像そのものを作り直す必要があります。この作業は、テキストの翻訳とは別に費用が発生します。

費用が大きく変わる要因は、次で整理します。

## 費用を左右する要因は何ですか？

言語数、ページ数、翻訳の方式、更新の頻度の4つで決まります。なかでも更新の頻度が、公開後の費用を最も大きく左右します。

初期費用だけを見て判断すると、この点を見落とします。順に説明します。

### 言語数とページ数の掛け算で増えます

翻訳の費用は、おおむね言語数とページ数の掛け算で増えます。3言語で20ページなら、日本語以外に60ページ分の文章が必要になります。

一方、実装の費用は掛け算では増えません。言語切替の仕組みは1度作れば使えます。言語を追加する分の費用は、最初の1言語目より小さくなります。

この違いが、見積もりの読み方に影響します。

| 増え方 | 該当する費用 |
| --- | --- |
| 言語数とページ数に比例して増える | 翻訳、校正、画像の差し替え |
| 最初に大きく、追加分は小さい | 言語切替の実装、URLの設計 |
| 言語数に応じて毎月増える | 翻訳内容の更新、ページの保守 |

### 翻訳の方式による違い

方式は大きく3つあります。費用と品質のどちらを取るかの判断になります。

1. 人による翻訳。費用は最も高くなりますが、内容の正しさと読みやすさが得られます
2. 機械翻訳に人が手を入れる方式。費用を抑えつつ、大きな誤りを避けられます
3. 機械翻訳のみ。費用は最も低いものの、内容の正しさは保証されません

商品の仕様や契約に関わるページでは、3つ目は避けてください。誤訳が取引の条件の誤解につながります。

会社案内やニュースのように、内容の誤りが取引に直結しないページであれば、2つ目で足りる場合があります。ページの性質で方式を分ける進め方が現実的です。

### 公開後の更新が費用を決めます

最も見落とされるのがここです。日本語のページを1つ直すたびに、対応する他言語のページも直す必要があります。

3言語に対応していれば、1つの修正が4つの作業になります。更新の頻度が高いサイトでは、この積み上がりが初期費用を超えることもあります。

対策は2つです。

- 更新の頻度が高いページ（ニュース、ブログ）は多言語化の対象から外す
- 更新が少ないページ（会社案内、サービス内容、問い合わせ）に絞る

この絞り込みが、費用を抑える最も効く手段になります。

### 実装者から見た、見積もりに乗りにくい作業

見積書に項目として現れにくいものが、いくつかあります。

- 言語によって文章の長さが変わるため、デザインの崩れを直す作業。ドイツ語のように語が長い言語では、ボタンからはみ出します
- 日付や金額、住所の表記を言語に合わせる作業
- 問い合わせフォームの入力チェックを言語ごとに調整する作業（郵便番号や電話番号の桁が国ごとに違います）
- 検索エンジンに言語の対応関係を伝える設定

最後の1つは、後から追加すると手戻りが大きくなります。URLの設計と合わせて、最初に決めておいてください。方式の選び方は次で説明します。

## 多言語対応の方式には、どんな選択肢がありますか？

大きく3つの方式があります。ページを言語ごとに作る方式、翻訳ツールを組み込む方式、既存サイトに自動翻訳をかぶせる方式です。

費用の安い順は3、2、1です。ただし検索エンジンからの評価と、公開後の手間は逆の順になります。

### 3つの方式の比較

| 方式 | 内容 | 初期費用 | 公開後の手間 |
| --- | --- | --- | --- |
| 言語ごとにページを作る | 言語別のURLで、それぞれのページを持つ | 高い | 更新のたびに各言語を直します |
| 翻訳ツールを組み込む | CMSに多言語の仕組みを入れ、管理画面から各言語を編集する | 中くらい | 管理画面でまとめて直せます |
| 自動翻訳をかぶせる | 既存サイトの表示を、閲覧時に機械翻訳で置き換える | 低い | 原文を直せば自動で反映されます |

3つ目は手軽ですが、訳文を自社で管理できません。商品名や社名が意図しない形に訳されることがあります。

### 検索エンジンからの評価という観点

海外からの検索での流入を期待するなら、1つ目か2つ目を選んでください。理由は、言語ごとに別のURLを持つ形になるためです。

3つ目の自動翻訳をかぶせる方式では、多くの場合、翻訳された内容が検索エンジンに登録される形になりません。表示は他言語になっても、検索の対象は日本語のページのままという状態です。

つまり、次のように整理できます。

- 海外から検索で見つけてほしい: 言語ごとにURLを持つ方式
- すでに接点のある海外の相手に、読んでもらえれば十分: 自動翻訳でも足ります

自社の目的がどちらなのかを先に決めてください。検索からの流入を期待しないのであれば、費用の低い方式で始めて構いません。

### どの方式を選ぶかの目安

判断の目安は次のとおりです。

1. 海外向けの営業に使い、問い合わせを取りたい。かつ対象ページが20ページ以内。言語ごとにページを作る方式が向きます
2. ページ数が多く、更新も定期的にある。翻訳ツールを組み込む方式が向きます
3. 既存の取引先に資料として見せる用途が中心。自動翻訳をかぶせる方式で足ります

つまずきやすい点を1つ申し添えます。3つ目で始めた後に1つ目へ移る場合、URLの設計をやり直すことになります。

将来的に検索からの流入を狙う見込みがあるなら、最初からURLを言語ごとに分ける設計にしておいてください。ページ数が少ないうちに決めておくほうが、費用は小さく済みます。

要件として何を決めるかは、次で整理します。

## 見積もりを取る前に、何を要件として決めますか？

対象の言語、対象のページ、翻訳の担当、公開後の更新の分担の4つを先に決めます。これを決めずに相見積もりを取ると、金額を比べられません。

前提が違う見積書が並ぶだけになります。安く見える提案は、翻訳が含まれていないだけという場合があります。

### 要件として書く7項目

1. 対象の言語（英語のみか、追加の言語があるか。将来追加する見込みも書きます）
2. 対象のページの一覧（URLで列挙します。全ページと書かないでください）
3. 翻訳の方式（人による翻訳か、機械翻訳に人が手を入れるか、機械翻訳のみか。ページごとに分けても構いません）
4. 翻訳の担当（自社で用意するか、制作会社経由で手配するか）
5. 多言語化の方式（言語ごとにページを持つか、自動翻訳をかぶせるか）
6. 公開後の更新の分担（誰がどの言語を直すか。月に何回程度かの見込みも添えます）
7. 画像内の文字の扱い（差し替える対象の画像を一覧にします）

2つ目が最も重要です。ページをURLで列挙すると、翻訳する文字量が概算できます。制作会社は文字量から翻訳費用を見積もるため、この一覧があるだけで見積もりの精度が上がります。

### RFPに含めるべき記載項目

RFP（提案依頼書）とは、発注者がベンダに対してシステムやサービスの提案を求めるために交付する公式文書です。IPA（情報処理推進機構）の学習教材では、RFI（情報提供依頼書）による市場調査を経た後、実際の調達フェーズで作成されるものとして位置づけられています。出典: IPA学習教材「調達計画・実施」。

実務解説資料に共通して挙げられている標準的な記載項目は、次のとおりです。

| 項目 | 多言語対応で書き足すこと |
| --- | --- |
| プロジェクトの背景と目的 | どの国や地域の、どんな相手に読ませたいのか |
| 現状の課題 | 現在、海外からの問い合わせがどう発生しているか |
| 機能要件（MustとWantに分ける） | 言語切替、言語ごとのURL、翻訳の管理画面 |
| 非機能要件 | 海外からの表示速度、言語ごとの表示の崩れの許容範囲 |
| 予算規模 | 翻訳費を含むか含まないかを明記します |
| 選定基準と評価方法 | 多言語の実績をどう評価するか |

出典: スパイスファクトリー「RFPとは？テンプレートと書き方ガイドで完全解説」、オーシャン・アンド・パートナーズ「RFPとは？書き方・サンプル・記載項目を完全解説」。

RFPの書き方そのものは、当サイトの「Web制作のRFP作り方｜記載項目・テンプレート付き」で扱っています。ここでは多言語対応で書き足す差分だけを示しました。

書きすぎにも注意が必要です。実務解説資料は、要件を詳細に書きすぎると特定ベンダの仕様に引き寄せられ、抽象的すぎると見積もりがベンダごとに大きくばらつくというトレードオフを指摘しています。機能要件は何を実現したいかを中心に書き、実現の手段はベンダの提案に委ねる形が推奨されています。出典: customedia「０から分かる！RFP（提案依頼書）の書き方解説」。

### 見積書で確認する箇所

受け取った見積書では、次の3点を確認してください。

1. 翻訳費が含まれているか。含まれていない場合、いくらで手配できるか
2. 言語の追加が1言語いくらか。将来の追加分の単価が分かります
3. 公開後の更新が月額に含まれるか。含まれない場合、1回あたりいくらか

3つ目が抜けている見積書が多くあります。ここを確認しないまま発注すると、公開後の更新が都度の追加費用になります。

## 費用を抑えるには、どこから始めればよいですか？

全ページではなく、問い合わせにつながるページから始めます。多言語化の範囲を絞ることが、費用を抑える最も確実な方法です。

翻訳の費用はページ数に比例します。範囲を半分にすれば、翻訳の費用も概ね半分になります。

### 段階的に進める手順

1. 海外からの問い合わせや閲覧が、現在どの程度あるかを確認する（所要の目安: 1日）。アクセス解析で国別の閲覧数を見ます
2. 多言語化するページを5ページから10ページに絞る（所要の目安: 2日）。会社案内、サービス内容、実績、問い合わせが中心になります
3. 言語は1つから始める（所要の目安: 判断のみ）。最初から複数にすると、費用と管理の手間が同時に増えます
4. URLの設計だけは、将来の言語追加を見込んで決める（所要の目安: 制作会社との打ち合わせ1回）。ここは後から変えると手戻りが大きくなります
5. 公開後3か月から6か月で、国別の閲覧数と問い合わせを確認し、範囲を広げるか判断する

手順4が肝心です。範囲は後から広げられますが、URLの設計は後から変えると検索での評価に影響します。

月額の費用も見込んでおいてください。ホームページの月額管理と保守の費用は、小規模サイトで月額5,000円からが相場の下限とされています。出典: あきばれホームページ「ホームページ維持費の相場は月いくら？ランニングコストの内訳を全公開」（2026年9月時点）。

多言語化すると、この月額に言語ごとの更新の分が上乗せされます。初期費用と合わせて、年間の負担として見積もってください。

### つまずきやすい点

| つまずく場面 | 対応 |
| --- | --- |
| 全ページを翻訳しようとして予算が合わない | 問い合わせにつながるページに絞ります。ブログとニュースは対象外にします |
| 公開後、日本語だけ更新され他言語が古くなる | 更新の担当と頻度を、公開前に運用手順として決めます |
| 自動翻訳で始めたが検索から流入がない | 目的が検索流入なら、最初から言語ごとにURLを持つ方式を選びます |
| 翻訳の品質に社内で異論が出る | 用語の対訳表を先に作り、社内で合意しておきます |

実装する側の実感として、2行目が最も多く起こります。公開の時点では全言語が揃っていても、半年後には他言語が古い情報のまま残っています。

古い情報が残ることは、翻訳がないことより悪い結果を招きます。料金や対応範囲が変わっていれば、海外の相手に誤った条件を伝えることになります。

更新を続けられる範囲に絞る、という判断が現実的です。年に数回しか変わらないページだけを多言語化しておけば、運用は続きます。

どのページを対象にすべきかは、現在の閲覧の状況と事業の方針で変わります。当社は代表自身が実装者として、アクセスの実績と更新の負担の両面から対象の範囲をお伝えしています。多言語対応をどこから進めるか整理したい場合は、[無料診断](/diagnostic)をご利用ください。

## よくあるご質問

多言語対応のご相談で実際に多い質問をまとめます。

### 自動翻訳だけで多言語対応としてよいですか？

用途によります。既存の取引先に資料として読んでもらう用途であれば足ります。

一方、海外から検索で見つけてもらいたい場合には向きません。自動翻訳をかぶせる方式では、多くの場合、翻訳された内容が検索エンジンに登録される形になりません。

また、訳文を自社で管理できない点にもご注意ください。社名やサービス名が意図しない形に訳されることがあります。商品の仕様や契約に関わるページでは避けてください。

### 多言語対応は、サブディレクトリとサブドメインのどちらがよいですか？

中小企業の規模であれば、サブディレクトリをおすすめします。理由は運用の手間です。

サブドメインにすると、サーバの設定や証明書の管理が言語ごとに増えます。国ごとに別の担当者が運用する体制でなければ、分ける利点は小さくなります。

いずれを選ぶ場合も、公開後に変更すると検索での評価に影響します。最初に決めてください。

### 英語だけ対応する場合と、複数言語に対応する場合で費用はどれくらい変わりますか？

翻訳の費用は言語数にほぼ比例します。3言語なら、1言語の3倍が目安になります。

実装の費用は比例しません。言語切替の仕組みは1度作れば使えるためです。2言語目以降の実装費は、1言語目より小さくなります。

具体的な金額は、案件の規模と要件により大きく変動します。ページ数と翻訳の方式を決めてから見積もりを取ってください。

### 公開後の翻訳の更新は、誰が行うことになりますか？

契約で決めた分担によります。決めていない場合、多くは発注者側に残ります。

見積書で確認する点は2つです。更新が月額の保守に含まれるか、含まれない場合は1回あたりいくらかです。

運用の現実として、日本語だけが更新され他言語が古くなる状態が起こりやすくなります。更新の担当と頻度を、公開前に運用手順として文書にしておいてください。

### 既存サイトに後から多言語対応を追加できますか？

できます。ただしURLの設計の見直しが必要になる場合があります。

確認する点は次の3つです。

1. 現在のCMSが多言語の管理に対応しているか
2. 既存のURLの構成が、言語ごとの階層を追加できる形か
3. 現在のページ数のうち、実際に翻訳する対象が何ページか

3つ目を先に絞ってください。既存サイトが50ページあっても、多言語化するのは5ページから10ページで足りる場合が多くあります。

後付けの費用は、既存サイトの作りによって差が出ます。現状を見ないと判断できない部分です。
