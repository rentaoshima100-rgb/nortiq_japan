# 建設業の工事写真と図面｜10年保存と検索の外注要件

## 保管義務のある資料はどれですか

発注の前に、建設業法施行規則で保存が義務付けられている図書と、義務ではないが実務で引き当てる資料を分けて一覧にします。この一覧が、保管の仕組みに載せる対象と、検索できる状態にしておく期間を決めます。

### 営業に関する図書は3種類で保存期間は10年

国土交通省の「『建設業法施行規則』の一部改正について」（平成20年8月。https://www.mlit.go.jp/common/000021720.pdf ）によると、発注者から直接建設工事を請け負った建設業者が保存を義務付けられている「営業に関する図書」は、完成図、発注者との打合せの記録、施工体系図の3種類です。同資料は「完成図」を工事目的物の完成時の状態を表現した図と定義しています。これらの図書の保存期間は10年です。この改正は平成18年の建設業法改正を受けたもので、施行は平成20年11月28日です。

| 資料 | 保存期間 | 根拠 |
|---|---|---|
| 完成図 | 10年 | 国土交通省「『建設業法施行規則』の一部改正について」（平成20年8月） |
| 発注者との打合せの記録 | 10年 | 同上 |
| 施工体系図 | 10年 | 同上 |
| 帳簿および添付資料としての請負契約の写し等 | 5年 | 同上 |

### 帳簿と請負契約の写し等は5年

同じ資料では、従来から義務付けられていた帳簿およびその添付資料としての請負契約の写し等の保存期間は、従前どおり5年とされています。つまり、同じ工事に関する資料でも、保存期間が2通りに分かれます。保管の仕組みを作るときは、資料の種類ごとに期間を持たせておく必要があります。

実装の段でつまずきやすいのがここです。工事単位でまとめて保管する作りにすると、5年で消してよい資料と10年残す資料が同じ束に入り、どちらの期間で扱うか判断できなくなります。資料の種類を登録時に選ぶ項目として持たせておくと、期間ごとの扱いを後から分けられます。

### 義務ではないが引き当てる資料を足す

1. 法令上の保存義務がある図書を上の表のとおり書き出します（所要時間の目安: 10分）。
2. 義務ではないものの、後から参照する資料を足します（例: 施工中の写真、近隣への説明の記録、協力会社とのやり取り）（つまずきやすい点: 「とりあえず全部」とすると移行の数量が膨らみ、見積もりが上がります。参照した経験がある資料に絞ります）。
3. 資料の種類ごとに、保管する期間を決めます。法令上の義務がないものは、自社で何年と決めて一覧に書きます（所要時間の目安: 30分）。
4. 一覧を、保存期間の長い順に並べ替えます。

現場の実態として、紙の管理は今も残っています。建設現場の業務実態調査では、現場で扱う資料の管理・共有を紙で行っている回答が4割を占め、クラウド利用は約1割にとどまっています。管理が属人化しているため、過去資料の検索性と外出先からの閲覧が課題として挙げられています（出典: 建設現場の業務実態調査。https://prtimes.jp/main/html/rd/p/000000484.000020202.html ）。

なお、国土交通省の「建設業許可業者数調査の結果概要（令和8年3月末現在）」によると、建設業許可業者数は483,823業者で、前年同月比123業者（0.03%）の増加です。兼業業者の割合は30.0%で、前年同月比0.4ポイントの増加となっています（https://www.mlit.go.jp/report/press/content/002000768.pdf ）。多くは総務と現場を兼ねる小規模な体制で、保管の作業に人手を割けないという前提で要件を考える必要があります。

検索条件の決め方は次の節で扱います。

## 何を検索条件にすれば過去の資料を引き当てられますか

検索条件は工事名だけでは足りず、工事名・工種・撮影または作成の日付・場所の4項目を登録の必須項目として要件に書きます。この4項目がそろっていれば、工事名を思い出せない場合でも日付と場所から絞り込めます。

### 登録時に必須にする項目を決める

| 項目 | 必須にする理由 | 入力の形 |
|---|---|---|
| 工事名 | 工事単位で引き当てる場面が最も多いため | 一覧から選ぶ |
| 工種 | 同じ工事の中で目的の写真を絞るため | 一覧から選ぶ |
| 撮影または作成の日付 | 工事名が曖昧なときの手がかりになるため | 自動取得と手修正の併用 |
| 場所 | 同じ工事の複数区画を区別するため | 一覧から選ぶか自由入力 |
| 資料の種類 | 保存期間の管理に使うため | 一覧から選ぶ |

自由入力の項目を増やすと、表記が人によって揺れて検索に引っかからなくなります。一覧から選ぶ形にできる項目は、選択式で要件に書きます。選択肢の初期値を誰が作るかも、発注時に決めておきます。

### 後から探す場面を3つ書き出して条件を逆算する

1. 直近1年で、過去の資料を探した場面を3つ書き出します（例: 発注者から是正の指摘を受けて該当箇所の施工時の写真を出した、近隣からの問い合わせに当時の記録で答えた、次の工事の見積もりで同種の工事の実績を参照した）（所要時間の目安: 30分）。
2. それぞれの場面で、最初に手元にある情報を書きます（つまずきやすい点: 「工事名は覚えていないが、おおよその時期と場所は分かる」という場面が多数です。この場合、工事名だけが検索条件だと引き当てられません）。
3. 手元にある情報が検索条件になっているかを確認し、足りない項目を必須項目に追加します（所要時間の目安: 15分）。

この3つの場面は、そのまま要件書に添える受け入れの確認項目にもなります。納品時に、同じ3つの場面で実際に引き当てられるかを試せば、検索の要件が満たされたかを判断できます。

### 命名規則だけに頼らない

ファイル名に工事名と日付を入れる運用で代用しようとする方法は、短期的には動きますが、担当者が変わると規則が崩れます。規則から外れた1件が、後から最も必要になる資料であることも起こります。

実装の観点では、ファイル名ではなく、登録時に入力した項目で検索する作りにしてもらう点が要点です。あわせて、次の2つを要件に書いておきます。

1. ファイル名を変えても検索の結果が変わらないこと。
2. 項目の入力が漏れた資料を、後から一覧で抽出できること（つまずきやすい点: 入力漏れを抽出できない作りにすると、漏れた資料は検索でも見つからず、保管したつもりで失われます）。

資料の種類ごとの保存期間を扱う画面については前の節で触れたとおりです。移行対象の決め方は次の節で扱います。

## 既存の資料をどこまで移行対象に含めますか

移行は全件ではなく、保存期間が残っている工事と、引き合いで参照する工事に絞って範囲を決めます。範囲を決めずに「過去分も全部」と依頼すると、見積もりの移行費用が読めず、各社の金額を比べられません。

### 引き渡し日から保存期間の残りを数える

国土交通省の「『建設業法施行規則』の一部改正について」（平成20年8月。https://www.mlit.go.jp/common/000021720.pdf ）によると、営業に関する図書の保存期間は10年です。保存の義務は、発注者から直接建設工事を請け負った建設業者に課されます。

1. 完成工事の一覧を引き渡し日の新しい順に並べます（所要時間の目安: 既存の工事台帳があれば30分）。
2. 引き渡し日から10年が経過していない工事に印を付けます。これが保存義務が残っている範囲です（つまずきやすい点: 引き渡し日が台帳に無く、竣工検査の日や請求の日で管理している会社があります。どの日付を起算に使うかを社内で統一してから数えます）。
3. 帳簿および請負契約の写し等は保存期間が5年のため、別の列で数えます（所要時間の目安: 20分）。
4. 保存義務が残っている工事の件数を集計します。この件数が、移行の見積もりに渡す数量になります。

### 紙とファイルサーバを分けて数量を把握する

移行の手間は、資料が紙かデータかで大きく変わります。両方の数量を分けて把握します。

| 保管の形 | 数え方 | 移行の作業 |
|---|---|---|
| 紙の図面と写真台帳 | 工事ごとのファイル冊数 | スキャンと項目の入力が必要 |
| ファイルサーバ内のデータ | 工事ごとのフォルダ数と容量 | 取り込みと項目の入力が必要 |
| 現場担当者の端末内の写真 | 担当者ごとの枚数の概数 | 回収の依頼から始まる |
| 施工管理ツール内のデータ | 工事ごとの件数 | 書き出しの可否を提供元に確認 |

現場の実態として、建設現場の業務実態調査では、現場で扱う資料の管理・共有を紙で行っている回答が4割を占め、クラウド利用は約1割にとどまっています（出典: 建設現場の業務実態調査。https://prtimes.jp/main/html/rd/p/000000484.000020202.html ）。紙が中心であれば、移行の費用の大半はスキャンと項目の入力になります。

実装の観点では、現場担当者の端末内に残っている写真が最も見落とされます。退職や異動で端末が手元を離れると回収できなくなるため、移行の対象に含めるかどうかを早い段階で決めておきます。

### 移行の作業を誰が行うかを見積もりの前に決める

1. スキャンを自社で行うか委託するかを決めます（つまずきやすい点: 自社で行う前提にすると費用は下がりますが、作業が止まったまま数か月が過ぎることがあります。誰がいつ行うかを決めてから自社と答えます）。
2. 項目の入力を自社で行うか委託するかを決めます。工事名と日付の入力は、当時の担当者でないと分からない場合があります。
3. 移行を一度で終えるか、保存期間の残りが短い工事から段階的に行うかを決めます（所要時間の目安: 検討30分）。
4. 決めた内容を要件書に数量つきで書きます。書き方は後述します。

## 現場から見る前提で何を要件に書きますか

現場からの閲覧を前提にする場合は、通信量、写真の表示サイズ、権限の3点を要件に書きます。この3点は、画面の見た目の要望よりも先に決める部分です。

### アップロード時の自動縮小を要件にする

現場で撮った写真は1枚あたりの容量が大きく、そのまま保管すると一覧を開くだけで時間がかかります。要件には次のように書きます。

1. アップロード時に、閲覧用の縮小版を自動で作ること（つまずきやすい点: 縮小版だけを残す作りにすると、後から黒板の文字が読めない場合があります。原寸を残したうえで、一覧には縮小版を出す形を指定します）。
2. 一覧の画面では縮小版を表示し、原寸は個別に開いたときだけ読み込むこと。
3. 電波の弱い現場を想定し、アップロードが途中で止まった場合に再開できること（所要時間の目安: 要件の記述は10分）。

公共工事の電子納品に使う写真は、国土交通省の「デジタル写真管理情報基準」の版によって有効画素数の指標が異なります。発注者ごとの要領でも指定が違うため、納品に使う写真の条件は契約図書で確認し、原寸をそのまま取り出せる作りにしておきます。

### 工事ごとの閲覧権限を決める

| 立場 | 見える範囲 | 書き込み |
|---|---|---|
| 現場監督 | 担当する工事のすべて | 登録と修正ができる |
| 他の現場の監督 | 閲覧のみ、または対象外 | できない |
| 総務および経営 | すべての工事 | 削除の権限を限定する |
| 協力会社 | 指定した工事の指定した範囲 | 登録のみ、修正はできない |

削除の権限は、保存期間が残っている資料を誤って消さないために絞ります。削除した記録が残る作りにしてもらう点も、要件に書いておきます。

### 協力会社に見せる範囲を決める

1. 協力会社に見せる必要があるかを工種ごとに判断します（所要時間の目安: 20分）。
2. 見せる場合、工事単位で招待する形にするか、特定のフォルダのみを共有する形にするかを決めます（つまずきやすい点: 会社単位でまとめて権限を与えると、担当を外れた後も見える状態が残ります。工事ごとに期限を付けて招待する形が管理しやすくなります）。
3. 協力会社の担当者が入れ替わったときに、誰が権限を外すかを決めます。
4. 原寸の写真を取り出せる相手を限定するかどうかを決めます。

権限の区分が決まると、要件書に書く項目がそろいます。要件書の書き方は次の節で扱います。

## 見積もりを比べるために要件書へ何を書きますか

要件書には、登録の必須項目、検索条件、移行対象の数量、権限の区分を数量つきで書き、初期の移行費用と月額の保管費用を分けて見積もるよう指定します。同じ要件書を複数社に渡すことが、比べられる見積もりを集める前提です。

### 数量を書くと見積もりが比べられる

| 要件書に書く項目 | 書き方の例 |
|---|---|
| 登録の必須項目 | 工事名・工種・日付・場所・資料の種類の5項目 |
| 検索条件 | 上記5項目の組み合わせで絞り込めること |
| 受け入れの確認 | 指定する3つの場面で実際に引き当てられること |
| 移行対象（紙） | 保存義務が残る工事のファイル冊数 |
| 移行対象（データ） | 工事ごとのフォルダ数と合計容量 |
| 保管する容量の見通し | 年間の工事件数と1件あたりの写真の枚数 |
| 権限の区分 | 現場監督・他の監督・総務・協力会社の4区分 |
| 利用する人数 | 社内の人数と、協力会社の同時利用の見込み |

数量が書かれていない要件書に対しては、各社が自社の標準で前提を埋めます。その結果、金額の差が仕様の差なのか前提の差なのか判断できなくなります。

### 初期の移行と月額の保管を分ける

1. 初期費用に含めるものを明記します（例: 画面の制作と設定、権限の初期登録、指定した数量の移行）（所要時間の目安: 20分）。
2. 月額費用に含めるものを明記します（例: 保管の容量、利用者の人数、障害時の対応）。
3. 容量が増えた場合に月額がどう変わるかを、段階ごとに示すよう求めます（つまずきやすい点: 初期の容量だけで比べると、3年後に月額が大きく変わる提案を選んでしまいます。容量の増加に対する金額の変わり方を必ず確認します）。
4. 協力会社の利用が人数に数えられるかを確認します。

### 保存期間が終わった資料の扱いを先に決める

保存期間が過ぎた資料を自動で消すか、残したまま一覧から外すかを決めておきます。要件には次の3点を書きます。

1. 保存期間が過ぎた資料を一覧で抽出できること。
2. 削除は自動で行わず、人が確認してから実行する形にすること（つまずきやすい点: 自動削除を入れると、保存期間の起算日の登録が誤っていた資料まで消えます。起算日の修正ができる作りと合わせて確認します）。
3. 削除した記録（いつ、誰が、何を）が残ること。

容量の費用は保管量に応じて増えるため、消してよい資料を消せる状態にしておくことが、月額を抑える唯一の手段になります。導入後の運用については次の節で扱います。

## 導入後に紙とExcelが残らないようにするには

登録の手間が現場の負担になると紙に戻るため、現場が登録する項目を最小限にし、事務所側で補う分担を決めておきます。導入そのものよりも、導入した後に運用が置き換わるかどうかが分かれ目になります。

この傾向は調査にも表れています。現場TECHが建設業従事者426名を対象に2026年3月に実施したWebアンケートでは、施工管理アプリを導入した後も62.5%がExcel中心の運用を続けているという結果が示されています。同じ調査では、施工管理のデジタル化の必要性を認識している回答が92.5%に達する一方で、実務の中心はExcelが68.5%でした。同調査は、デジタル化が進まない要因として、費用よりも現場定着、操作負担、二重管理といった運用面の課題を挙げています（出典: 現場TECH 2026年3月調査、n=426）。

### 現場が入力する項目を絞る

1. 登録の必須項目のうち、現場で入力するものと事務所で補うものを分けます（所要時間の目安: 20分）。
2. 工事名と工種は現場で選択式にし、資料の種類の判定は事務所で行う分担にします（つまずきやすい点: 5項目すべてを現場に求めると、撮影のたびに手が止まり、後でまとめて登録する運用になります。まとめて登録する運用になると、日付と場所の記憶が曖昧になり、検索条件の精度が落ちます）。
3. 日付は撮影時に自動で記録される値を使い、現場での入力を求めない形にします。
4. 事務所で補う作業にかかる時間を見積もり、誰がいつ行うかを決めます（所要時間の目安: 検討30分）。

### 登録漏れに気付く確認の日を決める

| 確認すること | 頻度 | 担当 |
|---|---|---|
| 必須項目が未入力の資料の一覧 | 週に1回 | 事務所の担当者 |
| 工事ごとの登録件数が0件のまま進んでいる工事 | 月に1回 | 総務または管理部門 |
| 端末内に残っている写真の有無 | 月に1回 | 各現場監督 |

前の節で挙げた「入力漏れを後から一覧で抽出できること」という要件は、この確認のために必要になります。抽出できない作りだと、確認の作業自体が成り立ちません。

### 既存の施工管理ツールとの役割を分ける

すでに施工管理ツールを使っている場合は、どの資料をどちらに置くかを決めます。同じ写真が両方に入ると、二重管理になり、どちらが最新か分からなくなります。

1. 施工中の進捗管理はツール側、引き渡し後に残す資料は保管の仕組み側、という分け方を基本にします。
2. ツールから資料を書き出せるかを、提供元に確認します（つまずきやすい点: 書き出しに対応していないツールもあります。その場合、引き渡しのたびに手作業で移す運用になるため、作業量を見積もっておきます）。
3. 工事が完了したときに、資料を移す担当と期限を決めます。

制度の側でも書類のやり取りを見直す動きがあります。国土交通省は、建設業におけるICTの導入と活用に向けた施策としてICT指針とその事例集を公表しており、元請と下請の間の書類等のやり取りの合理化、建設キャリアアップシステム、建退共の電子申請方式、電子契約の活用を推進しています。公共工事を受注する場合は、発注者側の要領の変更も併せて確認しておくと、二度手間を避けられます。

## よくある質問

発注前に多い疑問を、公的資料で確認できる範囲に限って整理します。確認できなかった点は、そのまま書いています。

### 工事写真そのものに法令上の保存期間はあるのでしょうか

国土交通省の「『建設業法施行規則』の一部改正について」（平成20年8月）で保存の対象として挙げられているのは、完成図、発注者との打合せの記録、施工体系図の3種類です。施工中の写真そのものがこの3種類に含まれるかどうかについての記載は、同資料では確認できませんでした。

実務では、公共工事の場合は発注者の要領で提出と保管の条件が定められます。民間工事の場合は、是正の指摘や近隣からの問い合わせに答えるために参照する資料として、自社で期間を決めて保管している会社が多くあります。法令上の義務とは分けて考え、保管の期間を社内で決めるのが現実的です。

### 営業に関する図書は電子データのままで保存してよいのでしょうか

電磁的記録による保存の可否について、今回参照した国土交通省の資料では明確な記載を確認できませんでした。電子で保存する前提で仕組みを作る場合は、所轄の行政庁または顧問の専門家に、自社の保存方法が要件を満たすかを確認してください。確認した結果を要件書に書いておくと、委託先との認識のずれを防げます。

### 保存期間の10年はいつから数えるのでしょうか

保存期間は、建設工事の目的物を引き渡したときから数えます。社内で引き渡し日を台帳に記録していない場合は、どの日付を起算に使うかを先に統一してください。竣工検査の日や請求の日で管理していると、工事によって数え方がずれます。

### 既存の紙の図面はすべてスキャンする必要がありますか

必要はありません。保存義務が残っている工事と、引き合いで参照する工事に絞るのが現実的です。保存義務が残っている工事は、引き渡し日から10年が経過していない工事です。帳簿および請負契約の写し等は5年で数えます。絞り込んだ件数が、移行の見積もりに渡す数量になります。

### 協力会社に写真を見せる場合、権限はどう分ければよいですか

工事単位で期限を付けて招待する形が管理しやすくなります。会社単位でまとめて権限を与えると、担当を外れた後も見える状態が残ります。あわせて、協力会社には登録のみを許可し、修正と削除はできない設定にしておくと、誤って上書きされる事故を避けられます。

### 施工管理ツールを入れていれば、別に保管の仕組みは不要ですか

ツールが引き渡し後も資料を保持し、検索できるのであれば兼用できます。確認するのは、契約を解約した後にデータを取り出せるかどうかです。取り出せない場合、保存期間が残っているうちは解約できないことになります。書き出しの形式と、解約後のデータの扱いを、提供元に確認してください。
