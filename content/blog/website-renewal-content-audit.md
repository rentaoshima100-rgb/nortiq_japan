# サイトリニューアルのページ棚卸し、残す基準の作り方

## 何から始める？ ページ一覧を作るところから

まず全ページのURL一覧を作り、そこに判断材料となる数字を並べます。感覚で残すページを選ぶと、後から理由を説明できません。

棚卸しは、どのページを残すかを決める作業です。決めた結果より、どの数字を根拠にしたかを残しておくほうが、後の議論で効きます。

### 一覧に入れる項目

一覧は表計算ソフトで足ります。1行に1ページを置き、次の項目を列にしてください。

| 列 | 入れる内容 |
| --- | --- |
| URL | 対象ページのアドレス |
| ページ種別 | サービス紹介、事例、コラム、会社情報など |
| 最終更新日 | 内容を最後に直した日 |
| 表示回数 | 検索結果に表示された回数 |
| クリック数 | 検索結果から訪問された回数 |
| 平均掲載順位 | 検索結果での平均の位置 |
| 役割 | 問い合わせ前に読まれる、採用で使うなど |

最終更新日を入れておくのは、自社サイトが最後に更新された時期を確認することが、リニューアル計画の起点になるためです。総務省「令和6年 通信利用動向調査報告書（企業編）」によれば、日本企業全体のホームページ開設率は9割前後で推移しており、中小企業ではホームページの有無だけでなく、内容の鮮度や機能の適切さが競合との差別化要因になっています。

### データをどこから取るか

数字は、Google Search Consoleと自社のアクセス解析から取ります。どちらも無料で、権限があれば担当者自身で書き出せます。

1. Search Consoleの検索パフォーマンスから、ページ別の表示回数、クリック数、平均掲載順位を書き出す（所要時間の目安: 1時間）。
2. アクセス解析から、ページ別の訪問数と問い合わせへの導線の通過状況を書き出す（つまずきやすい点: 集計期間を短く取ること。季節の偏りを避けるため、12か月分で見てください）。
3. 2つの書き出しをURLで突き合わせ、1つの一覧にまとめる。
4. 数字が取れないページに印を付ける。

4つめを飛ばさないでください。公開したばかりのページや、検索以外から見られているページは、数字が小さく出ます。この印が無いと、数字だけを見て削除の候補に入れてしまいます。

なお、リニューアルを社内で説明する場面では、公的統計や公式ドキュメントの数値を根拠として示すことが有効です。棚卸しの一覧も、その説明資料の土台になります。指標の読み方は次のセクションで扱います。

## どの数字で判断する？ 4つの指標の見方

判断には、表示回数、クリック数、掲載順位、そのページが担う役割の4つを使います。アクセス数だけで切ると、問い合わせ前に読まれるページを落とします。

4つのうち3つはSearch Consoleから取れます。残る1つの役割は、数字ではなく社内の判断です。

### 検索パフォーマンスの基本指標

Google Search Consoleの検索パフォーマンスで確認できる基本の指標は次のとおりです（出典: Google Search Console ヘルプ）。

| 指標 | 意味 | 棚卸しでの読み方 |
| --- | --- | --- |
| 表示回数 | 検索結果に表示された回数 | 需要があるかどうかを示す |
| クリック数 | 検索結果から訪問された回数 | 表示に対して選ばれているか |
| 平均掲載順位 | 検索結果での平均の位置 | 改善の余地が残っているか |

組み合わせて読むと、対応が分かれます。表示回数が多いのにクリックが少ないページは、内容ではなくタイトルと説明文に原因があることが多く、書き直しの候補です。

表示回数そのものが少ないページは、需要が無いか、検索で見つかっていないかのどちらかです。前者なら統合か削除、後者なら内容の見直しになります。

### 数字に出ない役割を持つページ

4つめの役割は、一覧の数字だけでは分かりません。次のようなページは、検索からの流入が少なくても残す判断になります。

- 問い合わせ前に読まれる、料金や事例のページ
- 営業資料やメールからリンクしているページ
- 採用の応募者が見るページ
- 取引先から求められて用意したページ

これらは、検索以外の経路で見られています。アクセス解析でそのページを経由した後の動きを見ると、問い合わせにつながっているかが確認できます。

1. 一覧の各ページに役割を記入する（所要時間の目安: 半日）。
2. 営業や採用の担当者に、業務で使っているページを聞く（つまずきやすい点: Web担当者だけで判断すること。社外に渡しているURLは把握しきれません）。
3. 役割がある行に印を付け、数字だけでは切らないようにする。

2つめは短時間で済みますが、効果は大きい作業です。削除した後に「あのページを取引先に案内していた」と判明する事態を防げます。

数字と役割が揃ったら、振り分けに進みます。基準の作り方は次のセクションで扱います。

## 残す、統合する、削除するをどう決める？ 判断の型

4つの指標を組み合わせ、残す、統合する、削除する、書き直すの4つに振り分けます。似た内容のページが複数あるなら、統合が第一候補です。

振り分けは一度で決めきらなくて構いません。まず機械的に仮の区分を付け、そのうえで役割の印が付いた行を個別に見直す順序が効率的です。

### 振り分けの基準表

仮の区分を付けるときの目安です。数字の閾値は自社の規模で調整してください。

| 状態 | 区分 | 理由 |
| --- | --- | --- |
| 表示もクリックもあり、順位も安定 | 残す | 現に機能しています |
| 表示は多いがクリックが少ない | 書き直す | 内容よりタイトルと説明文に原因があることが多い |
| 似た内容のページが複数ある | 統合する | 同じ検索意図で競合し、どちらも伸びません |
| 表示もクリックもほぼ無く、役割も無い | 削除する | 残す理由が見当たりません |
| 公開から日が浅い | 保留 | 判断できるだけの数字が溜まっていません |

最後の行を必ず入れてください。公開から数か月のページは、需要が無いのか、まだ見つかっていないだけなのかを区別できません。

役割の印が付いた行は、この表の結果にかかわらず残す側に寄せます。数字が小さくても、営業や採用で使っているなら機能しているページです。

### 統合するときの考え方

似た内容のページが複数あると、同じ検索意図で自社のページ同士が競合します。統合の判断は次の順で進めます。

1. 似ているページをグループにまとめる（つまずきやすい点: タイトルの言葉だけで似ていると判断すること。読者が知りたいことが同じかで見てください）。
2. 各グループで、数字が最も良いページを残す側に決める（所要時間の目安: 1グループあたり15分）。
3. 残す側に、他のページの内容で必要な部分を取り込む。
4. 取り込まれた側のURLの行き先を決める。

3つめで、単純に本文をつなげないでください。統合は、1つの問いに1つのページで答える形に整える作業です。内容を足すほど、何のページか分からなくなります。

4つめのURLの扱いは、公開後の流入に直結します。詳しくは後のセクションで扱います。

なお、振り分けの結果は一覧に列として残してください。誰が、いつ、どの数字を見て決めたかが分かる状態にしておくと、公開後に見直すときの出発点になります。

## 表示速度は判断に関わる？ 公式の合格基準を使う

ページ単位の作り直しを判断する材料として、Googleが公開している表示速度の合格基準が使えます。基準を満たしていないページは、書き直しの候補に入ります。

速度は、内容の良し悪しとは別の軸です。読む価値のある内容でも、表示に時間がかかれば読まれる前に離脱されます。

### Core Web Vitalsの合格基準

Googleは2021年6月より、ページエクスペリエンスのランキングシグナルとしてCore Web Vitalsを正式に採用しています。良好とされる基準は次のとおりです（出典: Google Search Central 公式ドキュメント）。

| 指標 | 何を測るか | 良好の基準 |
| --- | --- | --- |
| LCP | 主要な内容が表示されるまでの時間 | 2.5秒以内 |
| INP | 操作してから反応するまでの時間 | 200ミリ秒以内 |
| CLS | 表示中のレイアウトのずれ | 0.1以下 |

あわせて、Googleはモバイルファーストインデックスを採用しており、クロールとインデックス登録の基準をスマートフォン版のページに置いています。測定はスマートフォンの表示で行ってください。

これらの目標値は、要件定義の段階で決めておくと制作会社への発注仕様が明確になり、公開後の効果測定にも使えます。棚卸しの段階で現状の値を一覧に足しておくと、リニューアル後の比較もそのままできます。

### 速度を理由に作り直すかの判断

基準を満たしていないページを、すべて作り直す必要はありません。原因によって対応が変わります。

1. 対象ページの現状値を測り、一覧に列として足す（所要時間の目安: 主要ページ20件で2時間）。
2. 基準を外れているページについて、原因を大きく分ける（つまずきやすい点: ページ単位の問題とサイト共通の問題を混ぜること）。
3. サイト共通の原因なら、リニューアルの要件として一括で扱う。
4. ページ固有の原因なら、そのページを書き直す候補に入れる。

2つめの切り分けが要点です。共通のテンプレートや読み込んでいる外部の部品が原因なら、個別のページを書き直しても改善しません。逆に、特定のページだけ画像が極端に重いといった場合は、そのページの作り直しで解決します。

速度が基準を外れていることだけを理由に、内容の良いページを削除しないでください。速度は直せますが、内容は作り直す必要があります。判断の優先順位は、内容の価値が先です。

## 削除したページのURLはどうする？ 公開後の扱い

削除や統合をしたページのURLは、放置せず行き先を決めます。ここの処理を飛ばすと、リニューアル後に検索からの流入を落とします。

サイトリニューアルでURLが変わる場合、301リダイレクトを適切に設定しないと、Googleはそれまでの検索評価を引き継げません。Google Search Centralの公式ドキュメントも、URLを変更する際には301リダイレクトの設定とSearch ConsoleでのURL変更の通知を案内しています（出典: Google Search Central「Site Moves and Migrations」）。

### 行き先の決め方

行き先は、元のページで読者が知りたかったことに最も近いページにします。機械的にトップページへ集めないでください。

| 元のページの区分 | 行き先 |
| --- | --- |
| 統合した | 統合先のページ |
| 削除したが近い内容が残る | 内容が最も近いページ |
| 削除して近い内容も無い | 一覧ページ、またはそのまま消す |
| URLだけ変えて内容は残す | 新しいURL |

3行目の扱いは判断が分かれます。近い内容が本当に無いなら、無理に別のページへ飛ばすより、そのまま消すほうが読者にとって分かりやすいこともあります。

1行目と2行目が大半を占めるはずです。棚卸しの段階で統合先を決めているので、その情報がそのまま行き先になります。

### 処理の一覧を作って引き渡す

制作会社への引き渡しは、口頭ではなく一覧で行います。元のURLと新しいURLを1対1で並べた表を作ってください。

1. 棚卸しの一覧に、行き先URLの列を足す（所要時間の目安: 2時間）。
2. 元のURLと行き先URLの対応表として書き出す（つまずきやすい点: 末尾のスラッシュやパラメータ付きのURLを漏らすこと）。
3. 対応表を制作会社に渡し、公開前に反映してもらう。
4. 公開後、Search ConsoleでURL変更の通知と、エラーの発生状況を確認する。

4つめまでが1つの作業です。設定したつもりで漏れているURLは、公開後のエラーとして現れます。公開日から数日は、この確認を日課にしてください。

なお、中小企業庁の「2022年版中小企業白書」では、デジタルツールを導入しても活用が売上や業務効率の改善につながっていない例が多く、導入と活用の間にギャップがあることが課題として指摘されています（出典: 中小企業庁「2022年版中小企業白書」第2節）。リニューアルも同じで、公開して終わりにすると効果が出ません。棚卸しの一覧は、公開後の運用でもそのまま使えます。

## つまずきやすい点は？ 棚卸しで起きる3つの失敗

アクセス数だけで切る、公開直後のページを数字だけで判断する、棚卸しの結果を記録に残さないという3点が、後から効いてきます。前の2点はここまでで触れたため、記録の残し方を中心に整理します。

### 判断の根拠を残す

棚卸しの一覧は、作業が終わったら消さずに保管してください。次のリニューアルや、日々の更新でそのまま使えます。

一覧に残しておく列は次のとおりです。

| 残す列 | 後から何に使うか |
| --- | --- |
| 判断した区分 | なぜ削除したかを説明できる |
| 判断の根拠となった数字 | 当時の状態と比較できる |
| 判断日と判断者 | 誰に確認すればよいか分かる |
| 行き先URL | リダイレクトの漏れを追える |

数か月後に「このページはなぜ消したのか」と聞かれる場面は必ず来ます。そのときに数字と日付が残っていれば、議論が一度で済みます。

### 公開後に効果を測れる形にする

リニューアルは公開して終わりではありません。中小企業庁の「2022年版中小企業白書」でも、デジタルツールの導入と活用の間にギャップがあることが課題として指摘されています。

棚卸しの数字を取ったときと同じ条件で、公開後にも測ってください。条件を変えると、良くなったのか測り方が変わっただけなのか分からなくなります。

1. 公開前の数字を取った期間と条件を記録しておく（つまずきやすい点: 期間を書き残さないこと）。
2. 公開から3か月後に、同じ期間の長さで数字を取り直す（所要時間の目安: 1時間）。
3. 残したページ、統合したページ、書き直したページを区分ごとに比べる。
4. 想定と違った区分について、判断の基準そのものを見直す。

3つめの区分ごとの比較が要点です。全体の数字だけを見ると、どの判断が効いたのかが分かりません。統合したページが伸びていれば、次も同じ基準で進められます。

棚卸しは手間のかかる作業ですが、判断の根拠を残しておけば次回は短く済みます。自社のページをどう扱うか整理したい場合は、[無料診断](/diagnostic)もご利用いただけます。

## よくある質問

棚卸しの作業中に判断を迷いやすい点をまとめました。数字の閾値は自社の規模で変わるため、判断の順序を中心に整理しています。

### アクセスがほとんど無いページは、削除してしまってよいですか？

数字だけで決めないでください。まず、営業や採用の場面で使われていないか、取引先に案内していないかを社内に確認します。役割が無く、似た内容のページも無く、公開から十分な期間が経っているなら、削除の候補です。公開から日が浅いページは、需要が無いのかまだ見つかっていないだけなのかを区別できないため、保留にします。

### 似た内容のページは、どちらを残して統合すればよいですか？

表示回数、クリック数、平均掲載順位を比べ、数字が最も良いページを残す側にします。そのうえで、残す側に他のページの必要な部分を取り込みます。本文を単純につなげると、何のページか分からなくなるため、1つの問いに1つのページで答える形に整えてください。

### 削除したページのURLは、トップページへ転送してよいですか？

避けてください。行き先は、元のページで読者が知りたかったことに最も近いページにします。近い内容が本当に無い場合は、無理に別のページへ飛ばすより、そのまま消すほうが分かりやすいこともあります。元のURLと行き先URLの対応表を作り、制作会社に渡してください。

### 公開したばかりのページも、同じ基準で判断してよいですか？

同じ基準では判断できません。検索に表示されるまでにも、評価が安定するまでにも時間がかかります。棚卸しの一覧では保留の区分を設け、次回の棚卸しまで判断を持ち越してください。数字が取れないページに印を付けておくと、誤って削除の候補に入れずに済みます。

### 棚卸しの作業は、制作会社に任せられますか？

数字の書き出しと集計は任せられますが、ページの役割の判断は自社で行ってください。どのページを営業で使っているか、取引先に案内しているかは、業務を知る側にしか分かりません。制作会社に渡すのは、判断の済んだ一覧と、元のURLと行き先URLの対応表です。

最後に、棚卸しの流れをまとめます。

1. 全ページのURL一覧を作り、12か月分の数字を書き出す（所要時間の目安: 1日）。
2. 各ページに役割を記入し、営業や採用の担当者に確認する（つまずきやすい点: Web担当者だけで判断すること）。
3. 残す、書き直す、統合する、削除する、保留の5つに振り分ける。
4. 行き先URLの対応表を作り、公開後にエラーの発生状況を確認する。
