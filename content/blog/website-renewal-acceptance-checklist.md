# ホームページリニューアルの検収項目と通知期限

## 検収の前に確認しておくこと

検収の前に、契約書で定めた検収の期間と、不具合を伝える期限を確認します。納品の連絡を受けてから契約書を探し始めると、確認に使える日数がその分だけ減ります。

### 契約書のどこを見るか

見るべき条項は限られています。次の4点を先に抜き出しておくと、以降の作業が進めやすくなります。

1. 検収の期間。納品からいつまでに確認し、結果を伝えるかが書かれています。
2. 検収の方法。検収書を取り交わすのか、一定期間内に異議がなければ検収完了とみなすのかが書かれています。
3. 不具合を伝える期限。検収の完了後に不具合が見つかった場合、いつまでに通知すれば修補を求められるかが書かれています。
4. 契約の範囲。何を納品物とするかが書かれています。ここが検収時の線引きの土台になります。

つまずきやすいのは、「一定期間内に異議がなければ検収完了とみなす」という定めに気づかず、確認しないまま期間が過ぎてしまう場合です。この形式の契約では、何もしないことが承認と同じ意味になります。所要時間の目安は、契約書から4点を抜き出すだけであれば1時間程度です。

### 検収の期間が決まっていない場合にどうするか

契約書に検収の期間が書かれていないことがあります。その場合は、納品の連絡を受けた時点で制作会社と期間を決めてください。口頭ではなく、メールなど後から確認できる形で残します。

期間を決めるときは、社内で確認に関われる人数と、その人たちの空き状況から逆算します。担当者1人ですべてを見る前提だと、期間が足りずに形だけの検収になりがちです。部署をまたいで確認する場合は、依頼から回答までの日数も見込んでください。

あわせて、不具合を伝える期限についても確認しておきます。検収の期間と、検収後の通知期限は別のものです。この違いを押さえておかないと、検収書に押印した後で不具合が見つかったときに、何ができるのかが分からなくなります。詳しくは後のセクションで扱います。

### 確認する体制を先に決める

検収は、担当者1人で全部を見るよりも、役割を分けたほうが精度が上がります。文言と画像の内容は依頼した部署が見る、フォームの動作は実際に問い合わせを受ける担当が見る、といった分け方です。

つまずきやすいのは、確認の依頼を出したものの、誰も期限までに見ないまま検収の期間が終わる場合です。誰が何をいつまでに見るかを、確認項目の一覧とあわせて配ってください。項目の作り方は次のセクションで扱います。

## 検収の確認項目を一覧にする

確認は、表示、動作、内容、計測の4つに分けて進めると漏れが起きにくくなります。思いついた順に見ていくと、同じページを何度も開いたり、逆にどのページも見られていない箇所が残ったりします。

### 表示の確認 (パソコンとスマートフォン)

表示は、パソコンとスマートフォンの両方で確認します。制作会社の確認はパソコンが中心になりがちで、スマートフォンでの崩れが残ることがあります。

見る項目は次のとおりです。

- 主要なページが崩れずに表示されるか
- 文字が小さすぎて読めない箇所がないか
- 画像が横にはみ出していないか
- メニューが指で操作できる大きさか

つまずきやすいのは、担当者が自分の端末だけで確認する場合です。社内で使っている端末を2種類以上持ち寄ると、崩れが見つかりやすくなります。所要時間の目安は、主要な10ページ程度であれば半日です。

### 動作の確認 (フォームとリンク)

動作の確認で最も重要なのは問い合わせフォームです。ここが動かないと、リニューアルの目的そのものが達成できません。

- フォームから実際に送信し、通知メールが届くか
- 通知メールの宛先が正しいか (旧担当者のままになっていないか)
- 自動返信メールの文面が正しいか
- 必須項目の指定が意図どおりか
- 主要なリンクが切れていないか

実装の視点で注意点を1つ挙げると、通知メールが迷惑メールの扱いになる場合があります。届かないと感じたら、迷惑メールのフォルダも確認してください。

### 内容の確認 (文言と画像の差し替え漏れ)

制作の途中で使った仮の文言や画像が残っていないかを確認します。よくあるのは、会社概要の古い情報、以前の電話番号、テスト用に入れた文章です。

依頼した部署に原稿と突き合わせてもらうのが確実です。担当者が1人で全ページを読むと、見慣れた文章ほど読み飛ばしが起きます。

### 計測の確認 (アクセス解析とサーチコンソール)

見落とされやすいのが計測です。公開後に数値が取れていないと気づいても、その期間のデータは戻りません。

- アクセス解析のタグが全ページに入っているか
- サーチコンソールに新しいサイトが登録されているか
- 旧URLから新URLへの転送が設定されているか

つまずきやすいのは、転送の設定漏れです。URLが変わるリニューアルでは、検索からの流入が落ちる原因になります。転送の考え方については、当サイトの別記事でも扱っています。所要時間の目安は1時間から2時間です。

## 表示速度の確認は公式の基準に合わせる

表示速度の確認は、感覚ではなくGoogleが公開している指標の基準値に照らして行います。「なんとなく遅い」という伝え方では、制作会社側も何を直せばよいか判断できません。

### どの指標を見るか

Core Web Vitalsとして公開されている3つの指標と、その良好の基準は次のとおりです。

| 指標 | 内容 | 良好の基準 |
| --- | --- | --- |
| LCP | 最大コンテンツの描画 | 2.5秒以内 |
| INP | 次のペイントまでの操作 | 200ミリ秒以内 |
| CLS | 累積レイアウトシフト | 0.1以下 |

出典: Google Search Consoleヘルプ「Core Web Vitals レポート」

注意が必要なのは、評価の見方です。これらの指標は75パーセンタイルの値で評価されます (Google Search Consoleヘルプ「Google におけるパフォーマンス」)。1回の計測結果ではなく、実際の利用者の大半がその基準を満たしているかどうかで判断されるということです。

あわせて、Search Consoleの検索パフォーマンスレポートでは、クリック数、表示回数、CTR、平均掲載順位の4つの基本指標を確認できます (Google Search Consoleヘルプ「検索パフォーマンス レポート (検索結果): 概要と基本設定」)。こちらは公開後の推移を見るための指標で、検収の場では公開前後を比較する準備が整っているかを確認します。

### 基準を満たさない場合の伝え方

基準を満たさない場合は、指標名と実測値、対象ページを添えて伝えます。「トップページのLCPが基準の2.5秒に対して4秒台です」と伝えれば、制作会社は原因の切り分けに入れます。

つまずきやすいのは、自分の回線や端末の状態を考慮せずに「遅い」と伝えてしまう場合です。計測は同じ条件で複数回行い、パソコンとスマートフォンの両方で確認してください。所要時間の目安は、主要な数ページの計測で1時間程度です。

### 契約で速度の水準を定めていなかった場合

契約書に表示速度の水準が書かれていない場合、基準を満たさないことを理由に修補を求められるとは限りません。この点は正直に押さえておく必要があります。

その場合でも、実測値を示して相談する価値はあります。画像の軽量化のように対応しやすい箇所であれば、検収の範囲内で直してもらえることもあります。逆に、構造そのものに起因する場合は追加の作業になり、費用の話になります。契約の範囲と追加費用の線引きについては、次のセクションで扱います。

なお、次のリニューアルや新規の発注では、契約の段階で表示速度の水準を決めておくことをおすすめします。検収の場で初めて持ち出すよりも、最初に合意しておくほうが双方にとって明確です。

## 契約の範囲と追加費用の線引き

検収で見つかった事象が契約の範囲内の不具合か、範囲外の追加要望かで、費用の扱いが変わります。この線引きが曖昧なまま指摘を出すと、やり取りが長引きます。

判断の目安は、契約書や提案書で合意した内容と実際の納品物にずれがあるかどうかです。ずれがあれば不具合、ずれはないが今になって変えたくなったのであれば追加要望です。

### 契約範囲の認識のずれが起きやすい場面

ずれが起きやすいのは次のような場面です。

- ページ数が合意より少ない、または多い
- 原稿や画像を誰が用意するかの前提が食い違っている
- 既存サイトからの移行の範囲が曖昧になっている
- 公開後の修正が何回まで含まれるかが決まっていない

つまずきやすいのは、打ち合わせの口頭のやり取りを根拠にしてしまう場合です。指摘の根拠にできるのは、契約書、提案書、見積書、そしてメールなど記録に残った合意です。指摘を出す前に、その根拠がどれに当たるかを確認してください。

補助金を使ってリニューアルした場合は、補助の対象範囲にも注意が必要です。たとえばIT導入補助金2024の通常枠では、ホームページの制作費、デザイン費、コーディング費は補助の対象に含まれていません (中小企業庁「IT導入補助金2024」の公募要領)。補助の対象外の経費は自社の負担になるため、追加作業が発生する場合はその点も含めて判断してください。

### 追加費用になりやすい依頼

検収の場で出やすく、かつ追加費用になりやすいのは次のような依頼です。

- 検収の段階になってからのデザインの変更
- 合意していなかったページや機能の追加
- 原稿の全面的な書き直し
- 当初の合意になかった端末やブラウザへの対応

これらは制作会社の作業が増えるため、費用の話になるのが通常です。どうしても必要であれば、検収とは切り離して別の依頼として相談するほうが話が進みます。

### 判断がつかない場合の進め方

不具合か追加要望か判断がつかない事象もあります。その場合は、無理に自社で決めずに、事象と根拠を並べて制作会社に確認してください。

進め方としては、指摘の一覧に「根拠」の列を設け、契約書や提案書のどの記載に基づくかを書き添えます。根拠を書けない項目は、追加要望として扱われる可能性が高いものです。この整理を先に済ませておくと、費用をめぐるやり取りが短くなります。所要時間の目安は、指摘が20件程度であれば2時間から3時間です。

## 検収後に不具合が見つかった場合の通知期限

検収後に見つかった不具合は、契約書で定めた期間内に通知することで修補を求められます。検収書に押印したからといって、その後に見つかった不具合をすべて自社で抱えることになるとは限りません。

ただし、期限を過ぎると求めにくくなります。だからこそ、検収の段階で期限を把握しておくことが重要になります。

### 期限を確認する場所

確認するのは契約書です。条項の名称は契約によって異なり、契約不適合責任、瑕疵担保責任、保証期間といった表現が使われます。

見るべきは次の3点です。

1. いつから起算するか。納品日からか、検収完了日からかで、期限が変わります。
2. どれだけの期間か。月数で定められているのが一般的です。
3. 何が対象か。不具合の修補までか、それ以外の対応も含むかが書かれています。

つまずきやすいのは、保守契約と混同する場合です。保守契約は公開後の運用を支える別の契約で、不具合の通知期限とは性格が異なります。どちらに基づく依頼なのかを整理してから連絡してください。

### 通知の記録を残す方法

通知は、後から確認できる形で残します。電話だけで伝えると、いつ何を伝えたかが証明できません。

実務としては、次の内容をメールで送るのが確実です。

- 発見した日付
- 事象の内容 (どのページで、どの操作をしたときに、何が起きるか)
- 再現の手順
- 画面の記録 (スクリーンショットや画面の録画)

つまずきやすいのは、事象の説明が「表示がおかしい」のように曖昧な場合です。制作会社側で再現できないと、対応が進みません。再現の手順まで書くことが、結果として早い解決につながります。所要時間の目安は、1件あたり15分程度です。

### 期限を過ぎた場合にどうなるか

期限を過ぎた場合、契約に基づく修補を求めることは難しくなります。その後の対応は、有償の作業として相談することになります。

そのため、公開後しばらくは意識して確認する期間を設けてください。公開直後は問題が出やすく、また利用者の動きによって初めて分かる不具合もあります。公開から1か月、3か月といった区切りで、フォームの送信と主要ページの表示だけでも確認しておくと、期限内に気づける可能性が上がります。

なお、自社に担当者がいない場合は、この確認を保守契約の範囲に含められるかを制作会社に相談するという方法もあります。運用体制の決め方については、当サイトの別記事でも扱っています。

## 検収を進めるときの段取りとつまずきやすい点

検収は、確認、指摘、再確認、検収書の取り交わしという4つの手順で進めます。ここまでで見てきた確認項目と契約の確認を、実際の作業の順番に落とし込みます。

### 手順1: 確認項目を一覧にして分担する

表示、動作、内容、計測の4つの区分で項目を書き出し、誰がどの区分を見るかを決めます。項目ごとに「未確認」「問題なし」「要修正」を書き込める形にしておくと、進み具合が一目で分かります。

つまずきやすいのは、一覧を作らずに口頭で依頼する場合です。見たかどうかが誰にも分からなくなり、期限の直前に慌てて確認することになります。所要時間の目安は、一覧を作るだけであれば1時間程度です。

### 手順2: 指摘を1つの表にまとめて渡す

指摘は、思いついたたびに個別のメールで送るのではなく、1つの表にまとめて渡します。表に入れる列は次のとおりです。

- 対象のページ
- 事象の内容と再現の手順
- 根拠 (契約書や提案書のどの記載に基づくか)
- 優先度

つまずきやすいのは、複数の担当者がそれぞれ制作会社へ直接連絡してしまう場合です。同じ内容が重複したり、指摘が漏れたりします。窓口を1人に決めて、そこから渡してください。所要時間の目安は、指摘が20件程度であれば半日です。

### 手順3: 修正後に同じ項目を再確認する

修正の連絡を受けたら、指摘した項目を同じ表で再確認します。このとき、修正した箇所だけでなく、その周辺も見てください。1か所の修正が別の箇所に影響することがあります。

実装の視点で注意点を1つ挙げると、ブラウザに以前の表示が残っていて、修正が反映されていないように見えることがあります。表示が変わらない場合は、画面を再読み込みしてから判断してください。

### 手順4: 検収書を取り交わし、期限を記録する

すべての指摘が解消したら、検収書を取り交わします。このときに、あわせて記録しておくべきものがあります。

1. 検収の完了日
2. 契約不適合責任などの通知期限と、その起算日
3. 未解決のまま合意した事項があれば、その内容と今後の扱い

つまずきやすいのは、検収書を交わした後に誰もその期限を把握していない状態です。完了日と期限を社内の共有カレンダに登録し、公開から1か月と3か月の時点で確認する予定も入れておくと、期限内に気づける可能性が上がります。所要時間の目安は30分程度です。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。契約に基づく判断が必要な部分は、自社の契約書の記載を優先してください。

### 検収書に押印した後でも修正してもらえますか

契約書に定めがあれば、その期間内に通知することで修補を求められます。条項の名称は契約不適合責任、瑕疵担保責任、保証期間などさまざまです。

起算日が納品日か検収完了日かで期限が変わるため、検収の段階で確認しておいてください。期限を過ぎた場合は、有償の作業として相談することになります。

### 検収の期間は何日くらいが一般的ですか

契約によって異なります。まず自社の契約書を確認し、定めがなければ制作会社と決めてください。

期間を決めるときは、確認に関われる人数と空き状況から逆算します。担当者1人で全ページを見る前提だと、期間が足りずに形だけの検収になりがちです。

### 契約書に不具合を伝える期限が書かれていない場合はどうなりますか

その場合の扱いは契約の内容や状況によって変わるため、一律には言えません。放置せずに、制作会社に確認して認識をそろえておくことをおすすめします。

判断に迷う場合や金額が大きい場合は、弁護士など専門家に相談してください。本記事は一般的な進め方を示すもので、個別の契約についての法的な判断を示すものではありません。

### 検収で指摘した内容が追加費用と言われました。どう判断すればよいですか

合意した内容と納品物にずれがあるかどうかが目安です。ずれがあれば不具合、ずれはないが今になって変えたくなったのであれば追加要望にあたります。

根拠にできるのは、契約書、提案書、見積書、メールなど記録に残った合意です。指摘の一覧に根拠の列を設け、どの記載に基づくかを書き添えて相談してください。

### 表示速度が遅い場合、検収で指摘できますか

契約で速度の水準を定めていれば、それに照らして指摘できます。定めていない場合は、修補を求められるとは限りません。

いずれの場合も、指標名と実測値、対象ページを添えて伝えてください。LCPは2.5秒以内、INPは200ミリ秒以内、CLSは0.1以下が良好の基準とされています。画像の軽量化のように対応しやすい箇所であれば、検収の範囲内で直してもらえることもあります。
