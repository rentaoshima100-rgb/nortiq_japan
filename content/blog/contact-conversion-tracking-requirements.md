# ホームページの問い合わせ計測｜発注で決める6項目

## 問い合わせの件数を数えるには何を依頼する？

依頼するのは、問い合わせ完了を表すイベントの実装と、それを重要な行動として記録する設定の2つです。フォームを作ってもらうだけでは件数は残りません。

サイトを持っている企業は多数派です。総務省の「令和7年通信利用動向調査報告書 (企業編)」によると、自社のホームページを開設している企業の割合は全産業で93.3%で、前年から0.1ポイント上昇しています。業種別では情報通信業が100.0%、不動産業が97.5%、建設業が97.2%です。有効回答は2,489企業で、発送6,040件に対する有効回収率は55.3%です。

持っていることと、成果を数えられることは別です。問い合わせが何件入ったかを後から確認できる状態になっているかは、発注時の依頼の内容で決まります。

### 依頼するのは実装と設定の2つ

| 依頼する内容 | 何をしてもらうか |
| --- | --- |
| イベントの実装 | 問い合わせ完了にあたる行動が起きたことを、計測ツールへ送る仕組みを入れる |
| 重要な行動としての設定 | 送られてきたイベントを、件数として独立して数えられる状態にする |

Googleアナリティクスでは、問い合わせのためのフォーム送信に対応する推奨イベントとして generate_lead が用意されています。名前が決まっていること自体は便利ですが、名前があることと自動で送られることは別です。詳しくは次章で扱います。

出典: Googleアナリティクス ヘルプ「[GA4] 推奨イベント」、総務省「令和7年通信利用動向調査報告書 (企業編)」

### 先に決めるのは何を1件と数えるか

最初に決めるのは技術ではなく定義です。所要時間の目安は30分です。

1. 問い合わせ完了とみなす行動を1つに決めます。送信ボタンを押したときか、完了画面が表示されたときかを選びます
2. 数えない行動を決めます。採用への応募、資料請求、迷惑メールの類を分けるかを決めます
3. 問い合わせの入口を数えます。フォーム、電話、メール、チャットのうち、計測の対象にするものを挙げます

つまずきやすい点は、送信ボタンを押した時点を完了とすると、送信に失敗した分も数に入ることです。完了画面の表示を基準にすると、この取り違えは起きません。

### 見積もりに入っているかの確認

定義が決まったら、見積書で確認します。

- 計測の設定という項目があるか。無い場合は、何を含むのかを書面で確認します
- 動作確認が含まれるか。設定と確認は別の作業です
- 公開後のレポートの作成まで含むかを分けて確認します

当社が他社の見積書を読み解く相談を受けた経験では、「アクセス解析設置」という1行だけが入っていて、問い合わせ完了の計測は含まれていない例が多くあります。1行の中身を分解して確認します。

## なぜ放っておくと問い合わせ完了が記録されない？

問い合わせ完了にあたるイベントは、自動では送信されない種類のものだからです。フォームの操作は既定で記録されますが、完了の定義は実装しないと残りません。

### 自動で記録されるものと、されないもの

Googleアナリティクス ヘルプの「[GA4] 推奨イベント」は、generate_lead を「ユーザーが問い合わせのためにフォームまたはリクエストを送信したとき」のイベントとして定義しています。そして推奨イベントについて「これらが自動的に送信されることはありません」と明記しています。

| 区分 | 記録のされ方 |
| --- | --- |
| 自動的に収集されるイベント | 設定なしで記録されます |
| 拡張計測機能のイベント | 拡張計測機能が有効であれば既定で記録されます |
| 推奨イベント (generate_lead 等) | 自動では送信されず、実装が必要です |

名前が用意されているため設定済みだと思い込みやすい部分です。実装を依頼しなければ、公開後に数えられるのはページの表示回数だけになります。

出典: Googleアナリティクス ヘルプ「[GA4] 推奨イベント」

### フォームの操作が記録される条件

一方で、フォームの操作は既定で記録されます。Googleアナリティクス ヘルプの「拡張計測機能イベント」によると、form_start はユーザがセッション中に初めてフォームを操作したときに送信され、form_submit はフォームが送信されたときに送信されます。

ただし前提があります。

- 拡張計測機能が有効になっていること。Googleタグを使う場合は自動イベント検出でこのイベントが有効になっていること (既定では有効) が必要です
- form_id と form_name はHTMLのform要素の id 属性と name 属性の値を取得する仕組みのため、対象がHTMLのform要素であることが前提です
- form_submit_text は、送信ボタンのテキストが存在する場合のみ含まれます

実装者の視点で注意が必要なのは、2つ目です。入力欄をJavaScriptで組み立てていて form要素を使っていない作り方や、id と name が付いていないフォームでは、どのフォームからの送信かを後から区別できません。発注の時点で、フォームごとに id を付けるよう依頼します。

### 記録されていてもレポートで見られない場合

イベントが届いていても、レポートで内訳が見られないことがあります。同じ「拡張計測機能イベント」のページは、これらのパラメータをレポートで使うにはレポート用のカスタムディメンションを作成する必要があると記載しています。

つまずきやすい点は、ここを設定の漏れではなく「計測できていない」と判断してしまうことです。イベントは届いているので、必要なのはレポート側の設定です。要件に書く項目は次章で整理します。

出典: Googleアナリティクス ヘルプ「拡張計測機能イベント」

## 計測の要件に書く6項目とは？

書くのは、1件と数える条件、イベント名、重要な行動としての登録、フォームの識別、レポートで見たい切り口、データの保持期間の6項目です。

### 6項目の一覧

| 項目 | 書く内容 |
| --- | --- |
| 1. 1件と数える条件 | 完了画面の表示か、送信ボタンの押下か |
| 2. イベント名 | generate_lead を使うか、独自の名前にするか |
| 3. 重要な行動としての登録 | そのイベントをキーイベントとして登録すること |
| 4. フォームの識別 | フォームごとに id と name を付けること |
| 5. レポートで見たい切り口 | フォーム別、流入元別など、見たい内訳 |
| 6. データの保持期間 | 2か月と14か月のどちらを選ぶか |

6項目を書面にすると、見積もりの金額も比べやすくなります。

### イベント名と識別子の決め方

イベント名は、Googleが用意している generate_lead を使うのが無理のない選び方です。独自の名前を付けると、ツール側の説明や他社の事例と突き合わせにくくなります。

Googleアナリティクス ヘルプの「キーイベントについて」は、測定したいアクションを表すイベントを作成するか特定し、そのイベントにキーイベントとしてマークを付けると説明しています。実装だけでは件数として独立して追えないため、この登録までを要件に書きます。

フォームの識別については、form_id と form_name がHTMLのform要素の id 属性と name 属性の値を取得する仕組みです。問い合わせ、資料請求、採用への応募を別々に数えたい場合は、それぞれのフォームに別の id を付けてもらう必要があります。

実装の設計に関わる上限も公開されています。Googleアナリティクス ヘルプの「イベント収集の制限」によると、ウェブデータストリームのイベント名の数は上限なしですが、1イベントあたりのパラメータ数は25個、イベント名の長さは40文字、パラメータ名の長さは40文字、パラメータ値の長さは100文字です。独自の項目を多く送る設計にする場合は、この範囲に収まるかを確認します。

出典: Googleアナリティクス ヘルプ「キーイベントについて」「拡張計測機能イベント」「イベント収集の制限」

### 保持期間の設定を忘れない

保持期間は、後から前年と比べたいときに効いてきます。Googleアナリティクス ヘルプの「データの保持」によると、ユーザ単位のデータは2か月と14か月から選択でき、キーイベントのデータにも同じ期間が適用されます。その他のイベント単位のデータも2か月と14か月から選択でき、アナリティクス360のみ26か月、38か月、50か月も選択できます。

つまずきやすい点は、公開から1年以上たってから前年同月と比べようとして、データが残っていないと気付くことです。発注の時点で14か月を選ぶよう指定しておけば、この取りこぼしは起きません。

なお、年齢と性別とインタレストカテゴリのデータは設定に関係なく2か月、Googleシグナルのデータは設定にかかわらず最長26か月です。

出典: Googleアナリティクス ヘルプ「データの保持」

## 納品のときに何を受け取る？

受け取るのは、計測設定の一覧表と、実際に1件記録されたことを確認した記録の2つです。設定しただけで動作を確かめていない納品が起こりえます。

### 計測設定の一覧表に書かせる項目

一覧表は、後から自分で確認するための地図になります。書かせる項目は次の6つです。

| 項目 | 書かせる内容 |
| --- | --- |
| 計測ツールのアカウント | アカウント名とプロパティ名、測定ID |
| イベント名 | 問い合わせ完了に使っているイベントの名前 |
| 発火の条件 | どのページのどの操作でイベントが送られるか |
| キーイベントの登録 | 登録済みかどうか |
| フォームの識別子 | フォームごとの id と name の一覧 |
| 保持期間の設定 | 2か月と14か月のどちらに設定したか |

つまずきやすい点は、イベント名だけを聞いて満足してしまうことです。発火の条件が書かれていないと、数が合わないときにどこを見ればよいか分かりません。

### 動作確認の記録

一覧表と合わせて、実際に1件記録されたことの確認を受け取ります。確認の手順は次のとおりです。所要時間の目安は30分です。

1. テスト用の送信を1件行います。本番のフォームから、社内のアドレスで送信します
2. 計測ツールのリアルタイムの画面で、イベントが届いていることを確認します
3. 翌日以降、レポートに1件として反映されていることを確認します

3つ目を省略した納品が起こりえます。リアルタイムでは見えていても、キーイベントの登録が済んでいなければ件数としては追えません。公開前の最終確認として、この3段階を依頼します。

### アカウントの権限の受け取り

計測のアカウントが制作会社の管理下にあると、契約が終わった後に数字を見られなくなります。

- アカウントの所有者を御社の名義にしてもらいます
- 制作会社には編集者などの権限を付与する形にします
- 公開後に権限の一覧を受け取り、不要になった担当者を外します

当社が引き継ぎの相談を受けた経験では、前の制作会社のアカウント内に計測が作られていて、過去のデータを持ち出せない状態になっている例があります。発注の時点で名義を決めておけば避けられます。制作会社を変える場合の引き継ぎは「リニューアルの計測引き継ぎ｜発注で指定する項目」で扱っています。

## 公開後に数字が合わないときの確認順序は？

確認は、通知メールが届いているか、イベントが記録されているか、レポートの条件が合っているかの順に見ます。先に設定を疑うと時間がかかります。

### 通知メールが届かない場合

計測の数と手元に届いた通知メールの数が合わない場合、まず疑うのはメールの到達です。フォームは送信されているのに通知が届かない状態は、送信ドメイン認証の設定で起きます。

Googleの「メール送信者のガイドライン」は、すべての送信者への要件を2024年2月1日に適用開始しています。Gmail宛に1日5,000件を超えて送る場合はSPFとDKIMの両方とDMARCの設定が必要で、Postmaster Toolsで報告される迷惑メール率は0.3%未満に保つことが要件とされ、0.10%未満が推奨されています。認証されていないメッセージが拒否される場合は、エラーコード5.7.26が返ります。

国内の設定状況も参考になります。日本プルーフポイントの調査では、日経225企業のDMARC導入率は92%ですが、RejectまたはQuarantineのポリシーを適用しているのは43%です。業種別では金融と保険業が60%、製造業が47%です。総務省は2018年からJPドメイン名の送信ドメイン認証技術の設定状況の調査を行っています。

設定の手順そのものは「問い合わせフォームの通知メールが届かない原因と設定」で扱っています。

出典: Google「メール送信者のガイドライン」、日本プルーフポイント「DMARC導入状況の調査」、総務省 報道資料「JPドメイン名における送信ドメイン認証技術の設定状況の調査」

### イベントが記録されていない場合

通知は届いているのに計測の数が0件の場合は、実装の有無を確認します。

1. 問い合わせ完了のイベントが実装されているかを確認します。推奨イベントは自動的に送信されることはないため、実装がなければ0件のままです
2. キーイベントとしてマークが付いているかを確認します。付いていないと件数として独立して追えません
3. フォームの操作が記録されているかを見ます。form_start と form_submit は拡張計測機能で既定で収集されるため、こちらが記録されていれば計測ツール自体は動いています

つまずきやすい点は、3つ目を確認せずに「計測ツールが動いていない」と判断することです。フォームの操作が記録されていれば、足りないのは完了の実装だけです。

### 数が多すぎる場合と上限

実際の問い合わせより数が多い場合は、同じ操作で2回送られている可能性があります。完了画面の表示を条件にしていると、再読み込みで2件になります。

あわせて、収集の上限も確認します。Googleアナリティクス ヘルプの「イベント収集の制限」によると、ウェブデータストリームのイベント名の数は上限なしですが、1イベントあたりのパラメータ数は25個、イベント名の長さは40文字、パラメータ値の長さは100文字です。1ユーザ1日あたりのイベント数は100,000件、セッション数は2,000件が上限です。

通常の問い合わせの件数でこの上限に当たることはありません。当たっている場合は、意図しないイベントが大量に送られていると考えて実装を見直します。

出典: Googleアナリティクス ヘルプ「イベント収集の制限」「[GA4] 推奨イベント」「キーイベントについて」

## 計測の設計と発注を当社に相談する

何を1件と数えるかは、御社の営業の進め方によって変わります。当社は実装者が計測の設計から入り、納品時の確認方法まで決めます。

公開してから半年たって「問い合わせは増えたのか」と聞かれ、答えられないという相談は珍しくありません。原因はツールの選定ではなく、何を1件と数えるかを決めずに発注したことにあります。定義が無いまま実装すると、送信の失敗や採用への応募や迷惑メールが同じ数に混ざります。

当社の進め方は3段階です。

1. 何を問い合わせ完了とみなすかを決めます。フォーム、電話、メールのうち計測する入口も合わせて決めます
2. 要件を文書に落とします。この記事の6項目に、御社で必要な切り口を足した形にします
3. 公開前に動作を確認し、確認の記録を納品物として残します

3段階目を納品の条件にすることが、後から数字を確認できる状態を作ります。当社が制作を担当しない場合でも、要件の文書を作って他社へ渡す形での支援ができます。

当社の料金は、Web制作が300,000円から、AIチャットボット構築が100,000円から、DXコンサルと機械学習開発が500,000円からです。既存のサイトに計測だけを追加する場合の金額は、フォームの数と計測したい切り口によって変わります。

今の見積書に計測が含まれているかを読み解くところからでも構いません。無料診断でご相談ください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 問い合わせの件数は、設定しなくても自動で記録されますか

記録されません。Googleアナリティクス ヘルプの「[GA4] 推奨イベント」は、問い合わせのためのフォーム送信に対応する generate_lead を含む推奨イベントについて、自動的に送信されることはないと明記しています。

計測ツールのタグをページに入れただけでは、ページの表示回数は分かっても問い合わせの件数は分かりません。実装を発注の内容に入れてください。

### フォームの送信はどこまで自動で記録されますか

フォームの操作は、拡張計測機能によって既定で記録されます。ユーザがセッション中に初めてフォームを操作したときの form_start と、フォームが送信されたときの form_submit です。

ただし、どのフォームからの送信かを区別するには form 要素に id や name が付いている必要があります。また、これらのパラメータをレポートで使うにはカスタムディメンションの作成が必要です。

### 問い合わせ完了を1件と数える条件はどう決めればよいですか

完了画面が表示されたときを条件にするのが無理のない決め方です。送信ボタンを押した時点を条件にすると、送信に失敗した分も数に入ります。

あわせて、数えない行動も決めてください。採用への応募や資料請求を同じ数に混ぜると、後から営業の成果として説明できなくなります。

### 計測の設定は制作費に含まれていますか

見積書を確認する必要があります。「アクセス解析設置」という1行だけでは、問い合わせ完了の計測まで含むかどうかは分かりません。

確認するのは、イベントの実装が含まれるか、キーイベントとしての登録が含まれるか、動作確認が含まれるかの3点です。含まれない場合は、追加の見積もりを依頼します。

### 過去のデータは後からさかのぼって見られますか

保持期間の設定に依存します。Googleアナリティクス ヘルプの「データの保持」によると、ユーザ単位のデータとキーイベントのデータは2か月と14か月から選択でき、その他のイベント単位のデータも同じ選択肢です (アナリティクス360のみ26か月、38か月、50か月も選択可)。

2か月のままになっていると、前年の同じ月と比べられません。公開の前に14か月へ変更しておいてください。

### 数字が合わないとき、最初にどこを見ればよいですか

通知メールが届いているかを先に確認してください。フォームは動いているのに通知が届かない状態は、送信ドメイン認証の設定で起きます。

通知が届いているのに計測が0件であれば、完了のイベントの実装とキーイベントの登録を確認します。フォームの操作が記録されていれば、計測ツール自体は動いています。
