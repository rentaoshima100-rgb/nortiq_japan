# ホームページリニューアル｜公開日から逆算する手順

## 公開日が決まったら、まず何から始めますか？

最初に着手するのは、ドメイン名の管理指定事業者を変えるかどうかの確認です。変える場合は認証コードの取得に期限があり、ここだけは自社都合で短縮できません。

リニューアルの段取りでつまずくのは、デザインや原稿の遅れだけではありません。ドメイン名とDNS、検索エンジン側の手続きには、御社の都合で動かせない期限があります。先にそこを押さえてから、制作の日程を当てはめる順番が安全です。

### 動かせる工程と動かせない工程を分ける

工程は2種類に分かれます。人を増やせば縮む工程と、待つしかない工程です。

| 区分 | 主な工程 | 短縮の可否 |
| --- | --- | --- |
| 自社と制作会社で調整できる | 原稿の用意、デザインの確認、ページの実装、社内の承認 | 人員と優先度で縮められます |
| 外部の期限に従う | ドメイン名の管理指定事業者の変更、DNSの切り替えの浸透、検索結果への反映 | 縮められません |

よくある失敗は、後者を前者と同じ感覚で見積もることです。ドメイン名の移管は申請すればすぐ終わるものではなく、現在の事業者への確認が先に入ります。

### 公開日から逆算する3つの締切

公開日を決めたら、次の3つを先にカレンダへ置いてください。

1. ドメイン名の認証コードを取得する日。JPRSの「ドメイン名の管理指定事業者の変更」によると、認証コードの有効期限は発行日の翌日を1日目として35日後の23時59分59秒です。期限が切れると最初からやり直しになります。取得が早すぎても間に合わないため、公開日の35日以内に収まるよう逆算します。
2. DNSのTTLを短くする日。TTLはDNSの情報をキャッシュしてよい秒数で、JPRS用語辞典では記述例として3600秒 (1時間) が示されています。切り替えを短時間で行き渡らせたい場合は、事前に値を下げておきます。つまずきやすいのは、公開当日に下げても間に合わない点です。
3. リダイレクトの設置とアドレス変更ツールの申請日。Googleの「アドレス変更ツール」のヘルプでは、旧サイトのシグナルを新サイトへ優先的に移す動作が続く期間は180日とされています。公開日は起点であって終点ではありません。

それぞれの詳しい手順と所要日数は、このあとのセクションで順に説明します。

出典: JPRS「ドメイン名の管理指定事業者の変更」(https://jprs.jp/about/dom-rule/agent-change/index.html)、JPRS用語辞典「TTL」(https://jprs.jp/glossary/index.php?ID=0136)、Google Search Console ヘルプ「アドレス変更ツール」(https://support.google.com/webmasters/answer/9370220?hl=ja)

## ドメイン名の移管には、なぜ余裕が必要ですか？

JPドメイン名の管理指定事業者を変えるには認証コードが必要で、その有効期限は発行日の翌日を1日目として35日後までだからです。発行を依頼する相手は、いま契約している事業者です。

管理指定事業者とは、ドメイン名の登録や更新をJPRSに取り次ぐ事業者のことです。制作会社を変えるリニューアルでは、ここも併せて移すことがあります。

### 認証コードの取得までの流れ

JPRSの「ドメイン名の管理指定事業者の変更」によると、手続きは次の順で進みます。

1. 登録者が、現在の指定事業者に認証コードを確認します。所要の目安は数日です。つまずきやすいのは、窓口が制作会社経由になっていて、誰に聞けばよいか分からない場合です。
2. 現在の指定事業者がJPRSへ発行を依頼し、認証コードが通知されます。
3. 通知されたコードを使って、変更先の指定事業者へ変更を申し込みます。

認証コードはドメイン名ごとに発行され、登録者が文字列を指定することはできません。有効期限は発行日の翌日を1日目として35日後の23時59分59秒です。変更が承認されると、そのコードは再利用できません。

### 指定事業者変更ロックの解除を先に確認する

認証コードを取る前に確認したいのが、ロックの有無です。JPRSの同じページでは、指定事業者変更ロックやレジストリロックが設定されている場合、先に解除が必要とされています。

ロックは不正な移管を防ぐ仕組みです。設定していること自体は問題ありませんが、解除の依頼先はやはり現在の指定事業者です。認証コードの依頼とまとめて相談すると、往復が1回で済みます。

### 期限が切れたときの手戻り

35日を過ぎると、手続きは最初からやり直しになります。現在の指定事業者への確認から数え直すため、公開日を動かす判断が必要になることもあります。

実装の現場で多いのは、コードを早く取りすぎて期限が切れる順序の誤りです。制作が遅れそうなときほど、コードの取得は後ろへずらす判断が要ります。逆算の起点は公開日であって、着手日ではありません。

出典: JPRS「ドメイン名の管理指定事業者の変更」(https://jprs.jp/about/dom-rule/agent-change/index.html)

## DNSの切り替えは、公開日の何日前に準備しますか？

URLを変えない移転では、移転の少なくとも1週間前にDNSのTTLを数時間程度まで短くしておくようGoogleが案内しています。公開当日に下げても、古い値が残っている間は効きません。

準備の対象は、サーバを変えるかどうかです。ドメイン名もURLもそのままでサーバだけ移す場合でも、DNSの切り替えは発生します。

### TTLとは何か

TTLとは、DNSの情報をキャッシュに保持してよい時間を秒で示した値です。JPRS用語辞典によると、設定できる範囲は0から2147483647秒です。

値の意味は次のとおりです。

| TTLの値 | 意味 | 切り替えへの影響 |
| --- | --- | --- |
| 0 | キャッシュしてはならない | 切り替えは即時に近くなります |
| 3600 (1時間) | 最大1時間キャッシュしてよい | 最大1時間は古いサーバを見る利用者が残ります |
| 86400 (24時間) | 最大24時間キャッシュしてよい | 丸1日、新旧のサーバへアクセスが分かれます |

TTLはキャッシュに保持されたのち減少し、ゼロになるとその情報がキャッシュから削除されます。

### 切り替えが行き渡る時間の見積もり方

見積もりの基準は、切り替える前に設定されていたTTLの値です。下げた直後ではなく、下げる前の値がキャッシュから消えるまで待つ必要があります。

手順は次のようになります。

1. 現在のTTLの値を確認します。所要は数分です。
2. 公開日の1週間以上前に、TTLを数時間程度まで下げます。つまずきやすいのは、ここを制作会社に依頼し忘れ、当日に気づく進め方です。
3. 古いTTLの期間が過ぎるのを待ちます。元が24時間なら、丸1日は見ておきます。
4. 公開日にDNSのレコードを新しいサーバへ向けます。
5. 新旧のサーバログで、旧環境へのアクセスが止まったことを確認します。

旧サーバを止めるのは、この確認が終わってからです。切り替えの直後は、Googlebotのクロール頻度が一時的に下がり、数日かけて回復することがあります。順位が動いたように見えても、この期間は様子を見る判断が妥当です。

なお、ドメイン名やURLまで変える場合は、リダイレクトとSearch Console側の手続きが別に必要になります。次のセクションで扱います。

出典: JPRS用語辞典「TTL (Time To Live)」(https://jprs.jp/glossary/index.php?ID=0136)、Google 検索セントラル「URLの変更を伴わないサイト移転」(https://developers.google.com/search/docs/crawling-indexing/site-move-no-url-changes?hl=ja)

## ドメインを変える場合、Search Consoleの手続きはいつ行いますか？

301リダイレクトを設置した後に、アドレス変更ツールで移転をリクエストします。旧と新の両方のプロパティで所有者である必要があるため、権限の整理を公開前に済ませます。

順番が逆になると申請が通りません。リダイレクトが動いていることが、ツールを使う前提になっているためです。

### アドレス変更ツールを使える条件

Search Consoleのヘルプによると、条件は次のとおりです。

1. 旧プロパティと新プロパティの両方で所有者であること。同じGoogleアカウントを使います。
2. 旧サイトのトップページから新サイトのトップページへ301リダイレクトを設置していること。
3. ドメインレベルのプロパティであること。パスの単位 (example.com/shop/ のような形) では使えません。

申請後は、Googleが旧サイトのシグナルを新サイトへ優先的に移す動作が180日間続きます。移転リクエストをキャンセルできるのも、移行開始から180日が上限です。

リダイレクト自体は、少なくとも180日は維持します。Google検索セントラルは、サイト移転後のリダイレクトを一般的に1年以上保持するよう案内しています。旧ドメインも、悪用を防ぐため1年以上は契約を続けることが推奨されています。

### サブドメインは自動では移動しない

見落としやすいのがここです。指定したドメインの下位のサブドメイン (www など) は、自動では移動しません。

所有権を確認したうえで、サブドメインごとにツールを実行します。www あり、www なし、http、https の組み合わせが残っていないかを公開前に棚卸ししてください。

### 制作会社から権限を引き継ぐ段取り

Search Consoleの権限は、所有者、フルユーザ、制限付きユーザ、協力者の4種類です。プロパティには確認済み所有者が1人以上必要です。

制作会社を変えるリニューアルでは、次の順で進めると安全です。

1. 自社のアカウントを確認済み所有者として追加します。所要は数分ですが、所有権の確認方法 (DNSレコードやHTMLタグ) の用意に時間がかかることがあります。
2. 旧制作会社の所有者権限を外します。自社の所有者が残っていることを先に確認します。
3. ドメイン名を移管する場合は、JPRS WHOISで AgentChangeLocked の表示がないかを確認します。表示があれば指定事業者変更ロックが設定されているので、解除を依頼します。

JPRSによると、指定事業者変更の手続きは10段階に分かれ、認証コードの有効期限は生成日の翌日を1日目として35日後の23時59分59秒までです。権限の整理とロックの解除は、この35日が始まる前に終わらせておきます。

出典: Search Console ヘルプ「ユーザと権限の管理」(https://support.google.com/webmasters/answer/7687615?hl=ja)、Search Console ヘルプ「アドレス変更ツール」(https://support.google.com/webmasters/answer/9370220?hl=ja)、JPRS「ドメイン名の管理指定事業者の変更」(https://jprs.jp/about/dom-rule/agent-change/index.html)、JPRS「JPRS WHOIS検索結果の表示例」(https://jprs.jp/about/dom-search/jprs-whois/whois-guide-view.html)

## 公開日から逆算したスケジュールの例は？

ドメイン名を移管し、URLも変える場合は、公開日の約2か月前から動き始めると期限に追われずに済みます。制作の期間とは別に、手続きのための時間が必要だからです。

以下は工程の並べ方の一例です。サイトの規模や社内の承認の手順によって前後します。

### 公開8週間前から公開日までの工程表

| 時期 | 作業 | つまずきやすい点 |
| --- | --- | --- |
| 8週間前 | ドメイン名の契約状況とJPRS WHOISの表示を確認する | 登録者の連絡先が退職者のままになっていることがあります |
| 7週間前 | Search Consoleで自社を確認済み所有者として追加する | 所有権の確認にDNSレコードの追加が要る場合があります |
| 6週間前 | 指定事業者変更ロックの解除を依頼する | 依頼先は現在の指定事業者です |
| 4週間前 | 認証コードの発行を依頼し、変更先へ申し込む | 有効期限は発行日の翌日を1日目として35日後の23時59分59秒です |
| 2週間前 | 新旧URLの対応表を確定する | 削除するページは404または410を返す設計にします |
| 1週間前 | DNSのTTLを数時間程度まで下げる | 当日に下げても古い値が残っている間は効きません |
| 公開日 | DNSを切り替え、301リダイレクトを有効にする | リダイレクトのチェーンは5個未満、理想は3個以下に抑えます |
| 公開日 | アドレス変更ツールで移転をリクエストする | リダイレクトが動いていないと申請が通りません |

認証コードの取得を4週間前に置いているのは、35日の期限の中に公開日が収まるようにするためです。早く取りすぎると期限切れになります。

リダイレクトの連鎖については、Googlebotがたどれるのは最大10ホップですが、推奨はされていません。旧サイトで既にリダイレクトを使っている場合は、新しい行き先まで直接つなぎ直す作業が要ります。

### 当日の作業と切り戻しの判断

当日は、切り替えの順番を決めておきます。先にリダイレクトを有効にし、次にDNSを切り替え、最後にアドレス変更ツールを申請する流れです。

切り戻しの判断基準も、事前に文章にしておきます。基準の例は次のとおりです。

1. 主要なページでリダイレクトが意図した行き先に向いていない。
2. 問い合わせフォームや決済など、売上に直結する機能が動かない。
3. 新サーバが応答しない、または著しく遅い。

検索順位の変動は、当日の切り戻しの基準には向きません。移転中は一時的に動くことがあり、時間の経過とともに安定するとされているためです。慌てて戻すと、かえって新旧のシグナルが混ざります。

出典: JPRS「ドメイン名の管理指定事業者の変更」(https://jprs.jp/about/dom-rule/agent-change/index.html)、Google 検索セントラル「URLの変更を伴うサイト移転」(https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes?hl=ja)

## 公開した後も続く作業には何がありますか？

リダイレクトの維持とアドレス変更ツールの期限が残ります。公開日は終わりではなく、少なくとも180日は監視の対象です。

ここを見落とすと、公開の数か月後に検索からの流入が落ちます。契約の切れ目と期限の切れ目が重なるためです。

### リダイレクトをいつまで残すか

Google検索セントラルは、サイト移転後のリダイレクトをできるだけ長く保持することとし、一般的には1年以上を案内しています。ユーザの観点からは、無期限の保持も検討するようすすめています。

アドレス変更ツールを使う場合は、別の下限もあります。Search Consoleのヘルプでは、少なくとも180日間はリダイレクトを維持し、Google検索からのトラフィックが残る間はさらに延長するよう案内されています。

公開後に確認する項目は次のとおりです。

1. 旧URLのサイトマップのインデックス数が、時間とともに減っているか。
2. 新URLのサイトマップの登録数が増えているか。
3. 想定していないクロールエラーが出ていないか。
4. リダイレクトのチェーンが伸びていないか。推奨は5個未満、理想は3個以下です。

4つ目は見落としがちです。公開後にURLをさらに変えると、リダイレクトが数珠つなぎになります。新しい行き先へ直接つなぎ直す作業を、その都度行ってください。

### 旧ドメインの契約をいつまで続けるか

Search Consoleのヘルプによると、旧ドメインは悪用を防ぐため、少なくとも1年間は料金を払い続けることが推奨されています。

手放したドメイン名は、第三者が取得できる状態になります。過去の被リンクが残っていると、意図しない内容のサイトへ誘導されることがあります。年間の維持費は、リダイレクトの維持費用と合わせて予算に入れておく項目です。

| 項目 | 期限の目安 | 根拠 |
| --- | --- | --- |
| アドレス変更ツールの効果 | 180日 | Search Console ヘルプ |
| リダイレクトの最低維持期間 | 180日 | Search Console ヘルプ |
| リダイレクトの推奨保持期間 | 1年以上 | Google 検索セントラル |
| 旧ドメインの契約維持 | 1年以上 | Search Console ヘルプ |

旧サーバを止める時期と、旧サイトに残るデータの扱いについては、別の記事で詳しく扱っています。

出典: Search Console ヘルプ「アドレス変更ツール」(https://support.google.com/webmasters/answer/9370220?hl=ja)、Google 検索セントラル「URLの変更を伴うサイト移転」(https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes?hl=ja)

## 発注時に制作会社と決めておくことは？

誰がどの手続きを行うかを、ドメイン名、DNS、Search Consoleの3つに分けて書面で決めておきます。期限のある手続きほど、担当が曖昧なまま日が過ぎます。

「制作会社がやってくれるはず」と「お客様側で手配いただくもの」が食い違うと、そのまま公開日が動きます。

### 役割分担の確認項目

見積もりの段階で、次の表を埋めてもらうと齟齬が減ります。

| 手続き | 実行する側 | 必要な情報や権限 |
| --- | --- | --- |
| ドメイン名の登録者情報の確認と更新 | | 登録者のメールアドレスと連絡先 |
| 指定事業者変更ロックの解除依頼 | | 現在の指定事業者の窓口 |
| 認証コードの取得と変更の申し込み | | 登録者としての本人確認 |
| DNSのTTLの変更とレコードの切り替え | | DNSの管理画面のアカウント |
| 301リダイレクトの設計と設置 | | 新旧URLの対応表 |
| Search Consoleの所有者の追加と削除 | | 自社のGoogleアカウント |
| アドレス変更ツールの申請 | | 旧新両方の所有者権限 |
| 公開後のインデックスの監視 | | 監視の報告頻度 |

このうち、登録者としての本人確認が要る手続きは、制作会社に代行させられないことがあります。自社で動く前提の工程を切り分けておいてください。

### 公開日を動かす判断の基準

判断の基準も、発注時に握っておきます。以下の3つが代表的です。

1. 認証コードの有効期限に公開日が収まらないと分かったとき。
2. 新旧URLの対応表が、公開の2週間前までに確定していないとき。
3. 本番と同じ条件での動作確認が、公開の1週間前までに終わっていないとき。

公開日を動かすのは痛手ですが、期限切れのやり直しより損失は小さく済みます。あらかじめ基準を決めておけば、当日の判断が属人的になりません。

リニューアルの段取りは、制作の中身よりも、こうした手続きの管理で差が出ます。当社ではWebサイトの制作 (300,000円から) に加えて、ドメイン名とDNS、Search Consoleの引き継ぎまで含めた進行を担当しています。現在の契約状況が分からない、社内に詳しい人がいないという段階でも構いません。[無料診断](/diagnostic)で、御社の公開希望日から逆算した工程を一緒に確認します。

御社の状況に合わせた進め方を相談したい場合は、お問い合わせからご連絡ください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### ドメイン名の移管にはどのくらいの期間がかかりますか？

現在の指定事業者への確認から数えて、数週間を見ておくと安全です。JPRSによると、JPドメイン名の管理指定事業者を変える手続きは10段階に分かれます。認証コードの発行を依頼してから変更が承認されるまでは、双方の事業者の対応速度に左右されます。公開日の4週間前には申し込みを終えている状態が目安です。

### 認証コードの有効期限が切れたらどうなりますか？

最初からやり直しになります。JPRSによると、認証コードの有効期限は発行日の翌日を1日目として35日後の23時59分59秒です。期限を過ぎると、現在の指定事業者への確認からもう一度進めることになります。なお、変更が承認された認証コードは再利用できません。

### DNSのTTLは公開のどのくらい前に短くすればよいですか？

Google検索セントラルは、移転の少なくとも1週間前にTTLを数時間程度まで下げるよう案内しています。TTLはDNSの情報をキャッシュしてよい秒数で、JPRS用語辞典によると0から2147483647秒の範囲で設定できます。下げた値が効き始めるのは、それ以前のTTLの期間が過ぎてからです。元の値が24時間なら、丸1日の余裕を加えて考えます。

### アドレス変更ツールはURLを変えない場合にも必要ですか？

必要ありません。Search Consoleのヘルプによると、このツールが要るのはドメイン名やサブドメインを変える場合です。HTTPからHTTPSへの移行や、wwwの有無の切り替えには使いません。サーバだけを移す場合も不要で、DNSの切り替えとクロールの監視が中心になります。

### リダイレクトはいつまで残しておく必要がありますか？

アドレス変更ツールを使う場合は、少なくとも180日間です。Google検索セントラルは、サイト移転後のリダイレクトをできるだけ長く保持することとし、一般的には1年以上を案内しています。Google検索からの流入が旧URLに残っている間は、さらに延長します。旧ドメインの契約も、悪用を防ぐため1年以上は維持することが推奨されています。
