# ホームページ管理アカウントの棚卸｜退職時の手順

## 退職や交代が決まったら何から着手しますか

最初に行うのは、対象者が持っているアカウントの洗い出しです。削除から始めると、引き継ぎに必要な権限まで消してしまいます。復旧に数日かかる場合もあります。

国もこの整理を求めています。令和8年3月12日に公表された「不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況」は、アクセス管理者が講ずべき措置を5項目挙げています。そのうちの1項目が、ID・パスワードの適切な管理です。

出典: 国家公安委員会、総務大臣、経済産業大臣「不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況」(令和8年3月12日公表)

### 最終出社日から逆算する3つの期限

期限は3つに分けて考えます。最終出社日を基準に、次の表の順で進めてください。

| 時期 | やること |
|---|---|
| 最終出社日の2週間前 | アカウントの洗い出しと、引き継ぎ先の決定 |
| 最終出社日の前日まで | 引き継ぎ先への権限の付与と、動作の確認 |
| 最終出社日の当日 | 対象者のIDの削除またはパスワードの変更 |

洗い出しに必要な時間の目安は半日です。つまずきやすい点は、本人に聞くだけでは漏れることです。請求や経費の記録からも契約済みのサービスを拾ってください。

### 削除を先にしてはいけない理由

削除を先に行うと、引き継ぎができなくなる仕組みがあります。代表例がSearch Consoleです。

Search Consoleの権限は4種類あります。プロパティには確認済みの所有者が少なくとも1人必要で、全員を削除すると誰もアクセスできなくなります (出典: Google Search Console ヘルプ「ユーザ、所有者、権限の管理」)。先に引き継ぎ先を所有者として追加しておけば、この状態を避けられます。

一方で、削除を後回しにしてよいわけではありません。同じ公表資料は、ID・パスワードを知り得る立場にあった元従業員や委託先による不正アクセスが発生していることを挙げています。そのうえで、利用する立場でなくなった場合には、割り当てていたIDの削除またはパスワードの変更を速やかに行うよう求めています。

付与と削除の順番を決めておくこと、それ自体が備えになります。洗い出しの対象と手順は後述します。

## なぜ退職後のIDの削除が必要なのですか

ID・パスワードを知り得る立場にあった元従業員や委託先による不正アクセスが実際に起きています。そのため国は、アクセス管理者の措置としてIDの削除またはパスワードの変更を速やかに行うよう求めています。

ここでいうアクセス管理者とは、そのシステムを誰に使わせるかを決める立場の人です。サイトの場合は御社自身がこれに当たります。制作会社ではありません。

### 国が示すアクセス管理者の措置5項目

公表資料は、アクセス管理者が講ずべき措置を5項目挙げています。退職や交代に直接関わるのは3番目の項目です。

| 項目 | 内容 |
|---|---|
| 1 | 運用体制の構築等 |
| 2 | パスワードの適切な設定 |
| 3 | ID・パスワードの適切な管理 |
| 4 | ウェブシステムやVPN機器のぜい弱性を悪用した攻撃への対策 |
| 5 | フィッシング等への対策 |

3番目の項目には、利用する立場でなくなった場合にIDの削除またはパスワードの変更を速やかに行う、という記述があります。期限の日数は示されていません。文言は「速やかに」です。社内で日付を決めておく必要があります。

5番目の項目では、フィッシングに耐性のある認証技術の例としてパスキーの導入が挙げられています。こちらは退職時の作業ではなく、平時の認証の強化にあたります。

出典: 国家公安委員会ほか「不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況」(令和8年3月12日公表)

### 狙われているのは社員・会員用等の専用サイト

統計を見ると、狙われている場所が分かります。令和7年の不正アクセス行為の認知件数は7,190件でした。前年より1,832件増えています。

検挙件数のうち、他人のIDとパスワードを使う識別符号窃用型は399件です。この399件を不正に利用されたサービス別に見ると、次の順になります。

| 順位 | サービス | 件数 |
|---|---|---|
| 1 | 社員・会員用等の専用サイト | 122件 |
| 2 | コミュニティサイト | 92件 |
| 3 | インターネットショッピング | 67件 |

最多は、会社が自社で管理している専用サイトです。手口別に見ると、パスワードの設定・管理の甘さにつけ込んで入手が最多の84件でした。次がフィッシングサイトから入手の77件です。

つまり、未知のぜい弱性よりも、正しいIDとパスワードが他人の手に渡ることのほうが多いという状況です。退職者のIDをそのまま残す運用は、この入手経路を自ら開けておくことになります。棚卸の対象については次の見出しで扱います。

出典: 同資料 (令和8年3月12日公表)

## 棚卸の対象になるアカウントは何ですか

サーバ、ドメイン、CMS、計測ツール、外部サービスの5系統に分けて洗い出します。系統で分けると、聞き取りだけでは出てこないものに気づけます。

### 5系統の一覧表の作り方

次の表の形で1枚にまとめてください。1行につき、持っている人と引き継ぎ先を書きます。

| 系統 | 対象の例 | 確認する場所 |
|---|---|---|
| サーバ | レンタルサーバの管理画面、SSH、FTP | 契約時のメール、請求の記録 |
| ドメイン | 登録事業者の管理画面、DNSの設定 | 更新案内のメール |
| CMS | WordPressの管理ユーザ、投稿者の権限 | 管理画面のユーザ一覧 |
| 計測ツール | Search Console、アナリティクス、タグの管理 | 各ツールのユーザと権限の画面 |
| 外部サービス | フォーム、予約、チャット、SNSの管理 | 請求の記録、サイトに埋め込まれたコード |

作成の所要時間の目安は半日です。つまずきやすい点は、サイトに埋め込まれた外部サービスの見落としです。フォームやチャットは画面を見ても契約者が分かりません。ページのソースに残るコードから辿ってください。

### 見落としやすいアカウント

次の4つは、聞き取りでは出てこないことが多い対象です。

1. ステージング環境のBasic認証のIDとパスワード。公開前の確認用に設定したまま残りがちです。
2. 共有アカウント。1つのIDを複数人で使っている場合、退職者だけを外すことができません。パスワードの変更が必要です。
3. 個人のメールアドレスで登録されたサービス。退職後にパスワードの再設定ができなくなります。
4. サイトに埋め込まれた計測タグの管理アカウント。タグは動き続けるため、気づかれません。

ステージング環境のBasic認証については、仕組みの面でも注意が必要です。RFC 7617は、Basic認証が資格情報をBase64でエンコードして送ると記載しています。そして「This scheme is not considered to be a secure method of user authentication」とし、IDとパスワードが平文で送られるとしています。Base64は暗号化ではありません。

出典: RFC 7617「The 'Basic' HTTP Authentication Scheme」(IETF、2015年9月)

つまり、ステージング環境のIDとパスワードは、退職者の手元に残ったまま使われる可能性があります。公開後に不要であれば環境ごと閉じる、続けて使うならパスワードを変える、のどちらかを決めてください。手順の全体は次の見出しで扱います。

## 権限を外しただけでは不十分な仕組みはありますか

あります。Search Consoleでは、ユーザを削除しても所有権の確認トークンがサイトに残っていれば、再度確認を行ってアクセスを取り戻せます。権限の画面から消すだけでは終わりません。

### Search Consoleの権限と所有者の種類

Googleの公式ヘルプによると、権限は4種類です。

| 権限 | できること |
|---|---|
| オーナ | プロパティの完全な管理。ユーザの追加と削除、全データの閲覧 |
| フルユーザ | 全データの閲覧と、一部の操作 |
| 制限付きユーザ | 大半のデータの簡易な閲覧 |
| 関連付け | 特定の操作やデータへのアクセス。画面は開けない |

所有者には2種類あります。確認トークンでサイトの所有を証明した確認済みオーナと、確認済みオーナから権限を付与された委任オーナです。両者の権限は同じです。

### 未使用の所有権トークンの削除

ここが見落とされる箇所です。削除したユーザは直ちにアクセスできなくなります。しかし相手が確認済みオーナだった場合、トークンが残っていれば再確認でアクセスを取り戻せます。

削除の手順は次のとおりです。

1. ユーザと権限の画面で、対象者のアクセスを削除します。所要時間の目安は5分です。
2. 未使用の所有権トークンの一覧を開き、残っているトークンを確認します。
3. トークンの種類ごとに削除します。HTMLファイルとHTMLタグはサイトから削除し、DNSによる確認は該当するDNSレコードを削除します。

つまずきやすい点は、トークンの用途です。Merchant CenterやGoogle Workspace等の他のサービスでも使われている場合があり、削除するとそれらに影響する可能性があります。削除の前に、どのサービスが使っているかを確認してください。

出典: Google Search Console ヘルプ「ユーザ、所有者、権限の管理」

### 確認済み所有者を全員消したときに起きること

全員を削除すると、残りのユーザと委任オーナは猶予期間の後にアクセスを失います。データの収集自体は続きますが、誰も閲覧できなくなります。

これを避ける順番は決まっています。引き継ぎ先を先に所有者として追加し、動作を確認してから、退職者を削除します。順番を逆にすると、再度の所有権の確認からやり直すことになります。

なお、知らない所有者が一覧にある場合、公式ヘルプはサイトがハッキングされている可能性があると記載しています。棚卸のときに見覚えのない行があれば、そのまま消さずに記録を残してください。

## 棚卸の手順はどう進めますか

洗い出し、引き継ぎ先の決定、権限の付与、削除、記録の5つの順で進めます。削除は、引き継ぎ先への付与が終わった後に行います。

### 手順1から手順5までの流れ

1. **洗い出し**: 5系統の一覧表を埋めます。所要時間の目安は半日です。つまずきやすい点は、本人の記憶に頼ることです。請求の記録と、サイトに埋め込まれたコードの両方から拾ってください。
2. **引き継ぎ先の決定**: 1行ごとに、誰が引き継ぐかを決めます。所要時間の目安は1時間です。氏名ではなく役割で書いておくと、次の交代でも使えます。
3. **権限の付与と確認**: 引き継ぎ先に権限を付与し、実際にログインできるかを確認します。所要時間の目安は半日です。二要素認証が設定されている場合、認証の端末ごと引き継ぐ必要があります。
4. **削除またはパスワードの変更**: 対象者の権限を削除します。共有アカウントはパスワードを変更します。Search Consoleは未使用の所有権トークンまで確認します。
5. **記録**: いつ誰が何を削除したかを台帳に残します。所要時間の目安は30分です。次の見直しの時期も同時に書きます。

この順番の要点は、手順3と手順4を分けることです。同じ日にまとめて行うと、付与の失敗に気づかないまま削除してしまいます。

### 実装者としてつまずきやすい点

当社がサイトの保守を引き継ぐ場面で、実際に手間取る箇所が3つあります。

- **二要素認証の端末**: 退職者の携帯電話に認証アプリが入っていると、本人がいなくなった後にログインできません。手順3の段階で、引き継ぎ先の端末に設定し直す必要があります。
- **ドメインの連絡先メールアドレス**: 退職者の個人アドレスが登録されていると、更新案内が届かなくなります。期限切れに気づけないため、棚卸のときに差し替えてください。
- **サーバの自動処理**: バックアップや定期の処理が、退職者のアカウントで動いている場合があります。アカウントを消すと処理も止まります。消す前に、どの処理が誰の権限で動いているかを確認してください。

3つ目は特に気づきにくい箇所です。止まっても画面には何も出ないため、数週間後にバックアップが無いことで判明します。

御社で一覧表の作成から引き継ぎまでを進める時間が取れない場合は、当社の[無料診断](/diagnostic)で現状の整理からご相談いただけます。保守の引き継ぎでは、この5系統の確認を最初の作業として行っています。

記録の残し方と定期の見直しについては、次の見出しで扱います。

## 記録と定期の見直しはどう残しますか

誰がどのアカウントを持っているかの一覧を1つの台帳にまとめ、見直しの時期を決めます。IPAが公開している資産管理台帳のひな形が、そのまま使えます。

### IPAのひな形で足りる範囲

IPAの「中小企業の情報セキュリティ対策ガイドライン」は、2026年3月27日に第4.0版が公開されました。経営者編と実践編からなる本編は全70ページで、付録は8種類あります。

棚卸に使えるのは、付録の資産管理台帳 (サンプル) です。Excel形式で全9シートです。ほかに、5分でできる!情報セキュリティ自社診断 (全8ページ) と、情報セキュリティ関連規程 (サンプル、全59ページ、Word形式) が含まれます。

第4.0版の改訂では、自社診断の診断項目に次の2点が追加されました。

1. 外部から内部ネットワークへの不要な通信を遮断する
2. ウェブサイトの安全な運用に関する項目

出典: IPA「中小企業の情報セキュリティ対策ガイドライン」(第4.0版、2026年3月27日公開)

台帳に書く項目は、ひな形に御社の列を足すだけで足ります。最低限、次の5列があれば棚卸は回ります。

| 列 | 内容 |
|---|---|
| 系統 | サーバ、ドメイン、CMS、計測ツール、外部サービス |
| サービス名 | 具体的な契約先 |
| 権限を持つ役割 | 氏名ではなく役割で書く |
| 最終確認日 | 誰がいつ確認したか |
| 次の見直し | 時期と担当の役割 |

見直しの頻度は、人の出入りがある時期に合わせます。年に1回なら、人事の異動の前月に置くのが確実です。

### 制作会社との契約に書いておく項目

御社だけでは完結しません。制作会社や保守の委託先にも担当者の交代があります。契約または取り決めに、次の4点を入れてください。

1. 委託先の担当者が交代または退職した場合に、御社へ連絡すること
2. 委託先が持つアカウントの一覧を、年に1回提出すること
3. 契約終了時に、アカウントの削除と引き継ぎを行うこと
4. 共有アカウントを使う場合、パスワードの変更の責任をどちらが持つか

国が示すアクセス管理者の措置は、委託先に出していても御社の責任として残ります。IDを知り得る立場にあった委託先による不正アクセスが起きていることが、措置の理由として挙げられているためです。

制作会社と連絡が取れなくなった場合の対処は、別の記事「制作会社が廃業｜ドメインとデータの取り戻し方」で扱っています。本記事の範囲は、連絡が取れる平時の棚卸までです。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。公的資料で確認できる範囲にとどめています。

### 退職の何日前までにアカウントを消せばよいのですか

日数を定めた公的な期限はありません。国が示す措置の文言は「速やかに」です。実務では、最終出社日の当日に削除またはパスワードの変更を行う形が確実です。引き継ぎ先への権限の付与は、その前日までに終わらせてください。

### 制作会社の担当者が変わった場合も棚卸は必要ですか

必要です。国が示す措置は、ID・パスワードを知り得る立場にあった元従業員と委託先業者等による不正アクセスを理由に挙げています。委託先に出していても、アクセス管理者としての整理は御社の側に残ります。年に1回、委託先が持つアカウントの一覧を出してもらう取り決めが有効です。

### 共有アカウントを1つ使っている場合はどうすればよいですか

パスワードの変更で対応します。共有アカウントでは、退職者だけを外すことができません。変更後の共有の方法も同時に決めてください。長期的には、人ごとにアカウントを分けるほうが棚卸の手間が減ります。

### Search Consoleの所有者を全員削除してしまった場合はどうなりますか

残りのユーザと委任オーナは、猶予期間の後にアクセスを失います。データの収集自体は続きますが、誰も閲覧できなくなります。復旧には、サイトに確認トークンを設置して所有権の確認をやり直す作業が必要です (出典: Google Search Console ヘルプ「ユーザ、所有者、権限の管理」)。

### 棚卸の台帳は何を書けば足りますか

系統、サービス名、権限を持つ役割、最終確認日、次の見直しの5列があれば回ります。IPAが公開している資産管理台帳のひな形に列を足す形で足ります。氏名ではなく役割で書いておくと、次の交代でも使えます。

御社の管理アカウントの整理からお手伝いできます。5系統の一覧表の作成と、引き継ぎの順番の設計までを[無料診断](/diagnostic)でご相談いただけます。
