# CMS乗り換えのデータ移行｜範囲と費用の決まり方

## CMSを乗り換えると、既存の記事はどこまで移行される？

移行の範囲は見積もりで決める項目です。全件を自動で移せる前提にはならないため、件数と対象を指定する必要があります。

よくある誤解は、記事が入っているデータベースをそのまま移せば終わるという見方です。CMSが変わると、記事を保存している構造も変わります。移すのではなく、変換して入れ直す作業になります。

### 移行の対象になるもの

移行の見積もりに入る要素を整理します。御社の依頼内容を伝えるときは、この区分で指定してください。

| 対象 | 確認する点 |
|---|---|
| 記事の本文 | 件数。見出しや表、埋め込みの有無 |
| 画像と添付ファイル | 枚数。本文からの参照を張り替える必要があるか |
| 公開日と更新日 | 元の日付を保つか、移行日に揃えるか |
| カテゴリとタグ | 分類の体系を引き継ぐか、作り直すか |
| 著者の情報 | 複数の著者を区別して保つか |
| URL | 変えるか変えないか。変える場合は対応付けが必要 |
| 固定ページ | 会社概要や問い合わせなど、本文以外のページ |
| フォームの送信先と設定 | 問い合わせフォームは作り直しになることが多くあります |

このうち費用に効くのは、件数ではなく構造の揃い具合です。見出しの使い方が記事ごとに違っていたり、本文に直接HTMLが書かれていると、変換の作業が1件ずつの手作業に近づきます。

### 自動で移せないもの

一括で移せない要素を先に把握しておくと、見積もりの読み方が変わります。多いのは次の4つです。

1. 旧CMS固有の機能で作った部分（ショートコード、独自のブロック、プラグインで表示していた箇所）
2. 本文の中に直接書かれたHTMLやスタイル指定
3. フォーム、会員機能、検索などの動く仕組み
4. 外部サービスとの連携設定（アクセス解析、広告、配信ツールのタグ）

1番と2番は、記事ごとに現れ方が違います。一括の変換では崩れが残り、残った分を人が直す形になります。この「残りを直す作業」が、見積もりで見落としやすい部分です。

当社の実装経験では、移行の前に数件を試験的に変換して崩れ方を確認すると、全体の作業量の見通しが立ちます。見積もりの段階で、この試験移行を依頼する方法もあります。

どこまでを移すかが決まると、次に費用の決まり方が見えてきます。

## 移行費用はどう決まる？

件数ではなく、変換の手間で決まります。同じ100件でも、構造が揃っているかどうかで作業量が変わります。

そのため、件数だけを伝えて概算を求めても、幅の広い金額しか返ってきません。手間を左右する条件を揃えて伝えると、見積もりの精度が上がります。

### 費用を決める4つの要素

移行費用に効く要素は、次の4つに整理できます。

1. 件数（記事、固定ページ、画像のそれぞれの数）
2. 構造の揃い具合（見出しや表の書き方が記事ごとに揃っているか）
3. 変換が必要な要素の種類（旧CMS固有の記法、本文内のHTML、埋め込み）
4. 確認の範囲（全件を目視で確認するか、抽出して確認するか）

このうち2番と4番が、同じ件数でも金額が変わる理由です。構造が揃っていれば一括変換で大半が済み、揃っていなければ1件ずつの修正が残ります。

4番は発注側が選べる項目です。全件を目視で確認すれば確実ですが、件数に比例して作業が増えます。重要なページだけを全件確認し、残りは抽出で確認する形にすると費用が下がります。

なお、サイトのリニューアルそのものの費用相場については、公的統計に制作費用の直接的なデータは含まれていません。費用水準の把握には業界調査を参照することになりますが、調査主体が制作会社側である場合が多く、サンプル数や調査方法が明示されていないものもあります。参照するときは調査概要を確認してください。

### 見積書で分けて書いてもらう項目

見積書で移行が「データ移行費用 一式」と書かれている場合は、内訳を求めてください。分けてもらう項目は次のとおりです。

| 項目 | 確認する内容 |
|---|---|
| 変換の設計と試験移行 | 数件を試して崩れ方を確認する作業が入っているか |
| 一括変換の実施 | 対象の件数と、含まれる要素 |
| 崩れの修正 | 想定する修正の件数。超えた場合の扱い |
| 画像の移行と参照の張り替え | 枚数と、本文のリンクを直す作業の有無 |
| URLの対応付けとリダイレクトの設定 | 対象のURL数 |
| 確認の作業 | 全件か抽出か。誰が確認するか |
| 移行しないものの扱い | 対象外にするページの一覧と、その扱い |

最後の項目を入れておくと、後の認識の違いを防げます。移行しないと決めたページを一覧にして、削除するのか旧サイトに残すのかを決めておいてください。

前提として、企業のウェブサイト自体はすでに定着しています。総務省「令和6年 通信利用動向調査報告書（企業編）」によると、国内企業のホームページ開設率は全体で9割を超えています。移行の判断は、作るかどうかではなく、既存の資産をどこまで引き継ぐかという段階の話になります。

## URLを変えるかどうかで何が変わる？

Googleは、URLを変える移転と変えない移転で必要な対応が異なるとしています。URLを変えると、対応付けとリダイレクトの作業が加わります。

CMSの乗り換えでは、記事のURLの形が変わることがよくあります。この判断が、移行の作業量と公開後の保守を左右します。

### Google公式の区分

URLを変える移転について、Google検索セントラルの「サイトを移転する方法（URLの変更あり）」は、中規模のウェブサイトの場合、Googleが古いURLの代わりに新しいURLを段階的に表示し始めるまでに数週間以上かかることがあると説明しています。同じ文書には、移転中は検索での掲載順位が一時的に変動することがあるとも記載されています。出典: Google検索セントラル「サイトを移転する方法（URLの変更あり）」。

URLが変わらない移転は扱いが違います。同じくGoogle検索セントラルの「サイトを移転する方法（URLの変更なし）」は、移転直後にGooglebotのクロール頻度が一時的に下がるのは通常の動作であり、その後数日かけて徐々に上がっていくと説明しています。この文書に検索順位が変わるという記述はありません。準備として、移転の少なくとも1週間前にDNSのTTLを下げることが示されています。出典: Google検索セントラル「サイトを移転する方法（URLの変更なし）」。

2つの区分を並べます。

| 項目 | URLを変える | URLを変えない |
|---|---|---|
| 新しいURLの表示開始まで | 中規模のサイトで数週間以上 | 該当しません |
| 検索順位 | 移転中に一時的に変動することがある | 変わるという記述はありません |
| クロール頻度 | 再クロールとインデックス登録が必要 | 一時的に下がり、数日で戻ります |
| 事前の準備 | URLの対応付けの一覧 | 1週間前にDNSのTTLを下げる |
| 追加の作業 | リダイレクトの設定と保持 | 不要 |

CMSを乗り換えても、URLの形を旧サイトと揃えられる場合があります。移行の見積もりを取る前に、URLを維持できるかを確認してください。維持できるなら、作業量と検索への影響の両方が小さくなります。

### リダイレクトの作業量の見方

URLを変える場合は、旧URLと新URLの対応付けを1件ずつ作ります。これが移行費用に乗る部分です。

同じGoogleの文書は、リダイレクトをできるだけ長く保持することとし、一般的な目安として1年以上を示しています。ユーザの観点からは無期限に保持することも検討するよう述べられています。つまり、設定して終わりではなく、保持する期間の運用まで含めて考える作業です。

見積もりで確認する点を挙げます。

1. 対応付けの対象になるURLの件数
2. 対応付けの一覧を誰が作るか（発注側か制作会社か）
3. 規則で一括変換できる分と、個別に指定する分の区分
4. 設定の確認方法（全件を確認するか、抽出するか）
5. リダイレクトを保持する期間と、その間の保守の扱い

2番が費用を分ける箇所です。一覧を発注側で作れるなら、その分の作業は見積もりから外せます。表計算ファイルに旧URLと新URLを並べる形で足ります。

移行後の状態の確認には、公開されたしきい値が使えます。web.devによると、良好とされるしきい値はLCPが2.5秒以内、INPが200ミリ秒以下、CLSが0.1以下で、評価はモバイルとデスクトップに分けたページ読み込みの75パーセンタイルで行われます。出典: web.dev「Web Vitals」。移行して表示が重くなっていないかを、この基準で確かめてください。

## 自社でやる範囲と任せる範囲は、どう分ける？

原稿の取捨選択と最終確認は自社、変換と取り込みは制作会社が向いています。分担を見積もり前に決めると費用が下がります。

分け方の基準は単純です。判断が必要な作業は自社、量をこなす作業は制作会社に寄せてください。判断を外に出すと、確認のやり直しで時間と費用が増えます。

### 自社でやると費用が下がる作業

発注側で進められる作業を挙げます。いずれも専門の知識を必要としません。

1. 移行する記事の選定（残す、移行しない、書き直すの3区分に分ける）
2. 旧URLと新URLの対応付けの一覧づくり（表計算ファイルで足ります）
3. カテゴリとタグの整理（統合する分類、廃止する分類を決める）
4. 画像の差し替えの判断（古い写真を新しいものに替えるか）
5. 移行後の本文の最終確認（内容が正しいかどうかの確認）

1番が最も効きます。移行する件数そのものが減るため、変換も確認も比例して軽くなります。

5番も発注側が担う方が確実です。本文の内容が正しいかどうかは、書いた御社でなければ判断できません。制作会社の確認は、表示の崩れがないかの技術的な確認に絞ってもらってください。

### 任せた方が確実な作業

反対に、制作会社に任せた方がよい作業もあります。

| 作業 | 任せた方がよい理由 |
|---|---|
| 変換の設計と試験移行 | 旧CMSの記法の癖を読む必要があるためです |
| 一括変換の実施 | 件数が多いと手作業では現実的でないためです |
| 画像の参照の張り替え | 本文中のリンクを機械的に書き換える作業です |
| リダイレクトの設定 | 設定を誤ると表示できないページが生じます |
| 移行後の表示の確認 | 崩れが起きやすい箇所を把握しているためです |

分担は見積もりの前に決めてください。見積書に「発注側が用意するもの」として書き込んでもらえば、後から認識の違いが出ません。

当社の実装経験では、移行する記事の選定と最終確認を発注側が担う形にすると、進行も速くなります。確認の往復が1回で済むためです。選定の作業に時間が取れない場合は、アクセスのあるページから順に優先度を付ける方法もあります。

## 旧サイトのデータは、いつまで残す？

リダイレクトの保持期間と、書類や個人データの保存の必要性は別の基準で決まります。それぞれ公的資料に根拠があります。

混ざりやすい論点です。検索のために残すものと、法令上残す必要があるものを分けて考えてください。

### リダイレクトを保つ期間

URLを変えた場合、リダイレクトはできるだけ長く保持することとされ、一般的な目安として1年以上が示されています。出典: Google検索セントラル「URLの変更を伴うサイト移転」。

この期間はサーバの契約にも関わります。旧サイトのサーバでリダイレクトを設定している場合、その契約を1年以上続ける必要があります。移行費用の見積もりでは見えにくい部分なので、ランニングの費用として計算に入れてください。

リダイレクトを新しいサーバ側で処理できる構成にすれば、旧サーバの契約は不要になります。移行の設計の段階で、どちら側で処理するかを確認してください。

### 残す必要がある書類とデータ

法令上の保存が必要なものは、検索とは無関係に残します。代表的なものは帳簿書類です。

法人の帳簿書類の保存期間は、確定申告書の提出期限の翌日から7年とされています。青色申告書を提出した事業年度に欠損金が生じた場合は10年です。出典: 国税庁 タックスアンサー No.5930 法人の帳簿書類の保存期間。

ウェブサイトの移行で関係してくるのは、サイト上の仕組みで受け取っていた記録です。確認する対象を挙げます。

| 旧サイトにあるもの | 判断の基準 |
|---|---|
| ECサイトの受注と請求のデータ | 帳簿書類に当たるものは保存期間に従います |
| 問い合わせフォームの送信記録 | 個人データとして、利用目的と保管の必要性で判断します |
| 会員情報 | 新サイトに移すか、不要なら削除するかを決めます |
| アクセス解析のデータ | 外部サービス側に残るため、サイトの移行とは別です |
| 旧サイトのバックアップ一式 | 復元の必要がなくなった時点で削除の判断をします |

個人データを含むものは、必要がなくなった時点で削除するか、新サイトで引き続き使うかを決めてください。移行のついでに旧サーバに残したままにすると、管理の対象が二重になります。

当社の実装経験では、旧サイトの削除の日付を移行の計画に書き込んでおくと、この判断が流れません。公開日から1年後にリダイレクトの扱いを見直す、という形で予定として置いてください。

## 移行費用を抑える方法はある？

移行する件数を絞ることが最も効きます。補助金の対象になる場合もあるため、費目の確認も併せて行ってください。

費用の構造は、件数と手間の掛け算です。手間の単価を下げる交渉よりも、件数を減らす判断の方が結果に直結します。

### 件数を絞る判断の基準

全件を移さなければならない決まりはありません。絞る基準を4つ挙げます。

1. アクセスのあるページから順に優先する（直近1年の閲覧数で並べる）
2. 検索からの流入があるページを優先する（Search Consoleの表示回数で確認）
3. 内容が古くなったページは、移行せずに書き直す対象にする
4. 役割を終えたページ（終了したキャンペーン、古い採用情報）は移行しない

3番の扱いが判断の分かれ目です。移行して直すよりも、書き直した方が早い記事があります。移行の見積もりと、記事を書き直す費用を並べて比べてください。

絞ると検索からの流入が落ちるのではないかという懸念は当然です。ただし、閲覧も検索からの流入もないページは、移行してもその状態が続きます。移行しないと決めたページは、残すか削除するかを別に判断してください。

絞り方を金額に結びつけると、次のような見方になります。

| 絞り方 | 費用への効き方 |
|---|---|
| 移行する件数を半分にする | 変換と確認の作業が概ね比例して減ります |
| URLを維持する | 対応付けとリダイレクトの作業が不要になります |
| 確認を抽出に切り替える | 確認の作業時間が減ります。崩れの見落としは増えます |
| 画像を移行せず差し替える | 張り替えの作業は減りますが、素材の準備が必要です |

### 補助金と費目の確認

費用そのものを軽くする方法として、補助金の活用があります。中小企業庁の「デジタル化・AI導入補助金2026」（旧IT導入補助金）は、中小企業・小規模事業者等を対象に、ITツール導入費用の一部を補助する制度です。補助率と上限額は枠によって異なります。出典: 中小企業庁「デジタル化・AI導入補助金2026」制度概要ページ（2026年10月時点）。

申請を考える場合の確認点を挙げます。

1. 補助の対象になるITツールと支援事業者が、公式のツール検索システムに登録されているか
2. データ移行の作業が、補助の対象経費に含まれるか
3. 申請する枠の補助率と上限額
4. 発注してよい時期（交付決定の前に契約と発注をしないこと）

4番は見落とすと補助の対象外になります。移行の着手の時期を、交付決定の後ろに置いて計画してください。

要件と日程は回ごとに変わります。最新は公式サイトで確認してください。

## 当社に相談できることは？

移行の対象を絞る判断から、変換と取り込みまでご相談いただけます。見積もりは移行の件数と作業を分けてお出しします。

CMSの乗り換えでつまずくのは、技術ではなく範囲の決め方です。全件を移す前提で見積もりを取り、金額を見てから慌てて絞る流れになりがちです。

原因は、移行の作業が「一式」としてまとめられていることにあります。件数と作業が分かれていなければ、どこを削れば安くなるのかが読めません。

当社では、移行の見積もりを件数と作業に分けてお出しします。ご相談いただける範囲は次のとおりです。

| 段階 | 当社の対応 |
|---|---|
| 検討中 | 現サイトの件数と構造の確認、試験移行による崩れ方の確認 |
| 見積もり時 | 件数と作業に分けた見積書、自社で行う範囲の提案 |
| 移行中 | 変換、画像の張り替え、URLの対応付けとリダイレクトの設定 |
| 公開後 | 表示速度の確認、旧サイトの停止時期の計画 |

当社のWeb制作は300,000円からで、移行の作業はこれとは別に件数に応じてお見積もりします。試験移行だけを先に依頼することもできます。数件の変換結果を見てから、全体の範囲を決める進め方です。

なお、移行する記事の選定と本文の最終確認は、御社にお願いしています。内容が正しいかどうかは書いた側でなければ判断できないためです。当社が担うのは、表示の崩れがないかの技術的な確認までです。

現サイトのURLと記事の件数が分かれば、概算をお出しできます。まずは[無料診断](/diagnostic)からご相談ください。現サイトの構造を確認して、移行できる範囲と手間のかかる箇所をお伝えします。

見積もりの前に進め方を知りたい場合は、[料金ページ](/pricing)に基本の流れを載せています。

## よくあるご質問

CMSの乗り換えとデータ移行についてよく寄せられるご質問をまとめます。実際の作業量は現サイトの構造によって変わります。

### 記事を全件そのまま移行してもらえますか。

件数と構造によります。本文だけであれば一括変換で大半が移りますが、旧CMS固有の記法や本文内のHTMLが含まれていると、その部分は人が直す作業になります。

まず数件を試験的に変換して崩れ方を確認すると、全件移行が現実的かどうかが判断できます。

### 画像や添付ファイルも移行の対象になりますか。

対象にできますが、見積もりの別項目になります。ファイルを移すだけでなく、本文中の参照を新しい場所に書き換える作業が伴うためです。

枚数が多い場合は、本文から参照されていない画像を除く方法もあります。使われていないファイルを移しても意味がありません。

### 移行は自動化できないのですか。

一括変換はできますが、全自動にはなりません。CMSごとに記事の保存の仕組みが違うため、変換の規則を作る作業と、変換後の崩れを直す作業が残ります。

費用の大半は、この「規則を作る」と「残りを直す」の2つです。件数が少なくても規則づくりは必要なため、1件あたりの単価は件数が少ないほど高く見えます。

### 記事の公開日やカテゴリは引き継げますか。

引き継げます。ただし、引き継ぐかどうかは指定が必要です。何も指定しないと、移行した日付が公開日になる場合があります。

公開日は検索での扱いにも関わるため、元の日付を保つ指定を入れてください。カテゴリとタグは、この機会に整理する方法もあります。

### 移行する記事を絞ると検索流入は落ちますか。

落ちるのは、閲覧や検索からの流入があるページを移行しなかった場合です。流入のないページは、移行してもその状態が続きます。

絞るときは、Search Consoleの表示回数とアクセス解析の閲覧数で順に並べ、上から優先してください。移行しないと決めたページについては、残すか削除するかを別に判断します。URLを変える移転では、リダイレクトをできるだけ長く保持することとされ、一般的な目安として1年以上が示されています。出典: Google検索セントラル「URLの変更を伴うサイト移転」。
