# FAX注文書のAI読み取り外注｜精度の確認手順

## 何から始めるか: 自社の注文書30枚で測る

最初にやるのは、直近の注文書を30枚ほど集めて、どの項目をどこまで読み取れれば実務が回るかを決めることです。製品のカタログ値を比べる作業は、この後でかまいません。御社の注文書で測った数字がないと、見積もりに書く合格ラインも決められません。

AI読み取りとは、注文書の画像から品番や数量などの項目を機械が取り出し、データとして扱える形にする仕組みです。精度は注文書の書式と書き込み方で大きく変わります。だからこそ、他社の事例ではなく自社の紙で測る必要があります。

### 集める注文書の選び方 (手書き欄とFAXのかすれを必ず混ぜる)

きれいな注文書だけを集めると、測った数字が実務とずれます。次の手順で30枚をそろえてください。

1. 直近3か月の注文書から、取引先の数が多い順に10社分を抜き出す (目安30分)
2. 各社から、通常の注文書と、手書きの追記がある注文書を1枚ずつ選ぶ (目安30分)
3. FAXの受信でかすれた紙、斜めに入った紙、2枚が重なって届いた紙を混ぜる (目安15分)
4. 原本をスキャンし、ファイル名に取引先と受注日を入れて保存する (目安1時間)

つまずきやすいのは3番です。実装の現場で精度を落とすのは、文字の難しさよりも紙の状態です。かすれや傾きを含めない評価用のデータは、本番で必ず裏切ります。

### 読み取る項目を絞る (品番、数量、納期、届け先)

読み取る項目は、受注の登録に必要な最小限に絞ります。備考欄のような自由記述は、最初から対象外にするほうが早く入ります。

| 項目 | 読み取りの対象 | 間違えたときの影響 |
|---|---|---|
| 品番 | 対象にする | 誤出荷に直結する |
| 数量 | 対象にする | 欠品と過剰在庫になる |
| 納期 | 対象にする | 出荷日の組み直しが必要 |
| 届け先 | 対象にする | 再配送の費用が出る |
| 備考 | 対象外にして人が読む | 判断が必要で機械化しにくい |

この表のうち、品番と数量は人の承認を必ず通す設計にします。確認工程の置き方は後述します。

## 精度は文字単位と項目単位のどちらで測るか

発注の判断に使うのは項目単位の精度です。文字単位の数値は実務の合否と一致しません。項目単位の精度とは、品番や数量といった1項目をまるごと正しく取れた割合です。

精度の数値は、測り方によって差が出ます。自治体の実証を紹介する記事では、手書きの申請書など11種類73帳票を対象に、正読率が文字単位で平均93.3パーセント、項目単位で平均88.57パーセントだったと報告されています。ただしこれは自治体事例の紹介記事による数値で、一次資料は確認できていません。AI-OCRの精度について政府や自治体が公表した正式な検証報告書は確認できず、各社が掲げる数値も対象の帳票と測定単位が異なるため、横並びの比較には使えません。

### 文字単位の精度が高くても出荷が止まる理由

品番は1文字違えば別の商品になります。文字単位で99パーセント読めても、10桁の品番なら1項目あたりの誤りはそれより高い確率で起きます。

- 品番「AB-1203」の「0」を「8」と読む: 別商品として出荷される
- 数量「12」の末尾を落として「1」と読む: 欠品の連絡が後日になる
- 納期の月を読み違える: 出荷日の組み直しが発生する

当社が実装で見てきた限り、現場が困るのは平均の精度ではなく、特定の取引先の特定の欄だけが続けて外れる偏りです。平均値だけを見ると、この偏りは見えません。

### 項目単位での測り方と記録の様式

前のセクションでそろえた30枚を使い、次の手順で測ります。

1. 正解表を作る。30枚分の品番、数量、納期、届け先を人が入力する (目安2時間)
2. 候補のサービスに同じ30枚を読ませ、出力を書き出す (目安1時間)
3. 項目ごとに正解と突き合わせ、合った数を数える (目安2時間)
4. 項目別と取引先別の2つの表に分けて記録する (目安30分)

つまずきやすいのは4番です。全体の1つの数字にまとめると、どの取引先の紙が苦手なのかが消えてしまいます。取引先別に残しておくと、後で確認工程の濃淡を決める材料になります。

## 読み取り方式の違いは何を見て選ぶか

方式は精度の数値ではなく、注文書の書式が決まっているかどうかで選びます。先に見るのは、その方式が出す形式が、御社が欲しいデータの形と一致しているかどうかです。

### 書式が固定の注文書と、取引先ごとに違う注文書

同じ位置に同じ項目が並ぶ注文書と、取引先ごとに様式が違う注文書では、必要な方式が変わります。

| 注文書の状態 | 向いている方式 | 発注側が確認すること |
|---|---|---|
| 自社指定の様式で全社が提出 | 読み取る位置を指定する方式 | 様式が変わったときの修正の手間と費用 |
| 取引先ごとに様式が違う | 項目の意味で取り出す方式 | 新しい取引先を追加する手順と期間 |
| 手書きの追記が多い | 項目の意味で取り出す方式 | 読めなかった項目の扱いと確認画面の有無 |

位置を指定する方式は、様式が固定なら安定します。一方で、取引先が様式を少し変えるたびに設定の修正が必要です。見積もりでは、この修正を誰がどの費用で行うのかを必ず確認してください。

### 当社が画像からの構造化抽出でモデルを選んだときの判断

当社のエンジニアが担当したオープンプロジェクトで、画像から地図データ用のタグを構造化抽出する際に、3種類のモデルアプローチ (対照学習、物体検出、生成VLM) を実際に比較しました。結果として選定の決め手になったのは、精度の数値ではなく出力の形式でした。

- 対照学習モデル: あらかじめ用意したラベル候補との近さを返すだけで、構造化データ自体を出力しない
- 物体検出モデル: 画像内の位置を矩形で示す前提のため、画面全体にかかる属性には矩形が引けない
- 生成VLM: 求める構造化データを直接出力できたため、これを採用

採用した生成VLMは29言語に対応しており (出典: Qwen2.5-VLの公表仕様)、地域ごとに言語が異なる用途でも同じモデルで扱えました。

ここから持ち帰れる教訓は単純です。精度を比べる前に、その方式が出す形式が欲しいデータの形と合っているかを見てください。注文書の読み取りなら、品番と数量が項目として分かれて出てくるか、1枚の文字列としてまとめて出てくるかの違いがそれにあたります。

## 人が確認する工程をどこに置くか

確信度の低い項目だけを確認画面に出し、品番と数量は必ず人の承認を通す設計にします。読み取りを入れても、人の目が完全に外れる工程にはなりません。確認の量を減らすのが目的です。

確信度とは、読み取った結果に対して機械が自分で付ける確からしさの値です。この値が一定より低い項目だけを画面に出せば、確認の対象が全件から一部に絞れます。しきい値をどこに置くかは、前のセクションで測った項目別の精度から決めます。

### 全件確認と抜き取り確認の分け方

項目ごとに確認の濃さを変えます。すべてを同じ扱いにすると、確認の手間が読み取りの効果を打ち消します。

| 項目 | 確認の方法 | 理由 |
|---|---|---|
| 品番 | 全件を人が承認する | 誤りが誤出荷に直結する |
| 数量 | 全件を人が承認する | 誤りが欠品と過剰在庫になる |
| 納期 | 確信度が低いものだけ確認 | 誤りに気づく機会が後工程にもある |
| 届け先 | 新規の取引先のみ全件確認 | 既存は登録済みの住所と突き合わせられる |

突き合わせができる項目は、確認を機械に任せられます。届け先は取引先マスタと照合し、品番は商品マスタに存在するかを確認する処理を入れてください。マスタに無い値が出たら、その時点で確認画面へ回します。

実装で見落とされやすいのは、確信度が高いのに間違っている場合です。印字がきれいな誤読は確信度が下がらないため、確認画面に出てきません。だからこそ品番と数量は確信度に関係なく人の承認を通します。

### 確認の記録を残す (誰がいつ直したか)

確認画面での修正は、必ず記録に残す仕様にしてください。後から誤出荷の原因を追うとき、読み取りの誤りか人の修正の誤りかを切り分ける材料になります。

1. 読み取った元の値を消さずに保存する (修正後の値と並べて持つ)
2. 修正した担当者と日時を項目単位で記録する
3. 修正の多い項目と取引先を月単位で集計する
4. 集計をもとに、しきい値と確認対象の項目を見直す

つまずきやすいのは1番です。修正で上書きする作りにすると、どの項目がどれだけ外れていたのかが分からなくなります。元の値を残しておけば、運用しながら精度を測り続けられます。

## 保存する画像の要件は先に決める

読み取り精度とは別に、保存する画像が税務上の要件を満たすかを先に確認します。読み取れていても、保存した画像が要件を外していれば作り直しになります。

紙で受けた注文書をスキャンして保存する場合、読み取りの仕様は税務の保存要件から決まる部分があります。国税庁のスキャナ保存のパンフレットは、要件として「解像度: 200dpi (A4サイズで約387万画素相当) 以上による読み取りができること」を挙げています (出典: 国税庁『電子帳簿保存法 スキャナ保存』パンフレット)。読み取りの精度を上げる話より先に、この条件を満たす設定で取り込めているかを確かめてください。

### 解像度と階調の要件

要件は解像度と階調の2点です。いずれも機械の性能ではなく、取り込みの設定で決まります。

| 項目 | 要件 | 出典 |
|---|---|---|
| 解像度 | 200dpi相当以上 (A4サイズで約387万画素相当) | 国税庁『電子帳簿保存法 スキャナ保存』パンフレット |
| 階調 | 赤・緑・青それぞれ256階調 (24ビット) のカラーが原則 | 同パンフレット |
| 階調の例外 | 一般書類に限りグレースケールでの保存を認める | 同パンフレット |

実務でつまずきやすいのは、FAX複合機の既定の設定です。白黒2値や低い解像度で取り込む設定になっていると、要件を外すだけでなく読み取りの精度も落ちます。発注前に、現在の複合機がどの設定で保存しているかを1枚確認してください。確認は5分で終わります。

### タイムスタンプと入力期間の考え方

タイムスタンプについては、国税庁の一問一答 (スキャナ保存関係、令和5年6月) に入力期間と付与期限の考え方が示されています。付与の方式と期限は制度の改正で変わってきているため、要件書に書く前に最新の一問一答で確認する前提にしてください。

発注の実務では、次の順に決めると手戻りが出ません。

1. 自社が電子帳簿保存法のどの保存方法を使うかを決める (目安1時間、税理士に確認)
2. 取り込みの解像度と階調を、上の要件に合わせて設定する (目安30分)
3. タイムスタンプの付与と入力期間の運用を、誰がいつ行うかで決める (目安1時間)
4. 決めた内容を要件書に転記し、外注先に渡す (目安30分)

この順を飛ばして読み取りの精度だけを先に決めると、保存要件に合わせるための改修が後から乗ってきます。

## 外注の要件書と見積もりに書くこと

要件書には、測定した項目単位の精度、確認工程の置き場所、保存要件の3点を数字と画面単位で書きます。この3点が書かれていれば、各社の見積もりを同じ条件で並べられます。

書く内容は次のとおりです。すべて、ここまでのセクションで決めてきたものです。

| 要件書に書く項目 | 書き方の例 |
|---|---|
| 対象の注文書 | 取引先10社、月間の受注枚数、手書き追記の有無 |
| 読み取る項目 | 品番、数量、納期、届け先の4項目 (備考は対象外) |
| 現状の測定結果 | 自社の30枚で測った項目別と取引先別の正読率 |
| 確認工程 | 品番と数量は全件承認、他は確信度のしきい値で振り分け |
| 記録 | 読み取り元の値、修正者、日時を項目単位で保存 |
| 保存要件 | 解像度と階調、タイムスタンプの運用 |
| 連携 | 既存の販売管理システムへの受け渡し方式 |

### 合格ラインの決め方を契約の段階に合わせる

正解率を何パーセントとすれば完成と認める、といった水準を定めた公的な基準は確認できていません。参照できるのは、決め方の枠組みを示す資料です。

経済産業省の「AI・データの利用に関する契約ガイドライン (AI編)」(平成30年6月) は、契約の時点で成果の性能が確定しにくいAI技術の特性を踏まえ、アセスメント、PoC、開発、追加学習の4段階に分けて進める探索的段階型の開発方式と、各段階の契約方式や条項例を示しています。発注側から見ると、最初の契約で最終的な精度を約束させない形が前提になっています。

品質をどの軸で見るかは、AIプロダクト品質保証コンソーシアム (QA4AI、2018年4月1日設立) のガイドラインが参考になります。同ガイドラインは、品質保証を構築し評価する軸としてデータの整合性、モデルの頑健性、システムの品質、プロセスの機敏性、顧客の期待の5軸を挙げています。最新版の2025.04版は2025年4月10日に公開されています。モデル単体の数値だけで合否を決めない枠組みです。

品質として何を並べるかの一覧としては、産業技術総合研究所の「機械学習品質マネジメントガイドライン」第4版 (2023年12月12日公開) も使えます。

### 受け入れテストで使う注文書の指定

受け入れテストには、測定に使った30枚とは別の注文書を使います。同じ紙で測ると、その紙に合わせた調整が効いてしまいます。

1. 測定用30枚とは別に、同じ基準で30枚を選んで封をする (目安1時間)
2. 要件書に「受け入れテストは発注側が当日提示する注文書で行う」と書く (目安10分)
3. 項目別の正読率と、確認画面に回った件数の両方を記録する (目安1時間)
4. 合否は項目別に判定し、未達の項目だけを次の段階の対象にする (目安30分)

つまずきやすいのは2番です。テスト用の紙を事前に渡してしまうと、受け入れテストが調整済みの結果の確認になります。

## 取引先が紙とFAXのままでも進められるか

進められます。読み取りは移行期の受け皿で、取引先の電子化とは別に始められます。取引先に様式の変更を頼む必要はありません。

紙とFAXがどこまで残っているかは、公的な資料に数字があります。中小企業庁の「中小企業のデジタル化に向けて」(令和2年7月) は、企業間取引の電子化が進まず、7割程度の中小企業が電話・FAX・電子メールでの受発注取引を継続しているとし、EDIの導入率を2割程度としています。受注側の対応状況については、同庁の「受発注のデジタル化に関する推進方策 報告書」(2022年3月) が、2021年において受注側の48.5パーセントが電子受発注に対応していたとしています。

つまり、自社が受け取る側を整えても、送ってくる側が紙のままなら読み取りの工程は残ります。この前提で設計するのが現実的です。

### 読み取りで止めるか、注文フォームまで広げるかの線引き

判断は、取引先ごとの受注枚数で分けます。枚数の多い取引先からフォームに移し、残りは読み取りで受けます。

| 取引先の状態 | 進め方 | 理由 |
|---|---|---|
| 受注枚数が多く、担当者が固定 | 注文フォームへの移行を打診する | 移行の効果が枚数に比例する |
| 受注枚数が少ない | 読み取りで受け続ける | 移行の交渉の手間が効果を上回る |
| 発注側のシステムが決まっている | 読み取りで受け続ける | 相手側の都合で変えられない |

電子化の効果の目安としては、中小企業庁が中小企業共通EDIのページで、実証事業において受発注企業ともに5割程度の業務時間削減効果があったと報告しています。ただしこれはEDIでつないだ場合の数値です。読み取りは打ち直しを減らす手段で、同じ水準を前提にはできません。

読み取りとフォームは、どちらかを選ぶものではありません。受注の入り口を2つ用意し、入った後の受注一覧は1つにまとめる設計にしておけば、取引先ごとに移行の時期を変えられます。後からフォームを足すことを見据えて、要件書には受注データの持ち方を先に書いておいてください。

御社の受注が今も打ち直しで止まっているなら、原因は担当者の処理の速さではなく、入り口が紙とFAXしかないことにあります。当社はこの入り口の整理から、読み取りの検証、受注一覧と販売管理システムのつなぎ込みまでを一緒に進めています。実装を担当するエンジニアが要件の段階から入るため、測った数字をそのまま設計に落とせます。

何から手を付けるかの整理だけでも構いません。[無料診断](/diagnostic)で、現在の受注の流れと、読み取りが効く範囲をお伝えします。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。発注前の検討でよく確認される点から順に並べています。

### 手書きの注文書でも読み取れますか

読み取れますが、印字と同じ精度は前提にできません。手書きは書き手ごとの癖が出るため、取引先別に精度が分かれます。判断の材料は他社の事例ではなく、御社の手書き注文書を含めた30枚での測定結果です。手書きの欄が多い取引先は、最初から確認画面を全件通す対象にしておくと運用が安定します。

### 精度は何パーセントあれば実務で使えますか

一律の水準はありません。正解率を何パーセントとすれば完成と認める、といった水準を定めた公的な基準は確認できていません。判断は項目ごとに分けます。品番と数量は確認画面を全件通す前提なので、読み取りの精度が多少低くても運用は回ります。一方で、確認を省く項目は、確認を省いても業務が成立する精度が出ているかを測った数字で見てください。

### 読み取った後の紙の注文書は捨ててよいですか

税務上の保存方法をどう選ぶかで変わるため、税理士に確認してください。紙をスキャンして保存する方法を使う場合、国税庁のスキャナ保存の要件を満たす必要があります。要件は解像度と階調、タイムスタンプの運用に関わります。読み取りの仕組みを入れることと、紙を処分してよいかは別の判断です。

### 取引先にFAXをやめてもらう交渉は必要ですか

必要ありません。読み取りは、取引先が紙とFAXのままでも自社側だけで始められます。枚数の多い取引先に注文フォームを打診するかどうかは、移行の手間と効果を見て後から決められます。

### 読み取りの仕組みだけを先に入れて、後から受注システムにつなげられますか

つなげられます。ただし、後からつなぐ前提で受注データの持ち方を最初に決めておく必要があります。読み取った結果を画面で見るだけの作りにすると、後で販売管理システムへ渡す段階で作り直しになります。要件書の時点で、受注データの項目と受け渡しの方式を書いておいてください。

発注前に決めることを一通り整理したい場合は、お問い合わせから現在の受注の流れをお知らせください。
