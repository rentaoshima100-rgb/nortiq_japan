# AIチャットボットの有人引き継ぎ｜発注要件

## AIチャットボットの有人引き継ぎは、何から決めますか？

最初に決めるのは「引き継ぐ条件」です。答えられないときだけ渡すのか、特定の話題は最初から人に回すのかで、作るものと運用の人数が変わります。

引き継ぎは追加機能ではありません。引き継ぎのない設計は、答えられない質問が来た時点で利用者を取りこぼす設計です。

### 要件を決める4つの順番

1. 引き継ぐ条件を決める (目安: 半日)。話題で振り分けるのか、利用者の求めで切り替えるのかを選びます。つまずきやすい点は、AIの確信度だけを条件にすることで、間違った回答を自信をもって返す場合に引き継がれません。
2. 渡す情報を決める (目安: 2時間)。会話の履歴、利用者が入力した情報、どこで答えられなくなったかの3点が最低線です。
3. 対応時間の扱いを決める (目安: 2時間)。人が対応できない時間に引き継ぎが発生した場合をどうするかを決めます。
4. 要件書に落とす (目安: 1日)。上記3点と、記録の残し方、検収の確認方法を書面にします。

この4点のうち1が最も重く、ここだけは社内で決める必要があります。どの話題を人が受けるかは、業務を知っている側しか判断できません。

### 引き継ぎを要件に入れない場合に起きること

| 入れなかった場合 | 現場で起きること |
| --- | --- |
| 引き継ぎの手段がない | 「お答えできません」で会話が終わり、利用者が離脱します |
| 引き継ぎはあるが条件が曖昧 | 引き継ぎが多すぎて人の負担が増えるか、少なすぎて機能しません |
| 履歴を渡さない | 担当者が同じ質問を繰り返し、利用者が二度説明します |
| 対応時間の扱いを決めていない | 夜間の引き継ぎが誰にも届かず放置されます |

実装の側から見ると、4番目が最も多い失敗です。引き継ぎの導線を作ったものの、その先が営業時間内しか人のいない窓口になっており、夜間の問い合わせが宛先のないまま溜まります。

以降の見出しで、この4点をそれぞれ具体化します。

## どういう条件で人に引き継ぎますか？

引き継ぐ条件は、AIの確信度ではなく「話題」と「利用者の求め」で決めるのが実務的です。確信度だけを条件にすると、間違った回答を自信をもって返す場合に引き継がれません。

条件は3種類あり、組み合わせて使います。以下の順に設計すると漏れが出にくくなります。

### 話題で振り分ける条件

最初に決めるのは、AIに答えさせない話題です。次の4つは、答えが合っていても人が受けるべき領域です。

| 話題 | 人に回す理由 |
| --- | --- |
| 見積もり、価格の交渉 | 条件によって金額が変わり、回答が約束とみなされる可能性があります |
| 契約、解約、返金 | 判断に権限が必要で、誤った案内が実害につながります |
| 苦情、不具合の申し出 | 一次対応の口調と速度が結果を左右します |
| 個人の情報に関する照会 | 本人確認が必要で、AIの画面では確認が完結しません |

この振り分けは、キーワードではなく利用者の意図で判定させてください。「高い」「高すぎる」のような語だけで拾うと、関係のない会話まで人に回ります。

### 利用者の求めで切り替える条件

利用者が人と話したいと言った時点で引き継ぐ経路を、必ず用意してください。要件に入れる具体は次の3点です。

1. 画面上に常に出ている「担当者につなぐ」の操作 (探させないこと)
2. 同じ質問を2回繰り返した場合の自動の切り替え
3. 会話が一定の往復を超えた場合の自動の切り替え

2と3は、利用者が明示しなくても行き詰まりを検知する条件です。実装の側から見ると、2が最も費用対効果が高い条件になります。

### 確信度を条件にする場合の限界

AIの確信度を引き継ぎの条件に使うことはできますが、単独では足りません。確信度が高いまま誤った内容を返す場合があり、その場合は引き継ぎが発動しないからです。

国の枠組みも、出力そのものの正しさではなく、体制と関与の設計を求める形になっています。総務省と経済産業省は令和7年3月28日にAI事業者ガイドライン第1.1版を公表し、2017年のAI開発ガイドライン、2019年のAI利活用ガイドライン、2022年のAI原則実践のためのガバナンスガイドラインの3件を統合・改訂しています。

出典: 総務省「AI事業者ガイドラインの公表」

対策の整備状況も参考になります。総務省「令和8年版情報通信白書」では、生成AIのリスク対策として全社的な指針やガイドラインを整備していると答えた企業の割合は41.1%でした。半数以上が整備していない状況なので、引き継ぎの条件を要件書に書いておくことが、そのまま体制の整備になります。

出典: 総務省「令和8年版情報通信白書」図表Ⅰ-2-1-9

結論として、条件は「話題」を主、「利用者の求め」を補助、「確信度」を最後の網として重ねてください。

## 引き継ぐときに人へ何を渡しますか？

渡すのは会話の全履歴、利用者が入力した情報、AIがどこで答えられなくなったかの3点です。履歴を渡さない設計では、担当者が同じ質問を繰り返すことになります。

利用者から見ると、引き継ぎは「話が通じている相手に代わった」と感じられるかどうかで評価が決まります。ここは実装の手間に対して効果が大きい部分です。

### 引き継ぎに含める情報の一覧

| 渡す情報 | 何に使うか |
| --- | --- |
| 会話の全履歴 (時刻つき) | 担当者が経緯を読んでから応答できます |
| 利用者が入力した情報 (氏名、連絡先、注文番号等) | 聞き直しを避けられます |
| AIが答えられなくなった箇所と理由 | どこから話せばよいかがわかります |
| 引き継ぎの契機 (話題、本人の求め、確信度のどれか) | 条件の見直しの材料になります |
| 利用者が見ていたページのURL | 何について尋ねているかが絞れます |

要件書には、この5項目を「担当者の画面に表示する」まで書いてください。データとして保存されていても、画面に出ていなければ使われません。

### 個人情報を含む場合の扱い

引き継ぎの情報には、氏名や連絡先が含まれます。保存先と権限を要件に入れる必要があるのはこのためです。

漏えいが起きた場合の報告の枠組みも押さえておいてください。個人情報保護委員会は、漏えい等の速報を発覚日から3日から5日以内、確報を30日以内 (不正の目的で行われたおそれがある場合は60日以内) と示しています。報告が必要になる類型には、本人の数が1,000人を超える漏えい等も含まれます。

出典: 個人情報保護委員会「漏えい等が発生したら」

要配慮個人情報を扱う場合は、さらに基準が上がります。医療の分野では、厚生労働省が令和5年5月31日に「医療情報システムの安全管理に関するガイドライン 第6.0版」を策定し、概説編、経営管理編、企画管理編、システム運用編の4編で構成しています。医療や介護の事業者がチャットボットを導入する場合は、この枠組みに沿って外部委託時の責任の分界を決める必要があります。

出典: 「医療情報システムの安全管理に関するガイドライン 第6.0版」の策定について

実装の側から1点補足します。引き継ぎの履歴を担当者が使うツール (メールやチャット) に転送する設計にすると、個人情報がそのツールの中に複製されます。保存先を1か所にまとめ、担当者はリンクから参照する形にしたほうが、後の管理が楽になります。

なお、電話の一次応対を自動化する動機も同じ構造です。株式会社HERO innovationのクリニックの課題に関する調査 (2026年6月17日公表、有効回答154件) では、院内業務の課題として電話対応が多く窓口業務が中断されると答えたクリニックの割合は47.4%でした。

出典: 株式会社HERO innovation「クリニックの課題に関する調査」

## 対応できる時間と待ち時間はどう決めますか？

人が対応できる時間を超えた引き継ぎをどうするかを先に決めます。無人の時間に引き継ぎが発生した場合の受け付け方を決めていない設計が、最も多い失敗です。

決めるのは2つです。時間内と時間外で振り分ける先と、時間内に待たせる上限です。

### 対応時間内と時間外の振り分け

| 時間帯 | 引き継ぎ先 | 利用者への案内 |
| --- | --- | --- |
| 対応時間内 | 担当者のチャットまたは電話 | 待ち時間の目安を表示します |
| 対応時間内で全員が対応中 | 順番待ちか、連絡先の受け付け | どちらになるかを先に案内します |
| 対応時間外 | 連絡先の受け付け (フォーム化) | 翌営業日の何時までに返すかを明示します |
| 休業日 | 連絡先の受け付け | 次の営業日を明示します |

時間外は「受け付けて、いつ返すかを約束する」形にしてください。受け付けないと利用者は離脱し、約束しないと催促の連絡が増えます。

要件書には、対応時間の定義をシステムの設定値として外に出すことも書いてください。年末年始や臨時休業のたびに開発を依頼する形にすると、運用が止まります。

### 待ち時間の上限と代替の案内

時間内であっても、担当者が全員対応中であれば待ち時間が発生します。決める値は次の3つです。

1. 待ち時間の上限 (この時間を超えたら、順番待ちから連絡先の受け付けへ切り替える)
2. 待ち時間の表示の方法 (おおよその分数か、順番の人数か)
3. 待っている間にAIが何をするか (関連する情報を出すのか、黙って待つのか)

3は意見が分かれる部分です。実装の側の経験では、待っている間にAIが追加の案内を続ける設計は評価が下がります。人につながるのを待っている利用者にとって、AIの発言は邪魔になるからです。待機中は静かにして、進捗だけを表示するほうが無難です。

もう1点、要件に入れておくと効くのが取り逃がしの検知です。引き継ぎが発生したが担当者が応答しなかった件数を、日次で記録する形にしてください。この数字がないと、引き継ぎが機能しているかを誰も確認できません。

## AIの関与と人の関与を、どこで切り分けますか？

国のガイドラインは、AIの出力に人が関与する点をあらかじめ設計しておくことを求める枠組みになっています。引き継ぎの条件は、その人の関与をどこに置くかの設計にあたります。

つまり引き継ぎは、利用者への配慮であると同時に、自社の体制の一部です。

### 公的な枠組みが求める人の関与

参照できる枠組みは3つあります。

| 枠組み | 引き継ぎの設計に効く点 |
| --- | --- |
| 経済産業省「AI・データの利用に関する契約ガイドライン (AI編)」(2018年6月) | 開発をアセスメント、PoC、開発、追加学習の4段階に分け、段階ごとに契約を結ぶ進め方を示しています。出力の性能が契約時にわからない前提なので、誤った出力が出た場合の扱いを段階ごとに決めます |
| 総務省・経済産業省「AI事業者ガイドライン 第1.1版」(令和7年3月28日公表) | AIの開発者、提供者、利用者という主体ごとに取組を整理しています。引き継ぎの運用を誰が負うかの区分に使えます |
| QA4AIコンソーシアム「AIプロダクト品質保証ガイドライン」 | Data Integrity、Model Robustness、System Quality、Process Agility、Customer Expectationの5軸を示しています。引き継ぎはSystem QualityとCustomer Expectationにあたります |

AI事業者ガイドライン第1.1版は、2017年のAI開発ガイドライン、2019年のAI利活用ガイドライン、2022年のAI原則実践のためのガバナンスガイドラインの3件を統合・改訂したものです。

出典: 総務省「AI事業者ガイドラインの公表」、経済産業省「AI・データの利用に関する契約ガイドライン」関連資料、QA4AIガイドラインの概要解説

自社側の整備も問われます。総務省「令和8年版情報通信白書」では、生成AIのリスク対策として全社的な指針やガイドラインを整備していると答えた企業の割合は41.1%でした。

出典: 総務省「令和8年版情報通信白書」図表Ⅰ-2-1-9

### 自社の無人運用で人を挟んでいる箇所

当社はAIによる記事生成のパイプラインを自社で運用していますが、自動公開は実装していません。公開の引き金は人が実際に記事を読んで承認することだけで、生成物はすべて承認待ちで止まります。

人の関与が抜けた場合の備えも入れています。公開予定時刻から72時間を超えて承認されなかった記事は、自動で保留に戻します。担当者が不在のときに新規公開がゼロになるのが正しい挙動だという考え方です。品質の判定は単一のAIに委ねず2系統で行い、判定が食い違った場合は自動棄却も自動通過もさせず、不一致のフラグを付けて人の判断に上げます。

この設計から言えることを、チャットボットの引き継ぎに置き換えるとこうなります。

1. 人が必ず介在する点を先に決める (引き継ぐ条件)
2. その介在が抜けたときに安全側へ倒す (応答がない場合は受け付けに切り替える)
3. AIの判断が割れる場合は自動で決めない (確信度が低いときは人に回す)

無人化で難しいのは自動化する部分の実装ではなく、人がどこで必ず介在するかを決め、その介在が抜けたときにシステムが安全側に倒れるようにすることです。引き継ぎの要件は、まさにこの部分を決める作業です。

誤回答の責任分担そのものは別の記事で扱っています。

## 外注の要件書に書く項目は何ですか？

要件書には、引き継ぐ条件、渡す情報、対応時間の扱い、待ち時間の上限、記録の残し方、検収の確認方法の6つを書きます。この6つが揃っていれば、複数社の見積もりを同じ条件で比べられます。

### 要件書に書く6項目

| 項目 | 書く内容 |
| --- | --- |
| 引き継ぐ条件 | 人が受ける話題の一覧、利用者の求めによる切り替えの操作と自動の条件、確信度を使う場合の扱い |
| 渡す情報 | 担当者の画面に表示する項目と、その保存先 |
| 対応時間の扱い | 時間内と時間外と休業日の振り分け先、対応時間を設定で変えられること |
| 待ち時間の上限 | 上限の値、超えたときの切り替え先、利用者への表示の方法 |
| 記録の残し方 | 引き継ぎの件数、契機、応答しなかった件数を日次で記録すること |
| 検収の確認方法 | 下記の確認項目と、合否の判断の基準 |

発注側と受注側の役割の分け方も明記してください。医療の分野では外部委託時の責任の分界を定める考え方が示されており、厚生労働省が令和5年5月31日に策定した「医療情報システムの安全管理に関するガイドライン 第6.0版」は、概説編、経営管理編、企画管理編、システム運用編の4編で構成されています。医療や介護に限らず、外部に委託する範囲と自社が残す範囲を文書で分ける考え方は共通して使えます。

出典: 「医療情報システムの安全管理に関するガイドライン 第6.0版」の策定について

実装の側から1点。引き継ぐ条件の一覧は、要件書の別紙にして後から差し替えられる形にしてください。本文に埋め込むと、条件を1つ追加するたびに要件書の改訂が必要になります。

### 検収で確認する引き継ぎの動き

引き継ぎは画面の見た目では確認できません。検収では次の手順で動きを確かめます。

1. 人が受ける話題を実際に入力する (目安: 2時間)。価格の交渉や解約の申し出を、言い回しを変えて3通り入れ、すべて引き継がれるかを見ます。つまずきやすい点は、キーワード一致で判定している実装だと、言い回しを変えた途端に引き継がれないことです。
2. 利用者の求めによる切り替えを試す (目安: 1時間)。「人と話したい」と入力した場合と、常設の操作を押した場合の両方を確認します。
3. 同じ質問を2回繰り返す (目安: 30分)。自動の切り替えが働くかを見ます。
4. 渡される情報を担当者側の画面で確認する (目安: 1時間)。会話の履歴と入力された情報が、聞き直さずに済む形で表示されているかを見ます。
5. 対応時間外に引き継ぎを発生させる (目安: 1時間)。受け付けの画面が出て、いつ返すかが明示されるかを見ます。
6. 担当者が応答しない状態を作る (目安: 1時間)。待ち時間の上限を超えたときに受け付けへ切り替わるか、そして記録に残るかを見ます。

6は検収で飛ばされがちですが、ここが抜けていると運用開始後に取り逃がしが見えません。合否の基準としては、1から6のすべてが要件書どおりに動くことを条件にしてください。

検収の基準全般の決め方は別の記事で扱っています。

## 導入後に引き継ぎの条件を直す手順

引き継ぎの条件は導入時に決めきれないので、月次で引き継ぎの記録を見て条件を足す運用を前提にします。最初から完璧な条件を作ろうとすると、導入そのものが止まります。

前提として、条件の追加が開発の依頼にならない形にしてください。条件を設定として外に出しておけば、追加は社内の作業で済みます。

### 月次で見る3つの数字

| 見る数字 | 高すぎる場合に打つ手 | 低すぎる場合に打つ手 |
| --- | --- | --- |
| 引き継ぎの発生率 | AIが答えられる範囲を広げる (よくある質問を追記する) | 引き継ぐ条件が狭すぎる。取りこぼしの有無を会話の記録で確認する |
| 担当者が応答しなかった件数 | 対応時間の定義か人員の配置を見直す | 問題なし |
| 引き継ぎ後に用が足りた割合 | 問題なし | 渡している情報が足りないか、引き継ぎ先の担当が合っていない |

このうち2番目を見ていない運用が多いです。発生率と満足度だけを見ると、そもそも誰も応答しなかった会話が集計から落ちます。

手順は次の形です。

1. 月初に前月の引き継ぎの記録を出す (目安: 30分)。契機別の件数と、応答しなかった件数を並べます。
2. 引き継がれなかった取りこぼしを探す (目安: 1時間)。AIが「お答えできません」で終えた会話を読み、人が受けるべきだったものを拾います。つまずきやすい点は、この作業を自動化しようとすることで、最初の数か月は人が読むのが確実です。
3. 条件を追加する (目安: 30分)。拾った話題を人が受ける一覧に足します。
4. 追加した条件の効果を翌月に確認する (目安: 30分)。発生率が上がりすぎていないかを見ます。

3か月ほど回すと、条件の追加はほとんど止まります。そこから先は、サービスや商品が変わったときだけ見直す形になります。

### 当社に相談する場合の進め方

相談で多いのは、チャットボットを導入したが引き継ぎの先が決まっておらず、答えられない質問がそのまま終わっているという状態です。原因は導入時に引き継ぐ条件を要件にしていないことで、条件と宛先を決めれば既存の仕組みのままでも改善できる場合があります。

当社ではAIチャットボットの構築を100,000円からお受けしており、引き継ぐ条件と渡す情報、対応時間の扱いを要件書に明記してから着手します。他社で構築したチャットボットの引き継ぎの追加についても、現在の構成を確認したうえでお見積もりします。

いまのチャットボットが答えられない質問をどう扱っているかを確認したい場合は、無料診断で会話の記録をもとに取りこぼしの有無をご提示します。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。回答はいずれも2026年10月時点の情報です。

### AIチャットボットは、どのくらいの割合で人に引き継ぐことになりますか？

割合の目安を示す公的な統計は確認できないため、数値は記載しません。引き継ぎの割合は、人が受けると決めた話題の範囲でほぼ決まります。価格の交渉や契約の変更を人が受ける設計にすれば、その分だけ引き継ぎが増えます。導入前に割合を見積もるより、1か月運用して実際の記録から条件を調整するほうが確実です。

### 引き継ぎ先はメールと電話のどちらにすべきですか？

チャットのまま担当者に代わる形が、利用者の離脱が最も少ない選択です。会話の履歴がそのまま引き継がれるため、説明の繰り返しが起きません。電話は本人確認が必要な場合や、苦情の一次対応では有効ですが、電話番号の入力という手間が増えます。メールは対応時間外の受け付けに向いています。

### 営業時間外に引き継ぎが発生した場合はどうしますか？

受け付けて、いつ返すかを明示してください。時間外は連絡先を入力するフォームに切り替え、翌営業日の何時までに返すかを画面に出す形が基本です。受け付けないと利用者は離脱し、返す時期を示さないと催促の連絡が増えます。対応時間の定義は設定で変えられる形にしておくと、臨時休業にも対応できます。

### 引き継いだ会話の履歴はどこまで保存する必要がありますか？

保存期間は自社の個人情報の取り扱いの方針に合わせて決めてください。氏名や連絡先が含まれるため、保存先と権限を要件に入れる必要があります。漏えいが起きた場合、個人情報保護委員会は速報を発覚日から3日から5日以内、確報を30日以内 (不正の目的で行われたおそれがある場合は60日以内) と示しています。

出典: 個人情報保護委員会「漏えい等が発生したら」

### 引き継ぎの条件は後から変えられますか？

設定として外に出していれば変えられます。要件書の段階で「人が受ける話題の一覧は管理画面から編集できること」と書いてください。この一文がないと、条件を1つ追加するたびに開発の依頼と費用が発生します。
