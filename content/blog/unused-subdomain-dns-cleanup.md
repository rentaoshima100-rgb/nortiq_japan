# 使わないサブドメインの閉じ方｜DNSの消す順番

## 使わないサブドメインは何から閉じる？

先に閉じるのはサブドメインが指している先のサービスではなく、どこを指しているかの棚卸しです。指し先を確認せずにDNSレコードを消すと、まだ使われている経路を止めてしまいます。

サブドメインとは、自社のドメインの前に名前を付けた住所です。campaign.example.co.jpのcampaignの部分がそれに当たります。

### 残りやすいサブドメインの例

リニューアルの後に残るサブドメインには、よく出てくる型があります。どれも新サイトからリンクされていないため、気づかれにくいものです。

| サブドメインの例 | 作られた目的 | 残りやすい理由 |
| --- | --- | --- |
| campaign | 期間限定のキャンペーンページ | 期間が終わっても消す手続が決まっていない |
| old、old-site | 旧サイトの退避用 | 公開後に止める時期を誰も決めていない |
| stg、dev、test | 公開前の確認用 | 公開作業が終わると見に行かなくなる |
| mail、smtp | メールの送受信 | 止めると業務が止まるため、触られないまま残る |
| shop、form | 外部サービスで作った申込や予約の画面 | 外部サービスの契約が別で、解約と連動しない |

このうち、消してはいけないのはメール関連のレコードです。見た目には使われていないように見えても、止めると送受信ができなくなります。一方で、campaignやstgは止めても業務に影響しないことが多く、優先して整理できます。

### 指し先を確認する方法

棚卸しは、DNSの管理画面にある設定の一覧から始めます。確認するのは次の3点です。

1. 設定されているレコードの一覧を書き出す。名前、種類、値の3列で表にします。所要時間の目安は、レコードが数十件なら1時間です。
2. それぞれの値がどこを指しているかを調べる。自社のサーバのIPアドレスか、外部サービスのホスト名かで扱いが変わります。つまずきやすい点は、外部サービスのホスト名が社名と無関係な文字列になっており、どのサービスか分からないことです。
3. 現在も使われているかを確認する。アクセス解析やサーバのログで、直近の数か月にアクセスがあるかを見ます。

3の確認で迷ったら、消す前に一度止めてみる方法もあります。レコードを消すのではなく、一時的に別のページへ転送して様子を見る形です。社内から問い合わせが来なければ、使われていないと判断できます。

実装の面で注意したいのは、2で出てきた外部サービスです。サブドメインが外部サービスのホスト名を指している場合、そのサービスの契約を解約するとサブドメインの行き先が無くなります。この状態を放置するとどうなるかは、次のセクションで扱います。

## DNSレコードを消し忘れると何が起きる？

指している先のサービスを解約したのにレコードだけが残ると、その名前が第三者に使われる余地が生まれます。サブドメインは自社の名前のまま、中身だけが他人のものになります。

この状態は、政府のガイドラインでも対策の対象として挙げられています。

### 指し先が無くなったレコードの状態

デジタル庁の「デジタル社会推進標準ガイドライン DS-900 Webサイト等の整備及び廃止に係るドメイン管理ガイドライン」の2.3は、次のように定めています。「ドメインの移行・廃止に当たっては、当該ドメインの権威DNSサーバーに設定されたDNSレコード、クラウドサービス等の外部サービスで設定されたカスタムドメインの利用等のためのDNSレコードを削除することを含め、意図しない第三者が当該ドメインを利用することを防止する対策を行うものとする。」

出典: デジタル庁「デジタル社会推進標準ガイドライン DS-900 Webサイト等の整備及び廃止に係るドメイン管理ガイドライン」2.3

同ガイドラインは、具体的に注意すべきレコードの種類も挙げています。

| レコードの種類 | 主な用途 | 消し忘れたときの状態 |
| --- | --- | --- |
| CNAME | 外部サービスのホスト名を指す | 外部サービスの解約後、その名前を取得した第三者の内容が表示され得る |
| A、AAAA | サーバのIPアドレスを指す | サーバを解約した後、同じIPアドレスを使う別の利用者につながり得る |
| NS | 名前の管理を別のDNSサーバに任せる | 委任先の設定が他人の管理下に移っても気づけない |
| MX | メールの宛先サーバを指す | 受信の経路が残り、宛先の管理が他人に移り得る |

同ガイドラインは「『CNAMEレコード』、『A/AAAAレコード』、『NSレコード』、『MXレコード』等の削除漏れがないよう注意すること」としています。前のセクションで挙げた外部サービス向けのサブドメインは、このうちCNAMEに該当することが多くあります。

出典: 同ガイドライン

### 自社ドメイン全体への影響

影響はそのサブドメイン1つに留まりません。自社のドメイン名の一部として表示されるため、見た人は自社が出している内容だと受け取ります。

- 自社のドメイン名が付いた画面で、意図しない内容が表示される可能性があります。
- そのサブドメインを使って発行されていた証明書やアカウントの扱いが曖昧になります。
- 社内の誰も管理していないため、問題が起きても気づく経路がありません。

同ガイドラインは、管理の分担についても定めています。「DNSレコード情報の管理者とDNSサーバーの管理者が異なる場合、DNSサーバーの管理者はDNSレコード情報の管理者に対してレコード情報の確認を定期的に依頼し、使用していないドメインのDNSレコードが残存していないか確認すること」とされています。

出典: 同ガイドライン

なおこのガイドラインは政府機関を対象としたもので、中小企業に直接適用される規則ではありません。ただし、廃止時に何をすべきかの基準としては参照できます。自社でDNSを触っていない場合は、この確認を保守の作業として依頼先に頼む形になります。

実装の面で付け加えると、外部サービスのカスタムドメインは、サービス側の設定とDNSのレコードの2か所に設定が残ります。サービスを解約してもレコードは自動では消えません。解約の手続とレコードの削除は別の作業です。

## 消す順番はどうすればよい？

サービスの解約よりも先にDNSレコードを消します。順番を逆にすると、解約してからレコードを消すまでの間が無防備になります。

解約は手続を出した日に完了しないこともあります。その間にレコードが残っていると、行き先が無くなった名前が公開されたままになります。

### 手順1から5の進め方

1. 消す対象のレコードを一覧で確定する。棚卸しの表から、消すものと残すものに印を付けます。つまずきやすい点は、メール関連のレコードを誤って対象に入れてしまうことです。MXレコードと、送信に使う設定のレコードは残します。
2. 消す前にTTLを下げる。反映までの時間を短くしておくと、間違いに気づいたときに戻しやすくなります。所要時間の目安は設定の変更だけなら10分です。
3. DNSレコードを削除する。削除の前に、設定の内容を画面の写しかテキストで記録しておきます。戻す必要が出たときに、同じ値を入れ直せます。
4. 反映を確認する。削除したサブドメインが表示されなくなったかを、しばらく時間を置いて確認します。所要時間の目安は、TTLを下げている場合は数時間です。
5. 指し先のサービスを解約する。レコードが消えて反映されたことを確認した後に、外部サービスやサーバの契約を解約します。

この順番にすると、サブドメインが行き先の無い状態で公開される時間をなくせます。逆にしてしまった場合は、気づいた時点ですぐにレコードを消せば、無防備な期間を短くできます。

### レコードの種類ごとの注意点

消す作業の難しさは、レコードの種類で変わります。

| レコードの種類 | 消すときの注意 |
| --- | --- |
| CNAME | 外部サービス向けが多く、サービス側の設定も合わせて削除します |
| A、AAAA | 同じIPアドレスを指す別のレコードが残っていないかを確認します |
| MX | メールの受信に使われます。原則として残し、移行する場合も新しい設定を入れてから消します |
| TXT | 送信ドメイン認証や外部サービスの所有権確認に使われます。何のための値かを特定してから消します |
| NS | 名前の管理を委任している設定です。委任先のサービスを解約する前に消します |

このうち判断が難しいのはTXTです。文字列だけを見ても用途が分からないことが多く、消すと外部サービスの連携やメールの送信が止まることがあります。用途が特定できない値は、消さずに残して記録に書いておくほうが安全です。

実装の面では、1つのサブドメインに複数のレコードが設定されていることがあります。CNAMEとTXTが同じ名前に付いている場合、片方だけ消すと中途半端な状態になります。名前ごとにまとめて確認してから作業するのが確実です。

## 消してから止まるまでどのくらいかかる？

DNSの情報は一定の時間キャッシュされるため、レコードを消してもすぐには反映されません。反映までの時間はTTLという設定値で決まります。

削除した直後に表示が残っていても、設定の失敗とは限りません。待つべき時間は計算できます。

### TTLが決める反映までの時間

TTLとは、DNSの情報をキャッシュに保持してよい時間を秒単位で示す値です。JPRSの用語辞典は、TTLを「DNSにおいて、リソースレコードをキャッシュに保持してもよい時間を秒単位で示す31ビットに符号化された整数で、ゼロまたは正の値 (0から2147483647の値) を取ります」と定義しています。

出典: JPRS用語辞典「TTL」

同辞典によると、TTLをゼロに設定した場合はキャッシュしてはならないことを意味し、ゼロ以外の値はキャッシュしてよい最大時間を示します。TTLが3600のレコードは最大1時間キャッシュされます。キャッシュに保持されたTTLは減少していき、ゼロになるとそのリソースレコードがキャッシュから削除されます。

| 設定していたTTL | キャッシュが残る最大の時間 |
| --- | --- |
| 300 | 5分 |
| 3600 | 1時間 |
| 86400 | 24時間 |

ここで重要なのは、効いてくるのが「削除した時点のTTL」ではなく「削除する前に設定されていたTTL」だという点です。TTLが86400のまま消すと、最大24時間は古い情報を参照する経路が残ります。削除と同時にTTLを下げても、すでに配られたキャッシュには効きません。

### 切り替えや削除の前にTTLを下げる

そのため、TTLは削除の前に下げます。Google検索セントラルのURLの変更を伴わないサイト移転のドキュメントは、サーバを移す場面について、TTLを数時間程度の低い値に設定し、移転の少なくとも1週間前に下げるよう勧めています。

出典: Google検索セントラル「URLの変更を伴わないサイト移転」

サブドメインを閉じる場合も同じ考え方が使えます。作業の流れは次のとおりです。

1. 削除の1週間前にTTLを数時間程度まで下げる。つまずきやすい点は、下げた設定自体が元のTTLでキャッシュされているため、下げた値が全体に行き渡るまで時間がかかることです。
2. 下げた値が行き渡るのを待つ。所要時間の目安は、元のTTLが86400なら24時間です。
3. レコードを削除する。
4. 下げたTTLの時間だけ待って、反映を確認する。所要時間の目安は数時間です。

急いで消す必要がある場合は、TTLを下げる工程を省いて削除し、古い情報が参照される時間を受け入れる判断もあります。第三者に使われる余地を早く閉じたい場面では、こちらが優先されます。

同ドキュメントは、サーバ移転の場面で旧サーバを止める時期について、旧プロバイダのログを確認してトラフィックがゼロになったら停止するとしています。サブドメインの場合も、アクセスが来なくなったことを確認してから指し先を解約する流れが同じ考え方になります。

## ドメイン自体をやめる場合は何が違う？

サブドメインを閉じる場合と、ドメインの登録自体をやめる場合では、第三者に使われるまでの経路が違います。ドメインをやめる場合は、公的資料で求められている対策があります。

サブドメインは自社がドメインを持っている限り、他人が勝手に名前を取ることはできません。ドメインそのものを手放すと、名前自体が他人のものになります。

### ドメインを失ったときに起きること

JPRSは「ドメイン名の廃止に関する注意」で「ドメイン名を廃止した場合、一定期間経過した後に、第三者がそのドメイン名を登録できるようになります」と記載しています。

出典: JPRS「ドメイン名の廃止に関する注意」

期間も規則で決まっています。JPRSの「JPドメイン名のライフサイクル」によると、汎用・都道府県型JPドメイン名では次の流れになります。

| 段階 | 期間 |
| --- | --- |
| 有効期限 | 登録年月日の1年後の月末 |
| 廃止状態 (Suspended) | 期限の翌日から1カ月間 (月末まで) |
| 登録回復期間 | Suspendedになった月の1日から20日まで |
| 第三者が再登録できる時点 | Suspendedの期限翌日以降にデータが削除された後 |

出典: JPRS「JPドメイン名のライフサイクル」

属性型・地域型 (LG.JPを除く) では、廃止状態 (Deleted) の期間が廃止日または有効期限の翌日から6カ月間 (月末まで) で、登録回復期間はDeletedになった月の1日から20日までです。

同じJPRSの注意は、廃止前に行うべき対応として「ドメイン名の廃止前には、該当のWebサイトやメールアドレスを終了することを外部に周知したり、メールアドレスを利用したアカウントの削除や設定の削除、メールアドレスの変更をしておくことをお勧めします。」としています。メールアドレスを使って作った外部サービスのアカウントまで挙げられている点が見落としやすい部分です。ドメインを失うと、そのアドレスでパスワードを再設定できる経路も他人の手に渡ります。

### 廃止するときに求められる対策

デジタル庁のDS-900は、廃止の場合と移行の場合のそれぞれについて期間を定めています。単純廃止する場合は「当該ドメインの運用停止後も1年以上当該ドメインを保持し、第三者の組織が当該ドメインを早期に取得することによる、国民等利用者の困惑を避けるよう対策を講じた上で、廃止手続を行うものとする。」としています。移行する場合は「旧ドメインを1年以上運用し、旧ドメイン上で新ドメインの移行案内を行いつつ、廃止手続を行うものとする。」とされています。

出典: デジタル庁「デジタル社会推進標準ガイドライン DS-900 Webサイト等の整備及び廃止に係るドメイン管理ガイドライン」

さらに同ガイドラインは、廃止するWebサイト等について他のWebサイト等 (ソーシャルメディア等の民間サービスを含む) にリンク先等の関連情報を掲載している場合は、運用停止に合わせて関連情報の削除を行うものとするとしています。

なおこのガイドラインは政府機関を対象としたもので、中小企業に直接適用される規則ではありません。参照したPDFは日付が「2025 (令和7) 年XX月XX日」のままの版で、確定版の日付は確認できていません。基準としての参照にとどめてください。

リニューアルでドメインを変えた場合の旧ドメインの維持期間については、別の記事で扱っています。

## 制作会社とどう分担する？

DNSの管理画面に入れるのが制作会社だけの場合、閉じる作業を自社で進められません。アカウントの権限と、作業の依頼先を先に確認します。

棚卸しの表を作ろうとして、まず管理画面に入れないと気づく場面がよくあります。

### 権限の確認と記録の残し方

確認するのは次の3点です。いずれも作業を始める前に分かります。

1. ドメインを管理している事業者を調べる。契約書か、年次の請求書の宛先で確認できます。所要時間の目安は30分です。
2. DNSの設定を変更できるアカウントを誰が持っているかを確認する。制作会社だけが持っている場合は、自社用のアカウントを作れるかを聞きます。つまずきやすい点は、ドメインの契約先とDNSを設定している場所が別になっていることです。
3. 現在の設定の一覧を記録として受け取る。画面の写しでも構いません。これが棚卸しの出発点になります。

記録の残し方で効くのは、作業の前後で設定の一覧を2回取ることです。削除の前と後の差分が、そのまま作業の記録になります。後から「この名前は何のために消したのか」を確認できます。

| 確認する項目 | 自社で持っておきたい状態 |
| --- | --- |
| ドメインの契約名義 | 自社名義で、更新の通知が自社に届く |
| DNSの設定権限 | 自社のアカウントで管理画面に入れる |
| 現在のレコード一覧 | 社内に写しがあり、更新のたびに差し替える |
| 外部サービスとの対応表 | どのサブドメインがどのサービスを指しているかが分かる |

### 依頼するときに伝える内容

自社で作業できない場合は、依頼の文面に次の内容を入れます。曖昧に頼むと、必要なレコードまで消えることがあります。

- 消す対象のレコードを、名前と種類と値で特定して伝える
- 残すレコードも明記する。とくにMXと送信ドメイン認証のTXTは残すことを書く
- 削除の前にTTLを下げてほしい旨と、下げる値を伝える
- 削除の前後で設定の一覧を記録として渡してほしいと伝える
- 指し先の外部サービスの解約は、削除の反映を確認した後に行うと伝える

この5点を書面で渡すと、作業の範囲が揃います。口頭で「使っていないものを整理してください」と頼むのは避けてください。何が使われているかの判断を依頼先に委ねることになり、業務に使っている経路が止まる可能性があります。

当社がリニューアルを担当する場合は、公開後に不要になるサブドメインの一覧を、公開前の工程で作ってお渡ししています。公開の作業が終わってからでは、どの名前が何のためにあったのかを追うのに時間がかかるためです。

リニューアル後の整理で何から手をつけるか迷っている場合は、[無料診断](/diagnostic)からご相談ください。現在のDNSの設定の棚卸しからお手伝いします。

## よくあるご質問

使わないサブドメインの閉じ方について、多い質問と回答をまとめます。判断の軸は、指し先が残っているかと、業務で使われているかの2点です。

### サブドメインを消すと、そのページの検索順位はどうなりますか

そのサブドメインのページは検索結果から消えます。アクセスを引き継ぎたい場合は、消す前に新サイトの該当ページへリダイレクトを設定します。キャンペーンのように終了したページであれば、引き継ぐ先がないため、そのまま消して問題ありません。新サイトに同じ内容のページがある場合だけ、リダイレクトを検討してください。

### サブドメインは第三者に取られることがあるのですか

サブドメインの名前自体を他人が登録することはできません。自社がドメインを持っている限り、名前の管理権は自社にあります。問題になるのは、サブドメインが指している外部サービスを解約した後にレコードだけが残る場合です。この状態では、その外部サービスで同じ名前を取得した第三者の内容が、自社のサブドメインで表示され得ます。デジタル庁のガイドラインが、カスタムドメイン用のレコードの削除を含めて対策するよう定めているのはこのためです。

### DNSレコードを消したのに、まだ表示されるのはなぜですか

キャッシュが残っているためです。削除する前に設定されていたTTLの時間までは、古い情報を参照する経路が残ります。TTLが86400であれば最大24時間です。設定を見直す前に、まずその時間が過ぎたかを確認してください。

### 使っていないサブドメインを残しておく費用はかかりますか

DNSレコードを1件増やすこと自体に費用がかかる契約は多くありません。費用の面ではなく、管理されていない名前が公開されたままになることが問題になります。指し先が生きているなら、そのサービスの利用料は発生し続けます。費用が止まっているのに名前が残っている状態が、最も注意が必要な組み合わせです。

### どのレコードが使われているか分からない場合はどうしますか

分からない値は消さずに残し、記録に書いておいてください。とくにTXTレコードは文字列だけでは用途が判別できないことが多く、消すとメールの送信や外部サービスの連携が止まることがあります。判断を急がず、ドメインを管理している事業者か制作会社に、設定した時期と目的を照会するのが確実です。社内に記録がない場合は、この照会が棚卸しの最初の作業になります。
