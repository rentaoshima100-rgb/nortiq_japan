# ホームページ外注、自社更新の引き渡し範囲

## 公開後に自社で更新するには、何を引き渡してもらいますか？

管理画面のアカウント、操作マニュアル、使い方の説明の時間、更新してよい範囲の取り決めの4つです。どれも、求めなければ見積もりに入りません。

公開後に自社で更新する前提なら、サイトが完成することと、御社が更新できる状態になることは別だと考えてください。

### 引き渡しの対象一覧

| 対象 | 具体的な中身 | 無いと起きること |
| --- | --- | --- |
| 管理画面のアカウント | 更新する担当者それぞれのログイン情報と権限 | 1つのアカウントを共有することになり、誰が何を変えたか追えません |
| 操作マニュアル | 自社が行う操作の手順書 | 画面を触りながら手探りになります |
| 使い方の説明 | 担当者が実際に操作する形での説明の時間 | 読んだだけでは手が止まります |
| 更新の範囲の取り決め | 自社で触ってよい箇所と、触らない箇所 | 触ってはいけない設定を変えて表示が崩れます |

このほか、画像の元データと、サイトで使っているフォントやロゴの利用条件も受け取っておきます。あとから差し替えるときに要ります。

補助金を使って制作する場合は、経費の扱いにも注意が必要です。小規模事業者持続化補助金の一般型通常枠では、ウェブサイト関連費の上限が補助金総額の4分の1かつ50万円とされています。マニュアルの作成や説明の費用がこの枠に入るかは、公募要領の記載と事務局の確認によります。

### 引き渡しの時期

公開日と同じ日に全部を受け取る進め方は、おすすめしません。公開当日は、切り替えの確認で手がふさがります。

現実的な順序は次のとおりです。

1. 公開の2週間前に、テスト環境のアカウントを受け取ります。所要は即日です。
2. 公開の1週間前に、テスト環境で操作の説明を受けます。この時点なら、間違えても本番に影響しません。
3. 公開日に、本番環境のアカウントを受け取ります。
4. 公開の1週間後に、実際に1回更新してみて、分からなかった点を質問します。

つまずきやすいのは、4つ目を設けない進め方です。説明を受けた直後は分かったつもりでも、実際に自分で更新すると手が止まります。質問できる期間を見積もりに含めてもらってください。

出典: 小規模事業者持続化補助金 一般型通常枠 第19回公募 公募要領 (https://www.jizokukanb.com/jizokuka_r6h/doc/kobo/r6_19/19_%E9%80%9A%E5%B8%B8%E6%9E%A0_%E5%85%AC%E5%8B%9F%E8%A6%81%E9%A0%98_%E7%AC%AC6%E7%89%88.pdf)

## 自社で更新する範囲は、どこまでにしますか？

文章と写真の差し替えまでを自社、レイアウトと機能の変更を制作会社とする分け方が扱いやすくなります。表示が崩れる操作を自社側に残さないためです。

制作時の原稿と写真の分担と同じ考え方で、公開後も誰が何を用意するかを決めます。違うのは、公開後は期限が無いぶん曖昧になりやすい点です。

### 更新の種類で分ける

更新の作業は、次の4段階に分かれます。

| 段階 | 作業の例 | 担当の目安 |
| --- | --- | --- |
| 差し替え | お知らせの追加、文章の修正、写真の入れ替え | 自社 |
| 追加 | 新しいページの作成、既存ページへの項目の追加 | 自社または制作会社 |
| 配置の変更 | ページ内の並び順、メニューの構成 | 制作会社 |
| 機能の変更 | フォームの項目、連携している外部サービス | 制作会社 |

1段目は、管理画面から行えるように作られていれば自社で回せます。2段目は、サイトの作りによって難易度が変わります。発注の段階で、新しいページを自社で作れる形にするかを決めてください。

3段目と4段目を自社に残すと、知識のない状態で触って表示が崩れます。権限の設定で、触れないようにしておく対応が確実です。

### 分け方が曖昧だと起きること

線引きが無いまま運用すると、次のどちらかに寄ります。

1. 自社で触れる範囲を広く取りすぎ、崩れた表示の修正を制作会社に有償で依頼する。
2. 不安から何も触らなくなり、お知らせの更新も外注する。結果として更新が止まります。

2つ目は実際によく起きます。更新の依頼に費用と日数がかかるため、小さな修正が後回しになり、やがて誰も更新しなくなる流れです。

防ぐには、発注の段階で「自社が月に何回、どんな更新をするか」を具体的に伝えてください。伝えた内容に合わせて、管理画面の権限と操作マニュアルの範囲が決まります。

なお、誰が原稿と写真を用意するかという分担は、制作の段階でも論点になります。公開後の更新でも、文章と画像を誰が作るかを併せて決めておくと、運用が止まりにくくなります。

## 操作マニュアルは、どの粒度で依頼しますか？

全機能の網羅ではなく、自社が実際に行う操作に絞って依頼します。網羅した冊子は、作る手間の割に読まれません。

絞るためには、御社が何を更新するかを先に挙げる必要があります。順序としては、更新する作業の一覧を出してから、マニュアルの依頼に入ります。

### 依頼するときの書き方

次のように、作業の単位で指定してください。

1. お知らせを1件追加して公開する手順。
2. 既存のページの文章を直して反映する手順。
3. 写真を差し替える手順。推奨するサイズと形式を含めます。
4. 公開前に表示を確認する手順。
5. 間違えて公開した場合に、元に戻す手順。

5つ目は忘れられがちですが、最も問い合わせの多い場面です。最初に依頼しておいてください。

各手順には、実際の画面の画像を入れてもらいます。文章だけの手順書は、管理画面の見た目と結びつかず、読みながら迷います。

所要の目安は、5項目程度で半日から1日です。つまずきやすいのは、「マニュアル一式」とだけ依頼して、制作会社の標準テンプレートが納品される場合です。御社の管理画面の実際の表示と食い違うことがあります。

### 形式と更新の扱い

形式は、御社が後から直せるものを選びます。

| 形式 | 利点 | 注意点 |
| --- | --- | --- |
| 文書ファイル (編集可能な形式) | 社内で追記できます | 版の管理が必要です |
| PDF | 配布しやすく、表示が崩れません | 自社で直せません |
| 社内のWikiや共有ドキュメント | 検索でき、追記も容易です | 作成の手間が制作会社側で増えることがあります |

編集できる形式で受け取っておくと、運用しながら気づいた点を追記できます。あわせて、納品後に管理画面の仕様が変わった場合、マニュアルの修正を誰が行うかも決めてください。保守契約に含めるか、都度の依頼にするかの2択です。

## 使い方の説明は、どのくらいの時間が要りますか？

操作の説明は、実際に自社の担当者が手を動かす形で行います。回数と参加者を見積もりに入れます。

見ているだけの説明会では、後から自分で操作できません。手を動かす形にすると、分からない箇所がその場で出てきます。

### 説明の進め方

1回で終わらせず、2回に分ける構成をおすすめします。

1. 1回目は公開の1週間前、テスト環境で行います。お知らせの追加、文章の修正、写真の差し替えを、担当者が実際に操作します。所要は1時間から2時間です。
2. 2回目は公開の1週間後、本番環境で行います。1回目から実際に操作してみて出た質問に答えます。所要は30分から1時間です。

参加者は、更新する担当者本人に加えて、その代わりを務める人も入れてください。1人だけが分かっている状態を、最初から避ける設計です。

つまずきやすいのは、公開前の忙しい時期に1回だけ詰め込む進め方です。担当者が内容を消化できないまま公開を迎え、結局誰も更新しない状態になります。

### 録画と記録を残す

説明の様子は、画面を録画して残してください。後から入った担当者が、同じ説明を受け直さずに済みます。

残すものは次の3つです。

| 残すもの | 使う場面 |
| --- | --- |
| 説明の録画 | 担当者が交代したとき、操作の流れを追えます |
| 質疑の記録 | 同じ疑問が出たときに参照できます |
| 操作中に出たエラーの記録 | 制作会社へ問い合わせるときの材料になります |

録画を見積もりに入れるかは、事前に相談してください。制作会社側で録画の準備が要る場合があります。自社の会議ツールで記録する形なら、費用はかかりません。

なお、説明を受ける担当者は、当日までに自社が更新したい内容を1つ用意しておくと身につきます。架空の文章ではなく、実際に出したいお知らせを題材にしてください。

## 見積もりには、どう書いてもらいますか？

引き渡しの項目を、費用の行として分けて書いてもらいます。制作費に含まれているのか、別に積まれているのかが分かる形です。

「一式」にまとめられていると、値引きの交渉で最初に削られるのがこの部分です。分けて書いてあれば、削る判断を御社ができます。

### 見積書での確認項目

次の行が立っているかを確認してください。

| 行の名前の例 | 含まれるべき内容 |
| --- | --- |
| 管理画面の初期設定とアカウント発行 | 担当者ごとのアカウント、権限の設定 |
| 操作マニュアルの作成 | 対象とする操作の数、画面の画像の有無、納品の形式 |
| 操作説明 (1回目) | 実施の時期、所要時間、参加人数、テスト環境か本番か |
| 操作説明 (2回目) | 公開後のフォローの実施時期 |
| 公開後の質問対応 | 対応する期間と、回数または時間の上限 |

最後の行は、期間の定めがないと後から有償になります。公開から1か月など、明確な区切りを入れてもらってください。

中小企業庁の「2021年版中小企業白書」では、中小企業のデジタルツールの導入状況に企業規模間の格差があり、特に小規模企業で導入が遅れていることが示されています。社内に経験のある人がいないほど、引き渡しの内容を書面で確認する意味が大きくなります。

### 後から追加費用になりやすいもの

当初の見積もりに入りにくいのは、次の項目です。

1. 操作マニュアルの修正。管理画面の仕様が変わったときに発生します。
2. 担当者が交代したときの再説明。最初の説明は1回分しか見ていないことが多いためです。
3. 自社が更新した結果、表示が崩れた場合の修正。更新の範囲の取り決めが曖昧だと、責任の所在から話が始まります。
4. 画像のサイズ調整。推奨サイズの指定が無いと、毎回依頼することになります。

4つ目は、マニュアルに推奨するサイズと形式を書いてもらうだけで防げます。発注の段階で伝えてください。

相見積もりを取る場合は、これらの行が揃っているかで比べます。金額だけを並べると、引き渡しを含まない見積もりが安く見えます。

出典: 中小企業庁「2021年版中小企業白書」(https://www.chusho.meti.go.jp/pamflet/hakusyo/2021/chusho/b2_2_2.html)

## 更新が続かなくなる原因は何ですか？

担当者が1人に限られ、その人が異動や退職で抜けると止まります。サイトを持っていても、動かし続ける体制が別に要ります。

総務省「令和4年通信利用動向調査報告書 (企業編)」によると、従業者数100人未満の中小企業のホームページ開設率は77.7%でした。従業者数300人以上の大企業では95%を超えています。開設の段階でも差がありますが、公開後の運用ではさらに開きます。

### 社内の体制の問題

止まる原因は、だいたい次のどれかです。

| 原因 | 起きている状態 |
| --- | --- |
| 担当者が1人 | その人の退職や異動で、ログイン情報も手順も失われます |
| 更新の優先度が低い | 本業が忙しい時期に後回しになり、戻ってこなくなります |
| 手順を思い出せない | 数か月ぶりに触ると、操作を忘れています |
| 承認に時間がかかる | 1件のお知らせに複数人の確認が要り、出す前に鮮度が落ちます |

3つ目は、更新の頻度が月1回を下回ると顕著になります。手順書と録画を残しておく意味は、ここにあります。

4つ目は、サイトの問題ではなく社内の決裁の問題です。お知らせや実績のような軽い更新については、担当者の判断で出せる範囲を決めておいてください。

### 更新の負担を減らす設計

発注の段階で手を打てることもあります。

1. 更新する箇所を、管理画面の限られた場所にまとめてもらいます。探す手間が減ります。
2. 入力する項目を絞ってもらいます。任意の項目が多いほど、毎回迷います。
3. 公開の予約ができる形にしてもらいます。まとめて作って順に出せます。
4. 担当者を2人以上登録できる形にしてもらいます。アカウントの共有を避けられます。

2つ目は特に効きます。お知らせの入力欄が日付とタイトルと本文の3つだけなら、数か月ぶりでも迷いません。

更新が止まる前提で設計するのは後ろ向きに見えますが、実際には続けられる形にするための判断です。発注時に、自社が月に何回更新するかを正直に伝えてください。

出典: 総務省「令和4年通信利用動向調査報告書 (企業編)」(https://www.soumu.go.jp/johotsusintokei/statistics/pdf/HR202200_002.pdf)

## 発注前に決めておくチェックリストは？

誰が、何を、どのくらいの頻度で更新するかを先に決め、それを引き渡しの条件に落とします。この3つが決まれば、残りは制作会社が組み立てられます。

逆に、ここが決まらないまま「更新しやすいサイトでお願いします」と伝えても、噛み合いません。

### 発注前に決める5項目

1. 更新する担当者と、その代わりを務める人の2名を決めます。所要は社内の相談で数日です。
2. 更新する内容を具体的に挙げます。お知らせ、施工事例、スタッフの紹介といった単位です。
3. 更新の頻度を見込みで出します。月1回なのか週1回なのかで、設計が変わります。
4. 自社で触る範囲と、制作会社に依頼する範囲を分けます。文章と写真までを自社とする分け方が扱いやすくなります。
5. 承認の流れを決めます。担当者の判断で出せる更新と、上長の確認が要る更新を分けます。

つまずきやすいのは3つ目です。希望を込めて「週1回」と答えると、その前提で作られた管理画面が、実際には月1回しか使われません。正直な見込みを伝えてください。

### 制作会社への伝え方

決めた内容は、提案依頼の段階で文書にして渡します。口頭で伝えると、見積もりに反映されません。

伝える文面の例は次のとおりです。

| 項目 | 伝える内容の例 |
| --- | --- |
| 更新の担当 | 広報担当1名と総務1名の計2名。どちらも制作の経験はありません |
| 更新の内容 | お知らせの追加、既存ページの文章修正、写真の差し替え |
| 更新の頻度 | お知らせは月2回程度、その他は年数回 |
| 希望する引き渡し | 操作マニュアル、公開前と公開後の説明各1回、公開から1か月の質問対応 |
| 触らない範囲 | メニューの構成、フォームの項目、外部サービスとの連携 |

この5行があれば、各社から同じ前提の見積もりが返ってきます。

公開後に自社で更新していく体制は、サイトの作り方と一緒に設計するものです。当社ではWebサイトの制作 (300,000円から) をお受けしており、更新の担当者の人数や頻度に合わせて、管理画面の構成とマニュアルの範囲を決めるところから相談を承ります。[無料診断](/diagnostic)で、御社の体制に合う引き渡しの範囲を整理します。

発注前の検討材料としては、[DXガイドブック](/guidebook)も併せてご利用ください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 操作マニュアルは必ず作ってもらえますか？

発注時に依頼すれば作成してもらえますが、依頼しなければ付かないことがあります。制作費に含まれるか別の費用かは会社によって異なるため、見積もりの行として分けて書いてもらってください。依頼するときは、御社が実際に行う操作を単位にして挙げます。お知らせの追加、文章の修正、写真の差し替え、公開前の確認、公開を取り消す手順の5つが基本です。

### 自社で更新するとデザインが崩れませんか？

触れる範囲を限れば防げます。管理画面の権限を設定し、文章と写真の差し替えだけを自社に残す形が扱いやすくなります。メニューの構成、ページ内の並び順、フォームの項目は制作会社側に残してください。写真については、推奨するサイズと形式をマニュアルに書いてもらうと、入れ替えで表示が崩れる事態を減らせます。

### 更新の説明は何回くらい受ければよいですか？

2回に分ける構成をおすすめします。1回目は公開の1週間前にテスト環境で、担当者が実際に操作する形で1時間から2時間。2回目は公開の1週間後に本番環境で、実際にやってみて出た質問に答える形で30分から1時間です。1回で詰め込むと、公開前の忙しい時期に重なり、内容が消化されないまま終わります。

### 担当者が代わったときの引き継ぎはどうしますか？

最初から2名以上を登録しておく設計が前提です。そのうえで、説明の録画、操作マニュアル、質疑の記録の3つを社内で保管してください。新しい担当者は、録画を見てからマニュアルで手順をたどる形で、再説明を受けずに始められます。アカウントは個人ごとに発行し、交代のときは前任者の権限を外して新しいアカウントを追加します。共有アカウントの使い回しは避けてください。

### 自社更新にすると保守契約は不要になりますか？

不要にはなりません。自社で行うのは内容の更新で、保守契約が対象とするのはサーバやCMS、プラグインの更新、障害時の対応、セキュリティの監視といった領域です。領域が違います。自社更新に切り替えることで、更新の作業費は減らせます。保守の範囲を見直したい場合は、何を自社で行い何を任せるかを一覧にして、契約の内容と照らしてください。
