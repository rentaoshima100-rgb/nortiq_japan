# 管理画面の二要素認証｜国の統計と発注の要件

## 管理画面の二要素認証は何を根拠に判断しますか

国が公表している不正アクセスの統計と、アクセス管理者の講ずべき措置の記述を根拠にします。手口の最多はパスワードの管理です。

「念のため入れておく」では社内の承認が通りません。公表されている数字と記述を使ってください。

### 判断に使える3つの公的な材料

材料は次の3つです。いずれも国家公安委員会・総務大臣・経済産業大臣が令和8年3月12日に公表した「不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況」にあります。

| 材料 | 内容 |
|---|---|
| 認知件数 | 令和7年の不正アクセス行為の認知件数は7,190件 |
| 手口の内訳 | 最多は「パスワードの設定・管理の甘さにつけ込んで入手」で84件 |
| 国が挙げる措置 | ワンタイムパスワード等の二要素認証や二経路認証に加え、フィッシングに耐性のある認証技術の導入 |

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

3つ目が社内の説明で効きます。国が「講ずべき措置」として挙げている内容であれば、判断の根拠として示せます。

### 確認の手順

自社の状況を確認する手順は次の3段階です。

1. **管理画面にログインできるアカウントを数える**（所要の目安: 30分）。つまずきやすい点は、制作会社や外部の担当者のアカウントです。社内の人数だけでは足りません
2. **各アカウントの認証方式を確認する**（所要の目安: 30分）。IDとパスワードだけか、追加の要素があるかを見ます
3. **退職者や契約が終わった外部担当者のアカウントが残っていないかを確認する**（所要の目安: 1時間）

3で見つかることが多いです。同じ公表資料の手口別の内訳では、「識別符号を知り得る立場にあった元従業員や知人等による犯行」が令和7年に61件、令和6年には107件あります。

出典: 同上

当社がサイトの運用を引き継ぐときは、まずこの3段階を行います。認証方式を変える前に、誰がログインできる状態なのかを確定させる必要があります。

不正アクセスがどれくらい起きているかは次のセクションで扱います。

## 不正アクセスはどれくらい起きていますか

令和7年の不正アクセス行為の認知件数は7,190件です。前年比で約34.2%の増加でした。

減っている数字ではありません。この傾向が判断の前提になります。

### 認知件数と内訳

国家公安委員会・総務大臣・経済産業大臣が令和8年3月12日に公表した資料によると、令和7年における不正アクセス行為の認知件数は7,190件で、前年 (令和6年) と比べ1,832件 (約34.2%) 増加しました。

不正アクセス後に行われた行為別の内訳は次のとおりです。

| 行為 | 件数 |
|---|---|
| インターネットバンキングでの不正送金等 | 4,747件 |
| 証券会社のインターネット取引サービスでの不正取引等 | 1,484件 |
| インターネットショッピングでの不正購入 | 228件 |

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

金銭に直結する行為が上位を占めています。

### 手口別の内訳

令和7年に検挙した不正アクセス禁止法違反の検挙件数のうち、他人の識別符号を無断で入力する「識別符号窃用型」は399件で、全体の90%以上を占めています。

その手口別の内訳と、過去5年の推移は次のとおりです。

| 手口 | 令和3年 | 令和4年 | 令和5年 | 令和6年 | 令和7年 |
|---|---|---|---|---|---|
| 識別符号窃用型（計） | 398件 | 482件 | 475件 | 511件 | 399件 |
| パスワードの設定・管理の甘さにつけ込んで入手 | 153件 | 230件 | 203件 | 174件 | 84件 |
| フィッシングサイトから入手 | 70件 | 14件 | 10件 | 41件 | 77件 |

出典: 同上

令和7年の最多は「パスワードの設定・管理の甘さにつけ込んで入手」の84件、次が「フィッシングサイトから入手」の77件、「他人から入手」が75件です。

目を引くのはフィッシングの推移です。令和5年の10件から令和7年の77件へ増えています。

ここが二要素認証の判断に効きます。パスワードの管理を強くするだけでは、フィッシングでパスワードを渡してしまった場合に止まりません。国が「フィッシングに耐性のある認証技術」を挙げている理由がここにあります。

狙われている場所は次のセクションで扱います。

## 狙われているのはどこですか

検挙された識別符号窃用型399件のうち、不正に利用されたサービスで最も多いのは社員・会員用等の専用サイトです。122件で30.6%を占めます。

銀行やECが上位だと思われがちですが、件数の上では違います。

### サービス別の内訳

令和7年に検挙した識別符号窃用型の不正アクセス行為399件について、他人の識別符号を用いて不正に利用されたサービス別の内訳は次のとおりです。

| サービス | 件数 | 割合 |
|---|---|---|
| 社員・会員用等の専用サイト | 122件 | 30.6% |
| コミュニティサイト | 92件 | 23.1% |
| インターネットショッピング | 67件 | 16.8% |
| インターネットオークション | 55件 | 13.8% |
| インターネットバンキング | 46件 | 11.5% |
| オンラインゲーム | 9件 | 2.3% |
| 電子メール | 5件 | 1.3% |
| ウェブサイト公開サービス | 2件 | 0.5% |

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

前年 (令和6年) と比べると、社員・会員用等の専用サイトは99件減少、コミュニティサイトは16件減少しています。

### 自社サイトに当てはめる

「社員・会員用等の専用サイト」は、ログインで保護された領域を指します。自社サイトでこれに当たるのは次のようなものです。

1. サイトの管理画面 (CMSのログイン画面)
2. 会員向けのページや、取引先向けの資料のダウンロードページ
3. 採用応募者のマイページ
4. 社内向けの連絡ページ

1が最も身近です。CMSのログイン画面は、URLの形が広く知られています。IDとパスワードだけで守られていれば、総当たりの対象になります。

実装で注意が必要なのは、守る対象を1つに絞らないことです。管理画面に二要素認証を入れても、会員ページのログインが素のままなら、そちら側が入口になります。

当社がこの要件を扱うときは、ログインできる画面をすべて洗い出してから方式を決めます。画面ごとに利用者が違うため、同じ方式が使えないこともあります。

二要素認証が具体的に何を組み合わせるものかは次のセクションで扱います。

## 二要素認証とは何を組み合わせるものですか

三つの要素から二つを組み合わせる認証方式です。国の資料に定義があります。

言葉の定義を押さえておくと、提案された方式が本当に二要素なのかを判断できます。

### 公文書の定義

国家公安委員会・総務大臣・経済産業大臣の公表資料の注13は、二要素認証を次のように定義しています。

> 人の認証に用いられる三つの要素（本人だけが知っていること、本人だけが所有しているもの及び本人自身の特徴）から二つの要素を組み合わせて用いる認証方式をいう。

続けて具体例が示されています。

> 本人だけが知っているＩＤ・パスワードによる認証に、本人だけが所有するスマートフォンからのアプリによる認証を追加する場合等がこれに当たる。

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）注13

3つの要素を整理すると次のようになります。

| 要素 | 具体例 |
|---|---|
| 本人だけが知っていること | IDとパスワード、秘密の質問 |
| 本人だけが所有しているもの | スマートフォンのアプリ、物理的な鍵 |
| 本人自身の特徴 | 指紋、顔 |

定義から分かるのは、同じ要素を2回使っても二要素にならないという点です。パスワードを2つ設定しても、どちらも「知っていること」です。

### 二経路認証との違い

同じ資料の注14は、二経路認証を次のように定義しています。

> インターネットバンキング等において、コンピュータ（第一経路）で振り込み等の取引データを作成した後、携帯電話端末等（第二経路）で承認を行うことで取引を成立させる認証方式をいう。

出典: 同上

違いは次のとおりです。

| 方式 | 分けるもの |
|---|---|
| 二要素認証 | 認証に使う要素の種類 |
| 二経路認証 | 操作と承認を行う機器の経路 |

サイトの管理画面で一般的に使われるのは二要素認証です。二経路認証は、取引の承認が必要な場面で使われます。

実務でハマりやすいのは、提案された方式がどちらなのか曖昧なまま進むことです。「スマホで確認します」という説明だけでは、どの要素を使っているのか分かりません。発注時には、使う要素を文字で書いてもらってください。

国がどんな措置を挙げているかは次のセクションで扱います。

## 国はどんな措置を挙げていますか

ワンタイムパスワード等の二要素認証や二経路認証に加えて、フィッシングに耐性のある認証技術の導入を挙げています。

「アクセス管理者の講ずべき措置」という項に書かれています。サイトを運営する側が対象です。

### アクセス管理者の講ずべき措置

国家公安委員会・総務大臣・経済産業大臣の公表資料の「(5) フィッシング等への対策」は次のように記載しています。

> ワンタイムパスワード等の二要素認証や二経路認証に加え、フィッシングに耐性のある認証技術（例：パスキー）の積極的な導入等により認証を強化する。

同じ項では、自社のドメインになりすましたフィッシングメールの悪用を防止する観点で、送信ドメイン認証技術 (DMARC、SPF、DKIM) を計画的に導入することも挙げられています。

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

パスキーが例として挙げられている点が実務に関わります。ワンタイムパスワードは、フィッシングサイトに入力してしまえば渡ってしまいます。パスキーはサイトごとに紐づくため、偽サイトでは使えません。

### パスワードの設定と退職者のID

同じ資料は、認証の強化以外の措置も挙げています。

「(2) パスワードの適切な設定」では次が挙げられています。

1. 使用しなければならない文字の数を可能な限り増やすなど、容易に推測されるパスワードを設定できないようにする
2. 複数のウェブサイトやアプリ等で同じID・パスワードの組合せを使用しない (パスワードを使い回さない) よう利用権者に周知する

「(3) ＩＤ・パスワードの適切な管理」では次のように記載しています。

> ＩＤ・パスワードを知り得る立場にあった元従業員、委託先業者等の者による不正アクセス行為が発生していることから、利用権者が特定電子計算機を利用する立場でなくなった場合には、アクセス管理者が当該者に割り当てていたＩＤの削除又はパスワードの変更を速やかに行うなど、ＩＤ・パスワードの適切な管理を徹底する。

出典: 同上

「委託先業者等」が明記されています。制作会社の担当者が変わったときの処理が、この措置に当たります。

同じ資料の手口別の内訳では、「識別符号を知り得る立場にあった元従業員や知人等による犯行」が令和7年に61件、令和6年には107件あります。

出典: 同上

当社がサイトの運用に関わるときは、契約の終了時にアカウントを削除する手順を先に決めます。二要素認証を入れても、残ったアカウントからは入れてしまいます。

Basic認証で足りるかは次のセクションで扱います。

## Basic認証だけでは足りませんか

足りません。RFC 7617はBasic認証を安全な認証方式とはみなしておらず、TLS等との併用が前提とされています。

公開前のステージング環境を隠す用途では使われますが、管理画面の認証の代わりにはなりません。

### RFC 7617の記述

Basic認証の仕様はRFC 7617「The 'Basic' HTTP Authentication Scheme」(2015年9月) に定められています。

| 項目 | 原文の記述 |
|---|---|
| 資格情報のエンコード | 「transmits credentials as user-id/ password pairs, encoded using Base64」 |
| 安全性の評価 | 「This scheme is not considered to be a secure method of user authentication」 |
| 通信の状態 | 「the user-id and password are passed over the network as cleartext.」 |
| 使用の前提 | 「unless used in conjunction with some external secure system such as TLS」 |
| Section 4の記述 | 「it SHOULD NOT be used (without enhancements such as HTTPS」 |

出典: IETF『RFC 7617: The 'Basic' HTTP Authentication Scheme』（2015年9月）

Base64は暗号化ではなくエンコードです。元に戻せる変換なので、通信を見られれば内容が分かります。

ここから2つのことが言えます。第1に、Basic認証をかけるならHTTPSが前提です。第2に、Basic認証は要素としては「知っていること」1つだけなので、二要素にはなりません。

### 用途を分けて考える

実務では、用途ごとに方式を分けます。

| 用途 | 向いている方式 |
|---|---|
| 公開前の環境を第三者から隠す | Basic認証、IPによる制限 |
| 管理画面へのログイン | IDとパスワードに二要素認証を追加 |
| 会員向けページへのログイン | IDとパスワードに二要素認証を追加 |

Basic認証は「誰が入ったか」を記録する仕組みを持ちません。管理画面では、誰がいつ何をしたかを後から追える必要があります。この点でも代わりになりません。

実装で注意が必要なのは、Basic認証を管理画面の前段に重ねる構成です。守りは増えますが、二要素になったわけではありません。社内の説明で「二要素認証を入れました」と言えるものではない点に注意してください。

当社がこの構成を扱うときは、用途ごとに表を作って要件に書き出します。言葉が曖昧なまま進むと、納品後に「思っていたものと違う」という話になります。

発注時にどこまで指定するかは次のセクションで扱います。

## 発注時にどこまで要件として指定しますか

対象のアカウント、認証の方式、復旧の手順、退職時の処理の4点を文書で決めてください。

二要素認証を入れること自体は短い作業です。運用で詰まるのは、入れた後の手順を決めていない場合です。

### 発注時に文書化する4項目

| 項目 | 決めること |
|---|---|
| 対象のアカウント | どの画面の、誰のアカウントに適用するか |
| 認証の方式 | 使う2つの要素を文字で書く（例: パスワードとスマートフォンのアプリ） |
| 復旧の手順 | 端末を紛失したときに誰がどう解除するか |
| 退職時の処理 | アカウントの削除を誰が、いつまでに行うか |

3が最も抜けやすい項目です。端末をなくしたときに自力でログインできなければ、サイトの更新が止まります。解除を依頼する相手と、本人確認の方法を決めておいてください。

4については、国の公表資料が「利用権者が特定電子計算機を利用する立場でなくなった場合には、アクセス管理者が当該者に割り当てていたＩＤの削除又はパスワードの変更を速やかに行う」ことを挙げています。

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

「委託先業者等」も対象に含まれています。制作会社の担当者が変わったときの処理を、契約書か運用の手順書に書いてください。

### 運用で詰まる箇所

実際に運用が止まるのは次の場面です。

1. 更新担当者が1名で、その人の端末が壊れた
2. 二要素認証の設定が担当者の個人のスマートフォンに紐づいていて、退職時に引き継げない
3. 制作会社のアカウントにも二要素認証を入れたが、誰の端末に紐づいているか分からない

2が実務で多い状況です。個人の端末に紐づける運用そのものは問題ありませんが、退職時にどうするかを決めていなければ引き継げません。

対策としては、管理者のアカウントを2つ以上用意し、別々の端末に紐づけておく形があります。1つが使えなくなっても、もう1つから解除できます。

### 認証の要件と運用の手順を同じ場で決めます

二要素認証でつまずくのは、技術ではなく運用の設計です。誰のアカウントに適用し、端末をなくしたら誰が解除するのか。この整理を社内の担当者が1人で抱えると、入れた後に止まります。

当社は代表が実装者としてサイトを作ります。ログインできる画面の洗い出しから、認証の方式、復旧の手順、退職時の処理までを同じ場で決める進め方です。

まずは[無料診断](/diagnostic)で、御社のサイトのログインできるアカウントの確認からご相談ください。発注前に決める項目は[DXガイドブック](/guidebook)にもまとめています。

### 二要素認証と二段階認証は違いますか

国の資料にある定義は二要素認証です。三つの要素 (本人だけが知っていること、本人だけが所有しているもの、本人自身の特徴) から二つを組み合わせる方式とされています。

段階を分けても同じ要素を2回使う構成であれば、二要素にはなりません。発注時には、使う2つの要素を文字で書いてもらってください。

出典: 同上（注13）

### Basic認証をかけていれば二要素認証は不要ですか

要素としては「知っていること」1つだけなので、二要素にはなりません。

出典: IETF『RFC 7617: The 'Basic' HTTP Authentication Scheme』（2015年9月）

### 二要素認証の端末をなくしたらログインできなくなりますか

復旧の手順を決めていなければ、その状態になります。発注時に、端末を紛失したときに誰がどう解除するかを決めてください。

対策としては、管理者のアカウントを2つ以上用意し、別々の端末に紐づけておく形があります。

### 退職した担当者のアカウントはどう扱いますか

速やかに削除するか、パスワードを変更してください。国の公表資料は「利用権者が特定電子計算機を利用する立場でなくなった場合には、アクセス管理者が当該者に割り当てていたＩＤの削除又はパスワードの変更を速やかに行う」ことを挙げています。

「委託先業者等」も対象です。制作会社の担当者が変わったときも同じ処理が必要です。

出典: 国家公安委員会・総務大臣・経済産業大臣『不正アクセス行為の発生状況及びアクセス制御機能に関する技術の研究開発の状況』（令和8年3月12日公表）

### フィッシングでパスワードを渡してしまった場合も防げますか

ワンタイムパスワードは、偽サイトに入力してしまえば渡ります。国の資料がパスキーを例に挙げているのは、サイトごとに紐づく仕組みのためです。

同資料の手口別の内訳では、「フィッシングサイトから入手」が令和5年の10件から令和7年の77件へ増えています。

出典: 同上
