# 受発注の電話・FAX脱却｜外注前に決める手順

## まず決めるのは「取引先ごとの受付方法をどこまで自社で吸収するか」です

最初に決めるのは方針です。取引先に運用を変えてもらうのか、届いた電話とFAXを自社側で受け止めて電子化するのか。この選択で、作るものがまったく変わります。

### 2つの方針と、それぞれで作るものが変わる理由

方針は次の2つに分かれます。

| 方針 | 取引先に求めること | 自社が作るもの |
| --- | --- | --- |
| 取引先に移ってもらう | Webの注文フォームやEDIを使ってもらう | 発注側が使う注文画面と、受注データの取り込み |
| 自社側で吸収する | 何も変えなくてよい | 届いたFAXと電話の内容を電子化して取り込む仕組み |

取引先に移ってもらう方針は、実現すれば手入力が完全になくなります。ただし相手の協力が前提です。発注側に立場の強い取引先が多い場合、この方針だけで進めると途中で止まります。

自社側で吸収する方針は、相手の運用を変えません。そのぶん、FAXのPDFから項目を読み取る処理や、電話の内容を入力する画面が必要になります。手入力が完全になくなるわけではありませんが、打ち直しの回数は減らせます。

多くの中小企業では、この2つを併用することになります。移ってくれる取引先には注文フォームを使ってもらい、変わらない取引先は自社側で吸収する、という形です。

### 取引先の一覧を作って方針を割り当てる手順

1. **取引先を注文の件数順に並べる** (所要時間の目安: 60分)。上位の数社で全体の大半を占めることがほとんどです。効果はこの上位から出ます。
2. **現在の受付方法を書き込む** (所要時間の目安: 30分)。電話、FAX、メール、先方のWeb画面、というように実態を記録します。つまずきやすい点として、同じ取引先が複数の方法を使い分けている例があります。その場合は全部書き出してください。
3. **上位の取引先から順に方針を割り当てる** (所要時間の目安: 60分)。相談できる相手には移行を打診し、難しい相手は自社側で吸収する側へ回します。
4. **割り当ての結果を集計する** (所要時間の目安: 15分)。自社側で吸収する分が何割を占めるかで、作るものの重心が決まります。

この一覧は、後で外注先に渡す資料の中核になります。件数と受付方法が書かれた表があるだけで、提案の精度が変わります。次章では、電話とFAXが残っている状況が自社に固有のものではないことを、公表資料で確認します。

## 電話とFAXが残っているのは自社だけではありません

中小企業庁は「中小企業の受発注デジタル化」のページで、次のように整理しています。中小企業の受発注業務ではいまだに電話とFAXが主流であり、電子化している場合でも発注企業ごとに異なる複数のシステムへ対応しなければならない点が課題である、という内容です。

### 電子受発注の対応率と、そこから読み取れること

同ページに示された中小企業庁「令和3年度取引条件改善状況調査」(2021年) によれば、受注側で電子受発注に対応している割合は48.5%です。半数以上はまだ対応していないことになります。

この数字の読み方には注意が必要です。48.5%は「何らかの電子受発注に対応している」という割合であり、手入力がゼロになっている割合ではありません。先方のWeb画面で注文を確認し、それを自社の基幹システムへ打ち直している場合も、対応している側に含まれます。

つまり、電子化しているつもりの会社でも、打ち直しは残っている可能性があります。自社の現在地を測るときは、対応の有無ではなく入力の回数で見てください。

### 発注企業ごとに異なるシステムという構造的な問題

受発注の電子化が進みにくい理由は、自社の意思だけでは決まらない点にあります。発注側がそれぞれ別のシステムを使っていると、受注側は取引先の数だけ画面と手順を覚えることになります。

結果として、取引先が増えるほど負担が増える形になります。FAXのほうが速い、という現場の声が出てくるのはこのためです。電子化の設計では、取引先ごとの違いをどこで吸収するかが中心の論点になります。

### 共通EDIという選択肢の位置づけ

この問題に対して、中小企業庁は「中小企業共通EDI」を策定しています。中小企業庁の説明によれば、実証事業では受注側と発注側のいずれにも約50%程度の業務時間削減効果が確認されたとされています。

ただし、共通EDIは取引先も同じ仕組みに乗ることが前提です。相手が対応していなければ効果は出ません。まずは自社の取引先が対応できるかどうかを確認し、対応できない分をどう扱うかを別に考える、という順序になります。

なお、受発注をメールやWebへ移す場合は、電子帳簿保存法の保存要件も関わってきます。この点は後の章で扱います。

## 手入力が残る場所を、受注から請求まで洗い出します

電子化の効果は、同じ情報を何回打ち直しているかで決まります。まず受注・発注・出荷・請求の各段階で、入力が発生している箇所を数えてください。ここを飛ばすと、発注した後で「思ったより楽にならなかった」という結果になります。

中小企業庁「2021年版中小企業白書」第3節では、中小企業がITシステムを導入・外注する際の課題として、システムの仕様・要件をまとめる社内人材の不足が上位に挙げられています。洗い出しは、その不足を埋めるための最初の作業でもあります。

### 1件の注文が何回入力されているかを数える手順

1. **直近の注文を1件選ぶ** (所要時間の目安: 10分)。件数の多い取引先から、典型的な注文を選びます。
2. **その注文が通った画面と帳票を順に並べる** (所要時間の目安: 60分)。受注メモ、受注入力、在庫引当、出荷指示、納品書、請求データ、という流れを実際の画面で追います。
3. **各段階で誰が何を入力したかを書く** (所要時間の目安: 30分)。同じ品番や数量を入力している箇所には印を付けます。
4. **印の数を数える** (所要時間の目安: 5分)。これが1件あたりの打ち直しの回数です。

多くの場合、3回から5回は出てきます。この数字は、外注先に効果を説明してもらうときの基準になります。

### つまずきやすい点: 入力ではなく転記を見落とす

システムへの入力だけを数えると、実態より少なく出ます。見落としやすいのは次のような作業です。

- 受注内容をホワイトボードや紙のメモに書き写す
- 出荷の準備のために一覧を表計算ソフトへ貼り直す
- 月末に請求書と受注一覧を突き合わせて手で直す

これらも同じ情報の転記です。電子化の対象に含めるかどうかは別として、まず数えておいてください。数えていないものは、仕様にも入りません。

### 既存の基幹システムとの接点を確認する

洗い出しの最後に、既存の販売管理ソフトや基幹システムへ、どの形式でデータを渡せるかを確認します。確認するのは次の3点です。

- CSVなどのファイルで受注データを取り込む機能があるか
- 取り込みに使う項目名と桁数の仕様書が手元にあるか
- 取り込み後に修正できるか、取り込んだら確定してしまうか

IPAの「システム再構築を成功に導くユーザガイド」は、既存システムとの連携要件を発注前に文書化することを推奨しています。パッケージ側の公式な連携仕様を先に確認したうえで、カスタマイズの範囲を発注仕様書に明記する、という順序です。この3点が空欄のまま発注すると、結合の段階で手戻りが起きます。

## 外注前に仕様として言語化する6つの項目

発注前に決めるのは6つです。受付方法、項目の対応表、エラー時の扱い、既存システムへの渡し方、保存要件、移行の範囲。この6つが書かれていれば、提案の内容を比較できます。

### 6項目のそれぞれで決めること

| 項目 | 決めること | 決めないとどうなるか |
| --- | --- | --- |
| 受付方法 | 注文フォーム、FAXの取り込み、メールのどれを使うか | 取引先ごとの対応が後から追加になる |
| 項目の対応表 | 取引先の呼び方と自社の項目名の対応 | 取り込んだデータが自社の品番と一致しない |
| エラー時の扱い | 読み取れない、在庫が足りない、単価が違う場合の動き | 例外のたびに人が止まり、電話に戻る |
| 既存システムへの渡し方 | ファイル形式、項目、渡すタイミング | 結合の段階で手戻りが起きる |
| 保存要件 | 受発注データをどの形で保存するか | 法令上の要件を満たせない (次章で扱います) |
| 移行の範囲 | 過去の注文履歴を移すか、当月分から始めるか | 移行の作業が見積もりに入っておらず追加になる |

### 取引先ごとの項目名の違いをどう吸収するか

最も手間がかかるのは項目の対応表です。同じ商品でも、取引先ごとに品番や呼び方が違います。単位も、ケースと本が混在します。

作り方の順序は次のとおりです。

1. **取引先の注文書を1社1枚ずつ集める** (所要時間の目安: 60分)。直近1か月分で足ります。
2. **注文書に出てくる項目を書き出す** (所要時間の目安: 取引先1社あたり20分)。品番、品名、数量、単位、納期、届け先、備考、という粒度です。
3. **自社の項目名との対応を1行ずつ書く** (所要時間の目安: 取引先1社あたり30分)。対応するものがない項目は、空欄のまま残します。
4. **空欄になった項目の扱いを決める** (所要時間の目安: 30分)。無視する、備考に入れる、新しく項目を作る、のいずれかです。

この表は、外注先が作るものではありません。自社の商品と取引を知っている人にしか作れないためです。ここを外注先に任せると、確認のやり取りが延々と続きます。

### つまずきやすい点: 例外処理を決めずに発注する

仕様が固まらない原因の多くは、通常の流れではなく例外にあります。次の場面での動きを、発注前に文章で決めてください。

- FAXの文字が読み取れなかったとき、誰にどう知らせるか
- 注文された品番が自社に存在しないとき、受け付けるか止めるか
- 数量や納期が後から電話で変更されたとき、どこに記録するか

例外の扱いが決まっていないと、システムは動くのに運用が回らない、という状態になります。結果として電話とFAXに戻ってしまいます。3つとも紙に書けていれば、仕様としては十分です。

## 電子帳簿保存法の保存要件を、発注前の要件に含めます

電子取引でやり取りしたデータの電子保存は、全事業者に義務化されています。受発注をメールやWebへ移す場合は、保存要件を満たす形で残せるかを発注前に確認してください。ここを後から足すと、作り直しになります。

### 義務化の時期と、紙保存では足りない理由

経済産業省・中小企業庁のミラサポplus「どうすればいいの？「電子帳簿保存法」」によれば、電子取引データの電子保存が全事業者に義務化されたのは2024年1月1日です。それまで設けられていた宥恕期間は、2023年12月31日で終了しています。

重要なのは、紙に印刷して保存するだけでは要件を満たさない点です。メールで受けた注文書のPDFを印刷してファイルに綴じる、という運用は、現在の要件では足りません。

ここは受発注の電子化と直結します。電話とFAXを電子化に置き換えると、取引そのものが電子取引になります。つまり、電子化すると保存要件が新たに発生する、という関係です。

### 発注仕様に書いておく保存の条件

外注先に伝える保存の条件は、次の4点にまとめられます。

| 条件 | 発注仕様への書き方の例 |
| --- | --- |
| 受け取ったデータの原本を残す | 注文のPDFや電子データを、受信時の状態のまま保存すること |
| 後から探せる | 取引年月日、取引先名、金額で検索できること |
| 改ざんを防ぐ | 保存後に内容を書き換えられない、または変更の履歴が残ること |
| 保存期間を満たす | 法定の保存期間にわたって参照できること |

つまずきやすい点は、「取り込んだら原本を消す」という設計にしてしまうことです。FAXのPDFから項目を読み取って受注データを作る場合、読み取った結果だけを残し、元のPDFを破棄する実装になりがちです。原本は残す前提で仕様に書いてください。

なお、具体的にどの保存方法が自社の要件を満たすかは、税務の取り扱いに関わります。最終的な判断は顧問の税理士に確認してください。この記事では、発注前に外注先へ伝えるべき条件の整理にとどめます。

前章の6項目のうち、保存要件はこの内容を指します。残る「既存システムへの渡し方」の確認は、外注先の選定そのものに関わるため、次章で扱います。

## 外注先の選定と、打ち直しが残る納品を避ける確認

確認すべきは1点です。自社の既存システムへデータを渡す方法を、提案の時点で具体的に示せるかどうか。ここが曖昧な提案は、受注を電子で受けたあとに人が打ち直す形で終わります。

### 提案で必ず確認する3つの質問

1. **当社の販売管理ソフトへ、どの形式でデータを渡しますか** (つまずきやすい点: 「連携可能です」という回答で止めてしまう)。ファイル形式、項目名、渡すタイミングまで答えてもらいます。
2. **項目の対応表は誰が作りますか** (つまずきやすい点: 双方が相手の作業だと思っている)。前章で作った対応表を見せて、そのまま使えるかを確認します。
3. **取り込みに失敗した注文はどう扱われますか** (つまずきやすい点: 失敗時の画面が用意されていない)。誰が気づき、どこで直すのかを確認します。

3問とも具体的に答えられる相手であれば、見積もりの前提が揃っています。逆に、1問目で言葉が濁る場合は、実際に連携した経験が少ない可能性があります。

### 段階的に導入して効果を確かめる進め方

一度に全取引先へ広げる必要はありません。次の順序で進めると、判断を戻せます。

| 段階 | 対象 | 確かめること |
| --- | --- | --- |
| 第1段階 | 件数の多い取引先1社 | 打ち直しの回数が実際に減るか |
| 第2段階 | 同じ受付方法の取引先へ拡大 | 取引先ごとの差をどこまで吸収できたか |
| 第3段階 | 残りの取引先と例外処理 | 電話に戻る場面が残っていないか |

第1段階の検証には、前章で数えた「1件あたりの打ち直しの回数」を使います。導入前と導入後で同じ数え方をすれば、効果は数字で比べられます。

### 既存システムが古い場合に先に確認すること

既存の基幹システムが古いと、そもそも外部からデータを取り込む口がないことがあります。経済産業省が2018年9月に公表した「DXレポート ITシステム「2025年の崖」の克服とDXの本格的な展開」は、老朽化・複雑化・ブラックボックス化した既存システムがデータの一元管理やシステム間連携の障壁になっている実態を示しました。同レポートでは、2025年に大企業の約6割で基幹系システムが導入から21年以上経過すると予測し、放置した場合に2025年から2030年の間に最大で年間12兆円の経済損失が生じる可能性を指摘しています。

中小企業でも構造は同じです。次の2点を先に確認してください。

- 保守を担当している会社に、外部からの取り込みが可能かを聞く
- 可能な場合、項目仕様書を出してもらえるかを確認する

仕様書が出てこない場合、連携の開発費は上振れします。その前提で見積もりを比べてください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 取引先がFAXをやめてくれない場合、電子化はあきらめるしかないのでしょうか。

あきらめる必要はありません。取引先の運用を変えずに、届いたFAXを自社側で電子化する方針があります。FAXを複合機で紙に出さず、PDFとして受信する設定に変えるだけでも、原本の保存と検索は楽になります。

そのうえで、PDFから品番と数量を読み取って受注データの下書きを作る仕組みを足すと、打ち直しの回数が減ります。読み取りの精度は100%にはならないため、人が確認する画面を必ず残してください。

### 中小企業共通EDIを使えば、取引先ごとの個別対応はなくなりますか。

取引先も同じ仕組みに乗っている場合に限られます。共通EDIは、発注企業ごとに異なるシステムへ個別対応する負担を減らすために策定されたものですが、相手が対応していなければ効果は出ません。

まず自社の主要な取引先が対応できるかを確認してください。対応できない取引先が残る前提で、その分をどう扱うかを別に決めておく必要があります。

### 受注メールをPDFで保存しておけば電子帳簿保存法の要件は満たせますか。

保存の形式だけでは判断できません。原本を受信時の状態で残すこと、取引年月日や取引先名や金額で検索できること、保存後に書き換えられないことなど、複数の条件があります。

自社の運用が要件を満たすかどうかは税務の取り扱いに関わるため、顧問の税理士に確認してください。外注先には、これらの条件を発注仕様として伝えることになります。

### 既存の販売管理ソフトを入れ替えずに、受注だけ電子化できますか。

できる場合が多くあります。受注の入口だけを新しく作り、既存ソフトへはファイルで取り込む形です。ただし、既存ソフト側に取り込みの機能と項目仕様書があることが前提になります。

保守を担当している会社に、取り込みが可能かと、項目仕様書を出してもらえるかを先に確認してください。この2点が確認できていれば、入れ替えずに進められる可能性が高くなります。

### 小さく始める場合、どの取引先から着手するのがよいですか。

注文の件数が多く、かつ注文書の様式が安定している取引先です。件数が多ければ効果が数字に出ますし、様式が安定していれば読み取りや取り込みの精度を確かめやすくなります。

逆に、注文のたびに書き方が変わる取引先や、電話での変更が多い取引先は後回しにしてください。最初の1社で例外処理に追われると、効果の検証ができないまま導入の判断が止まります。
