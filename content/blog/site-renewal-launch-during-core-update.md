# サイトリニューアル公開はずらすべき？展開中の判断基準

## まず確認すること｜Search Status Dashboardで展開中かを見る

公開日を動かすかどうかを決める前に、Google Search Status Dashboardでランキング更新が展開中かどうかを確認してください。展開中かどうかが分からないまま公開日を議論しても、判断の前提が定まりません。確認は数分で終わります。

### ダッシュボードのどこを見るか

手順は次の3つです。

1. Google Search Status Dashboardのランキング更新の履歴ページ (https://status.search.google.com/products/rGHU1u87FJnkP6W2GwMi/history) を開きます。所要時間の目安は1分です。
2. 一覧の最上段にある更新の名称と開始日を見ます。所要時間の目安は1分です。つまずきやすい点として、コアアップデートとスパムアップデートは別の更新として並ぶため、名称に「core update」とあるかどうかを確認してください。
3. その更新の所要期間の欄を見ます。所要時間の目安は1分です。

Google Search Status Dashboardのランキング更新の履歴によると、2026年11月のコアアップデートは2026年11月10日に展開を開始しました。

### 所要期間の欄が空欄のときに読み取れること

所要期間の欄に値が入っていない場合、その更新は展開が続いているか、完了がまだ反映されていない状態です。終了した更新には所要期間が記載されるため、この欄の有無が展開中かどうかの判断材料になります。

残り期間を見積もりたくなりますが、同じ履歴ページに記載された過去の所要期間には大きな幅があります。

| コアアップデート | 所要期間 |
| --- | --- |
| 2024年3月 | 45日 |
| 2024年11月 | 23日13時間 |
| 2024年12月 | 6日4時間 |
| 2025年12月 | 18日2時間 |
| 2026年3月 | 12日4時間 |
| 2026年5月 | 11日21時間 |

いずれもGoogle Search Status Dashboardのランキング更新の履歴に記載された値です。6日4時間から45日まで開きがあるため、一律で2週間と見込むと実際とずれます。展開の終わりを前提に公開日を組むのではなく、そのつど履歴ページで状態を確認する運用にしてください。

### 確認にかかる時間の目安

公開日の調整を判断するための確認は、上記の3手順で5分以内に終わります。公開の直前に1回見るのではなく、公開日を決めた時点と公開の前日の2回見ておくと、決定後に新しい更新が始まっていた場合にも気づけます。実務上つまずきやすいのは、このページが英語表記であることと、日本時間ではなく協定世界時 (UTC) の日付で記載されている点です。開始日が1日ずれて見える場合があるため、社内の記録に残すときはどちらの時刻かを併記しておくことをおすすめします。

## Googleは展開中の公開を禁じていない｜公式に書かれていることと書かれていないこと

コアアップデートの展開中にサイトを公開してはならないというGoogleの記述は確認できず、公開日の判断は自社で行うことになります。禁止されていないという事実を押さえておくと、公開を遅らせる話を社内で進めるときの前提が整います。

### 公式ドキュメントに書かれていること

公開の時期と、公開後の見方について、Googleが書いているのは次の4点です。

| 書かれていること | 出典 |
| --- | --- |
| 交通量が季節や曜日で落ち込む場合は、その落ち込む時期に移転する | Google検索セントラル URLの変更を伴うサイト移転 |
| 小中規模のサイトでは、ほとんどのページの移転がGoogle検索に反映されるまでに数週間かかる | 同上 |
| リダイレクトは可能なかぎり長く、一般的には少なくとも1年維持する | 同上 |
| コアアップデートの完了後、Search Consoleで分析を始める前に1週間以上待つ | Google検索セントラル Google検索のコアアップデートとウェブサイト |

公開日の判断に直接関わるのは1行目です。Googleが時期について述べているのは、アップデートとの重なりではなく、自社サイトの交通量が落ち込む時期を選ぶという観点です。影響を受けるユーザが少なく、Googlebotのためにサーバの余力を確保できることが理由として挙げられています。

### 書かれていないこと

展開中にサイトを公開または移転してよいかという点について、Googleが明示的に述べた記述は確認できませんでした。つまり「展開中は公開を避けるべき」という指示も、「展開中でも問題ない」という保証も、どちらも公式には存在しません。

確認できるのは、分析は完了後に1週間以上待つよう推奨されていること、移転の反映には数週間かかることの2点だけです。この2点から導けるのは、展開中に公開すると順位の変動の原因が切り分けにくくなるという事実関係までで、公開を見送るべきという結論までは公式には出ていません。詳しくは次のセクションで扱います。

### 断定された情報を見かけたときの確かめ方

「アップデート中のリニューアルは危険」といった断定を見かけた場合は、次の順で確かめてください。

1. その記述がGoogleの公式ドキュメントを出典としているかを見ます。所要時間の目安は1分です。
2. 出典とされたページを実際に開き、同じ趣旨の記述があるかを確認します。所要時間の目安は5分です。つまずきやすい点として、Google社員の発言を紹介した記事は公式ドキュメントとは扱いが異なるため、ドキュメントに同じ記載があるかを別に確認してください。
3. 見つからない場合は、社内の判断材料から外します。

公式に書かれていないことを根拠に公開日を動かすと、遅らせた理由を後から説明できなくなります。

## 展開中に公開すると起きること｜順位が動いた原因を切り分けられなくなる

展開中に公開すると、順位の変動がアップデートによるものか公開によるものか切り分けられなくなります。順位が下がっても上がっても、どちらの要因かを説明できない状態が数週間続くことになります。

### 分析を始める時期についての公式の推奨

Google検索セントラルのコアアップデートに関するドキュメントは、コアアップデートの完了後に少なくとも1週間待ってからSearch Consoleでサイトを分析することを推奨しています。比較の対象は、その1週間と、アップデートが始まる前の1週間です。展開の途中で前後の数字を比べて判断することは、公式には勧められていません。

同じドキュメントは、検索ステータスダッシュボードでアップデートの開始日と終了日を確認して記録しておくよう案内しています。また、Google検索の順位は固定的なものではないとも書かれており、アップデートとは無関係な通常の変動もあり得ることになります。

待つ期間は、展開期間に完了後の1週間を足した長さです。Google Search Status Dashboardのランキング更新の履歴によると、2026年のアップデートの所要期間は次のとおりです。

| アップデート | 開始日 | 所要期間 |
| --- | --- | --- |
| March 2026 spam update | 2026年3月24日 | 19時間30分 |
| March 2026 core update | 2026年3月27日 | 12日4時間 |
| May 2026 core update | 2026年5月21日 | 11日21時間 |
| June 2026 spam update | 2026年6月24日 | 2日1時間 |
| August 2026 spam update | 2026年8月18日 | 2日16時間 |
| September 2026 spam update | 2026年9月24日 | 13日16時間 |

同じスパムアップデートでも19時間30分で終わったものと13日16時間かかったものがあり、名称の種類から展開期間を見積もることはできません。13日16時間かかったSeptember 2026 spam updateの例に完了後の1週間を足すと、開始から3週間程度は確定的な評価ができない計算になります。

### 公開が検索に反映されるまでの期間

一方、公開の側にも時間がかかります。Google検索セントラルのURLの変更を伴うサイト移転のドキュメントによると、小中規模のサイトではほとんどのページの移転がGoogle検索に反映されるまでに数週間かかり、大規模なサイトではさらに時間がかかります。Googlebotが旧URLと新URLのすべてを少なくとも1回訪問するまで、移転は完了とみなされません。

### 2つが重なると判断がつかなくなる理由

アップデートの評価に3週間程度、公開の反映に数週間かかるため、両方が同時に進むと、観測期間がそのまま重なります。重なった期間の数字には、アップデートによる変動と、公開によるインデックスの入れ替わりが同時に含まれます。どちらが効いたかを分離する手段は、Search Consoleの画面上にはありません。

実務上つまずきやすいのは、ダッシュボードに掲載されているのが開始日と所要期間であり、終了日は自分で足して求める点です。開始時刻は掲載されていないため、終了日は日単位の目安として扱ってください。この重なりを避けられない場合に何を記録しておくかは、後のセクションで扱います。

## 公開日をずらすかどうかの判断基準3つ

ずらすかどうかは、公開の効果を計測して社内に説明する必要があるか、公開を遅らせる費用がいくらか、展開の残り期間が読めるかの3点で決めます。この3点を並べると、ほとんどの場合は結論が出ます。

| 判断基準 | ずらす方に傾く場合 | ずらさない方に傾く場合 |
| --- | --- | --- |
| 計測して説明する必要 | リニューアルの効果を数字で報告する約束がある | 公開そのものが目的で、効果の報告は求められていない |
| 公開を遅らせる費用 | 遅らせても追加費用や機会損失がほぼ無い | キャンペーンや契約の期日に紐づいている |
| 展開の残り期間 | ダッシュボードで完了が確認できている | 開始したばかりで終わりが読めない |

### 計測して説明する必要があるか

リニューアルの効果を検索流入の数字で社内に報告する予定がある場合は、ずらす価値があります。Google検索セントラルのコアアップデートに関するドキュメントは、コアアップデートの完了後に少なくとも1週間待ってからSearch Consoleで分析することを推奨しており、比較の対象はその1週間とアップデートが始まる前の1週間です。展開中に公開すると、この比較の前半にアップデートの影響が混ざります。

逆に、サイトが古くて作り直すことが目的であり、効果の報告を求められていない場合は、計測のために公開を遅らせる理由は弱くなります。

### 公開を遅らせる費用と機会損失

遅らせる側の費用も並べてください。確認する項目は次の3つです。

1. 制作会社の作業期間を延ばす場合の追加費用があるかを見積書と契約書で確認します。所要時間の目安は30分です。
2. 旧サイトのサーバやドメインの契約期日と重なっていないかを確認します。所要時間の目安は30分です。つまずきやすい点として、旧サーバの解約日を先に決めている場合、公開を遅らせると二重に費用が発生します。
3. 展示会や採用の募集開始など、公開日に紐づいた社外の予定があるかを営業部門と採用担当に確認します。所要時間の目安は1時間です。

公開を1週間遅らせる費用が、計測の精度より重いなら、ずらさない判断になります。

### 展開の残り期間は読めないという前提

3点目は、残り期間を見込んで公開日を決めることはできないという前提です。Google Search Status Dashboardのランキング更新の履歴によると、コアアップデートの所要期間は2024年12月の6日4時間から2024年3月の45日まで開きがあります。2026年11月のコアアップデートは2026年11月10日に展開を開始しています。

したがって「あと数日で終わるはずだから、それまで待つ」という組み方は成立しません。取れる形は、完了が確認できるまで公開日を未定にしておくか、完了を待たずに公開して記録を残すかの二択です。前者を選べる現場は多くないため、実際には後者の準備を整えることになります。その手順を次のセクションで扱います。

## ずらさずに公開する場合の手順｜後から切り分けられるようにする

公開日を動かせない場合は、公開前の基準データを取り、公開日とアップデートの開始日を記録しておけば、後から切り分けられます。完全には分離できませんが、何も残さずに公開するのとは結果が大きく変わります。

### 公開前に書き出しておくデータ

公開の前日までに、次の4つを手元のファイルとして保存してください。公開してしまうと旧サイトの状態では取り直せません。

1. Search Consoleの検索パフォーマンスのデータを、クエリ別とページ別の両方で書き出します。所要時間の目安は30分です。つまずきやすい点として、画面の既定の期間は直近の短い範囲になっているため、期間を手動で広げてから書き出してください。
2. 主要なページのURLの一覧と、各ページの表示回数とクリック数を書き出します。所要時間の目安は30分です。
3. アクセス解析のセッション数と流入元の内訳を書き出します。所要時間の目安は30分です。
4. 旧サイトのURLと新サイトのURLの対応表を保存します。所要時間の目安は、ページ数によりますが1時間から数時間です。

4番目は、公開後に順位を見るときの単位をそろえるために使います。Google検索セントラルのURLの変更を伴うサイト移転のドキュメントによると、Googlebotが旧URLと新URLのすべてを少なくとも1回訪問するまで移転は完了とみなされず、小中規模のサイトでもほとんどのページの反映に数週間かかります。対応表が無いと、数字が下がったページが新旧どちらの系列なのか追えなくなります。

### 記録しておく日付と記録の置き場所

残す日付は次の4つです。1行の表にして、リニューアルの資料と同じ場所に置いてください。

| 記録する項目 | 取得元 |
| --- | --- |
| 公開を実施した日付と時刻 | 自社または制作会社の作業記録 |
| 展開中だったアップデートの名称と開始日 | Google Search Status Dashboard ランキング更新の履歴 |
| そのアップデートの完了日 (後日記入) | 同上 |
| リダイレクトの設定日と解除予定日 | 自社または制作会社の作業記録 |

リダイレクトの解除予定日を書いておく理由は、Google検索セントラルのURLの変更を伴うサイト移転のドキュメントが、リダイレクトを可能なかぎり長く、一般的には少なくとも1年維持するよう記載しているためです。公開から1年未満で解除すると、そこから先の数字の変動に新しい要因が加わります。

### 比較する週の取り方

比較は、アップデートの完了が確認できてから始めます。Google検索セントラルのコアアップデートに関するドキュメントは、完了後に少なくとも1週間待ってからSearch Consoleで分析することを推奨しており、比較の対象はその1週間と、アップデートが始まる前の1週間です。

公開がアップデートの展開中に入った場合は、アップデート開始前の1週間が、同時に公開前の週にもなります。この週の数字を公開前に書き出しておけば、完了後の1週間と突き合わせられます。ただしその差には公開の影響も含まれるため、アップデート単独の影響としては読まないでください。下落に気づいた後の切り分けの手順は、当社の別の記事で扱っています。

## 公開後に順位が下がったときの対応の線引き

わずかな下落では手を加えず、大きく継続的に下落した場合にサイト全体を見直します。Google検索セントラルのコアアップデートとウェブサイトのドキュメントは、この線引きを掲載順位の例で示しています。

| 下落の程度 | Googleが例示する掲載順位の変化 | 取る対応 |
| --- | --- | --- |
| 小さい下落 | 2位から4位 | 大きな対応は通常不要 |
| 大きい下落 | 4位から29位 | サイト全体を自社で評価し直す |

公開とアップデートが重なった状況では、この線引きが特に効きます。重なっている間は原因を分離できないため、下落の幅だけを見て動くかどうかを決めるほうが、推測で手を入れるより安全です。

### 応急的な修正を避ける理由

同じドキュメントは、すでに評価されているコンテンツは変更しないよう助言し、応急的な修正を避けるよう述べています。公開直後は、リニューアルの作業そのものに不備がある可能性も残っています。ここで本文の書き換えやタイトルの一括変更を加えると、変更の層がさらに増え、何が効いたのかを永久に分からなくしてしまいます。

公開直後に手を入れてよいのは、原因が不備だと特定できるものだけです。確認する順序は次のとおりです。

1. リダイレクトが設定どおりに動いているかを、主要なURLで実際にアクセスして確かめます。所要時間の目安は1時間です。つまずきやすい点として、検証環境で設定したnoindexやrobots.txtの制限が残っていないかを必ず確認してください。
2. Search Consoleのインデックス作成の状況で、新しいURLが登録されているかを見ます。所要時間の目安は30分です。
3. 以上に問題が無ければ、内容には触れずに待ちます。

### コンテンツの削除を最後の手段とする理由

同ドキュメントでは、コンテンツの削除は最後の手段と位置づけられています。削除すると、そのページが持っていた検索からの流入と、他のページからのリンクの受け皿が同時に失われます。公開とアップデートが重なった期間の数字は、アップデートの影響が落ち着いた後に戻る場合もあるため、その判断がつく前に消すと取り返せません。

### 変化が見えるまでの期間の目安

待つ期間の目安は、アップデートの完了から1週間以上です。Google検索セントラルは、完了後に少なくとも1週間待ってから比較を始めるよう示しています。完了日は、Google Search Status Dashboardのランキング更新の履歴で開始日に所要期間を足して求めます。所要期間の実績は、2026年3月のスパムアップデートの19時間30分から、2026年9月のスパムアップデートの13日16時間、2026年2月のDiscoverのアップデートの21日17時間まで幅があります。

さらに、同ドキュメントは変化が数日で反映される場合もあるものの、Googleのシステムが学習して確認するまでに数か月かかる場合もあると説明しています。数か月たっても変化が見られない場合は、次のコアアップデートを待つことになりうるとも述べられています。公開後の報告は、1週間後の暫定値と、数か月後の確定値の2段構えにしておくと、社内の期待とずれません。

## 制作会社に依頼しておくこと｜公開日の調整と計測の分担

公開日を動かせる余地と、公開前後のデータ取得を、発注の段階で依頼範囲に入れておきます。公開の直前になってから相談すると、作業の空きが無い、追加費用がかかる、データを取る担当が決まっていないという理由で、どれも実行できなくなります。

### 発注時に伝える項目

見積もりや契約の確認時に、次の4点を書面で共有してください。

1. 公開日は検索のアップデートの状況を見て前後させる可能性があることを、工程表の前提として伝えます。所要時間の目安は、打ち合わせ1回分です。
2. 公開前に旧サイトの検索データとアクセスデータを書き出す作業を、どちらが行うかを決めます。所要時間の目安は、打ち合わせ1回分です。つまずきやすい点として、Search Consoleやアクセス解析の管理権限が制作会社側にしか無い場合は、書き出しを依頼するか、閲覧権限を自社にも付与してもらう必要があります。
3. 旧URLと新URLの対応表を、公開前の成果物として提出してもらうことを依頼範囲に含めます。
4. リダイレクトをいつまで維持するか、誰が解除の判断をするかを決めます。

4点目は、公開から相当の期間が経った後の作業になるため、担当者が交代していることが珍しくありません。契約書か議事録に残しておいてください。

### 公開日の変更を申し出る期限

公開日を後ろへずらす場合、現実的には次の2つの期限が先に来ます。

| 期限 | 確認先 |
| --- | --- |
| 制作会社の作業要員を確保している期間の変更可否と、その申し出の締切 | 制作会社の担当者 |
| 旧サーバとドメインの契約の更新日または解約日 | 自社の契約管理の担当者 |

どちらも公開日の直前には動かせません。公開日を仮で置いた段階で、「何日前までなら無償で変更できるか」を制作会社に聞いておくと、判断が必要になった日に即答できます。

### 公開後の計測を誰がやるか

計測の分担は、次の3点を決めれば足ります。

1. 公開後に数字を見る担当者を、自社と制作会社のどちらかに決めます。
2. 見る頻度と、報告する時点を決めます。公開直後の暫定の報告と、後日の確定の報告を分けておくと、重なった期間の数字を確定値として扱ってしまう事故を防げます。
3. 下落が見つかった場合に、内容へ手を入れる判断を誰が下すかを決めます。

3点目を決めずに公開すると、制作会社が独自に修正を加え、何が効いたのか分からなくなることがあります。公開後の一定期間は内容を凍結し、不備の修正だけを行う運用にしておくと、後の判断がしやすくなります。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。公開日の判断で迷ったときの確認先としてお使いください。

### コアアップデートの展開中にリニューアルを公開してはいけないのですか

禁止されていません。展開中にサイトを公開または移転してよいかという点について、Googleが明示的に述べた記述は確認できませんでした。公開日の判断は自社で行うことになります。

ただし、展開中に公開すると順位の変動の原因が切り分けにくくなります。効果を数字で社内に報告する予定がある場合は、公開日をずらすか、公開前のデータを書き出しておくかのどちらかを選んでください。

### コアアップデートの展開はどのくらいの期間で終わりますか

事前には分かりません。Google Search Status Dashboardのランキング更新の履歴に記載された所要期間は、2024年12月のコアアップデートの6日4時間から、2024年3月のコアアップデートの45日まで開きがあります。

一律で2週間と見込むと実際とずれるため、残り期間を前提にした公開日の組み方は成立しません。完了が確認できるまで公開日を未定にしておくか、完了を待たずに公開して記録を残すかの二択になります。

### いま展開中かどうかはどこで確認できますか

Google Search Status Dashboardのランキング更新の履歴ページで確認できます。一覧の最上段にある更新の名称と開始日を見て、所要期間の欄に値が入っていなければ、展開が続いているか、完了がまだ反映されていない状態です。

確認は5分程度で終わります。公開日を決めた時点と公開の前日の2回見ておくと、決定後に新しい更新が始まっていた場合にも気づけます。

### 公開後、順位を確認し始めるのはいつからがよいですか

アップデートの完了後に少なくとも1週間待ってからです。Google検索セントラルのコアアップデートとウェブサイトのドキュメントが、完了後に少なくとも1週間待ってからSearch Consoleでサイトを分析することを推奨しています。比較の対象は、その1週間と、アップデートが始まる前の1週間です。

なお、変化が数日で反映される場合もあるものの、Googleのシステムが学習して確認するまでに数か月かかる場合もあると同ドキュメントは説明しています。1週間後の数字は暫定値として扱ってください。

### 公開とコアアップデートが重なってしまった場合、原因は切り分けられますか

完全には切り分けられません。Search Consoleの画面上で、アップデートによる変動と公開によるインデックスの入れ替わりを分離する手段はありません。

それでも、公開前の検索データとアクセスデータ、旧URLと新URLの対応表、公開日とアップデートの開始日と完了日を残しておけば、どの期間に何が起きていたかは説明できます。公開してしまった後では旧サイトのデータは取り直せないため、記録が残っていない場合は、下落の幅だけを見て対応するかどうかを決めることになります。
