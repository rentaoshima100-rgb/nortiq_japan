# 外注先の生成AI利用、契約で決める4項目

## 外注先が生成AIを使うことを認めてよいですか？

一律に禁止する必要はありませんが、使う範囲と開示の仕方を決めずに任せる状態は避けます。使っているかどうかを御社が把握できないことが問題だからです。

制作や開発の現場では、下調べや文章の下書き、コードの補助に生成AIを使うことが広がっています。禁止するか認めるかの前に、何を取り決めるかを考えてください。

### 禁止が現実的でない理由

まず、自社の側の状況を押さえておきます。総務省「令和7年版情報通信白書」によると、生成AIの活用方針を策定している日本企業の割合は、2024年度の調査で49.7%でした。2023年度の調査では42.7%です。

半数近くの企業が、自社の方針を決めないまま生成AIに接している状態です。自社の方針が無いまま外注先だけに禁止を求めても、根拠を説明できません。

禁止が難しい理由は、ほかにも2つあります。

1. 利用の形が見えにくいためです。検索の代わりに使う、文章を整える、コードの誤りを探すといった使い方は、成果物の見た目に表れません。
2. 一律に禁止すると、費用と納期に跳ね返ります。使わない前提の工数で見積もりが出ます。

### 決めずに任せたときに起きること

取り決めが無い状態で困るのは、次の場面です。

| 場面 | 起きること |
| --- | --- |
| 機密情報を渡したとき | どのサービスへ入力され、どこに保管されたかを把握できません |
| 成果物を自社で改変するとき | 生成物の権利の扱いが契約に無く、判断の根拠がありません |
| 誤った内容が含まれていたとき | 確認の責任が御社と外注先のどちらにあるかが曖昧になります |
| 第三者から指摘を受けたとき | 制作の過程を説明できません |

Googleは生成AIで作ったコンテンツについて、公開前に手動でファクトチェックし見直すことが重要と記載しています。その対象には、タイトル、メタディスクリプション、構造化データ、画像の代替テキストも含まれます。確認を誰がどこまで行うかは、発注の段階で決めておく項目です。

次のセクションで、契約に落とす4項目を示します。

## 契約で決めておく項目は何ですか？

開示、入力してよい情報、成果物の権利、責任の分担の4つです。すべてを一から考える必要はなく、公的なひな型と解説が揃っています。

参照できる資料は次のとおりです。経済産業省の「AI・データの利用に関する契約ガイドライン」は平成30年6月の公表で、AI編は開発を4段階 (アセスメント、PoC、開発、追加学習) に分ける考え方を示しています。段階型を採る理由として、学習済みモデルの特徴を4点挙げています。

同省は、令和7年2月に「AIの利用・開発に関する契約チェックリスト」も公表しています。総務省と経済産業省の「AI事業者ガイドライン」第1.1版は、令和7年3月28日の公表です。著作権については、文化庁が令和6年3月15日に「AIと著作権に関する考え方について」を、令和6年7月31日に「AIと著作権に関するチェックリスト&ガイダンス」を公表しています。

### 4項目の中身

| 項目 | 決めること | 決めないと起きること |
| --- | --- | --- |
| 開示 | 生成AIを使った工程を報告してもらうか、どの粒度で報告するか | 使ったかどうかを御社が把握できません |
| 入力してよい情報 | 御社から渡した資料や個人情報を、外部のサービスへ入力してよいか | 機密情報の行き先を追えなくなります |
| 成果物の権利 | 生成物を御社が自由に使い、改変してよいか | 改変の可否を後から確認することになります |
| 責任の分担 | 誤りや第三者の権利の侵害が見つかったとき、誰が確認し誰が直すか | 問題が起きてから分担の話し合いが始まります |

4つのうち、実務で最初に効くのは開示です。使っているかが分かれば、残りの3つを必要な範囲で詰められます。

### どの書面に書くか

書く場所は2つに分かれます。

1. 継続的に取引する相手なら、基本契約書または業務委託契約書に条項として入れます。案件ごとに書き直す手間がありません。
2. 単発の発注なら、発注書と仕様書に記載します。仕様書の「制作の条件」の欄に入れる形が扱いやすくなります。

つまずきやすいのは、秘密保持契約書だけで足りると考えることです。秘密保持契約書は情報を漏らさないことを定めますが、外部のサービスへ入力する行為が該当するかは、文面によって解釈が分かれます。入力の可否は、別に明記してください。

出典: 経済産業省「AI・データの利用に関する契約ガイドライン」(https://www.meti.go.jp/policy/mono_info_service/connected_industries/sharing_and_utilization/20180615001-3.pdf)、経済産業省「AIの利用・開発に関する契約チェックリスト」(https://www.meti.go.jp/policy/mono_info_service/connected_industries/sharing_and_utilization/20250218003-ar.pdf)、総務省・経済産業省「AI事業者ガイドライン 第1.1版」(https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/pdf/20250328_1.pdf)、文化庁「AIと著作権について」(https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html)

## 外注先に渡した情報は、どこへ送られますか？

渡した情報がどのサービスへ入り、どの国のサーバに保管されるかを確認します。外注先の手元で止まっているとは限りません。

個人情報保護委員会は、令和5年6月2日に生成AIサービスの利用に関する注意喚起等を公表しています。生成AIを業務で使う際の留意点は、公的機関からも示されています。

### 保管場所を確認する手順

確認は、サービスの名前から入ります。質問の順序は次のとおりです。

1. 制作や開発のどの工程で、どのサービスを使うかを挙げてもらいます。名前とプランまで聞きます。
2. そのサービスの利用規約で、入力したデータが学習に使われるかを確認します。同じサービスでも、個人向けと法人向けでは扱いが異なることがあります。
3. データの保管される地域を確認します。設定で選べる場合は、どの設定を使っているかまで聞きます。
4. 再委託先がある場合、その先でも同じ条件が守られるかを確認します。

つまずきやすいのは、2つ目です。利用規約の変更は予告なく行われることがあり、発注時の確認が1年後も有効とは限りません。継続的な取引では、年に1度は確認し直す運用にしてください。

### 外国にある第三者への提供に当たる場合

御社が渡す資料に個人情報が含まれる場合は、扱いが変わります。外注先が国外のサービスへその情報を入力すると、外国への提供に関する手続きの検討が必要になることがあります。

判断は、渡す情報の中身と、使われるサービスの条件によって分かれます。次のどれかに当てはまる場合は、法務または専門家への確認をおすすめします。

1. 顧客の氏名や連絡先を含む資料を外注先へ渡す。
2. 社員の情報を含む名簿やアンケートの回答を渡す。
3. 問い合わせの履歴をAIチャットボットの学習や検証に使う。

対応の方向は2つです。個人情報を含む部分を伏せてから渡すか、入力してよい情報の範囲を契約で限定するかです。前者のほうが運用は単純です。

なお、総務省と経済産業省の「AI事業者ガイドライン」は第1.2版が令和8年3月31日に公表されています。参照する際は版を確認してください。

出典: 個人情報保護委員会「生成AIサービスの利用に関する注意喚起等について」(https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert/)、総務省・経済産業省「AI事業者ガイドライン (第1.2版)」(https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/pdf/20260331_1.pdf)

## 生成AIで作った成果物の権利はどうなりますか？

学習用データと学習済みモデル、生成物のそれぞれについて、誰が何をしてよいかを分けて決めます。ひとまとめに「権利は当社に帰属する」と書いても、対象が特定できません。

生成AIを使った制作では、やり取りされるものが複数あります。分けて考えると、契約に落としやすくなります。

### 参照できる公的なガイドライン

文化庁は、令和6年3月15日に「AIと著作権に関する考え方について」を公表しています。令和6年7月31日には「AIと著作権に関するチェックリスト&ガイダンス」も公表されています。著作権の論点は、まずここを確認してください。

契約の作り方については、経済産業省の「AI・データの利用に関する契約ガイドライン」が参照できます。AI編は開発を4段階 (アセスメント、PoC、開発、追加学習) に分ける考え方を示しており、段階型を採る理由として学習済みモデルの特徴を4点挙げています。

同省は令和7年2月に「AIの利用・開発に関する契約チェックリスト」を、総務省と共同で令和7年3月28日に「AI事業者ガイドライン」第1.1版を公表しています。自社で文面を起こす前に、これらの項目立てを土台にしてください。

### 契約で分けて書く対象

| 対象 | 決めること | 想定される場面 |
| --- | --- | --- |
| 御社が渡したデータ | 学習や検証に使ってよいか、使うなら終了後に削除するか | 問い合わせ履歴を渡してAIチャットボットを作る場合 |
| 学習済みモデル | 誰が保持し、他社の案件へ流用してよいか | 自社向けに追加学習したモデルがある場合 |
| 生成物 | 御社が自由に使い、改変してよいか | 文章、画像、コードを生成AIで下書きした場合 |
| 第三者の権利の確認 | 誰がどこまで確認するか | 既存の作品に似ていないかを調べる場合 |

実務で見落とされやすいのは、2番目です。御社の資料で追加学習したモデルが、外注先の資産として残り、他社の案件に使われる可能性があります。流用の可否は明記してください。

4番目については、確認の範囲を「できる限り」と書くと実質的に意味を持ちません。何を使って、どの程度調べるかを具体的に書いてください。

出典: 文化庁「AIと著作権について」(https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html)、経済産業省「AI・データの利用に関する契約ガイドライン」(https://www.meti.go.jp/policy/mono_info_service/connected_industries/sharing_and_utilization/20180615001-3.pdf)、経済産業省「AIの利用・開発に関する契約チェックリスト」(https://www.meti.go.jp/policy/mono_info_service/connected_industries/sharing_and_utilization/20250218003-ar.pdf)

## 社内の方針はどう決めますか？

自社の生成AIの活用方針を先に決め、その内容を外注の条件へ写します。自社に基準が無いまま外注先だけに求めても、線引きが揺れます。

総務省「令和7年版情報通信白書」によると、生成AIの活用方針を策定している日本企業の割合は、2024年度の調査で49.7%でした。2023年度の調査では42.7%で、1年で7.0ポイント上がっています。半数は、まだ方針を持っていません。

### 方針の策定状況

数値の読み方として、2つの見方があります。

1. 半数の企業が方針を定めているため、取引先から方針の提示を求められる場面が増えます。
2. 残りの半数は未策定のため、外注先に方針がない可能性も見込んでおく必要があります。

外注先に「御社の生成AIの利用方針を見せてください」と尋ねて、出てこないことは珍しくありません。その場合は、御社の条件を仕様書に書いて合意する形になります。

### 方針に書く最低限の項目

網羅的な文書を作る必要はありません。次の5項目があれば、外注の条件へ写せます。

| 項目 | 書く内容の例 |
| --- | --- |
| 使ってよい業務 | 下調べ、文章の下書き、コードの補助は可。顧客への回答文の自動生成は要確認 |
| 入力してはいけない情報 | 顧客の個人情報、取引先から預かった資料、未公開の価格 |
| 使ってよいサービス | 法人向けの契約をしているサービスに限る |
| 確認の義務 | 生成した内容は担当者が事実を確認してから使う |
| 記録 | どの工程で使ったかを案件ごとに残す |

作成の所要は、たたき台で半日程度です。つまずきやすいのは、網羅性を求めて作業が止まることです。使ってよい業務と入力してはいけない情報の2つだけでも、先に決めて運用を始めてください。

方針ができたら、発注の仕様書に同じ内容を転記します。社内と社外で基準が違うと、確認の手間が倍になります。

出典: 総務省「令和7年版情報通信白書」(https://www.soumu.go.jp/johotsusintokei/whitepaper/ja/r07/html/nd112220.html)

## 外注先への確認は、どの段階で行いますか？

見積もりの依頼時に質問し、発注書と契約書へ反映します。着手後の確認では遅くなります。

着手してから条件を足すと、工数の積み増しか、すでに入力済みの情報を取り戻せない状況に直面します。

### 見積もり依頼時の質問項目

依頼書に次の質問を添えると、各社の回答を並べて比較できます。

1. 制作や開発のどの工程で生成AIを使う予定がありますか。使わない工程も示してください。
2. 使用するサービスの名前と契約しているプランを教えてください。
3. 当社から提供する資料を、外部のサービスへ入力する予定はありますか。
4. 生成した内容の事実確認は、どの工程で誰が行いますか。
5. 成果物に第三者の権利を侵害するものが含まれていないかの確認は、どこまで行いますか。
6. 再委託する場合、委託先にも同じ条件を適用できますか。

所要は、先方の回答まで含めて数日です。つまずきやすいのは、質問が抽象的で「適切に管理しています」という回答しか返らない場合です。サービス名とプランを具体的に聞くと、回答の粒度が揃います。

回答を得たら、採用する条件を発注書と仕様書に書きます。見積もりの比較だけに使って契約へ落とさないと、合意した証拠が残りません。

### 納品時に確認すること

納品の段階では、次を確認します。

| 確認する対象 | 見るところ |
| --- | --- |
| 事実関係 | 数値、固有名詞、出典が実在するか。生成AIは存在しない出典を書くことがあります |
| 既存の作品との類似 | 文章やデザインが、既存のものに似ていないか |
| 開示の記録 | どの工程で生成AIを使ったかの報告が提出されているか |
| 入力の範囲 | 入力してはいけないと決めた情報が使われていないか |

1つ目は、御社の側でも確認してください。出典のURLが実在するか、数値が出典のページに書かれているかを見るだけでも、多くは防げます。

当社では記事やシステムの制作にAIを活用していますが、事実確認と出典の照合は人が行う工程として分けています。生成AIを使うかどうかより、確認の工程が設計されているかのほうが成果物の品質を左右します。

## 禁止する場合は何を書きますか？

禁止の範囲を工程の単位で書き、違反したときの扱いまで決めます。「生成AIの使用を禁止する」だけでは、何が違反に当たるかが定まりません。

扱う情報の性質によっては、禁止が妥当な場合もあります。その場合も、書き方次第で実効性が変わります。

### 工程ごとに分けて書く

全工程を一律に禁止するか、工程を限って禁止するかを選びます。

| 書き方 | 例 | 向いている場面 |
| --- | --- | --- |
| 全面的な禁止 | 本件の遂行にあたり、生成AIサービスの使用を認めない | 扱う情報の機密性が特に高い場合 |
| 入力の禁止 | 当社が提供する資料および本件で知り得た情報を、生成AIサービスへ入力することを認めない | 情報の流出だけを防ぎたい場合 |
| 成果物の禁止 | 納品物に、生成AIが出力した内容をそのまま含めることを認めない | 下調べでの利用は許容する場合 |
| 工程の限定 | 文章の下書きとコードの補助に限り認め、顧客向けの最終文面には使用しない | 費用と納期への影響を抑えたい場合 |

実務でよく合うのは、2行目の「入力の禁止」です。情報の流出という最も避けたい事態に絞りつつ、外注先の作業の自由度を残せます。全面的な禁止は、費用と納期に跳ね返りやすい書き方です。

### 確認の方法を添える

禁止の条項を書くだけでは、守られているかを確かめられません。次のどちらかを添えてください。

1. 報告を求める方法。案件の完了時に、生成AIを使用していない旨の報告書を提出してもらいます。手間は小さく、記録が残ります。
2. 違反時の扱いを決める方法。違反が判明した場合の対応 (成果物の作り直し、契約の解除、損害の扱い) を契約に書きます。

つまずきやすいのは、確認の方法を書かないまま禁止だけを定めることです。守られているかを御社が判断できないため、条項があっても運用されません。

どこまで厳しくするかは、扱う情報の性質と費用のつり合いで決まります。判断に迷う場合は、自社の方針を整理するところから進めてください。当社ではAIチャットボット構築 (100,000円から) やDXコンサル (500,000円から) をお受けしており、社内の生成AI活用方針づくりと、外注先への条件の落とし込みも併せて相談を承ります。[無料診断](/diagnostic)で、御社の案件に必要な取り決めの範囲を整理します。

生成AIの業務への取り入れ方を広く知りたい場合は、[DXガイドブック](/guidebook)も参考にしてください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 外注先に生成AIの利用を禁止することはできますか？

契約で定めること自体は可能です。ただし、全面的な禁止は費用と納期に跳ね返ります。実務で合いやすいのは、御社が提供する資料と本件で知り得た情報を生成AIサービスへ入力することを禁じる書き方です。情報の流出という最も避けたい事態に絞れます。禁止を定める場合は、守られているかを確認する方法 (完了時の報告書など) と、違反が判明したときの扱いを併せて書いてください。

### 生成AIで作った成果物に著作権はありますか？

個別の判断になるため、この記事では結論を示しません。文化庁が令和6年3月15日に「AIと著作権に関する考え方について」を、令和6年7月31日に「AIと著作権に関するチェックリスト&ガイダンス」を公表しています。まずこの2つを確認してください。契約の実務としては、著作権の有無とは別に、御社が成果物を自由に使い改変してよいかを条項として定めておく対応が現実的です。

### 外注先が使っているAIサービスを教えてもらえますか？

見積もりの依頼時に質問すれば、多くの場合は回答が得られます。聞き方が重要で、「適切に管理していますか」ではなく、サービスの名前と契約しているプランを具体的に尋ねてください。同じサービスでも、個人向けと法人向けでは入力したデータの扱いが異なることがあります。回答が得られない場合は、入力してよい情報の範囲を御社の側から指定する形で合意します。

### 機密情報を入力しないという約束はどう確認しますか？

完全に検証する方法はありません。現実的な対応は3つです。1つ目は、そもそも機密にあたる部分を伏せてから資料を渡すことです。2つ目は、案件の完了時に遵守の報告を提出してもらうことです。3つ目は、違反が判明したときの扱いを契約に書いて抑止力にすることです。秘密保持契約書だけでは、外部サービスへの入力が該当するかの解釈が分かれるため、入力の可否は別に明記してください。

### 生成AIを使ったことを記事やサイトに表示する必要はありますか？

一律の義務を定めた法令は、この記事の調査範囲では確認できませんでした。Googleは生成AIで作ったコンテンツについて、公開前に手動でファクトチェックし見直すことが重要と記載しており、その対象にタイトル、メタディスクリプション、構造化データ、画像の代替テキストを含めています。表示の有無より、確認の工程を設けることが先です。表示する場合は、自社の方針として基準を決めてから始めてください。
