# ホームページ公開前に発注側が試す動作確認

## 公開前の検収で、発注側は何から確認する？

表示ではなく動作から確認します。最初に試すのは、問い合わせフォームを送って自社に実際に届くかどうかです。

見た目の確認は後に回します。色や余白の違和感は直せば済みますが、フォームが届かない状態で公開すると、問い合わせを取りこぼしたことにすら気づけません。

### 確認の順番

次の順で進めます。

1. 問い合わせフォームを送信し、自社のメールに届くかを確認します。所要時間の目安は30分です。つまずきやすいのは、迷惑メールのフォルダに入っていて届いていないと判断してしまう点です。
2. 電話番号とメールアドレスのリンクを押し、正しい番号と宛先になっているかを確認します。目安は10分です。
3. スマートフォンの実機で全ページを開きます。目安は1時間です。
4. 文章の内容と、社名や役職の表記を確認します。目安は半日です。
5. 公開直前に外す設定が残っていないかを確認します。目安は30分です。
6. 見た目の仕上がりを確認します。

| 確認の種類 | 公開後に直せるか |
|---|---|
| フォームが届くか | 直せますが、その間の問い合わせは失われます |
| 電話番号の誤り | 直せますが、間違い電話が先に起きます |
| スマートフォンでの崩れ | 直せます |
| 文章の誤り | 直せます |
| 検索避けの設定残り | 直せますが、検索に出るまで時間がかかります |

公開後に直せないものから先に確認する、という順番だと覚えておくと迷いません。

### 自分で確認する範囲と制作会社に任せる範囲

全部を自分で見る必要はありません。分担の目安は次のとおりです。

- 発注側が見る: 文章の内容、社名や役職の表記、電話番号とメールアドレス、掲載してよい写真かどうか、フォームが届くか
- 制作会社が担う: 複数の機種とブラウザでの表示、リンク切れの一括確認、ページの表示速度、検索エンジン向けの設定

制作会社が担う範囲については、確認した結果を一覧で出してもらう形にします。「確認しました」という回答だけでは、何を確認したのかが分かりません。確認した機種とブラウザの名前、確認した日付が入った一覧があれば、後から不具合が出たときに切り分けられます。

実際に見てきた範囲では、この一覧を求めずに検収を終えているケースが多くあります。求めること自体は追加の費用がかからない場合が多いので、契約の段階で検収時に提出してもらう取り決めにしておくと確実です。

## 公開前に必ず試す動作チェックは？

フォームの送信と受信、電話番号のリンク、スマートフォンでの表示の3つです。この3つは、専門の知識がなくても発注側で確認できます。

### フォームの送信と受信を試す

送って届くかを確かめます。確認の手順は次のとおりです。

1. フォームの全項目に、テストと分かる内容を入れて送信します。所要時間の目安は5分です。
2. 自社の受信先にメールが届いたかを確認します。迷惑メールのフォルダも必ず見ます。
3. 届いたメールに、入力した内容がすべて入っているかを確認します。つまずきやすいのは、項目を追加したのにメールの本文に反映されておらず、一部が欠けている状態です。
4. 送信者に自動返信を送る設定の場合は、入力したメールアドレスにも届いたかを確認します。
5. 必須項目を空にしたまま送信し、エラーが出るかを確認します。目安は5分です。

受信先を複数人にしている場合は、全員に届いたかを確認します。1人だけ受信設定で弾かれていることがあります。

### 電話番号とリンクを押してみる

目で見て合っていても、押すと違う番号にかかることがあります。これは、表示している文字と、リンクに設定された番号が別に書かれているためです。

| 確認する箇所 | 確認の方法 |
|---|---|
| ヘッダとフッタの電話番号 | スマートフォンで押し、発信画面の番号を見ます |
| 本文中の電話番号 | 同じく押して番号を確認します |
| メールアドレス | 押してメールアプリの宛先を確認します |
| 地図のリンク | 押して表示される場所が自社かを確認します |
| 外部サイトへのリンク | 押して意図した先に飛ぶかを確認します |

発信画面が出たら、そのまま発信せずに番号だけを確認します。番号が1桁違う状態で公開すると、他社に問い合わせが流れます。

### スマートフォンの実機で見る

パソコンの画面を狭めた確認では足りません。実機で見ると、次の違いが出ます。

- 文字が小さすぎて読めない箇所がある
- 表が横にはみ出して見えない
- 問い合わせのボタンが画面の下に埋もれている
- 画像の読み込みが遅く、表示されるまで時間がかかる

実装者として見てきた範囲では、表の横はみ出しが最も多く残ります。パソコンでは収まる表が、スマートフォンでは読めない状態になります。料金表や施工の仕様を表で載せている場合は、必ず実機で確認してください。

確認する機種は、社内にあるiPhoneとAndroidの端末を1台ずつで十分です。全機種を試す必要はありません。足りない範囲は、制作会社の確認結果の一覧で補います。

## 公開の直前に外し忘れると困る設定は？

制作中に入れていた検索避けの指定と、動作確認用の設定です。外し忘れると、公開したのに検索結果に出てこない状態が続きます。

この種の不具合は、見た目には何も現れません。サイトは正しく表示され、問い合わせフォームも動きます。検索に出ないことに気づくのは、たいてい公開から数週間後です。

### 検索避けの指定を外したかの確認

制作中のサイトは、検索結果に出ないように指定した状態で作られます。公開のときにこの指定を外す必要があります。

| 指定の種類 | 外し忘れたときの症状 |
|---|---|
| ページごとの検索避けの指定 | そのページが検索結果に出ません |
| サイト全体のクロール拒否 | サイト全体が検索結果に出ません |
| 閲覧用のパスワード | 一般の訪問者がサイトを見られません |

パスワードの外し忘れは、公開直後に誰かが見て気づきます。検索避けの指定は、気づくまでに時間がかかる分、影響が長く残ります。

発注側での確認の手順は次のとおりです。

1. 公開後に、Googleで「site:自社のドメイン」と検索します。所要時間の目安は5分です。
2. 自社のページが一覧に出てくるかを確認します。公開直後は反映されていない場合があるため、数日あけて再度確認します。
3. 出てこない場合は、指定が残っている可能性があるため制作会社に確認を依頼します。つまずきやすいのは、公開直後に出ないことを指定の残りと即断してしまう点です。反映には時間がかかります。

テスト環境を検索結果に出さないための指定の方法そのものは、別記事で扱っています。ここでは、公開時に外したかの確認に絞ります。

### 計測の設定が動いているかの確認

アクセス解析の設定も、公開のタイミングで確認します。確認は次の2点です。

1. 自分でサイトを開き、計測の画面でその訪問が記録されるかを確認します。所要時間の目安は15分です。
2. 問い合わせフォームの送信を、成果として数える設定が入っているかを確認します。

計測の設定は、サイトが正しく動いていても入っていないことがあります。見た目では分からないため、検収の項目として明示的に確認しておきます。

公開の直前に外す設定と、入っているかを確認する設定は、どちらも制作会社に一覧で確認してもらう形が確実です。確認の依頼は、公開日の数日前に出しておきます。公開当日に依頼すると、作業が重なって見落としが起きます。

## 原稿と画像の確認はどこまで発注側の仕事？

文章の内容と、社名や役職の表記は発注側が確認します。制作会社は渡された原稿のとおりに作るため、内容の正しさまでは担保されません。

契約書に「原稿は発注者が支給する」と書かれている場合、内容の責任は発注側にあります。制作会社が文章を書く契約であっても、事実関係の確認は発注側でしか行えません。

### 発注側が見る項目

次の項目を確認します。

1. 社名の表記。株式会社が前につくか後につくか、英字表記の有無を確認します。所要時間の目安は10分です。
2. 代表者と担当者の氏名と役職。つまずきやすいのは、制作期間中に異動や昇任があり、原稿を渡した時点の役職が古くなっている場合です。
3. 住所と営業時間、定休日。移転の予定がある場合は公開日との前後を確認します。
4. 許認可の番号と有効期限。建設業許可や各種の登録番号は、桁数まで見ます。目安は30分です。
5. 料金や仕様の数値。見積もりの条件が付く場合は、その条件も書かれているかを確認します。
6. 実績として挙げた取引先の名称。掲載の許可を得ているかを確認します。

| 項目 | 誤りが残ったときの影響 |
|---|---|
| 社名や役職の表記 | 取引先からの信頼に関わります |
| 許認可の番号 | 法令上の表示に関わる場合があります |
| 料金や仕様の数値 | 問い合わせ後の食い違いになります |
| 取引先の名称 | 無許可の掲載は先方との関係に関わります |

許認可の表示が必要な業種では、記載の要否と内容を所管の官公庁の情報で確認してください。本記事はその要件を示すものではありません。

### 画像と地図の確認

画像は、写っているものと権利の2点を見ます。

- 自社で撮影した写真か、購入した素材かを区別できる状態にしておきます
- 従業員や取引先の人物が写っている場合は、掲載の同意を得ているかを確認します
- 現場の写真に、工事の施主が特定できる情報が写り込んでいないかを確認します
- 地図は、押して表示される場所が自社の所在地かを確認します

購入した素材を使っている場合、利用の範囲が契約で決まっています。制作会社が購入した素材をそのまま使う場合、サイトの作り直しや他の用途への転用で制約が出ることがあります。どの画像が購入素材かの一覧を、検収の時点で受け取っておくと後から困りません。

実際に見てきた範囲では、この一覧を受け取っていないために、数年後のリニューアルで使える画像が分からなくなるケースがあります。ファイル名と出所をまとめた表があれば十分です。

## 公開後に不具合が見つかったら、どこまで直してもらえる？

契約不適合責任として通知できる期間に制限があります。期間内に通知すれば修補を求められますが、何を不適合とするかは契約の記載によって変わります。

### 民法が定める期間制限

民法第637条第1項は、次のように定めています。「注文者がその不適合を知った時から1年以内にその旨を請負人に通知しないときは、注文者は、その不適合を理由として、履行の追完の請求、報酬の減額の請求、損害賠償の請求及び契約の解除をすることができない」

起算点は、引渡しの時ではありません。発注者が不適合を知った時です。改正前の民法は、瑕疵の修補や損害賠償の請求を引渡しの時から1年以内としていましたが、現行の規定では知った時から1年以内の通知に変わっています。このため、公開から1年以上が経って見つかった不具合であっても、それだけで期限が過ぎたことにはなりません。

例外もあります。民法第637条第2項は、引渡しの時において請負人がその不適合を知り、または重大な過失によって知らなかったときは、第1項の規定を適用しないと定めています。制作会社が不具合を知りながら引き渡した場合には、1年の通知期限にかかわらず請求できる余地が残ります。

| 状況 | 通知の期限 |
|---|---|
| 発注側が不具合を知った | 知った時から1年以内に通知します |
| 制作会社が知りながら引き渡した | 第1項の期限は適用されません |
| 制作会社が重大な過失で知らなかった | 同じく適用されません |

実務上は、見つけた時点で日付を記録し、速やかに書面で通知する形にしておけば足ります。期限そのものを契約で何年にするかの決め方は、別記事で扱っています。

### 脆弱性が見つかった場合の扱い

どこまでが契約不適合に当たるかは、契約でどのような水準を約したかによって決まります。IPAは2020年12月22日に「情報システム・モデル取引・契約書」第二版を公開し、見直しのポイントとして「契約不適合責任における『権利行使の期間制限』への対応」を挙げています。あわせて「情報システム開発契約のセキュリティ仕様作成のためのガイドライン」と「セキュリティ仕様策定プロセス」が同時に公開されました。

出典: IPA「情報システム・モデル取引・契約書」第二版（2020年12月22日公開）

ここから読める実務上の含みは1つです。何が不適合に当たるかを後から争わずに済ませるには、発注の段階でセキュリティ仕様を文書として定めておく必要があります。仕様に書かれていない事項は、不適合かどうかの判断が契約の解釈に委ねられます。

なお、公開後に見つかった不具合のうちどれだけが無償修理の対象になったかという統計は、確認できる公的な出典がありません。無償で直るかどうかは契約書の定めと民法第637条の適用で決まるため、個別の判断は自社の契約書の記載に即して行ってください。本記事は法令の解釈を示すものではありません。

## 公開後に不具合が出る前提で、検収時に何を記録する？

確認した項目と日付、確認できなかった項目を書き残します。公開後に見つかった不具合が検収時に確認した範囲かどうかの切り分けに使います。

### 届出と修正の実態

公開後に不具合や脆弱性が指摘されること自体は、例外的な事態ではありません。IPAが2026年7月16日に公表した「ソフトウェア等の脆弱性関連情報に関する届出状況 2026年第2四半期」によると、脆弱性の届出の累計は20,315件で、その内訳はソフトウェア製品に関するものが6,716件、ウェブサイトに関するものが13,599件です。累計の約7割がウェブサイトに関する届出になります。

同四半期の届出は合計247件で、ソフトウェア製品が182件、ウェブサイトが65件です。四半期末までの1就業日あたりの届出件数は3.80件でした。

出典: IPA「ソフトウェア等の脆弱性関連情報に関する届出状況 2026年第2四半期」（2026年7月16日公表）

修正の実態も同じ資料から読み取れます。同四半期に修正が完了したウェブサイトは18件で、累計は8,956件です。内訳はウェブアプリケーションの修正が14件で78%、ページ削除が4件で22%、運用による回避が0件で0%でした。修正が完了した18件のうち、ウェブサイト運営者へ脆弱性関連情報を通知してから90日以内に修正が完了したものは15件で83%です。

| 修正の手段 | 件数 | 割合 |
|---|---|---|
| ウェブアプリケーションの修正 | 14件 | 78% |
| ページ削除 | 4件 | 22% |
| 運用による回避 | 0件 | 0% |

注目したいのは、ページ削除が22%を占めている点です。修正の手段は作り直すだけでなく、該当のページを削除するという選択も実際に取られています。公開後に問題が出たページを一時的に下げる判断も、現実的な選択肢に入ります。

### 記録に残す項目

検収の記録は、次の形で残します。

1. 確認した日付と確認した人の氏名を書きます。所要時間の目安は10分です。
2. 確認した項目を一覧にし、結果を合否で書きます。
3. 確認できなかった項目を明示します。つまずきやすいのは、確認しなかった項目を空欄にしてしまい、後から確認済みと誤解される点です。
4. 制作会社から受け取った確認結果の一覧を添付します。
5. この記録を双方で共有し、合意した日付を残します。

| 記録する項目 | 公開後に使う場面 |
|---|---|
| 確認した日付 | 不具合を知った時の起算点の整理に使います |
| 確認した項目と結果 | 検収の範囲内かどうかの切り分けに使います |
| 確認できなかった項目 | 範囲外であることの説明に使います |
| 制作会社の確認結果 | どの機種で確認済みかの確認に使います |

この記録があると、公開後に不具合が出たときの話が早く進みます。検収で確認した項目に不具合があれば、確認時点では問題が出ていなかったという事実が残ります。確認できなかった項目であれば、そもそも検収の範囲外だったという整理になります。

形式はExcelの表でも、メールのやり取りの残しでもかまいません。日付と項目と結果の3つが揃っていることが大切です。

## 社内の誰が公開前の確認を担う？

確認する項目ごとに担当を分けます。1人で全部を見る形にすると、業務の合間に流し見になり、公開後に気づく不具合が増えます。

### 項目と担当の割り振り

項目の性質によって、見るべき人が変わります。

| 確認する項目 | 向いている担当 |
|---|---|
| 社名、役職、許認可の番号 | 総務または管理の担当者 |
| 料金と仕様の数値 | 営業または見積もりを作る担当者 |
| 実績に挙げた取引先の名称 | その取引先を担当している人 |
| フォームの送受信 | 問い合わせを受け取る担当者 |
| スマートフォンでの表示 | 誰でも確認できます |

フォームの確認は、実際に問い合わせを受け取る人に任せるのが確実です。届いたメールの形で業務が回るかどうかは、受け取る本人にしか判断できません。項目の順番や自動返信の文面に手直しが必要な場合も、この段階で分かります。

割り振りの進め方は次のとおりです。

1. 確認する項目を一覧にします。所要時間の目安は30分です。
2. 項目ごとに担当者を1名決めます。つまずきやすいのは、複数名を割り当てて誰も見ない状態になる点です。
3. 期限を決めます。公開日の1週間前を目安にします。
4. 結果を1箇所に集めます。表でもメールでもかまいません。

### 期間が取れない場合の優先順位

確認の期間が数日しか取れないこともあります。その場合は、公開後に直せないものから見ます。

1. フォームが届くか
2. 電話番号とメールアドレス
3. 社名と許認可の番号
4. 料金と仕様の数値
5. スマートフォンでの表示

上の3つまで確認できれば、致命的な取りこぼしは避けられます。残りは公開後に順次確認し、見つけた不具合を記録して通知する形にします。

ただし、期間が取れないことを理由に確認を省いた場合は、そのことを記録に残しておきます。確認していない項目に不具合が見つかったとき、検収の範囲外だったという整理ができます。

御社でこの確認を担う人が社内にいない場合、確認の項目表を用意するところから手が止まります。当社は実装者が発注の段階から同席し、検収で何を確認するかを項目表の形にしてお渡ししています。制作を他社に出している場合でも、確認の観点だけのご相談を受けています。まずは[無料診断](/diagnostic)で、公開までに決めることの整理からお話しください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 検収にはどのくらいの期間をもらえますか？

契約で定めた期間によります。期間の定めが契約書に書かれていない場合は、公開日から逆算して確保できる日数が実質的な期間になります。確認の項目を分担して進めると、本記事で挙げた範囲は1週間程度で回せます。公開日が先に決まっている案件では、制作の遅れがそのまま検収の期間を削ります。契約の段階で、検収に充てる日数を明記しておくことをおすすめします。

### 公開してからでないと確認できない項目はありますか？

あります。検索結果に自社のページが出てくるかは、公開後でなければ確認できません。制作中のサイトは検索結果に出ない指定がされているためです。公開後にGoogleで「site:自社のドメイン」と検索し、ページが一覧に出てくるかを確認します。公開直後は反映されていないことがあるため、数日あけて再度確認してください。

### 不具合を見つけたら、どう伝えればよいですか？

見つけた日付と、不具合の内容、確認した環境を書いて伝えます。環境とは、使った機種とブラウザのことです。「表示が崩れています」だけでは制作会社が再現できず、やり取りが往復します。画面を撮った画像を添えると確実です。民法第637条第1項は、不適合を知った時から1年以内に通知しない場合の制限を定めているため、見つけた日付を記録しておくことに意味があります。

### 検収で合格を出した後に見つかった不具合は自己負担ですか？

合格を出したことで、以後の不具合がすべて自己負担になるわけではありません。民法第637条第1項は、不適合を知った時から1年以内に通知すれば請求できる旨を定めており、起算点は引渡しの時ではなく知った時です。ただし、何を不適合とするかは契約の記載によって決まります。自社の契約書に、どのような水準を約したかが書かれているかを確認してください。判断に迷う場合は、弁護士など法律の専門家にご相談ください。

### 確認する時間が取れない場合、最低限どこを見ればよいですか？

フォームが届くか、電話番号とメールアドレスが正しいか、社名と許認可の番号が正しいかの3点です。この3つは、誤りがあると公開後に実害が出ます。残りの項目は公開後に順次確認し、見つけた不具合を記録して通知する形で進められます。確認を省いた項目は、省いたことを記録に残しておきます。

### 制作会社のテスト結果を見せてもらうことはできますか？

依頼すれば出してもらえる場合が多くあります。求める内容は、確認した機種とブラウザの名前、確認した日付、確認した項目と結果です。「確認しました」という回答だけでは、何を確認したのかが分かりません。契約の段階で、検収時に確認結果の一覧を提出してもらう取り決めにしておくと確実です。
