# ホームページ公開後の修正｜無償の範囲の決め方

## 無償か有償かは契約の書き方で決まる

公開後の修正が無償になるかどうかは、作業の軽さではなく契約でどう定めたかで決まります。まず着手するのは、手元の保守契約と見積書を読み直すことです。

### 「軽微」の定義は契約ごとに違う

発注側が軽微だと感じる作業と、制作会社が軽微として扱う作業は一致しません。文字の差し替え1か所でも、確認と公開の手順を含めれば作業時間は発生します。

契約書に「軽微な修正は無償」と書かれている場合、問題はその軽微の範囲が定義されていないことです。定義が無ければ、依頼のたびに個別の判断になり、断られたときに根拠を示せません。

### まず保守契約の作業範囲を読む

確認の手順は次の3つです。

1. **保守契約の作業範囲の条項を読む** (目安30分): 修正、更新、変更といった語を探します。
2. **無償の範囲が数で示されているか見る** (目安15分): 月○回、年○時間といった形の記載を探します。
3. **範囲外の単価が書かれているか見る** (目安15分): つまずきやすい点として、範囲外の作業の単価が書かれていない契約があります。その場合、依頼のたびに見積もりを待つことになります。

3つのうち1つでも空欄なら、取り決めを足す余地があります。何を決めればよいかは後のセクションで扱います。

### つまずきやすい点: 見積書に修正の回数が書かれていない

制作時の見積書には、公開までの作業が書かれていても、公開後の修正に関する記載が無いことがあります。この状態で公開すると、最初の修正依頼の時点で費用の話が始まります。

公開後の作業には、内容の変更以外にも継続して発生するものがあります。この点は3つ目のセクションで扱います。まずは、無償と有償を分けているのは作業の軽さではなく契約の記載であるという前提を押さえてください。

## 不具合の修正と内容の変更は別の扱いになる

納品物に欠陥があった場合の修正と、公開後に内容を変えたい場合の修正は、契約上の根拠が違います。前者は契約不適合責任の話で、後者は作業の依頼です。

### 契約不適合責任の期間制限と起算点

IPAが公開する「情報システム・モデル取引・契約書」の見直しのポイントには、期間制限の考え方が示されています。同資料は「期間制限の起算点を検収完了時という客観的なものとする規律は維持する」と記載し、「モデル契約上の期間制限の表記は『〇ヶ月／〇年』とする」と明記しています (出典: IPA 情報システム・モデル取引・契約書 の見直しのポイント)。

つまり、期間の長さそのものは当事者が決める前提です。自社の契約書に何か月と書かれているかを確認することが出発点になります。

同資料は、改正民法の内容として「契約不適合を知った時から1年以内にその旨の通知をすればよいことになり」と説明しています。気づいた時点で通知することが必要という建て付けです。

### 適用除外になる場合

期間制限には例外が置かれています。同資料は「契約不適合がベンダの故意・重過失に起因する場合には、客観的な起算点からの期間制限を適用除外にする」と明記しています。

この区別が実務で効くのは、公開から時間が経って見つかった不具合の扱いです。期間制限を過ぎていても、原因が重大な過失にあたる場合は別の扱いになり得ます。発注側としては、見つかった時点で原因を記録に残してください。

### つまずきやすい点: 表示崩れがどちらに当たるかは原因で変わる

判断が難しいのは、スマートフォンでの表示崩れのような症状です。納品時から崩れていたのであれば不具合の可能性があり、ブラウザの更新や追加した画像が原因であれば公開後の変更にあたります。

発注側として伝えるときは、症状と一緒に次の3点を添えてください。

1. **いつから起きているか** (目安5分): 納品時からか、ある時点からかを分けます。
2. **その前後で何を変えたか** (目安10分): 自社で記事や画像を追加したかを確認します。
3. **どの環境で起きているか** (目安10分): 端末とブラウザを記録します。つまずきやすい点として、「スマホで崩れている」だけでは原因の切り分けが進みません。

この3点があると、不具合か変更かの判断が早まります。なお、公開後に見つかった脆弱性が契約不適合にあたるかどうかについて、公的機関が示す一律の基準は確認できていません。契約書の記載と期間制限に沿って個別に判断することになります。

## 公開後も発生し続ける作業がある

脆弱性の修正と表示性能の計測は、公開して終わりではなく継続して発生する作業です。この2つは内容の変更とは別の枠で、保守の範囲に含めるかを決める対象になります。

### 脆弱性の届出と修正の実態

IPAが公表している脆弱性の届出状況によりますと、届出受付開始からの累計は20,315件で、内訳はソフトウェア製品が6,716件、ウェブサイトが13,599件です。ウェブサイトに関する届出が累計の約7割を占めています (出典: IPA 脆弱性届出状況 2026年第2四半期)。

直近の四半期の数字も公表されています。

| 項目 | 件数 |
|---|---|
| 2026年第2四半期の届出 (ソフトウェア製品) | 182件 |
| 2026年第2四半期の届出 (ウェブサイト) | 65件 |
| 同四半期の届出 合計 | 247件 |
| 同四半期に修正が完了したウェブサイト | 18件 |
| ウェブサイトの修正完了の累計 | 8,956件 |

修正の内訳は、ウェブアプリケーションの修正が14件 (78%)、ページ削除が4件 (22%)、運用で回避が0件 (0%) でした。修正の2割強はページを削除する形で終わっています。また、修正が完了した18件のうち90日以内に完了したものは15件 (83%) でした。

公開したサイトに脆弱性が見つかることは珍しい出来事ではなく、見つかった場合の対応には日数がかかるという前提で考えることになります。

### 計測と改善が続く理由

表示性能についても、公開後に見る項目があります。web.dev が公開している Web Vitals は、サイトの表示に関する指標を定めており、公開後に計測して改善する前提の仕組みです (出典: web.dev Web Vitals)。

内容を変えていなくても、画像を追加したり記事を増やしたりすれば表示の速さは変わります。この計測と改善を保守に含めるのか、別の作業として依頼するのかは、取り決めの対象です。

### 所要時間の目安: 年間の作業量の見積もりに半日

無償の範囲を決める前に、年間でどれくらいの作業が発生しそうかを見積もってください。手順は次の3つです。

1. **内容の変更の見込みを数える** (目安2時間): 新着情報の追加、価格の改定、担当者の交代といった予定を並べます。
2. **継続して発生する作業を分ける** (目安1時間): 脆弱性の対応と表示性能の計測を、内容の変更とは別の枠に置きます。
3. **どちらを保守に含めるかを決める** (目安1時間): つまずきやすい点として、脆弱性の対応を回数制の無償枠に入れると、1回で枠を使い切ることがあります。

## 無償の範囲を決める5項目

取り決めるのは、対象の作業、回数または時間、依頼の方法、対応までの日数、範囲外の単価の5つです。この5つが埋まれば、依頼のたびに費用の相談をする必要がなくなります。

### 5項目の決め方

| 決める項目 | 具体例 | 決めておかないと起きること |
|---|---|---|
| 対象の作業 | 既存ページの文字の差し替え、写真の差し替え、新着情報の追加 | 依頼のたびに対象かどうかの判断が必要になる |
| 回数または時間 | 月2回まで、または月1時間まで | 枠の上限が分からず、際限なく頼むか遠慮するかに偏る |
| 依頼の方法 | 指定のメールアドレス宛、または管理画面のフォーム | 担当者個人への連絡になり、不在時に止まる |
| 対応までの日数 | 依頼から3営業日以内に公開 | 急ぎの依頼のたびに交渉が発生する |
| 範囲外の単価 | 1時間あたりの単価、または作業ごとの金額 | 範囲外の依頼で毎回見積もりを待つことになる |

具体例は書き方の例で、金額や回数の相場を示すものではありません。保守契約の範囲や月額費用の相場について、公的な統計は確認できていません。自社で必要な作業量から決めてください。

対象の作業を決めるときは、含めるものを列挙する形にしてください。除外するものを列挙する形にすると、書かれていない作業の扱いが毎回争点になります。

### 回数制と時間制の違い

無償枠の数え方には2通りあります。

- **回数制**: 月2回までといった形。1回の作業量が小さい場合は管理が簡単ですが、1回に大きな依頼を入れられると制作会社側の負担が偏ります。
- **時間制**: 月1時間までといった形。作業量に応じて数えられますが、何分かかったかの記録と共有が必要になります。

文字や写真の差し替えが中心であれば回数制、ページの追加や構成の変更が混ざるなら時間制が扱いやすくなります。どちらにするかは、前のセクションで見積もった年間の作業量から決めてください。

### つまずきやすい点: 回数だけ決めて作業の種類を決めない

よくあるのは、月2回までという回数だけを決めて、何を1回とするかを決めないことです。1ページの文字修正と、新しいページの追加が同じ1回として扱われるのかが分かりません。

手順としては、対象の作業を先に列挙し、その後に回数または時間を決めてください。順番を逆にすると、枠の意味が定まりません。

## 補助金を使った場合の注意点

補助金で制作した場合、公開後の年額費用のうち補助の対象になる範囲は限られます。無償枠の取り決めとあわせて、補助の対象外になる部分を把握しておく必要があります。

### 補助対象になる範囲

デジタル化・AI導入補助金2026 (旧IT導入補助金) の通常枠では、補助対象経費がソフトウェア購入費、クラウド利用費、導入関連費と定められています。このうちクラウド利用費として補助に乗るのは最大2年分までです (出典: デジタル化・AI導入補助金2026 公募要領 通常枠)。

| 項目 | 内容 |
|---|---|
| 補助対象経費 | ソフトウェア購入費、クラウド利用費、導入関連費 |
| クラウド利用費の対象期間 (通常枠) | 最大2年分 |
| 通常枠の補助額 | 350万円以下 |
| 補助率 (中小企業・小規模事業者等) | 2/3以内 |

補助額と補助率は、中小企業庁が公表した事業概要にもとづきます (出典: 中小企業庁「中小企業デジタル化・AI導入支援事業 デジタル化・AI導入補助金2026の概要」令和8年4月)。枠によって扱いは異なり、複数者連携枠の消費動向等分析経費ではクラウド利用料が1年分に限られます。

ここから分かるのは、年額で払い続ける利用料のうち3年目以降は自社の負担として見込む必要があるということです。修正の無償枠を保守費の中に設計する場合、その保守費が補助の対象期間を過ぎた後も続く前提で金額を考えてください。

### 実績報告との関係

補助金を使った場合、対象経費と対象外の経費を分けて整理する必要があります。軽微な修正の対応が保守費に含まれている場合、その保守費が補助対象のクラウド利用費にあたるのか、対象外の作業費にあたるのかで扱いが変わります。

制作会社に見積もりを依頼する段階で、補助の対象になる項目と対象外の項目を分けて記載してもらってください。1行にまとめた見積書では、後から分けられません。

### つまずきやすい点: 補助対象外の作業を見積もりに混ぜない

避けたいのは、修正対応の費用を補助対象の項目に混ぜて記載することです。実績報告の段階で説明できなくなります。

手順としては次の2つです。

1. **見積書を項目ごとに分けてもらう** (目安30分): 初期構築、クラウド利用費、保守および修正対応を別の行にします。
2. **公募要領の対象経費と突き合わせる** (目安1時間): つまずきやすい点として、対象経費の定義は枠ごとに違います。自社が申請する枠の公募要領で確認してください。

補助の対象範囲そのものの詳しい判断は、保守費と補助金の関係を扱った記事を参照してください。

## 既に公開している場合の決め方

すでに公開している場合は、直近1年の依頼内容を洗い出してから取り決めを作ります。実際に何を何回頼んだかが分かれば、適切な枠の大きさが決まります。

### 依頼の記録から回数を決める

手順は次の3つです。

1. **制作会社とのやり取りを1年分さかのぼる** (目安1時間): メールの送信履歴から修正依頼を拾います。
2. **依頼を種類ごとに分ける** (目安30分): 文字の差し替え、写真の差し替え、ページの追加、不具合の指摘に分類します。
3. **月あたりの件数を出す** (目安30分): つまずきやすい点として、繁忙期に偏っている場合は平均だけで決めないでください。月ごとの差が大きいなら、年間の総枠で決める方が合います。

洗い出すと、実際の依頼が思っていたより少ないことも、特定の種類に偏っていることも分かります。偏りが分かれば、その種類を無償の対象に含めるかどうかの判断ができます。

あわせて、不具合の指摘として出していた依頼が混ざっていないかを確認してください。不具合の修正は前のセクションで触れたとおり契約不適合責任の話で、無償枠の消費とは別の扱いになります。

### 制作会社との協議の進め方

取り決めを足す協議は、既存の契約条件を変える話になります。進め方としては次の順序が現実的です。

1. **洗い出した実績を共有する** (目安30分): 1年間の依頼の種類と件数を先に見せます。
2. **5項目の案を自社から出す** (目安1時間): 対象の作業、回数または時間、依頼の方法、対応までの日数、範囲外の単価を埋めた案を作ります。
3. **金額の増減を含めて協議する** (目安打ち合わせ1回から2回): つまずきやすい点として、無償枠を広げる場合は月額が上がる可能性があります。枠と金額をセットで話してください。

実績を先に共有する理由は、議論の前提を揃えるためです。実績を示さずに枠の数字だけを提示すると、根拠のない要求として扱われます。

### 所要時間の目安: 洗い出しに2時間

依頼の洗い出しは、2時間程度で形になります。協議の時間は含みません。

公開後の修正は、1件ずつ見れば小さな作業です。ただ、取り決めが無いまま続けると、頼みにくさや費用の不透明さが積み重なります。2時間の洗い出しで、その状態を解消する材料が揃います。年間費用の内訳と相場については、公開後の維持費を扱った記事を参照してください。

## よくあるご質問

この記事に関して多い質問と回答をまとめます。

### 文字の修正くらいなら無料でやってもらえますか

契約の記載によります。無償か有償かは作業の軽さではなく、保守契約や見積書でどう定めたかで決まります。「軽微な修正は無償」と書かれていても、軽微の範囲が定義されていなければ、依頼のたびに個別の判断になります。まず手元の契約で、対象の作業と回数または時間、範囲外の単価が書かれているかを確認してください。

### 公開後に見つかった表示崩れは無償で直してもらえますか

原因によって扱いが変わります。納品時から崩れていたのであれば契約不適合の可能性があり、ブラウザの更新や自社で追加した画像が原因であれば公開後の変更にあたります。伝えるときは、いつから起きているか、その前後で何を変えたか、どの端末とブラウザで起きているかの3点を添えてください。

### 保守契約に修正は何回まで含めるのが一般的ですか

保守契約の範囲や月額費用の相場について、公的な統計は確認できていません。一般的な回数を示すのではなく、自社の実績から決める方が確実です。すでに公開している場合は、直近1年の依頼をメールの履歴から拾い、種類ごとに分けて月あたりの件数を出してください。

### 修正の依頼はメールでよいですか

依頼の方法も取り決めの対象です。担当者個人のメールアドレス宛にすると、その人が不在のときに止まります。指定のアドレスか管理画面のフォームなど、窓口を決めておいてください。あわせて、依頼から公開までの日数も決めておくと、急ぎの依頼のたびに交渉する必要がなくなります。

### 補助金で作ったホームページの修正費用も補助の対象になりますか

枠と経費の区分によります。デジタル化・AI導入補助金2026の通常枠では、補助対象経費はソフトウェア購入費、クラウド利用費、導入関連費で、クラウド利用費として補助に乗るのは最大2年分までです。修正対応の費用がどの区分にあたるかは公募要領で確認が必要です。見積書は初期構築、クラウド利用費、保守と修正対応を別の行に分けてもらってください。
