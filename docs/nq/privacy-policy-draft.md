## 3. 改定案の本文

現行の文体（「当社」、です・ます、半角かっこの前後に空白）に合わせてある。

### 8. Cookie およびアクセス解析ツールの利用

> 当社サイトでは、サービス向上のため Cookie を使用します。また、サイトの利用状況を把握するために、Google LLC が提供するアクセス解析ツール「Google アナリティクス 4」を利用しています。Google アナリティクス 4 は Cookie を使用して、閲覧したページ、滞在時間、流入元、端末やブラウザの種類などの情報を収集します。これらの情報に、氏名やメールアドレスなど個人を特定する情報は含まれません。収集された情報は Google 社のプライバシーポリシーに基づいて管理されます。ブラウザの設定で Cookie の受け入れを拒否すること、および Google 社が提供する「Google アナリティクス オプトアウト アドオン」により収集を無効にすることが可能です。

### 9. ブラウザの保存領域 (Web Storage) の利用

> 当社サイトでは、ご案内するページを選ぶために、お使いのブラウザの保存領域 (Web Storage) に次の情報を保存します。(1) 1回のご訪問の間だけ保持する情報 (sessionStorage): ご訪問ごとに無作為に生成する識別子、そのご訪問で閲覧した当社サイト内のページとおおよその閲覧の深さ、表示したご案内とその操作の記録。これらはブラウザのタブを閉じると消去されます。(2) 再訪であることを示す目印 (localStorage): 以前に当社サイトを訪れたことがあるかどうかを示す値のみで、識別子は保存しません。いずれの情報からも、当社が特定の個人を識別することはできません。ブラウザの設定でサイトデータの保存を無効にした場合、この機能は動作せず、標準の内容が表示されます。

### 10. 閲覧行動の要約を用いたページ表示の最適化

> 当社サイトでは、閲覧行動の要約をもとに、記事やサービスページの中でご案内するページやボタンの文言を選んで表示することがあります。要約に含まれるのは、閲覧したページの題名と種類、どの程度読み進めたか、流入元の種類 (検索・SNS など)、初回のご訪問か再訪か、端末の種類 (スマートフォン・PC) です。表示される文章はすべて当社があらかじめ用意し確認したもので、AI がその場で文章を作成することはありません。この要約の分類には、米国の事業者が提供する AI の API を利用しており、要約は同事業者のサーバーに送信されます。送信するのは上記の要約のみで、氏名、メールアドレス、IP アドレス、お問い合わせフォームの入力内容など、個人を特定できる情報は送信しません。分類の結果と、ご案内の表示・クリックの記録は、個人を特定しない形で保存し、サイトの改善と統計分析に利用します。記録は 13ヶ月を過ぎた時点で削除し、以後は月ごとの集計値のみを保持します。本機能は、採用選考その他の個人に対する審査や評価には利用しません。

## 6. 専門家に確認してほしい点

1. **個人情報保護法**: 送信・保存する情報（無作為の識別子と閲覧行動の要約）が、当社にとって個人情報・個人関連情報のどちらに当たるか。
   資料請求フォーム（サービスLP `/service/*` のフォームを含む）の送信の事実を同じ識別子で記録する点（上の表「フォームとの関係」）が、この整理に影響しないか。
2. **外国にある第三者への提供**: AI の API の事業者に送る要約が個人データに当たらない前提で、同法28条の対応が不要と整理してよいか。
   本文の「米国の事業者」という書き方で足りるか、事業者名を明記するべきか。
3. **電気通信事業法の外部送信規律**: 当社サイト（自社の事業を紹介するコーポレートサイトとオウンドメディア）が対象に当たるか。
   当たる場合、GA4 と AI の API への送信について、送信先・送信される情報・利用目的の公表の形がこの本文で足りるか。
4. **同意の要否**: Web Storage への保存と表示の最適化について、現行の「告知のみ」で足りるか。同意の取得（バナーなど）が必要か。
5. **EU・英国など国外からの訪問者**: 当社サイトは日本語で国内向けだが、GDPR / ePrivacy の適用を考慮する必要があるか。
6. **AI の事業者の規約**: 入力データの保存期間、モデルの学習への利用の有無、再委託先。本文の「個人を特定できる情報は送信しません」と矛盾しないか。
7. **クライアントサイトへの横展開**（設計書13章フェーズ5）: 同じ仕組みを顧客の採用サイトに入れるとき、ポリシーのひな形と、
   学習済みの重みを引き継ぐことの契約上の書き方（`open-decisions.md` A8）。設計書は「選考や審査への利用は対象外」としており、本文 10 の最後の一文がそれに当たる。
8. **判定ごとの識別子の書き方**: 本文 9 が識別子として挙げるのは「ご訪問ごとに無作為に生成する識別子」だけだが、実装ではこのほかに、
   ご案内の判定1回ごとに当社サーバが発行する識別子（発行時刻と乱数から作る。5章の表「判定ごとの識別子」）が sessionStorage に入り、
   当社サーバのイベント記録と GA4 のイベントにも載る。本文 9 の「表示したご案内とその操作の記録」を
   「表示したご案内とその操作の記録 (ご案内ごとに当社サーバーが発行する識別子を含みます)」のように明記するべきか。
   GA4 の記録と当社の判定ログが同じ識別子を持つことが、1 と 3 の整理に影響しないか。
9. **本文 10 が挙げる「要約」の範囲**: 実装が AI の API に送る状態（5章の表「当社サーバ → AI の API に送るもの」）には、本文 10 が列挙する項目のほかに、
   着地ページの分類タグ（`topic` / `industry`、記事の対象読者）と、**そのご訪問で表示したが押されなかったご案内の ID**（`見送った提案`）が入る。
   前者は「ページの種類」の言い換えとして読めるが、後者は本文 10 に無い。「表示したご案内のうちご覧にならなかったものの種別」のように足すべきか。
