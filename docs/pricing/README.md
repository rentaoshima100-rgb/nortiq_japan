# 料金の管理（1か所管理と検査）

サイトに出る料金・期間・税の表記は、`content-data.jsx` の `NORTIQ_PRICING` **1か所**が出典です。
2026-09 の料金統一の前は、/pricing・各サービスページ・トップ・meta・静的LP・data/*.json・記事が
それぞれ数字を手書きしていて、同じプランの金額や期間の書き方がページごとに食い違っていました。

- 未決事項と、外部で作り直す PDF の依頼リスト: [open-items.md](open-items.md)
- 検査スクリプト: リポジトリ直下の `pricing-check.js`（`npm run pricing:check`）

最終更新: 2026-09-21

---

## 1. 出典は `NORTIQ_PRICING` の1か所

`content-data.jsx` の `NORTIQ_STATS` の直下に、目印のコメントで囲んで置いてあります。

```
// NORTIQ_PRICING:BEGIN
const NORTIQ_PRICING = { ... };
// NORTIQ_PRICING:END

// NORTIQ_PRICING_HELPERS:BEGIN
const priceFrom = ...      // 30 -> "30万円〜"
...
// NORTIQ_PRICING_HELPERS:END
```

| キー | 中身 |
|---|---|
| `tax` / `taxNote` | 「税別」／「表示価格はすべて税別です」 |
| `consult` | 初回相談（無料・オンライン・30〜60分）、返信（営業日24時間以内） |
| `web` `chatbot` `dx` | 3プランの開始価格（万円・税別）、期間、ページ数、サポート月数、tagline、features |
| `maintenance` | 保守・運用の月額の開始価格と、プラン別の対応件数 |
| `solutions` | 業種ソリューション5本の初期費用レンジ・月額レンジ・導入期間 |
| `lps` | 静的LP2本の料金表の**写し**（LP は参照できないので、LP を変えたらここも同時に直す） |

決まりごと（詳しくは `content-data.jsx` のコメント）:

- 目印の行には他の文字を足さない。2つのブロックの中は JSX も `window` も使わない純粋な JS にする
  （`pricing-check.js` が目印の間を切り出して `vm` で評価するため）。
- 金額の単位は万円・税別。`min` は「〜」の付く開始価格、`max` は目安レンジの上限。
- `kind: 'initial'` は初期費用、`'monthly'` は月額。カードでは「初期費用」「月額」のラベルで区別する。
- プラン別の月額が決まっていないもの（AIチャットボット・保守）は、サービス全体の `monthlyMin` だけを持つ。
  **決まっていない数字を作らない。**

### 参照できるもの・できないもの

| 種類 | 参照 | 食い違いの防ぎ方 |
|---|---|---|
| JSX のページ（top-page / service-pages / info-pages / extra-pages / app.jsx の meta） | できる | `price*` ヘルパー経由で描画する。金額を文字列で直書きしない（検査 c が落とす） |
| `components.jsx` | 関数の中（描画時）だけできる | 読み込み順が `content-data.jsx` より先なので、モジュール直下では未定義になる |
| 静的LP `lp/service/*/index.html` | できない | 検査 b |
| `data/blocks.json` `data/catalog-pages.json` | できない | 検査 a |
| 記事 `content/blog/*.md` | できない | 検査 d（警告のみ） |
| PDF（`assets/Nortiq_Service_Deck.pdf`、`assets/pdf/*.pdf`） | できない | 検査の対象外。作り直しを [open-items.md](open-items.md) の依頼リストで管理 |
| `prerendered/` `dist/` | — | 生成物。CI が再生成するので手で直さない・検査もしない |

## 2. 料金を変える手順

1. `git fetch` して最新に合わせる（このリポジトリはリモートが頻繁に進む）。
2. `content-data.jsx` の `NORTIQ_PRICING` を直す。JSX のページ（/pricing・/web・/chatbot・/dx・/support・
   トップ・業種ページ・meta）は、これだけで全部変わる。
3. `npm run pricing:check` を実行する。手書きの写しが古いままの場所が `file:行` で出る。
4. 指摘された LP・`data/*.json`・記事を直す。
   - 静的LPの料金を変えるときは、**LP の料金表と JSON-LD Offer の `price`** と **`NORTIQ_PRICING.lps`** を同時に直す。
   - `data/blocks.json` は字数上限がある（title 28字・body 60字など。ファイル先頭の `_comment`）。
     直したら `docs/nq/copy-sources.md` の照合表も合わせる。
5. `npm run pricing:check` が「失敗 0 件」になるまで 3〜4 を繰り返す。警告は内容を読んで判断する。
6. PDF に同じ数字が載っている場合は、[open-items.md](open-items.md) の依頼リストに足す（リポジトリでは直せない）。
7. `prerendered/` はローカルで作り直さない（CI が main への push で再生成する）。

新しいサービスや LP を足すときは、`NORTIQ_PRICING` にデータを足し、`pricing-check.js` の `buildSets()`
（リンク先ごとの許可集合）にそのリンク先を足します。`lps` は `href` で LP のフォルダと対応づけているので、
`lp/service/<名前>/` を足して `lps.<key>.href = '/service/<名前>'` を書けば検査に乗ります。

## 3. 表記ルール

| 対象 | 書き方 | 使わない書き方 |
|---|---|---|
| 開始価格 | `30万円〜`（半角数字、スペースなし） | `30 万円〜` `30万円から` `¥300,000〜` `300,000円から` `10万円台` |
| レンジ | `60〜180万円`、`200〜2,000万円`（1,000以上はカンマ） | `60〜180万円〜`（レンジの後ろに「〜」を重ねない） |
| 初期＋月額 | `60〜180万円＋月額3〜8万円`（全角＋、スペースなし） | `＋月額運用3〜8万円` `+ 月額運用 3〜8 万円` |
| 月額 | 文中は `月額10万円〜`。カードは数字に「月額」「初期費用」のラベルを付ける | `10万円/月〜` `月10万円〜` |
| 税 | 料金表の見出し・注記に `（税別）`。/pricing の lede に「表示価格はすべて税別です」 | 税表記なし |
| 期間 | 3ヶ月未満の制作期間は `週間`、それ以上は `ヶ月`。`8〜12週間` `公開後3ヶ月` | `か月` `ヵ月`、`8〜12 週間` |
| プラン名 | カードは `LIGHT / STANDARD / PREMIUM`、文中は `Light / Standard / Premium`。DX は `PoC / 本実装 / 運用` | `POC` |
| 無料相談・返信 | `初回相談無料（オンライン30〜60分）`、`営業日24時間以内` | — |

- 円単位の数字を書くのは JSON-LD の `price` だけ。
- 静的LPの運用プランは固定額なので「〜」を付けない（`月2万円`、監理団体LPは `2万円／月`）。LP の中で一貫していれば、この書き方のままでよい。
- 市場相場・補助金額・他社比較の数字（自社の料金でないもの）と記事タイトルは、このルールの対象外。変えない。
- 既存の言い回しが意味として同じなら、無理に書き換えない（数字が同じであることが目的）。

## 4. `pricing-check.js` が見ていること

依存パッケージなしの Node スクリプトです。`NORTIQ_PRICING` とヘルパーを評価して、リンク先ごとに
「書いてよい金額・期間・相談時間」の集合を作り、手書きの数字がその中に在るかを見ます。
文字列はヘルパー（画面と同じ関数）で作るので、書式を検査側で二重に持ちません。

| 検査 | 対象 | 内容 | 結果 |
|---|---|---|---|
| a | `data/blocks.json` `data/catalog-pages.json` | `target_url` / `url` ごとに、文中の金額・期間・相談時間が許可集合に在るか。金額と期間の組の取り違え | 失敗。金額があるのに「税別」が無い variant・summary は警告（字数上限があるため） |
| b | `lp/service/*/index.html` | JSON-LD Offer の `price` `minPrice` が `lps` の `min`×10000 と一致、`valueAddedTaxIncluded`、title・meta・og・twitter・JSON-LD の name / description の金額と期間、料金表（`plan__price` `plan__period`）、本文の金額、「30万円〜」と「4週間」のような組の取り違え、金額の近くの「税別」 | 失敗 |
| c | リポジトリ直下の `*.jsx` | 2つのブロックの外に金額の生リテラル（`\d+\s*万円`、`¥\d{1,3},\d{3}`）が無いか | 失敗 |
| d | `content/blog/*.md` | 自社語（当社・弊社・Nortiq・私たち・ノーティック）と金額が同じ行にあり、許可集合に無い金額。金額の手前のサービス名（Web制作・チャットボット・DX・保守）から、どのサービスの料金かを推し量る | **警告のみ** |
| e | a〜c の対象（d の行は警告） | 表記の lint:「30 万円」「万円から」「◯万円台」「60〜180万円〜」「か月」「円単位」「万円/月」「月額運用3〜8万円」 | 失敗 |
| self | ヘルパー | ヘルパーの出力が表記ルールを守り、この検査で読めること | 失敗 |

失敗が1件でもあれば exit 1、警告だけなら exit 0 です。`--no-warn` で警告を隠せます。

### 誤検知のとき: 許可リスト

自社の料金ではない数字（市場相場・補助金額・他社比較・会社情報・記事見出し）は、`pricing-check.js` の先頭の
`ALLOW`（JSX と LP の本文）か `ALLOW_BLOG`（記事）に足します。

```js
{ file: 'service-pages.jsx', has: 'them="200〜500万円"', why: '/dx 他社比較の他社相場' },
```

- **行番号では指定しない**（編集のたびにずれる）。`file` と、その行に含まれる文字列 `has`（または正規表現 `re`）で指定する。
- `why` に理由を必ず書く。「自社の料金だが直すのが面倒」は理由にならない。
- 元の行が消えると「許可リストの項目が使われていません」という警告が出る。そのときは項目も消す。

### この検査で見つけられないもの

- 自社語の無い行に書かれた自社料金（記事の表の中など）。記事を直すときは、表と前後の段落を目で確かめる。
- プランの中身（features）やページ数の文言の食い違い。数字（金額・期間・相談時間）だけを見ている。
- PDF と画像の中の数字。
- 「Web制作の 25万円〜」のように、別サービスの料金とたまたま同じ数字（data/*.json と LP はリンク先ごとに見るので拾える。
  記事はサービス名が近くに無いと拾えない）。

### まだつないでいないところ

`build.js` と `.github/workflows/prerender.yml` からは呼んでいません（どちらも今回の対象外）。
料金を触ったら手で `npm run pricing:check` を回してください。CI に入れるなら、ビルドの前段に1行足すだけです。
